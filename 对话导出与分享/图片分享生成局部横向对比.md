# 对话图片分享生成局部横向对比

> 对比对象：AIO Hub、NextChat、Cherry Studio、DeepChat、Risuai、VCPChat、RikkaHub、LobeHub
>
> 对比更新日期：2026-11-05
>
> 依据：文末八篇单项目调查笔记及各自代码快照，笔记更新日期与代码提交日期分别以单篇元数据为准；均为静态源码调查，未运行生成图片。AstrBot 的导出笔记只确认 JSONL 数据交换，未形成 PNG 生成主链。RikkaHub 笔记同时覆盖 Markdown 文本导出、配置二维码与全量备份，本对比只取其 PNG 长图生成主链。Open WebUI 的文档交付止于浏览器端 PDF（样式化与纯文本两种模式，后端 PDF 端点已移除），未找到 PNG 生成；VCPMobile 与 Jan 在各自类目笔记中只有入站分享收件箱与表格导出，不构成图片生成链路。
>
> 对比方法：按导出源、分享稿生产、捕获路线、生成历史、交付方式和明确边界比较“把对话内容生成 PNG/长图”的主链
>
> 对比范围：对话或消息图片生成；不覆盖模型生图、原图下载、Artifact 图片导出、普通窗口截图、PDF/HTML 和远端链接分享。OpenClaw 本次未找到对话整图/长图与图片分享链路（其导出为 HTML/Markdown/JSONL 本机文件），不属于本对比的图片生成比较维度；RikkaHub 的 Markdown 导出、配置二维码与全量备份链路不在本对比范围；LobeHub 的文本/PDF/JSON 导出、链接分享页与工作区站点发布同样不在本对比范围
>
> 文档定位：实现学习与跨项目横向比较，不作为整改方案

## 结论摘要

八个项目形成四种清晰路线：AIO Hub 是“分享稿工作台”，NextChat 是“固定模板重排”，Cherry Studio 是“离屏复刻完整消息列表”，DeepChat 是“现场滚动分段截图”；Risuai 属第三条路线家族内的变体，介于 Cherry Studio 与 DeepChat 之间，走“无分享稿表面的逐消息现场捕获”；VCPChat 则是“单消息原文重渲染后的查看器截图”；RikkaHub 也逼近离屏路线，离屏复刻的对象是专用导出组件，与 Cherry Studio 复刻完整消息列表的做法不同，固定 540dp 宽并裁掉文档/音视频与工具内容。LobeHub 用独立分享版式包裹复用的消息组件，单次成像后可直接输出 JPG/PNG/SVG/WEBP。八者都能把聊天内容变成 PNG，但导出源、可编辑性和结果生命周期差异很大，不能只用“支持图片导出”一个布尔字段比较。

AIO Hub 是当前唯一提供多次生成结果历史的样本；NextChat 提供最明确的任意消息选择和固定品牌页；Cherry Studio 为完整 Topic 专门解决分页、虚拟化和本地图片内联；DeepChat 则用短按/长按快速覆盖当前问答组与截至当前消息的长截图。Risuai 全量挂载后逐消息截取现场 DOM 合并为单张 PNG，无预览、无尺寸或水印配置，也没有 Canvas 上限治理，长会话可能触及平台单画布上限。RikkaHub 与它们一样是即时生成、无历史，但多了一个固定 10000dp×10000dp 的尺寸上限，并会把图片额外写入相册。LobeHub 同样即时生成、无历史，六项开关只改变版式与元素显隐，不改变正文。

## 1. 导出源的对象差异

AIO Hub 和 NextChat 都允许逐条选择，但来源不同。AIO Hub 的截图对话框只有一处实例化（`ChatArea.vue`），消息一律来自当前活动路径加最多 `displayPresetCount` 条开场白展示消息：隐藏分支和压缩隐藏节点不进入，但禁用节点与压缩摘要节点仍在候选内；消息菜单、树图节点菜单与导出弹窗的「生成分享长图」都汇入同一对话框，导出弹窗设置的区间不会传入截图对话框。NextChat 明确从当前 Session 的消息数组筛选，并可在前面整体加入 Mask context。

Cherry Studio 面向 Topic 建立独立数据加载链：每页 200 条、包含 siblings，再经数据层投影到完整离屏列表。它解决的是当前页面未加载全部历史与虚拟列表无法完整截图的问题。siblings 取舍在数据层完成：助手消息按模型分桶、每桶只保留活动成员或该桶最新兄弟，用户分支只保留会话路径上的那条，因此重生成队列在图中只有一条气泡，纯多模型组则保留多条。取图入口有两条：列表菜单经 action bus 挂载专用捕获宿主，历史记录面板等菜单由当前 live 列表响应，两者共用同一捕获工具与串行队列。

DeepChat 不重新查询数据，范围完全由当前 DOM 计算。短按找当前 assistant 与父 user 的外接矩形；长按从第一个已挂载消息截到当前消息。因此“从顶部”指当前消息容器中的顶部，与数据库会话第一条可以落在不同位置。

RikkaHub 这两种做法都不用：入口是聊天列表的多选态，勾选结果按消息节点 id 汇总交给导出面板，既不查询完整会话树也不读取页面 DOM。导出时按下标顺序遍历选中节点，每条只取当前选中的那条消息，因此范围同样是“消息序列”而非“分支树”，也没有 range、时间或角色过滤。消息面板的「分享」动作把会话开头到该条消息全部选中，实际是“截取到此处”的整段导出。

LobeHub 的范围固定为当前 Topic 的全部消息，没有勾选、连续区间或分支选择；单消息分享弹窗只对助手消息开放，一次取其一条。截图、文本与 PDF 共用聊天现场的展示口径，JSON 另取数据库原始口径。

## 2. 分享稿生产能力形成明显梯度

### AIO Hub：可迭代分享稿

AIO Hub 把消息选择、布局覆盖、背景、水印、品牌和元素显隐作为分享稿状态。预览与最终生成分离：配置实时变化，PNG 只在用户手动生成时创建。这个结构允许在同一对话框内保留多个输出并识别哪些结果已经落后于当前配置。

### NextChat：固定品牌模板

NextChat 也重新排版，而非截当前视口，但模板固定。用户可以选择消息和 context，不能改变图片宽度、主题、品牌、水印或消息元信息。图片顶部主动补充模型、话题和参与者信息，输出更接近一张标准分享卡。

### Cherry Studio、DeepChat 与 Risuai：复刻现有表面

Cherry Studio 的离屏 `MessageList` 是工程化的完整复刻，捕获前预内联本地与远端图片，远端抓取受并发池与时间预算约束，捕获调用经 `ExportService` 的 Promise 队列串行执行；DeepChat 则直接移动当前滚动表面并截图，Risuai 介于两者之间：全量挂载后对现场消息逐个转 Canvas 再纵向合并。三者都没有独立分享稿配置；优点是都与聊天现场一致，限制是导出内容容易受消息列表显示规则、折叠状态和主题影响。

### VCPChat：单消息原文的独立阅读截图

VCPChat 不截取当前聊天气泡。阅读模式按 Agent/群组、Topic 与 message ID 从 `history.json` 取原始 content，交给 text viewer 重新解析，再截取该查看器内容容器。它满足“对话内容 -> PNG”的抽取与生成主链，但范围只到单条消息，且多模态数组在该阅读模式中可能降级为空文本，不能与完整 Topic 或任意选区长图等同。

### RikkaHub：固定参数的离屏导出组件

RikkaHub 没有分享稿状态，导出面板只提供 Markdown 与图片两个按钮；“包含思考内容”开关同时作用于 Markdown 与图片且默认开启，“展开思考”只在图片侧生效，并在前者关闭时置灰。宽度（540dp）、主题（跟随应用主题）、标题/时间/水印与助手消息的模型图标模型名全部写死在导出组件里，用户不能改变布局、背景或品牌。它既不像 AIO Hub 那样保留可迭代的分享稿配置，也不像 Cherry Studio 那样复用聊天消息列表，而是另建一个只服务于导出的 Compose 组件。

### LobeHub：配置有限的专用分享版式

LobeHub 在四 Tab 导出弹窗里建了独立分享版式：顶部品牌与模型标签、可选 system 区、消息列表与可选页脚，成像前就是最终 DOM，没有独立的渲染/生成两条管线。可调项只有六项——宽度（480px 或 100%）、装饰背景、页脚品牌、system 区、模型/插件标签与图片格式；没有水印、品牌覆盖、分页或字体配置，也没有结果历史。它比 AIO Hub 少了可迭代的工作台，比 Cherry Studio 多一层自定义版式。

## 3. 长图技术路线与失败边界

| 路线 | 收益 | 已确认限制 |
|---|---|---|
| 逐消息 DOM -> Canvas -> 拼接（AIO Hub） | 可按消息控制间距、背景与装饰；不必滚动现场 | 最终大 Canvas 的平台上限和极端内存尚未验证 |
| 整个模板 DOM -> 单 Canvas（NextChat） | 实现紧凑，预览与输出结构直接 | 未见分段、分页或明确最大尺寸处理 |
| 完整离屏或隐藏捕获表面 -> 单 Canvas（Cherry Studio） | 可先加载完整 Topic，规避现场分页与虚拟化；捕获调用串行执行 | 宽/高超过 32767px 明确失败 |
| 多次窗口截屏 -> 主进程拼接（DeepChat） | 不依赖 DOM-to-SVG 对复杂内容的兼容性 | 默认最多 30 段，命中上限静默截断；滚动期间内容必须稳定 |
| 现场逐消息 DOM -> Canvas -> 纵向合并（Risuai） | 逐消息截取现场 DOM，所见即所得且无需滚动现场 | 全量挂载 DOM 压力大；无 Canvas 上限治理，长会话可能超过平台单画布限制 |
| 原文消息 -> 独立查看器 -> PNG（VCPChat） | 不依赖当前聊天列表挂载，明确以 message ID 限定抽取源 | 只支持单条消息；最长边限制 14,000px；富内容保真未运行验证 |
| 专用分享版式 DOM -> 单次成像（LobeHub） | 版式与输出格式可配，复用现场渲染器 | 无分段与尺寸上限处理；远端图片依赖公共 CORS 代理，保真未运行验证 |
| 专用 Compose 组件离屏复刻 -> 单张位图（RikkaHub） | 复用应用主题与消息组件，不依赖现场挂载或滚动 | 单张 10000dp×10000dp 上限；固定 100ms 等待异步内容；文档/视频/音频与工具内容被有意裁剪 |

## 4. 富内容与资源策略

AIO Hub 通过专用渲染器复用消息组件，并额外处理 CSS 变量、`content-visibility`、代码/表格 overflow 和壁纸毛玻璃。Cherry Studio 捕获前先等待 `document.fonts.ready`（最长 1 秒），临时内联本地图片、预热 `html-to-image` 缓存，并明确排除交互 HTML Artifact；远端图片经并发上限 4 的抓取池预内联（单源 10 秒、全阶段 20 秒预算），HTTP 错误或显式非图片 MIME 降级为占位，但没有响应大小或文件魔数校验。

NextChat 的正文走 Markdown，消息图片另行插入 `<img>`：Service Worker 可用时图片先落到本应用缓存路径，否则用 Canvas 压缩成不超过 256KB 的 data URL，因此多数图片在 `html-to-image` 内联时不触发跨域污染；用户直接粘贴的第三方 URL 不做代理或跨域处理。DeepChat 直接捕获 Electron 窗口像素，对浏览器已经显示出来的复杂内容更接近所见即所得，但分页接缝、动态高度和折叠状态需运行验证。

RikkaHub 的图像与正文一样进入位图，异步网络图片同样只靠固定延迟等待；与被有意裁掉的文档、视频、音频相比，工具步骤只保留标题行，思考内容默认折叠、需开启“展开思考”才进入长图。VCPChat 的多模态数组在原文重渲染路径上可能降级为空文本，两者的富内容保真都未运行验证。LobeHub 用 `snapdom` 对分享版式 DOM 成像并在成像时内联资源，栅格格式经公共 CORS 代理抓取远端图片；六项开关只改变版式与元素显隐，不改变正文。

八个项目当前都没有在图片工作流中确认到敏感信息自动扫描。AIO Hub 提供较多元素开关，NextChat 可关闭 Mask context；Cherry Studio、DeepChat 和 Risuai 主要继承当前可见内容；RikkaHub 的图片导出会一并裁掉 system 与工具内容、默认折叠思考，但没有内容级过滤开关；VCPChat 从未过滤的单条原始 content 重渲染。

## 5. 版本、交付与“分享”的含义

AIO Hub 的历史项保存 Canvas 和 Data URL，可切换、删除、复制和保存；配置变化只标记旧图过时。该历史没有持久化证据，属于工作台运行时版本，不应与会话分支或文件版本混为一谈。

其余七个项目均为即时生成、即时交付。NextChat 虽在图片预览中提供 Share 按钮，但它调用 client `share(messages)` 返回网页 URL，上传重新投影的消息内容，不包含 PNG。RikkaHub 生成后把 PNG 交给 Android 系统分享面板，同时写入相册，同样没有工作台历史。LobeHub 的截图与文本/JSON 一样即时生成，选项变化重渲染即得新结果，没有历史列表。八个项目中，本次都没有确认远端图片托管、图片访问控制、图片撤销或过期。

## 6. 已确认边界与未验证事项

- 本对比全部来自静态源码，没有验证实际像素、字体、图片、代码、数学和工具卡保真。
- DeepChat 历史分页、NextChat 第三方跨域图片，以及 Cherry Studio 两条捕获入口在真实菜单组合下的行为仍待确认；AIO Hub 的候选范围已确认限于活动路径加开场页展示消息。
- RikkaHub 的图片保真（代码高亮、LaTeX/表格、工具步骤与思考折叠）与相册写入、分享面板行为依赖真机与系统版本；它用固定 100ms 等待异步内容，远程图片能否加载完成未验证。
- LobeHub 截图经公共 CORS 代理取远端图片，代理可用性、`snapdom` 成像保真与多格式下载未运行验证。
- 剪贴板能力受浏览器/Electron/Tauri 与平台权限影响，静态调用不能证明所有平台成功。
- “支持保存 PNG”和“支持把图片分享给他人”是两层能力；当前样本主要完成本地交付，远端分享治理需要另看链接分享类项目。
