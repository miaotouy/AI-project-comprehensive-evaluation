# 对话图片分享生成局部横向对比

> 对比对象：AIO Hub、NextChat、Cherry Studio、DeepChat、Risuai、VCPChat
>
> 对比更新日期：2026-08-31
>
> 依据：本目录六篇单项目调查笔记及各自代码快照；均为静态源码调查，未运行生成图片。AstrBot 的本轮笔记仅确认 JSONL 数据交换，未纳入 PNG 主链。
>
> 对比方法：按导出源、分享稿生产、捕获路线、生成历史、交付方式和明确边界比较“把对话内容生成 PNG/长图”的主链
>
> 对比范围：对话或消息图片生成；不覆盖模型生图、原图下载、Artifact 图片导出、普通窗口截图、PDF/HTML 和远端链接分享
>
> 文档定位：实现学习与跨项目横向比较，不作为整改方案

## 结论摘要

六个项目形成四种清晰路线：AIO Hub 是“分享稿工作台”，NextChat 是“固定模板重排”，Cherry Studio 是“离屏复刻完整消息列表”，DeepChat 是“现场滚动分段截图”；Risuai 属第三条路线家族内的变体，介于 Cherry Studio 与 DeepChat 之间，走“无分享稿表面的逐消息现场捕获”；VCPChat 则是“单消息原文重渲染后的查看器截图”。六者都能把聊天内容变成 PNG，但导出源、可编辑性和结果生命周期差异很大，不能只用“支持图片导出”一个布尔字段比较。

AIO Hub 是当前唯一提供多次生成结果历史的样本；NextChat 提供最明确的任意消息选择和固定品牌页；Cherry Studio 为完整 Topic 专门解决分页、虚拟化和本地图片内联；DeepChat 则用短按/长按快速覆盖当前问答组与截至当前消息的长截图。Risuai 全量挂载后逐消息截取现场 DOM 合并为单张 PNG，无预览、无尺寸或水印配置，也没有 Canvas 上限治理，长会话可能触及平台单画布上限。

## 统一比较

| 维度 | AIO Hub | NextChat | Cherry Studio | DeepChat | Risuai | VCPChat |

## 1. 导出源的对象差异

AIO Hub 和 NextChat 都允许逐条选择，但来源不同。AIO Hub 的截图对话框消费调用方提供的 `ChatMessageNode[]`，当前尚未确认它是否总是活动路径；NextChat 明确从当前 Session 的消息数组筛选，并可在前面整体加入 Mask context。

Cherry Studio 面向 Topic 建立独立数据加载链：每页 200 条、包含 siblings，再投影到完整离屏列表。它解决的是当前页面未加载全部历史和虚拟列表无法完整截图的问题。最终图片是否显示非活动 siblings 尚未确认。

DeepChat 不重新查询数据，范围完全由当前 DOM 计算。短按找当前 assistant 与父 user 的外接矩形；长按从第一个已挂载消息截到当前消息。因此“从顶部”表示当前消息容器中的顶部，不自动等同于数据库会话第一条。

## 2. 分享稿生产能力形成明显梯度

### AIO Hub：可迭代分享稿

AIO Hub 把消息选择、布局覆盖、背景、水印、品牌和元素显隐作为分享稿状态。预览与最终生成分离：配置实时变化，PNG 只在用户手动生成时创建。这个结构允许在同一对话框内保留多个输出并识别哪些结果已经落后于当前配置。

### NextChat：固定品牌模板

NextChat 也重新排版，而非截当前视口，但模板固定。用户可以选择消息和 context，不能改变图片宽度、主题、品牌、水印或消息元信息。图片顶部主动补充模型、话题和参与者信息，输出更接近一张标准分享卡。

### Cherry Studio、DeepChat 与 Risuai：复刻现有表面

Cherry Studio 的离屏 `MessageList` 是工程化的完整复刻，DeepChat 则直接移动当前滚动表面并截图，Risuai 介于两者之间：全量挂载后对现场消息逐个转 Canvas 再纵向合并。三者都没有独立分享稿配置；优点是都与聊天现场一致，限制是导出内容容易受消息列表显示规则、折叠状态和主题影响。

### VCPChat：单消息原文的独立阅读截图

VCPChat 不截取当前聊天气泡。阅读模式按 Agent/群组、Topic 与 message ID 从 `history.json` 取原始 content，交给 text viewer 重新解析，再截取该查看器内容容器。它满足“对话内容 -> PNG”的抽取与生成主链，但范围只到单条消息，且多模态数组在该阅读模式中可能降级为空文本，不能与完整 Topic 或任意选区长图等同。

## 3. 长图技术路线与失败边界

| 路线 | 收益 | 已确认限制 |
|---|---|---|
| 逐消息 DOM -> Canvas -> 拼接（AIO Hub） | 可按消息控制间距、背景与装饰；不必滚动现场 | 最终大 Canvas 的平台上限和极端内存尚未验证 |
| 整个模板 DOM -> 单 Canvas（NextChat） | 实现紧凑，预览与输出结构直接 | 未见分段、分页或明确最大尺寸处理 |
| 完整离屏列表 -> 单 Canvas（Cherry Studio） | 可先加载完整 Topic，规避现场分页与虚拟化 | 宽/高超过 32767px 明确失败 |
| 多次窗口截屏 -> 主进程拼接（DeepChat） | 不依赖 DOM-to-SVG 对复杂内容的兼容性 | 默认最多 30 段；滚动期间内容必须稳定 |
| 现场逐消息 DOM -> Canvas -> 纵向合并（Risuai） | 逐消息截取现场 DOM，所见即所得且无需滚动现场 | 全量挂载 DOM 压力大；无 Canvas 上限治理，长会话可能超过平台单画布限制 |
| 原文消息 -> 独立查看器 -> PNG（VCPChat） | 不依赖当前聊天列表挂载，明确以 message ID 限定抽取源 | 只支持单条消息；最长边限制 14,000px；富内容保真未运行验证 |

## 4. 富内容与资源策略

AIO Hub 通过专用渲染器复用消息组件，并额外处理 CSS 变量、`content-visibility`、代码/表格 overflow 和壁纸毛玻璃。Cherry Studio 临时内联本地图片、预热 `html-to-image` 缓存，并明确排除交互 HTML Artifact。

NextChat 的正文走 Markdown，消息图片另行插入 `<img>`；远端图片能否跨域进入 PNG 取决于 `html-to-image` 和资源响应。DeepChat 直接捕获 Electron 窗口像素，对浏览器已经显示出来的复杂内容更接近所见即所得，但分页接缝、动态高度和折叠状态需运行验证。

六个项目当前都没有在图片工作流中确认到敏感信息自动扫描。AIO Hub 提供较多元素开关，NextChat 可关闭 Mask context；Cherry Studio、DeepChat 和 Risuai 主要继承当前可见内容；VCPChat 从未过滤的单条原始 content 重渲染。

## 5. 版本、交付与“分享”的含义

AIO Hub 的历史项保存 Canvas 和 Data URL，可切换、删除、复制和保存；配置变化只标记旧图过时。该历史没有持久化证据，属于工作台运行时版本，不应与会话分支或文件版本混为一谈。

其余五个项目均为即时生成、即时交付。NextChat 虽在图片预览中提供 Share 按钮，但它调用 client `share(messages)` 返回网页 URL，上传重新投影的消息内容，不包含 PNG。六个项目中，本次都没有确认远端图片托管、图片访问控制、图片撤销或过期。

## 6. 已确认边界与未验证事项

- 本对比全部来自静态源码，没有验证实际像素、字体、图片、代码、数学和工具卡保真。
- AIO Hub 截图调用方的完整消息范围、Cherry Studio siblings 的最终显示、DeepChat 历史分页和 NextChat 跨域图片仍待确认。
- 剪贴板能力受浏览器/Electron/Tauri 与平台权限影响，静态调用不能证明所有平台成功。
- “支持保存 PNG”和“支持把图片分享给他人”是两层能力；当前样本主要完成本地交付，远端分享治理需要另看链接分享类项目。
