# 独特功能调查指南

本指南用于发现和调查无法被现有通用类目完整承接、但足以形成项目产品辨识度的能力。通用写作、元数据、证据和调查深度要求见 [`../AGENTS.md`](../AGENTS.md)。本类目采用**项目驱动**而非统一矩阵驱动的方法：不要求每个项目拥有同一种能力，也不因某项目没有独特功能而记缺失或扣分。

## 类目目标

现有 Agent 角色、Agent 工具、LLM 渠道、会话与消息、请求与上下文、Chat UI、消息渲染和生成式运行时等类目用于建立可横向比较的共同基线。它们不能稳定覆盖以下情况：

- 只有一两个项目拥有的完整产品工作流；
- 横跨多个通用类目、拆开后会失去产品语义的组合能力；
- 项目自带的媒体、桌面、协作、记忆、自动化、社会化或研究子系统；
- README、产品文档或模块目录反复强调，但现有调查指南没有对应必查项的能力；
- 名称与常见能力相似，实际事实对象、生命周期或用户目标完全不同的实现。

本类目的产出用于回答：**去除普通 Chat 和通用 Agent 底座后，这个项目还提供了什么难以替代的产品能力？**

## 非对称调查原则

1. **不要求项目齐全**：项目可以有十项候选，也可以写“本轮未发现超出现有类目的独特功能”。
2. **不填对称空格**：横向文档不为其他项目批量填写 `不支持` 或 `N/A`，只记录实际存在且已调查的能力。
3. **不以数量判优**：功能拆得细不等于贡献更大；同一用户工作流只记一个能力族。
4. **不把介绍当实现**：README、官网、截图和更新日志只能生成候选，必须继续定位源码入口、状态和执行链。
5. **不重复已有结论**：能够被现有类目完整解释的能力，回链原笔记并标记“归并已有类目”，不在本类目重写一遍。
6. **允许项目专属术语**：FlowLock、AgentDream、Tape、ACP、Pages、Channels 等名称先按项目自身语义调查，不为追求统一而提前改名。
7. **比较只发生在自然聚类后**：至少三个项目出现相近用户目标、事实对象和生命周期时，才建立局部横向比较；否则保留为稀有能力卡片。

## 候选进入条件

满足下列任一条件即可进入待查清单：

- 项目介绍把它列为主要功能、旗舰功能、核心优势或近期重大更新；
- 仓库存在独立模块、服务、窗口、数据库、协议、插件族或专门文档；
- 它改变了用户与 Agent 的基本关系，例如主动工作、长期生活、多人协作、跨设备连续性或对象持续维护；
- 它组合了三个以上现有类目，单独拆开会掩盖完整体验；
- 当前样本中只有一两个项目拥有，但实现已经形成可走通的主链；
- 现有横向对比或组合构想多次引用它，却没有对应单项目专项结论。

以下内容默认不进入本类目：

- 普通会话、流式回复、Markdown、复制、重试、主题和基础 Provider 配置；
- 只有一个按钮、设置字段、接口声明或未接线类的能力骨架；
- 纯粹的代码量、测试量、框架选型和性能实现，除非它直接形成独特产品契约；
- 仓库外商业版、外部 SaaS 或伴生项目能力，除非本仓库存在明确接入主链；
- 只因命名新颖而被包装成独特能力的常见功能。

## 证据状态

| 状态 | 含义 | 能否进入特色贡献统计 |
|---|---|---|
| `介绍候选` | README、官网、截图或更新日志声明存在，尚未检查源码 | 否 |
| `入口确认` | 找到 UI、路由、协议、模块或持久化入口，尚未走通完整链路 | 否 |
| `主链确认` | 已确认触发、状态、执行、输出及主要持久化/恢复语义 | 可以，需标静态证据 |
| `运行确认` | 主链经过运行、测试或可复现场景验证 | 可以 |
| `声明不符` | 介绍与当前可执行路径不一致，或主链没有接通 | 否，保留差异说明 |
| `归并已有类目` | 已被现有调查完整覆盖，不需要独特功能专项 | 不重复计数 |
| `暂缓` | 依赖外部服务、商业版、缺少环境或当前证据不足 | 否 |

状态必须按证据升级，不能从 `介绍候选` 直接写成项目事实。功能被确认不存在时，写清检查范围和搜索依据。

## 调查流程

1. **扫描项目介绍**：读取根 README、中文介绍、产品文档索引、功能矩阵、近期更新和截图说明，建立原始候选列表。
2. **核对快照**：比较笔记代码快照与仓库当前 HEAD。高频迭代项目存在旧快照时，先标出受影响的既有笔记。
3. **浏览产品表面**：检查路由、窗口、菜单、模块注册、插件目录、服务入口和持久化实体，判断能力是否属于当前仓库。
4. **与既有类目去重**：明确哪些部分已经由角色、工具、上下文、运行时等笔记覆盖，专项只补完整体验和未覆盖链路。
5. **选择调查对象**：优先调查项目介绍反复强调、用户工作流完整、现有统计会因遗漏而明显失真的候选；不要求机械调查全部小工具。
6. **走通主链**：至少确认一次“入口 -> 状态/对象 -> 执行 -> 用户结果 -> 持久化或下一次触发”。主动和后台能力还需确认调度、取消、预算和结果归属。
7. **记录边界**：区分本仓库实现、外部服务、伴生仓库、文档愿景、默认关闭插件和实验性代码。
8. **更新待查清单**：每次调查后更新状态、证据文档、未解决问题和对特色统计的影响。

## 单项能力必查问题

每项独特能力使用一张能力卡回答以下问题；不存在的维度可以省略，不需要为了格式填空。

1. **用户目标**：它解决什么普通 Chat 或通用 Agent 流程无法解决的问题？
2. **入口与触发者**：由用户、模型、后台调度、远端事件、插件还是其他 Agent 触发？
3. **事实对象**：核心对象是会话、任务、记忆、文档、桌面挂件、帖子、工作区、媒体项目还是协议事件？
4. **完整主链**：入口、状态、执行器、结果表面和后续动作如何连接？
5. **持续性**：状态保存在哪里，重启、跨设备、跨会话或跨节点后如何恢复？
6. **主动性与取消**：能力能否在用户不发消息时继续运行？谁能暂停、终止或修改任务？
7. **人机与多 Agent 关系**：用户是否能检查、编辑、批准或接管；其他 Agent 如何发现和参与？
8. **外部依赖与执行域**：哪些部分位于本机、服务端、浏览器、远端节点、商业服务或伴生仓库？
9. **安全与资源边界**：能力获得哪些文件、网络、进程、账号、记忆或宿主权限？失败时如何收口？
10. **独特性判断**：为什么它不能由已有类目中的一个普通子项完整解释？与最接近项目的关键差别是什么？
11. **证据强度**：哪些是源码事实、静态推断、运行确认、介绍声明或尚未验证事项？

## 常见稀有能力标签

标签用于检索和聚类，不是固定类目，也不要求每个项目填写：

| 标签 | 典型含义 |
|---|---|
| `主动 Agent` | FlowLock、follow-up、定时 Agent、后台持续任务 |
| `记忆演化` | AgentDream、用户建模、记忆合并、元思考、长期认知 |
| `Agent 社会` | 论坛、帖子、巡航、Agent 间社会关系和公共空间 |
| `活对象` | 桌面挂件、持续 Artifact、可恢复运行对象 |
| `协同工作区` | Pages、Notes、Canvas、群文件、共享项目空间 |
| `人类工具面` | 将 Agent 工具自动投影为人类可操作 GUI 或工作流 |
| `分布式多模态` | 跨节点工具、文件来源追踪、媒体传输与能力转译 |
| `上下文语言` | TVS、消息配方、宏、注入 DSL 和上下文编译器；通常至少具备可持久化编辑对象、明确编译阶段或顺序、影响最终请求、调试或可解释表面四项中的三项，单段 system prompt、普通模板库和固定摘要算法不据此进入独特功能 |
| `外部 Agent 协议` | ACP 或其他 Agent runtime 作为一等执行对象接入 |
| `自进化 Skill` | 从经验生成、评估和改进 Skill 的闭环 |
| `研究轨迹` | 会话轨迹生成、压缩、导出和训练数据生产 |
| `多表面连续性` | CLI、桌面、Web、IM 或移动端共享同一任务与状态 |
| `创作工作站` | 媒体生成、模型资产、工作流、编辑器和任务队列的组合 |

## 推荐单项目结构

独特功能笔记不要求所有项目使用相同数量的小节。推荐结构如下：

```md
## 结论摘要
## 介绍声明与候选盘点
## 已确认的独特能力
### <能力一：按能力卡组织>
### <能力二>
## 已归并到现有类目的能力
## 声明不符、外部依赖与暂缓项
## 对特色贡献统计的影响
## 未验证事项
## 关键源码索引
```

项目没有进入专项调查的候选时，可以只写候选盘点、归并结果和未验证事项。不得复制其他项目的标题制造表面对称。

## 横向汇总规则

- 横向汇总优先采用“能力卡索引 + 标签聚类”，不建立全项目大矩阵。
- 只有达到 `主链确认` 的能力才能作为主贡献或辅助贡献进入特色统计。
- 同一工作流的支撑机制合并计数。例如会话谱系和压缩谱系若属于同一用户能力，不拆成两个主贡献。
- 工程、安全和可靠性机制单独标注，不与用户可见产品特性混成一个总分。
- README 信息密度不同，不以候选数量直接比较项目；介绍过于简略时，应补看本地产品文档、路由和模块注册表。
- 横向比较必须区分“项目没有该能力”“该能力不适用于项目”“尚未调查”和“介绍声明未被实现”。
