## 结论摘要

RikkaHub 的产品母体是原生 Android 单机 LLM 客户端，它的辨识度在于把两种通常属于桌面或服务端的能力装进了手机应用：一是基于 PRoot 的本机用户态 Linux 工作区，二是把 App 自身变成局域网服务端、用随包 React 前端多端访问。这两项是本次确认的主贡献。本笔记承担这两项及其他候选的路由与归并判断，机制本体分别属于既有主题笔记。

其余候选多数落在既有类目内，只在实现形态上有局部差异。jieba 分词的会话全文检索、二维码渠道交换可以形成辅助能力卡；助手/会话两级注入的机制已由上下文编译类目覆盖；MCP 客户端与 OAuth、模型能力静态推断、消息分支、图片生成工作台、Skill、WebView 运行环境由既有类目完整承接，本类目只做交接。

## 介绍声明与候选盘点

根 README 的功能列表（`README_ZH_CN.md`「功能特色」段）把工作区与 Web 多端访问列在前两项，其余条目（多 Provider、多模态输入、Markdown 渲染、搜索、Prompt 变量、二维码导入导出、智能体自定义、记忆、翻译、自定义请求头体）都能被现有类目承接。README 英文版另列出 Message Branching 与 Silly Tavern character card import，中文版未列，但两者在既有笔记中均已确认实现。

README 与实现存在一处措辞差异：README 写作「类 ChatGPT 记忆功能」，实际实现是纯文本记忆行整表注入系统消息加一个模型可调用的增删改工具，没有嵌入、相似度召回或后台整理，这一实现事实已由检索增强类笔记逐条确认，本笔记不再展开。

## 候选能力与归并判断

以下五张能力卡回答「它是什么、为何独特、机制归属哪篇笔记」。各机制的完整主链与源码定位不在此展开，只在卡末给出一处复查入口。

### 能力卡 1：PRoot Linux 工作区（外部执行体，而非普通工具沙箱）

它是什么：一个由 PRoot 在应用进程内拉起的本机用户态 Linux 工作区，文件区、Linux 根目录与临时区三块持久在应用私有目录，模型经四个工作区工具操作，用户可在终端页用 PTY 接管同一环境。

独特性判断：同类执行域见 AstrBot 的远端/桌面容器与 VCPToolBox 的浏览器托管运行时。RikkaHub 的差别在于执行域是手机本机、由 PRoot 在应用用户权限下做路径与 root 身份重映射，且额外提供一个与模型共享环境的人类终端，因此它既不是「工具沙箱」，也不是「远端执行体」，而是端侧 Linux 工作区。

机制归属：三块区域的划分见 `workspace/src/main/java/me/rerere/workspace/WorkspaceManager.kt:24-45`；创建、安装、shell 执行与审批边界的完整主链，以及 PTY 会话与工具并发关系，由[外部执行体与应用协作笔记](../外部执行体与应用协作/RikkaHub-外部执行体与应用协作调查笔记.md)承接，本笔记只保留上述候选判定。

证据强度：`主链确认`（静态源码可走通入口、安装、执行、结果与持久化）。未在设备上运行 PRoot，未安装真实 rootfs。

### 能力卡 2：内嵌 Ktor Web 服务器 + web-ui 多端访问（宿主进程充当服务端）

它是什么：用户在设置页开启服务器后，App 内的 Ktor CIO 托管随包 React 前端，浏览器经 REST 与 SSE 读写宿主已有的会话、助手与设置数据，手机进程本身就是服务端。

独特性判断：Open WebUI、LobeHub 是「服务端/网页优先，客户端是前端」，这里相反，是 Android 应用内嵌服务端 + 随包前端 + 局域网访问。它与 DeepChat 的远程控制、VCPChat 的多端同属「多表面连续性」，但执行宿主是手机进程、共享的是本地数据，不经过任何中转服务。

机制归属：启动、端口与仅本机选择、mDNS 注册、JWT 与访问口令、路由分组，以及全局事件流携带完整设置快照这一数据流边界，均由[外部执行体与应用协作笔记](../外部执行体与应用协作/RikkaHub-外部执行体与应用协作调查笔记.md)承接；服务器装配入口在 `app/src/main/java/me/rerere/rikkahub/web/WebServerManager.kt:53-108`。

证据强度：`主链确认`（静态）。未启动服务器、未验证 mDNS 解析、JWT 往返与 SSE 重连。

### 能力卡 3：jieba 分词的会话全文检索（人机双面）

它是什么：一张独立于 Room 实体的 FTS5 虚拟表，同一索引同时服务应用内历史检索页、内嵌 Web 的检索接口与模型可调用的会话检索工具，语料不出本机。

独特性判断：NextChat、Cherry Studio 等也有会话搜索，但多数是应用层字符串或简单 LIKE 检索；这里用 SQLite FTS5 加自定义中文分词扩展与随包词典，同一份索引既供人工检索又是 Agent 的检索能力。它属于「关键词召回」谱系里实现较完整的一支，但不能与向量检索或 RAG 管线混为一谈。

机制归属：虚表与 jieba 分词函数的装载、索引维护时机与消息数据模型，由[会话与消息管理笔记](../会话与消息管理/RikkaHub-会话与消息管理调查笔记.md)承接；检索工具的作用域差异（会话引用工具绑定当前助手，会话检索工具在仓库层未传助手参数）已在[检索增强与认知编排笔记](../检索增强与认知编排/RikkaHub-检索增强与认知编排调查笔记.md)记录，本笔记只保留「人机双面」这一定性。

证据强度：`主链确认`（静态）。未在设备上验证分词质量、片段高亮与词典解压失败时的降级。

### 能力卡 4：助手/会话两级提示词注入与 Lorebook

它是什么：在不修改系统提示词的前提下，按常驻或条件（关键词、正则）把文本注入请求，并支持从 SillyTavern 世界书迁移。

独特性判断：在该类目的横向比较里，RikkaHub 的可辨识点是「全局定义 + 助手/会话两级绑定，且会话级为替换而非叠加」，以及导入侧对 SillyTavern 世界书的兼容。这些不构成新的顶层能力，只影响既有类目的横向位置。

机制归属：注入规则对象、五种注入位置、优先级与分组、编译顺序，以及 Lorebook 的触发与展开，都由[上下文编译与提示词工程笔记](../上下文编译与提示词工程/RikkaHub-上下文编译与提示词工程调查笔记.md)完整覆盖，本类目不重复计数，也不在此重述其主链。

证据强度：`主链确认`（静态），有单元测试覆盖作用域、优先级与扫描深度样例。

### 能力卡 5：二维码 Provider 配置交换

它是什么：把一条渠道配置（端点、密钥、请求头等）编码成固定前缀加 Base64 的文本并生成二维码，扫码即反序列化为新渠道实例插入列表。

独特性判断：常见的分享对象是对话或备份文件，以二维码直接交换含凭据的渠道配置少见，产品价值在快速配对，风险面也来自同一设计——编码内容含明文 `apiKey`，没有签名、有效期或来源校验，任何能扫到二维码的人都可得到该密钥。

机制归属：编解码字段与「只校验前缀」的解析实现由 [LLM 渠道管理笔记](../LLM渠道管理/RikkaHub-LLM渠道管理调查笔记.md)承接，本笔记只保留「含凭据、明文传播」这一安全定性作为候选项结论。

证据强度：`主链确认`（静态），有编解码往返测试。未在真机上验证扫码与相册识别。

## 已归并到现有类目的能力

以下能力在当前快照中已形成主链，但可被既有类目完整解释，本类目不重复计数，只标注归并依据与必要交点。

- **MCP 客户端与 OAuth**：MCP 作为外部工具服务接入、工具命名与审批回退、工具目录随服务器合并落库，已由 [Agent 工具](../Agent工具/RikkaHub-Agent工具调查笔记.md)与[外部执行体与应用协作](../外部执行体与应用协作/RikkaHub-外部执行体与应用协作调查笔记.md)笔记确认；OAuth 的发现顺序、PKCE、回环回调服务器与令牌刷新属支撑机制，同落在外部执行体笔记。
- **模型能力静态推断**：`ModelRegistry` 用静态定义表对模型 ID 分词打分推断模态、能力与上下文长度，并在模型加入渠道时快照，是 [LLM 渠道管理](../LLM渠道管理/RikkaHub-LLM渠道管理调查笔记.md)笔记的结论；可辨识点是「能力不来自远端模型卡」，但它是渠道管理的子机制。
- **消息分支与上下文压缩**：同一消息节点下多条备选消息加选中索引表达版本，压缩是用户手动触发的替换式摘要重建，已由[会话与消息管理](../会话与消息管理/RikkaHub-会话与消息管理调查笔记.md)与[对话请求与上下文](../对话请求与上下文/RikkaHub-对话请求与上下文调查笔记.md)笔记覆盖。
- **图片生成独立工作台**：从聊天抽屉进入的专用生成页，走 OpenAI 兼容的图像生成与编辑接口，结果落应用私有目录并登记生成媒体表，配套图库可预览、复制提示词、导出与批量删除；[媒体创作笔记](../媒体创作/RikkaHub-媒体创作调查笔记.md)已判定其为模型生成工作站与资产工作区的轻量组合。需要交接的边界是：它与聊天内图片走不同目录与表，生成结果不能直接作为下一次生成的参考图或聊天附件，也不随内置备份带出。
- **Skill 与本地 JavaScript**：技能是本地目录中的说明文件，经模型工具按启用名单加载；唯一语言运行时是应用进程内的 QuickJS 求值工具，代码块只有展示与 WebView 预览、没有执行入口，已在 [Agent 工具](../Agent工具/RikkaHub-Agent工具调查笔记.md)与[生成式输出与运行时](../生成式输出与运行时/RikkaHub-生成式输出与运行时调查笔记.md)笔记确认。
- **SillyTavern 角色卡与 Chatbox/Cherry Studio 导入**：角色卡映射到助手字段与预设消息、Chatbox 会话导入挂到当前助手、Cherry Studio 只导入渠道，已由 [Agent 角色](../Agent角色/RikkaHub-Agent角色配置调查笔记.md)与[对话导出与分享](../对话导出与分享/RikkaHub-对话导出与分享调查笔记.md)笔记覆盖。
- **多 Provider 协议适配与多 Key 轮询**：三族协议与协议内分支、Key 轮询只决定「用哪个 Key」、重试只发生在同一渠道内，已由 [LLM 渠道管理](../LLM渠道管理/RikkaHub-LLM渠道管理调查笔记.md)笔记覆盖。
- **记忆与网页搜索**：记忆是纯文本整表注入加模型工具，网页搜索是单一 provider 的工具化检索，已由[检索增强与认知编排笔记](../检索增强与认知编排/RikkaHub-检索增强与认知编排调查笔记.md)覆盖。

## 声明不符、外部依赖与暂缓项

- **工作区不是内核级隔离**：PRoot 在宿主用户权限下做路径与 root 身份重映射，`--root-id` 让 rootfs 内进程看到 root；rootfs 内容由用户自行下载、不由应用分发；x86_64 与 arm64 的兼容行为、`PROOT_NO_SECCOMP` 模式均需目标环境验证。
- **内嵌 Web 默认无鉴权**：JWT 与访问口令默认关闭/为空，关闭时整组 API 与静态资源不要求鉴权；全局事件流的设置快照包含访问口令字段，其可见范围等于 SSE 的鉴权范围。以上为当前实现的默认值与数据流事实。
- **二维码明文携带凭据**：分享串含 `apiKey`，无签名、无有效期、无来源校验，不可撤销。
- **视频生成模块存在但未接线**：videogen 具备任务状态机与可取消轮询，但应用侧只有 Gradle 依赖、没有调用点，[媒体创作](../媒体创作/RikkaHub-媒体创作调查笔记.md)与[主动 Agent 与后台任务](../主动Agent与后台任务/RikkaHub-主动Agent与后台任务调查笔记.md)笔记均记为未闭环，本类目不把视频创作计入。
- **定时与周期性主动运行不存在**：当前快照未找到 cron 表达式、WorkManager Worker、AlarmManager 或广播接收器；「时间提醒」「备份提醒」「更新提醒」都不是调度器。后台运行的实质是会话级生成加前台服务保活，属通用类目，不计入本类目。
- **Web 端不暴露渠道管理**：内嵌 Web 只暴露助手级设置，不含渠道列表或 Key；渠道 CRUD 与二维码都在 Android 应用内。

## 对特色贡献统计的影响

建议进入主贡献：PRoot Linux 工作区（外部执行体标签）、内嵌 Web 服务器与 web-ui 多端访问（多表面连续性标签）。辅助贡献：jieba 分词会话全文检索、二维码 Provider 配置交换。助手/会话两级提示词注入按上下文编译类目合并计数，不单独贡献。图片生成工作台、MCP 与 OAuth、模型能力推断、消息分支、Skill、WebView 运行环境均不重复计数。跨项目聚类上，两项主贡献分别落在「外部执行体与应用协作」与「多表面与远程连续性」，可与 AstrBot Agent Sandbox、VCPToolBox 浏览器运行时、DeepChat 远程控制、OpenCode 多表面会话等对照，但事实对象与执行域不同，不合并为同一能力。

## 未验证事项

- 未在设备或模拟器上运行 PRoot：rootfs 安装与解包、`--link2symlink`、`PROOT_NO_SECCOMP` 兼容模式、超时与取消时子进程树是否完全回收、arm64 与 x86_64 差异均未实测。
- 未启动内嵌 Web 服务器：端口占用检查、mDNS 注册与 `hostname.local` 解析、JWT 换取与失效、SSE 在移动网络切换下的重连、多客户端并发订阅与写操作的收敛行为均未验证。
- 未运行工作区终端：PTY 会话与模型工具并发操作同一 rootfs 时的相互影响未观察。
- 未运行 FTS 检索：`libsimple.so` 在目标 ABI 上的装载、jieba 分词与片段高亮在中文/英文/混合文本上的表现、词典解压失败时的降级、全库重建在大会话量下的实际耗时均未验证。
- 未扫描二维码：相机与相册两条解码路径、跨设备传递、分享串在外部应用间的落地形态均未运行核对。
