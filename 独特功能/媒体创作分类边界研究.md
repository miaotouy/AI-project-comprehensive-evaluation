# 媒体创作分类边界研究

> 对比对象：AIO Hub、VCPToolBox、Chatbox、VCPChat，以及被检查的 Open WebUI、Cherry Studio、Jan、LobeHub
>
> 对比更新日期：2026-08-14
>
> 依据：独特功能、Agent 工具、生成式输出与运行时、LLM 渠道单项目笔记；`项目调查笔记` 仓库提交 `b9f9e81`、`d0b4f16`；当前 `媒体创作` 类目指南与横向对比
>
> 调查方式：回溯自然聚类的形成记录，复核三项目的媒体主链和相邻能力，明确独立类目的准入与排除边界
>
> 文档定位：记录类目形成过程与边界，不作为项目排名、原创归属或整改建议

## 结论

“媒体创作”应从独特功能中的“创作工作站”自然聚类升级为正式稀疏类目，但不应把所有媒体相关代码都纳入。最小成立样本是 AIO Hub、VCPToolBox、Chatbox：三者分别提供多模型媒体工作站、服务端可编程媒体插件族和独立图像生成工作台，均有专用入口、独立事实对象、持续性和结果复用链。VCPChat 是重要扩展样本，但其 ComfyGen、Loom、Scriptorium 和 Hi-Fi 播放器分属外部生成配置、交互创作、富文档协作和播放子系统，不应未经对象层对齐就并入核心矩阵。

## 分类创立过程

### 1. 候选阶段

独特功能调查体系在 `b9f9e81`（2026-08-11）建立“创作工作站”标签，初始定义包括媒体生成、模型资产、工作流、编辑器和任务队列。此时它是用于发现跨类目组合能力的标签，不是独立横向类目。

### 2. 能力确认阶段

在 `d0b4f16`（2026-08-12）完成十六项目专项调查后，AIO Hub 的媒体工作站/资产管理器、VCPToolBox 的多媒体生成与媒体插件族、Chatbox 的图像生成工作台均达到 `主链确认`。特色统计据此形成 F48“媒体生成与资产创作工作站”；AIO 的中央资产层另形成 F49，避免把资产基础设施和创作工作站混为同一能力。

### 3. 正式化阶段

本次（2026-08-14）把 F48 背后的共同对象和生命周期抽出来，建立 [`媒体创作`](../媒体创作/媒体创作横向对比.md) 类目。正式化的理由不是功能数量，而是三项目都要解决同一个未被通用 Chat 类目表达的问题：作品生成后如何保留历史、任务和资产，并在下一次创作中继续使用。

## 准入门槛

候选能力同时满足以下三类条件才进入核心比较：

1. **媒体专用契约**：有媒体工作台、渲染器、插件族、模型能力目录或专用工程对象；
2. **持续对象**：保存任务、历史、资产、工程或版本，而非把结果当作一次性附件；
3. **创作闭环**：支持重试、分支、编辑、合成、回流、再引用或异步恢复中的至少一项。

外部模型、ComfyUI、Chrome、FFmpeg 或文件服务可以是执行依赖，但本仓库必须存在明确的接入和结果回流主链。只在 README、设置字段、接口声明或未接线方法中出现的能力保持 `介绍候选` 或 `声明不符`。

## 核心样本为何成立

| 项目 | 共同门槛证据 | 不同产品契约 |
|---|---|---|
| AIO Hub | `GenerationSession`/`MediaTask`/`Asset` 三类对象；历史、任务和资产持久化；动态 Agent 方法和结果回流 | 应用级桌面资产工作站，强调多模型、分支、参数清洁和跨工具复用 |
| VCPToolBox | MediaRenderer 与多生成插件；文件服务托管结果；视频异步回注；资源/源码/帧/采样限制 | 服务端媒体能力供给层，强调协议化插件、可编程渲染和异步编排，不提供同等桌面历史 UI |
| Chatbox | ImageGeneration record + 图片 blob；参考图来源 DAG；取消/恢复/重试；聊天任务回填 | 单一图像工作台，强调记录可追踪、参考图关系和较窄但完整的用户流程 |

## 相邻能力的处理

- **VCPChat ComfyGen**：配置面板与工作流导入已闭环，生成仍由外部 ComfyUI/后端执行；作为 M2/M5 扩展样本，不与本地生成工作站等价。
- **VCPChat LoomAPP**：可编程 Web 应用、页面快照和动作协议形成互动创作运行时；它更接近生成式输出与运行时的活对象，只有涉及媒体工程时才进入本类目交接。
- **VCPChat Scriptorium**：VDOCX/VPPTX、文脉和 Agent PR 构成富文档创作；它是创作工作站的文档分支，但当前作为相邻协同文档能力单列。
- **VCPChat Hi-Fi 播放器**：Agent 可点歌、桌面挂件和 DSP 形成播放子系统；没有已确认的媒体创作输入或工程对象，不能按生成能力重复计数。
- **AIO Hub FFmpeg/弹幕/字幕/OCR**：其中 FFmpeg 回流是媒体工作站的支撑机制；播放器、字幕和转写分别留在工具或生成式运行时，除非形成可保存创作结果。
- **Open WebUI、Cherry Studio、Jan、LobeHub**：本轮已检查的 Artifact、语音/视频、workspace、Mini Program 和本地推理器均被相邻类目解释，未找到独立媒体历史/资产工作站，暂不建空白样本。

## 与现有统计的交接

正式类目不新增产品分，也不改变 F48 的项目归属：AIO Hub、VCPToolBox、Chatbox 仍按原统计口径计入“媒体生成与资产创作工作站”；AIO Hub 的 F49 中央资产层继续单独记录。VCPChat 的 ComfyGen/Loom/Scriptorium/Hi-Fi 依据各自对象和用户目标分别归入扩展或相邻功能族，防止一个项目凭多个旁路模块重复抬高媒体生成贡献。

## 未验证事项

- 分类形成依据来自笔记仓库提交和静态源码调查，没有作者访谈或产品路线图证据；“创立”表示调查体系中的文档分类演进，不是项目作者的历史首创声明。
- 三个核心样本的真实模型调用、媒体视觉/听觉质量、取消和重启恢复尚未统一运行验证。
- VCPToolBox 的外部插件启用、FFmpeg/Chrome 环境、内网资源开关和音频验证码需实机复核。
- VCPChat 扩展是否能在未来统一为“媒体工程”对象，取决于跨模块事实源和版本/导出语义，当前不能预先合并。
