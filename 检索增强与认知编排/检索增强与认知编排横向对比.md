# 检索增强与认知编排横向对比

> 对比对象：VCPToolBox、AIO Hub、Dify、Open WebUI、Chatbox、Jan、SillyTavern、Risuai、VCPChat
>
> 对比更新日期：2026-08-28
>
> 依据：同目录九份以各项目当前源码快照直接调查的单项目笔记
>
> 对比方法：先按长期事实对象、检索循环所有者和结果契约划分谱系，再在局部比较摄取、候选、写回、作用域、预算、观察与恢复；不进行质量、延迟或成熟度排名
>
> 对比范围：知识资产、相似度召回、上下文即时注入、工具化检索、检索驱动认知编排和记忆维护；普通上下文压缩、网页搜索和客户端事件展示不单独视为检索算法
>
> 文档定位：实现学习与跨项目横向比较，不作为整改方案

## 结论摘要

这些项目不是一条从“简单 RAG”升级到“高级 RAG”的单轴序列。它们回答的问题不同：Dify、Open WebUI、Chatbox 和 AIO Knowledge 维护文档资产；Chatbox、Jan、Open WebUI 与 AIO Knowledge 把查询暴露给模型工具循环；SillyTavern、Risuai 及 AIO Recall 在发送前选择文本；VCPToolBox 则把检索产物作为后续阶段的查询方向和可维护的认知资产。评价时应先保持这些边界。

1. **VCPToolBox 是本组唯一已确认的检索驱动认知编排实现。** 元思考链将前一思维簇命中的向量与原查询融合，作为下一簇的查询；RiverMemo 的输出还包含多路候选覆盖、拓扑排序和结构观察。维护者的部署运行观察显示，约 98% 日记来自会话内主动或指导式 DailyNote 写入，再进入索引管线；同一部署目录快照中五类思维簇已有 32 个文件。Dream 占比低，却会生成独立的梦境叙事和联想内容，不应归约为普通整理；快照中 Nova/咕咕梦目录分别有 226/209 文件。代码快照中的 Dream manifest 为 `.block`，故此运行状态属于已启用的具体部署，不能外推为默认安装或从文件数推断来源比例。详见 [VCPToolBox 单项目笔记](VCPToolBox-检索增强与认知编排调查笔记.md)。
2. **知识资产管线的重心在生命周期与治理。** Dify 维护租户级 Dataset、Document、分段、异步索引、发布版 Pipeline 和运行记录；Open WebUI 维护知识库、文件、集合、外部知识连接和授权；Chatbox 与 AIO Knowledge 在本地持久化文件、chunk 和索引。它们都能有混合检索、重排或工作流，但当前主链的默认产物仍是本次问题的候选内容或来源。
3. **工具循环不自动构成查询规划。** Chatbox、Jan 和 Open WebUI 把工具结果回送给模型，模型可再查询或读块。AIO Knowledge research 还有由命中、缺口和粗略冲突触发的固定 search/read 循环。它们的循环所有者分别是模型或规则，并未确认有固定的“结果向量生成下一阶段查询”协议。
4. **发送前选择与历史记忆是另一组问题。** AIO Recall、SillyTavern World Info/Vector Storage 和 Risuai Lorebook/记忆引擎决定本轮携带哪些条目或历史。Risuai Hypa V3、SillyTavern Data Bank 和 AIO Recall 均有多信号候选或扩展，但输出仍是 prompt 文本，不是连续认知路径。
5. **记忆写回必须与检索分开比较。** Open WebUI 的 Persistent Memory 可由工具或默认关闭的后台复盘直接写入用户集合；SillyTavern 摘要随新消息写回聊天；Risuai 记忆压缩写回聊天字段；VCPToolBox 的 DailyNote 是会话内显式工具写入。其 Dream 在实际启用部署中是低频的独立梦境叙事和联想链，后续变更仍须管理员审批。写回存在不代表检索已成为认知编排。
6. **VCPChat 是远端能力的客户端观察和操作面。** 它能请求日记搜索、呈现远端关联结果、显示 RAG/元思考事件和发送审批响应，但当前仓库不实现远端的摄取、Embedding、排序或元思考。

## 谱系地图

```text
长期资料与索引
  |- 知识资产管线：Dify、Open WebUI、Chatbox 知识库、AIO Knowledge
  |- 模型工具化检索：Chatbox、Jan、Open WebUI、AIO Knowledge
  `- 相似度/混合候选：上述资料库，以及 AIO Recall

发送前上下文选择
  |- AIO Recall（占位符和 binding）
  |- SillyTavern（World Info、摘要、Vector Storage/Data Bank）
  `- Risuai（Lorebook、聊天记忆压缩和历史语义选择）

连续认知方向与长期维护
  `- VCPToolBox（TagMemo/RiverMemo、元思考链、DailyNote 会话记录；可选 AgentDream）

远端消费与观察
  `- VCPChat
```

谱系可以重叠。例如 Open WebUI 同时有知识库、native 检索工具和用户记忆；AIO 同时有 Recall 与 Knowledge。图中归类描述调查到的执行链，不表示产品全部功能，也不表示质量排序。

## 局部比较

### 知识资产摄取与检索治理

| 维度 | Dify | Open WebUI | Chatbox 知识库 | AIO Knowledge |
| --- | --- | --- | --- | --- |
| 资产边界 | tenant Dataset、文档和分段 | 知识库、文件、集合与外部连接 | 单知识库及其文件 | 每资料库独立 SQLite、文档和 chunk |
| 摄取执行 | tenant 隔离 Celery 队列和阶段状态 | 文件状态与向量化任务/修复 | 主进程常驻 worker | 可领取任务、lease 和前端 worker |
| 候选 | 关键词、向量、全文、混合及跨库处理 | 向量、BM25 hybrid、重排 | 向量 top-20，可选 rerank top-5 | FTS/BM25、向量、邻块与跨域 RRF 服务 |
| 访问边界 | tenant 与 Dataset 权限 | 所有者、组和 AccessGrants | 本地会话选择的单库 | Agent `knowledgeAccess` allowlist |
| 运行记录 | 查询审计、trace、Pipeline/节点执行 | 事件、日志和 source 事件 | 日志及附件开发面板 | trace、来源、进度和降级理由 |

这四者可比较资料的可编辑性、索引恢复、混合候选、来源契约和授权位置。不能只按“是否支持 rerank”排序：Dify 的 Pipeline 强调摄取发布，Open WebUI 还接入外部库，Chatbox 的知识库目前是桌面端单库，AIO Knowledge 以本地 Agent 授权及按空间检索为主。

### 模型按需检索

| 维度 | Chatbox | Jan | Open WebUI native | AIO Knowledge |
| --- | --- | --- | --- | --- |
| 发现对象 | 绑定知识库或本回合大附件 | 当前 thread/project 附件 | 有权限且绑定的知识库/文件 | Agent allowlist 内资料库 |
| 读取粒度 | chunk；附件可再读父块 | chunk；可按范围读块 | 语义片段、单文件或受限文件工具 | search、chunk read、research |
| 工具循环 | AI SDK 继续步骤 | tool output 自动续发 | 通用工具循环最多 256 次 | 模型工具调用；research 内部另有规则循环 |
| 特有预算 | 附件召回 20、返回最多 12 | 默认 top-k 3 | 工具迭代上限和文件工具输出上限 | research 默认 3 轮、12 次读取/查询、120 秒 |

它们共同的事实是“模型可基于前一工具结果再行动”。静态代码不能保证模型会形成稳定计划。AIO 的 research 虽有补充查询，但补充条件是固定规则，不应同 VCPToolBox 的向量阶段反馈混同。

### 发送前上下文选择与历史维护

| 维度 | AIO Recall | SillyTavern | Risuai | Open WebUI Persistent Memory |
| --- | --- | --- | --- | --- |
| 主对象 | 完整条目和带权标签 | Lorebook、摘要、聊天/附件向量 | 三源 Lorebook、聊天摘要/历史 | 用户事实和路径化 context 记忆 |
| 激活/候选 | 关键词、内容向量、标签邻近/共现 | 关键词/规则递归或 KNN | 关键词/正则递归；摘要相似度 | 用户消息窗口的语义 top-8 与路径邻域 |
| 输出 | 格式化条目替换占位符 | prompt 槽和历史重排 | system 文本 | system 中的 memory context |
| 写回 | 用户或 Agent 工具显式写条目 | 摘要在新消息后写聊天 | 发送时压缩写聊天字段 | API/工具写入；可选后台复盘直写 |

这些实现都能改变本轮 prompt，部分还会写回长期或聊天级状态。AIO 的标签扩散、SillyTavern 的 World Info 递归和 Risuai 的 Lorebook 递归只扩大当前候选或扫描缓冲；它们不产生新的模型回合或由候选向量决定的下一阶段检索。Open WebUI 的后台复盘是主动写回，但它不把检索结果组织成思维簇阶段。

### 检索驱动认知编排与客户端观察

VCPToolBox 的 RiverMemo 和元思考链是本轮唯一能确认“检索结果改变后续查询方向”的主链：前者把结构化候选与拓扑证据作为查询侧读出，后者在预设思维簇间传播融合向量。DailyNote 解决的是会话中的显式记录和索引衔接，不应被误写成 Dream 的附属路径；维护者的部署观察进一步显示，Dream 是低频但内容独立的梦境叙事和联想链，而不只是整理器。它的可比较对象应具备相同的阶段状态、反馈契约、终止条件和路径解释；本组其他项目目前没有该同类实现。

VCPChat 不能填入上述算法比较表。它适合单列比较“用户是否能查看候选来源、检索事件和待审批动作”：客户端显示的信息来自远端返回，断线重连也不证明事件或远端状态可恢复。

## 已确认边界与未验证事项

- 全部单项目结论以静态源码为主。VCPToolBox 另补充维护者的单一部署观察和目录统计：约 98% 日记来自会话内主动/指导式记录，五类思维簇共有 32 个文件，且存在独立梦目录；这些不是统一的召回率、引用正确性、延迟、成本、并发或用户体验 benchmark，也不能由文件数反推写入来源。
- “本次未发现查询反馈”均限定于各笔记列出的入口和搜索范围，不能作为项目或生态的绝对否定。用户可借 Dify Workflow、模型工具调用或插件自行组成额外循环，这不等于其检索组件内建该循环。
- 资料中的提示注入隔离普遍未运行验证。多个项目会将检索文本直接交给模型；来源、引用或权限字段能帮助追溯，不能单独证明内容安全。
- 权限的比较应区分服务端租户/ACL、桌面本地 collection、Agent allowlist 与 UI 过滤。VCPChat 隐藏文件夹、Jan thread scope 或 Chatbox 当前会话附件都不是 Dify/Open WebUI 式多租户授权模型。
- 写回的比较应区分：聊天摘要覆盖、用户事实直接写入、会话内显式工具编辑与人工审批后的后台文件变更。VCPToolBox 的维护者观察表明，前者 DailyNote 是约 98% 的主来源；后者 Dream 是低频但独立的梦境内容链。该比例与内容体验是单一部署的运行事实，其他项目的可逆性、冲突和故障一致性仍须分别验证。
