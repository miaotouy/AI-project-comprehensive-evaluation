# LLM 渠道管理调查指南

本指南用于调查 Provider、Endpoint、模型目录、凭据和请求路由。通用要求见 [`../AGENTS.md`](../AGENTS.md)。开始调查前，应先定义项目中的“Provider、渠道、Endpoint、模型、凭据、Profile”各指什么，避免把不同层级混为一谈。本次生成任务何时请求解析渠道属于 [`../对话请求与上下文/调查指南.md`](../对话请求与上下文/调查指南.md)，聊天界面中的模型或渠道选择器属于 [`../Chat UI/调查指南.md`](<../Chat UI/调查指南.md>)；本类目负责渠道配置与管理，以及从引用到真实连接、协议和凭据的解析机制。

## 必查问题

1. **渠道实体**：Provider 是代码注册项、用户实例还是运行时连接？同一 Provider 能否创建多个 Endpoint？
2. **配置生命周期与管理入口**：创建、查看、编辑、复制、启停、删除、导入、导出和迁移如何实现？配置文件、CLI、TUI、Web 和桌面端分别暴露哪些操作；已有渠道与新建渠道的可操作范围是否一致？默认配置与用户配置如何合并？
3. **凭据边界**：API Key、Header 和代理信息存在哪里，如何进入请求？是否加密、脱敏并排除在导出或日志之外？
4. **模型目录**：模型来自静态表、远端拉取还是用户输入？能力、上下文长度、价格和模态元数据如何维护？
5. **协议与 Adapter**：OpenAI、Anthropic、Gemini 等协议在哪里统一？Base URL、路径、Header 和协议级请求体由谁组装？上游通用上下文从哪里交接？
6. **运行时选择**：会话、Agent、模型名称和用户设置如何解析为具体渠道实例？是否存在别名、语义路由或负载均衡？
7. **多 Key 与健康状态**：Key 如何轮询、限流、冷却、熔断和恢复？健康状态是否持久化？
8. **失败处理**：超时、重试、模型 fallback 和跨 Provider failover 分别在哪一层发生？是否可能重复计费或重复生成？
9. **可观测性**：连接测试、请求日志、错误归一化、用量、成本和延迟是否可见？测试请求是否复用真实运行链路？
10. **平台边界**：浏览器、桌面主进程、服务端和本地模型服务分别承担什么职责？

## 与相邻类目的边界

| 相邻类目 | LLM 渠道管理记录 | 留在相邻类目的内容 |
|---|---|---|
| 对话请求与上下文 | 模型或渠道引用如何解析为具体 Endpoint、凭据和 Adapter | 本次任务的历史、system prompt、工具、附件和通用消息如何构建 |
| Chat UI | 渠道设置或管理界面的操作覆盖，以及可供界面展示的 Provider、模型、能力和连接状态 | 聊天界面中的模型选择器、快速切换、作用域提示和连接错误工作流 |
| 会话与消息管理 | 可持久化的渠道、模型或 profile 引用及兼容字段 | 引用在会话中的绑定、快照、迁移和恢复 |
| Agent 角色 | 角色可声明的模型、Provider 和生成参数契约 | 角色配置、覆盖优先级和角色内部字段 |

## 调查注意事项

- “支持多个 Provider”不等于支持运行时自动故障转移。
- 配置 schema、文件格式或后端 API 支持某项操作，不等于各前端都提供了对应入口。应按配置文件、CLI、TUI、Web 和桌面端分别记录查看、新增、编辑、复制、启停、删除、导入、导出和连接测试等操作，并区分“底层不支持”与“当前界面不可达”。
- 渠道管理界面的操作覆盖属于必查项；视觉样式、动画、键盘操作和无障碍等通用 UI 审计仅在扩展调查中记录。静态代码只能确认界面入口、状态和事件绑定，保存能否成功、修改何时生效及不同平台上的实际表现需要运行验证。
- 模型 fallback、同渠道重试、Key 轮换和跨渠道 failover 应分别记录。
- 设置页的连接测试可能使用独立请求路径，不能据此推断真实聊天请求一定可用。
- 凭据安全结论要同时检查静态存储、进程间传递、日志、备份、导出和前端可见性。

## 横向比较字段

至少记录：渠道实体粒度、自定义 Endpoint、配置入口及操作覆盖、凭据存储、模型目录来源、协议适配位置、多 Key 策略、重试层级、跨渠道故障转移、路由依据和可观测性。配置入口及操作覆盖应按前端分别描述，不能只用“有 UI”概括。
