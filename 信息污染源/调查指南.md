# 信息污染源调查指南

本指南用于调查非预期、不可信或跨边界的信息如何进入模型上下文、用户界面、执行环境、持久化数据或日志。通用要求见 [`../AGENTS.md`](../AGENTS.md)。本类别记录数据流和信任边界，不以堆列危险 API 代替可验证的影响链。

## 范围定义

信息污染至少要说明“来源—转换—落点—影响”。正常的用户配置、明确授权的提示词注入或经过隔离的富内容，不因能够改变输出就自动算作污染源。

常见落点包括：

- LLM 上下文与 system prompt；
- Markdown、HTML、Artifact 和 WebView；
- 工具、代码执行器、插件和 MCP；
- 会话、记忆、知识库、缓存和配置文件；
- 日志、遥测、剪贴板、导入导出与共享内容；
- 认证状态、凭据和跨窗口或跨进程消息。

## 必查问题

1. **来源**：用户输入、模型输出、网页、文件、知识库、工具结果、插件、远程服务和本地 IPC 中哪些数据不可信？
2. **信任边界**：数据在哪些进程、权限域、网络边界和用户身份之间流动？
3. **转换链**：数据经过模板拼装、反序列化、Markdown/HTML 解析、变量替换、正则或协议解析时发生什么变化？
4. **落点**：污染内容最终进入模型上下文、DOM、命令参数、文件路径、数据库、日志还是凭据容器？
5. **持久化与传播**：内容会不会进入长期记忆、摘要、共享配置、导出文件或下一轮模型请求？
6. **防护**：schema 校验、清洗、转义、sandbox、权限审批、来源标记、长度限制和机密过滤位于哪里？
7. **绕过条件**：编码、嵌套结构、重定向、协议差异、跨窗口消息或二次解析是否改变防护效果？
8. **可观察影响**：当前证据能确认的是错误展示、上下文偏移、数据泄露、越权执行，还是仅有潜在入口？
9. **恢复与追踪**：用户能否识别来源、删除污染数据、撤销传播并从日志定位链路？

## 推荐结构

```md
## 结论摘要
## 调查范围与信任边界
## 总体数据流
## 1. 进入模型上下文的来源
## 2. 前端渲染与导航输入
## 3. 工具、插件与代码执行输入
## 4. 持久化、记忆与二次传播
## 5. 凭据、认证、日志与导出
## 6. 现有校验、清洗与隔离
## 7. 已确认的影响链
## 8. 潜在入口与验证前提
## 9. 未验证事项
## 10. 关键源码索引
```

## 调查注意事项

- 分开记录“已确认影响”和“具备危险组合但尚未验证”。后者必须写出缺失的触发条件。
- 证明某一层做了清洗后，还要检查内容是否在后续被解码或用另一种解析器再次解释。
- 提示注入、XSS、命令执行、路径穿越和凭据泄露属于不同落点，不应笼统归为一个问题。
- 不在笔记中放入真实密钥、隐私数据或可直接复用的破坏性载荷；验证样例使用无害占位内容。

## 横向比较字段

至少记录：不可信来源、首个信任边界、主要转换器、最终落点、持久化范围、二次传播、防护位置、用户可见性和验证状态。
