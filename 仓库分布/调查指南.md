# 仓库分布调查指南

本指南用于调查项目的仓库组织、代码与配套资产分布。通用写作、元数据、深度和证据要求见 [`../AGENTS.md`](../AGENTS.md)。本方向描述当前代码快照的结构，不把文件多、目录深或某种语言占比直接解释为质量高低。

## 调查目标

说明一个项目如何把产品能力拆进仓库：主要模块在哪里、各模块量级如何、语言和运行时怎样分工、文档与测试覆盖在哪些区域，以及桌面端、Web、移动端、服务端或命令行等平台代码如何组织。调查结果应同时支持快速理解单个仓库和跨项目横向比较。

## 统一统计口径

1. **快照边界**：只统计当前 commit 的 Git 跟踪文件；不统计 `.git`、未跟踪文件、本地依赖、构建缓存和运行时数据。
2. **量级单位**：同时记录文件数与物理行数。行数包含空行和注释，只用于仓库内部与同口径项目间的近似量级比较，不等同于功能量或开发工作量。
3. **语言识别**：按源文件扩展名归类；JSON、YAML、锁文件、图片和二进制资源不计入编程语言行数。模板内嵌语言按文件主扩展名归类，例如 `.vue` 归为 Vue、`.svelte` 归为 Svelte。
4. **文档识别**：统计下列扩展名，同时按一级目录和 README/翻译副本等用途解释分布。文档文件数不等于独立主题数。

   ```text
   .md、.mdx、.rst、.adoc、.asciidoc、.txt
   ```

5. **测试识别**：按测试目录或测试文件名模式识别，目录与文件名模式如下；夹具、快照和测试资源可计入文件数，测试代码行只统计可识别源码扩展名。

   ```text
   目录名：test(s)、spec(s)、__tests__、e2e、playwright、cypress
   文件名：.test.*、.spec.*、test_*.py、*_test.py
   ```
6. **模块量级**：先按一级目录统计文件数和源码行数，再结合 workspace 清单、包清单、构建入口和主程序入口解释真实模块边界。一级目录只是物理分布，不能自动视为架构模块。
7. **生成与第三方代码**：若仓库跟踪生成代码、vendor、静态站点或大型资源，单独标注其影响；需要时给出“全仓口径”和“排除后口径”，不得静默剔除。
8. **跨平台判定**：必须找到平台构建配置、条件编译、平台专属目录或发布工作流等依据。README 中的支持声明与代码组织分别记录；未运行构建时明确标为静态确认。

仓库随附的 [`统计仓库.ps1`](统计仓库.ps1) 实现上述机械统计口径。它用于生成调查底稿，最终结论仍需结合源码入口和构建配置复核。

## 必查问题

1. **仓库形态**：单包、前后端合仓、monorepo、插件集合还是多运行时工作区？使用什么 workspace 与构建编排工具？
2. **模块分布**：一级目录和核心 package 各承担什么职责？代码主要集中在哪里？是否存在明显的大包、共享层、适配层或扩展边界？
3. **语言分工**：主语言、次语言和平台语言分别服务哪些模块？语言占比是否被生成代码、文档站或 vendored 代码显著影响？
4. **文档分布**：用户文档、开发文档、架构文档、API/协议说明和多语言副本分别位于哪里？数量与主题覆盖如何？
5. **测试分布**：单元、集成、端到端、契约、快照和性能测试分布在哪些模块？哪些主要模块有测试，哪些在本次扫描中未找到同目录或邻近测试？
6. **跨平台组织**：Web、桌面、移动、服务端、CLI 或不同操作系统如何共享代码？是单一响应式实现、平台适配层、条件编译，还是独立入口/独立包？
7. **工程配套**：CI、发布、迁移、脚本、示例、国际化、资源和部署文件占据什么位置？它们是否形成独立维护边界？
8. **结构信号**：目录、workspace 声明与实际依赖方向是否一致？是否存在历史实现并存、同类模块重复、根目录堆积或命名边界模糊等可观察现象？

## 推荐结构

```md
## 结论摘要
## 统计口径与仓库形态
## 1. 模块分布与量级
## 2. 语言分布与运行时分工
## 3. 文档分布与数量
## 4. 测试分布与数量
## 5. 跨平台与发布组织
## 6. 工程配套与结构特征
## 7. 设计取舍与已确认边界
## 8. 未验证事项
## 9. 关键源码索引
```

## 横向比较字段

至少记录：仓库形态、workspace/构建工具、Git 跟踪文件数、源码文件数与行数、前三种语言及占比、主要模块及量级、文档文件数与集中位置、测试文件数与集中位置、测试/源码文件比、产品平台、平台代码组织方式、生成或第三方代码影响。

横向表中的百分比只在统一口径内计算。项目不支持某平台、未发现对应代码、尚未运行验证三种情况必须分开表述。
