# AI 项目仓库分布横向对比

> 对比对象：AIO Hub、AstrBot、Chatbox、Cherry Studio、DeepChat、Hermes Agent、Jan、LobeHub、Manifold Desktop、NextChat、Open WebUI、OpenCode、Pi、SillyTavern、VCPChat、VCPToolBox
>
> 对比更新日期：2026-08-12
>
> 依据：本目录 16 份单项目仓库分布调查笔记及各项目笔记所列 HEAD 代码快照；`统计仓库.ps1` 在 UTF-8 控制台下对 16 个仓库重跑复核
>
> 对比方法：只统计 Git 跟踪文件，按统一扩展名、目录与文件名规则计算源码、语言、文档和测试，再复核 workspace、构建配置与平台入口
>
> 对比范围：仓库形态、模块量级、语言、文档、测试和跨平台组织；不评价代码质量，不以行数推算工作量，未运行全量构建与测试
>
> 文档定位：实现学习与跨项目横向比较，不作为整改方案

## 结论摘要

这些项目的仓库形态可以分为四组：以 Electron/Tauri 为中心的多端客户端、前后端合仓的 Web 服务、按能力拆包的 Agent/CLI monorepo，以及插件/附属程序集合。规模最大的 LobeHub 和 Hermes Agent 都接近 200 万源码行，但前者主要是高度统一的 TypeScript 应用与业务包，后者是 Python Agent 核心、TypeScript 多种 UI、测试、技能和文档的混合仓库；总行数相近，组织含义完全不同。

文件数同样不能直接代表源码规模。Open WebUI 的 5,031 个跟踪文件中有 3,870 个位于 `static/`；VCPToolBox 跟踪了 AdminPanel 的 `vendor` 与 `dist`；VCPChat 最大源码区域是 `vendor`；OpenCode 的文档主要是多语言文档站；Hermes Agent 的大量文档来自 skills。横向理解仓库必须同时看源码行、目录用途和被跟踪的配套资产。

测试数量只表示仓内可见测试资产，不表示覆盖率。Hermes Agent、LobeHub、Cherry Studio、DeepChat、Pi 和 OpenCode 有大规模、按模块分布的测试；Open WebUI 虽声明 Pytest/Vitest 依赖，本快照只识别到 2 个跟踪测试文件；Manifold Desktop 未识别到显式测试树。这些是仓库结构事实，不足以推导运行质量。

### 结构模式

- **共享前端、多壳复用**：Chatbox、AIO Hub、Jan 和 NextChat 让 Web 技术前端被桌面或移动壳复用，但复用深度不同。Chatbox 把桌面/Web/Capacitor 差异收敛进 `src` 的平台层；AIO Hub 明确保留单独 `mobile/src`；Jan 共享 `web-app`，平台能力在 Tauri 插件与 feature 中分化；NextChat 的 Tauri 层最薄。
- **主应用与内部包并重**：Cherry Studio、LobeHub、OpenCode、Pi。Cherry 的主进程/renderer 仍占绝对多数；LobeHub 与 OpenCode 已把数据库、模型运行时、工具和平台入口拆成大量包；Pi 的每个顶层包本身就是可说明、可测试的发布能力。
- **前后端同一发行单元**：AstrBot 与 Open WebUI 都把 Python 服务和 Web 前端合仓。AstrBot 打包时显式把 Dashboard 产物嵌入 Python 包；Open WebUI 的 Python wheel 强制包含前端 build。
- **扩展集合式仓库**：VCPToolBox、VCPChat、Hermes Agent 都含大量插件/skills/附属进程。Hermes 已有 Python/npm workspace 与明确应用边界；VCP 两仓更多依靠目录和进程协议组织，量级统计容易被 vendor、dist、知识与技能资料影响。

## 4. 文档分布

文档组织大致有五种：

| 类型 | 代表项目 | 可观察分布 |
| --- | --- | --- |
| 独立用户/开发文档树 | AIO Hub、AstrBot、LobeHub、Jan | `docs` 按 user guide、architecture、self-hosting 或语言拆分 |
| 文档站及翻译副本 | OpenCode、Hermes Agent | OpenCode 的 `packages/web` 有 616 份文档；Hermes 的 `website/docs` 与 `website/i18n` 共 709 份 |
| Skills/知识本身就是内容资产 | Hermes Agent、VCPToolBox | skills、optional-skills、SkillBridge、knowledge 贡献大量文档，不能都视为开发说明 |
| 文档与实现共置 | AIO Hub、Cherry Studio | 工具说明、主进程说明或 Agent 指令进入源码/隐藏目录 |
| 仓内只保留入口说明 | Open WebUI、SillyTavern、Manifold Desktop | 当前仓的 Markdown/TXT 数量少，完整文档可能在外部站点或尚未展开 |

特别的统计偏差包括：LobeHub 的两个 changelog 文件合计约 4.8 万行；Cherry Studio 的 `v2-refactor-temp`（166 份）与 `.agents/skills`（87 份）合计 253 份；AstrBot 的 441 份文档中有 200 份 changelog；VCPToolBox 的 692 份文档中，SkillBridge 和 knowledge 占多数。

## 7. 统计边界与复算

本次统一统计由 [`统计仓库.ps1`](统计仓库.ps1) 生成，规则见 [`调查指南.md`](调查指南.md)。复算示例：

```powershell
./统计仓库.ps1 -WorkspaceRoot E:\works\git -Projects @('aio-hub', 'AstrBot')
```

本次对象是工作区内 16 个 AI 项目仓库。`UserScript` 是通用用户脚本集合，未作为 AI 产品项目纳入；`项目调查笔记` 自身也不属于调查对象。统计结果绑定各单项目笔记所列 HEAD 代码快照（jan、Manifold-Desktop、open-webui、SillyTavern 自上一批统计起无提交，数字未变）；项目更新后应重新运行脚本并同步更新单项目笔记与本文。

口径差异：脚本在 GBK 控制台（Windows PowerShell 5.1 默认）下会把含中文路径的跟踪文件解码成乱码而漏计，复算应在 UTF-8 控制台（`[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`）下运行。aio-hub、VCPChat、VCPToolBox 三行数字按各自单项目笔记为准：aio-hub 文档为 `*.md` 口径（372 份，全模式含 `.txt` 为 376）；VCPChat 按笔记重算口径（源码 598 文件/334,822 行，剔除 vendor/测试/文档；文档 48/9,919 为 `*.md` 且不含 vendor/测试内；测试 24/6,543 含 `tests/` 与 `SovitsTest/`；vendor 文本 22/42,870 单列）；VCPToolBox 文档 692/161,572 包含 `knowledge/`、`dailynote/` 等文本知识资产。统一脚本口径（UTF-8 运行）对照值：aio-hub 源码 2,364/727,324、文档 376/73,778、测试 341/59,547；VCPChat 源码 536/348,804、文档 64/13,348、测试 20/5,868；VCPToolBox 源码 1,283/459,877、文档 692/161,572、测试 32/7,066（与笔记的差值为计行方式造成的几十行以内偏差，VCPToolBox 文档数完全一致）。
