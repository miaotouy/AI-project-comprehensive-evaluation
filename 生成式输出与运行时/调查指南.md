# 生成式输出与运行时调查指南

本指南用于调查模型产出的内容如何成为可展示、可交互、可执行、可编辑和可持续维护的对象。通用要求见 [`../AGENTS.md`](../AGENTS.md)。输出对象在生成任务中如何被创建或更新属于 [`../对话请求与上下文/调查指南.md`](../对话请求与上下文/调查指南.md) 的交接范围；用户如何从聊天工作台打开、关闭或返回对象属于 [`../Chat UI/调查指南.md`](<../Chat UI/调查指南.md>)；普通 Markdown、工具卡和附件如何映射为消息 DOM 属于 [`../消息渲染器/调查指南.md`](../消息渲染器/调查指南.md)。本类目从“输出获得独立对象身份或专用运行环境”开始。

## 类目定义

**生成式输出与运行时**研究以下完整链路：

```text
模型文本、结构化事件或工具结果
  -> 输出协议与对象模型
  -> 增量生成、替换或补丁
  -> 消息内、侧栏、工作区、画布、桌面或外部文件投影
  -> 静态渲染、声明式组件、脚本沙箱或代码执行环境
  -> 用户交互、编辑和宿主能力请求
  -> 持久化、版本、分享与导出
  -> 状态或源码重新进入模型上下文
```

满足下列条件之一的能力应纳入本类目：

- 输出拥有区别于普通消息正文的稳定 ID、类型、状态或生命周期；
- 输出进入专用预览、编辑器、画布、桌面挂件、应用窗口或执行环境；
- 用户可以操作、编辑、运行、保存、分享或继续迭代该输出；
- 模型能够查询已有输出的状态或源码，并对同一对象继续修改；
- 输出通过受控桥接调用网络、存储、模型、媒体或宿主动作。

仅有 Markdown 样式、代码高亮、KaTeX、静态 Mermaid 或图片展示时，默认留在消息渲染器类目。它们只有在获得独立对象、运行、编辑或持久化生命周期后才进入本类目。

## 统一术语

| 术语 | 含义 |
|---|---|
| 输出对象 | 由模型生成或驱动创建、可被单独寻址和继续操作的结果实体 |
| 输出协议 | 模型或工具用来声明对象类型、内容、目标和更新方式的格式 |
| 投影表面 | 对象出现的位置，如消息内、侧栏、独立窗口、文档画布、空间画布或系统桌面 |
| 运行时 | 将输出解释为视觉内容、交互组件或程序的环境 |
| 能力桥 | 输出运行时向宿主请求网络、存储、模型、文件、媒体或其他动作的受控接口 |
| 回流 | 用户修改、运行状态、对象源码或交互结果重新进入模型上下文的过程 |
| 活对象 | 离开生成回合后仍保有状态，并可由用户或模型继续操作的输出对象 |

“Canvas”在不同产品中可能指文档编辑区、空间布局平面、代码工作区或图片编排视图，不能直接作为统一对象类型。“Artifact”也可能只表示一个 HTML 预览。调查时应按对象模型、投影表面和运行能力拆解，不沿用产品名推断机制。

## 必查问题

1. **触发与输出协议**：能力由用户命令、模型自由文本、特殊标记、结构化 part、工具调用还是文件变更触发？协议如何处理半截流、转义、嵌套和误触发？
2. **对象模型**：对象是否有稳定 ID、类型、来源消息、创建者、版本、状态和能力声明？聊天记录、文件和运行实例谁是事实源？
3. **生成与更新链**：系统等待完整结果、逐 token 注入、按 AST 节点更新、应用 diff/patch，还是调用工具直接修改目标？最终化和失败如何收口？
4. **投影表面**：对象位于消息正文、消息旁侧、独立标签页、编辑器、无限画布、桌面、外部浏览器还是本地文件？同一对象能否有多个同步投影？
5. **表现与运行时**：支持静态媒体、图表、声明式组件、HTML/CSS/JS、Canvas/WebGL、语言解释器、完整项目或原生应用中的哪些层级？依赖如何提供？
6. **交互和事件**：用户输入、组件事件、日志、错误、尺寸和运行状态如何回传宿主？交互状态是否在重载后恢复？
7. **编辑与协作**：用户和模型能否修改同一对象？采用全文覆盖、选区编辑、结构化 patch、文件 diff 还是 CRDT？冲突、接受、拒绝、撤销和分支如何表达？
8. **能力与执行位置**：代码运行在宿主 DOM、iframe、WebView、worker、容器、远端沙箱还是本机进程？网络、存储、文件、模型调用和宿主动作按什么能力授予？
9. **持久化与版本**：保存的是源文本、AST、文件树、运行状态、快照还是事件日志？对象如何恢复、复制、分享、导出、删除和迁移？
10. **模型回流与维护**：模型能否查询对象列表、读取源码、观察运行状态、定位目标并继续修改？对象身份如何绑定到后续回合，避免每次重新生成一份？
11. **生命周期与性能**：不可见对象是否暂停、冻结或卸载？定时器、动画、WebGL、媒体、进程和临时文件如何登记与释放？长会话或多对象场景如何限额？
12. **验证体系**：是否覆盖协议解析、流式最终一致性、视觉快照、交互回放、保存恢复、版本冲突、能力边界和资源回收？哪些结论经过运行验证？

## 能力谱系

以下等级描述输出深度，不表示产品成熟度。一个项目可以同时支持多个等级。

| 级别 | 输出形态 | 判定要点 |
|---|---|---|
| `G0` | 格式化回复 | 文本、Markdown 和普通代码块，没有独立对象生命周期 |
| `G1` | 富静态结果 | 图表、媒体、文档或文件可以单独查看、下载或复用 |
| `G2` | 声明式交互对象 | 宿主按 schema 渲染控件，动作由注册表或 intent 处理，不运行模型任意脚本 |
| `G3` | 可执行 Artifact | HTML/JS、代码或项目进入专用运行环境，用户可实际操作 |
| `G4` | 可编辑工作区 | 用户与模型围绕同一对象持续编辑，具备 diff、版本、接受/拒绝或文件管理 |
| `G5` | 环境化活对象 | 对象长期存在于桌面或工作环境，模型可感知其状态、定向修改并持续维护 |

横向对比时还需单列以下轴，不能用一个总等级代替：

- **协议开放度**：自由文本探测、私有标记、typed part、UI schema、文件或项目；
- **更新粒度**：整段、稳定前缀/尾部、节点 patch、文件 diff、目标选择器；
- **投影表面**：inline、sidecar、document canvas、spatial canvas、desktop、external；
- **执行强度**：静态、声明式、浏览器脚本、语言进程、完整开发环境；
- **持续性**：临时预览、会话对象、项目资产、跨会话活对象；
- **闭环程度**：只生成、可交互、可编辑、可查询、可由模型继续维护；
- **能力范围**：无桥接、窄 API、逐项授权能力、宽宿主桥；
- **可移植性**：仅宿主可用、可导出单文件、可分享、可作为标准项目运行。

## 与相邻类目的边界

| 相邻类目 | 本类目接手的位置 | 仍留在相邻类目的内容 |
|---|---|---|
| 会话与消息管理 | 输出对象引用、来源消息或版本标识开始具有独立持久化语义时 | 会话树、消息 schema、索引、迁移和恢复 |
| 对话请求与上下文 | 任务事件已经声明要创建、引用或更新独立输出对象时 | 上下文装配、发送、中止、重试、流式任务和最终回写 |
| Chat UI | 对象打开后进入专用表面或交互结果需要回流时 | 工作台布局、入口、关闭与返回路径、生成反馈和普通消息操作 |
| 消息渲染器 | 内容获得独立身份、专用表面或运行生命周期时 | 气泡、列表、Markdown、普通结构化 part 的显示 |
| Agent 工具 | 工具结果被物化为用户可操作对象时 | 工具注册、参数校验、审批、调度和任务执行语义 |
| Agent 角色 | 角色定义影响输出协议或可用表面时只记录交点 | 人格、提示词、知识、记忆和角色版本 |
| 插件与应用生态 | 模型生成对象如何调用或嵌入插件时 | 插件发现、安装、更新、依赖和发布治理 |
| 文件与项目工作区 | 模型输出如何落盘、预览和回流时 | 通用文件浏览、Git 操作和与生成式输出无关的 IDE 功能 |

同一机制可能跨类目。例如代码解释器的执行调度属于 Agent 工具；生成的图表、文件和可继续操作的 notebook 单元属于本类目。正文应说明交接点，避免重复抄写整条实现。

## 调查方法

- 先找对象身份和事实源，再看视觉组件。一个 iframe 或编辑器只能证明存在承载面，不能证明对象可恢复或可继续维护。
- 至少走通一条“触发 -> 生成 -> 展示/运行 -> 交互或编辑 -> 保存 -> 重新打开”的主链；若模型可继续维护，再补“查询 -> 读取 -> 定向修改”的闭环。
- 将产品文档中的“沙箱”“实时”“可维护”等表述与实际执行位置、IPC、文件写入和资源释放入口对照。文档与实现不一致时并列记录。
- 区分源、投影和运行实例。预览 DOM、源代码文件和持久化对象可能是三份状态，需确认谁覆盖谁、何时同步。
- 普通视觉审美不作为默认审计项；重点记录表达种类、交互语义、运行能力、生命周期和回流机制。
- 不因能力强度高就给出更高评价。声明式组件、严格隔离的 Artifact 和桌面活对象面向不同目标，横向对比应保留适用场景。
