# 消息渲染器调查指南

本指南用于调查消息从状态或流式事件进入可见 UI 的过程。通用要求见 [`../AGENTS.md`](../AGENTS.md)。上下文如何发送给模型属于 [`../对话请求与上下文/调查指南.md`](../对话请求与上下文/调查指南.md)；Composer、会话侧栏和发送控制属于 [`../Chat UI/调查指南.md`](<../Chat UI/调查指南.md>)；HTML、PDF、图片等导出 sink 如何转换对话内容属于 [`../对话导出与分享/调查指南.md`](../对话导出与分享/调查指南.md)。只有相关转换同时改变聊天现场显示结果时，才在本笔记中记录交接点。

## 必查问题

1. **输入模型**：渲染器接收完整字符串、消息 parts、AST、事件流还是 DOM 片段？角色和状态如何分派？
2. **流式链路**：可显示的 chunk 或状态事件进入渲染层后，经过哪些缓冲、合并和节流触发界面更新？完成态如何替换或收口？
3. **列表层**：可见消息列表是否分页、虚拟化或窗口化？高度测量、滚动锚定、活动路径和分支切换后的重绘如何处理？
4. **消息壳层**：用户、助手、系统、错误、工具和 reasoning 消息由哪些组件承载？操作栏如何装配，内容状态如何反馈？
5. **Markdown 管线**：解析器、插件、代码高亮、数学公式、Mermaid、链接和 HTML 按什么顺序处理？
6. **结构化内容**：工具调用、引用、附件、图片、音频、文件、表格和自定义协议如何映射到组件？
7. **内容承载边界**：HTML、iframe、Artifact、脚本、样式、URL 和本地文件协议如何承载或隔离？只调查到足以解释渲染行为和扩展边界，不写成通用安全审计。
8. **内容交互状态**：复制、折叠、预览、下载、工具卡审批控件和键盘操作如何反馈成功、失败与加载？完整操作工作流链接 Chat UI。
9. **性能策略**：增量 AST、缓存、memo、worker、延迟渲染和动画排除用于解决什么问题？是否有测试或基准？
10. **扩展机制**：新增节点类型或渲染插件需要修改哪些注册表、schema、组件和承载边界？

## 与相邻类目的边界

| 相邻类目 | 本类目记录 | 留在相邻类目的内容 |
|---|---|---|
| 会话与消息管理 | 渲染器实际接收的消息、part、活动路径和分页接口 | 持久化 schema、CRUD、分支数据语义、索引和搜索结果 |
| 对话请求与上下文 | 可显示事件进入渲染层后的缓冲、合并和最终替换 | 模型请求、网络流、任务取消、重试、上下文和落盘语义 |
| Chat UI | 消息列表和消息壳内部的组件装配与内容反馈 | 工作台、Composer、会话导航、搜索面板和完整消息操作工作流 |
| 对话导出与分享 | 导出端复用的消息组件、AST/DOM 交接和不支持内容的显示降级 | 导出范围、内容口径、分享稿、文件/图片生成、交付和访问语义 |
| 生成式输出与运行时 | 普通消息内的静态内容和结构化 part | 具有独立身份、专用表面、执行或持久化生命周期的输出对象 |

## 调查注意事项

- 依赖列表只能证明库被安装，必须找到实际入口和运行时调用。
- `dangerouslySetInnerHTML`、`v-html` 或 iframe 本身不能直接证明存在漏洞；需要继续确认清洗、sandbox、CSP、协议限制和内容来源。
- 静态代码能说明采用了虚拟列表或缓存，不能代替长会话性能测试。
- 流式渲染应区分“每个 chunk 更新视图”“更新状态对象”和“持久化消息”三种频率；本类目重点解释第一种，并标出与后两种的交接点。
- 禁止在调查笔记文档中包含改进建议。
- 重点要突出描述其特色能力（如果有）。
- 不要在单篇笔记中提前写横向对比表格，这个要留给专门的对比文档中。
