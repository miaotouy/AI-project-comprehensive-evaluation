# 媒体创作横向对比

> 对比对象：AIO Hub、VCPToolBox、Chatbox、Cherry Studio、LobeHub、NextChat、OpenClaw、Risuai、SillyTavern；扩展样本为 VCPChat
>
> 对比更新日期：2026-09-04
>
> 依据：同目录九份正式样本与一份扩展样本的媒体创作单项目笔记，其中 OpenClaw 依据 [OpenClaw-媒体创作调查笔记](./OpenClaw-媒体创作调查笔记.md)（静态主链确认、未运行真实 Provider/Gateway）；代码快照、静态证据和运行验证范围以各笔记元数据为准
>
> 对比方法：按用户目标、创作事实对象、任务执行、媒体结果、持续性、Agent 回流和治理边界比较；同一项目的支撑机制不单独计为产品功能
>
> 对比范围：具有独立媒体入口、任务/历史/资产/工程对象和结果复用链的图片、视频、音频、动画或可编排媒体创作；普通附件、静态 Artifact、播放器和通用转码工具排除
>
> 文档定位：实现学习与跨项目横向比较，不作为功能数量排名、原创归属或运行质量结论

## 结论摘要

九个正式样本都具备媒体专用入口和生成后的预览、重试或复用链，但任务/历史/资产对象的完整度差别明显；比较的重点是这些对象怎样贯穿创作流程，而不是产品是否调用某一种模型或渲染器。VCPChat 以 Scriptorium 工程满足主链，但与图像/视频工作站的对象和执行域不统一，保留为扩展样本。

九种正式实现并不等价：

- **AIO Hub** 是应用级桌面工作站：媒体会话树、全局任务池和中央资产库相互连接，用户与 Agent 共用生成入口。
- **VCPToolBox** 是服务端媒体供给层：模型通过统一 VCP 工具协议调用渲染/生成插件，结果进入文件服务并可异步回注；它没有独立聊天 UI。
- **Chatbox** 是窄而完整的图像工作台：每次 Image Creator 记录持久化 prompt、模型、参考图和图片，并支持取消、恢复、重试和聊天任务回填。
- **Cherry Studio** 是主进程执行的绘画工作台：`painting` 收据行 + 文件引用构成事实源，工作台历史与 Agent 工具共享 `AiService.generateImage` 生成核心但持久化分叉。
- **LobeHub** 是服务端双媒体工作台：主题/批次/生成三层记录 + S3 资产，lambda/async 双路由执行，重生成、复用设置和主题封面回写构成复用链。
- **NextChat** 是轻量 Stable Diffusion 工作台：持久化任务列表保存参数、结果和错误，支持预览、原参数重试及删除。
- **Risuai** 将聊天生成图像转存为独立 inlay 资产，并在后续提示中再次解析为多模态输入。
- **SillyTavern** 将图像/视频结果附着于聊天消息，消息级 media swipe、slash command 和可选模型工具共享再生成主链。
- **OpenClaw** 是任务化的 Agent 驱动媒体生成：三个媒体专用工具由插件注册的 Provider/能力目录驱动，会话内请求建立后台任务，完成事件唤醒原 Agent 会话并产出带结构化媒体的可见回复，再以受会话保护的托管 Artifact 提供预览与下载。它没有独立媒体工作台、历史树或可编辑工程，M1 只以任务化子集成立，另叠加 M4 插件化编排与 M5 Agent 驱动创作。
- **VCPChat** 的 Scriptorium 是可继续编辑的媒体工程与 Agent 审阅链；ComfyGen 仍只是到外部 VCPToolBox/ComfyUI 的配置交接，不能计为本仓库生成工作台。

AIO Hub 的媒体任务池现按全部工作区共享的并发上限调度，并可在完成后延迟清理任务而保留会话结果节点；VCPToolBox 的 MediaRenderer 可把受控浏览器渲染的 HTML 打包成 CUR/ANI、预览与安装 ZIP。后者扩大了交付文件种类，但仍是文件服务中的一次性结果，不形成可版本化的媒体工程对象。

## 样本口径

正式样本按“专用入口 + 独立持久化对象 + 后续创作链”纳入；普通附件、播放器、静态 Artifact 与孤立转码工具不单列。详细准入规则见[调查指南](调查指南.md)。

**Open WebUI** 与 **Jan** 经快照复核未形成独立媒体历史/资产工作台，归并相邻类目不计入；**VCPChat** 虽有以 Scriptorium 工程为准的完整创作链，但该工程、ComfyGen 配置与 Loom 的对象、数据和进程不统一，故保留为扩展样本而非核心同质样本。

## 正式样本的对象边界

NextChat 的正式性来自持久化的 `draw` 任务列表，而不是聊天内 DALL-E URL 消息；它是范围窄、以重试为主的 M1 工作台。Risuai 的正式主链必须限定为聊天收口写入的 inlay 资产，Playground 的临时 data URI 不足以单独证明资产闭环。SillyTavern 的正式主链以聊天消息和媒体文件为事实源，缺少全局媒体库并不否定其专用入口、结果持久化、消息级重生和工具回流所构成的完整链。

OpenClaw 的正式性来自可走通的“Agent 专用工具 → session-backed 媒体任务 → 托管媒体/transcript → 原会话回流 → Artifact 预览下载”最小主链，而不是一次普通 Provider 图片调用；但它不能按完整媒体工作台计：`task_runs` 行承载任务生命周期却不等同完整创作历史，结果以会话托管 Artifact 存在，跨会话资产库、版本对象与可编辑工程本次未找到。它的 M1 只以任务化子集成立，主体归类是 M4/M5（插件化媒体编排 + Agent 驱动创作）。

VCPChat 的新专项笔记与原扩展结论相符：Scriptorium 确有工程、内容寻址资源、导出和带人工回执的 Agent PR 主链，因此不是“仅配置面”；但它并未把 Scriptorium、ComfyGen 的外部配置及 Loom 合并为统一媒体任务和资产体系，仍不宜与九个核心工作站按同质对象排名。

## 关键差异

### 工作站与供给层

AIO Hub 的 `GenerationSession`/`MediaTask` 将创作历史与全局任务池分开，结果经资产导入入口进入应用级资产层；它最适合作为“资产中心 + 多模型工作站”参考。VCPToolBox 没有同等的最终用户历史 UI，事实源是插件 job、文件服务和异步回调，因此应作为“媒体能力供给/编排层”比较，不能把服务端文件 URL 当作桌面资产库等价物。

### 生成对象与可编程渲染

Chatbox 的事实对象是图像生成记录，参考图通过来源 record id 形成 DAG，范围集中且闭环清晰。VCPToolBox 的 MediaRenderer 则允许模型生成 HTML/SVG/JS 作品、逐帧动画和确定性程序音乐，资源白名单、源码/帧/采样上限和音频验证码构成其核心治理契约；这属于 M2 可编程媒体渲染，不应简化成“调用图片 API”。

### Agent 回流与人机接管

AIO Hub 与 Chatbox 都将结果回写到聊天或资产层，用户仍可在工作台中重试/查看。VCPToolBox 主要通过 `{{VCP_ASYNC_RESULT}}` 或文件 URL 回注，审批与外部依赖更多，运行时验证仍未完成。OpenClaw 把回流做成任务层闭环：后台完成事件唤醒原会话 Agent 产出带全部结构化媒体的可见回复，投递未确认前任务不标记为普通成功（blocked 终态），而用户主要经聊天参与，缺少独立工作台式的重试入口。VCPChat 的 Scriptorium 进一步加入人类审阅 PR，但其对象是富文档工程，属于媒体创作与协同文档的交叉边界。

## 设计取舍与已确认边界

- 不按“生成模型数量”计数；模型目录只是入口，产品能力取决于任务、历史、资产和复用链。
- 不把普通图片/音频消息、单次 `tool_call`、静态 Artifact、播放器、字幕和转写单独计入媒体创作。
- AIO Hub 的 `generateMedia` 文档声明是占位，实际 Agent 入口是动态方法族；统计以可执行路径为准。
- AIO Hub 的 audio.cpp 路径不是内嵌语音引擎：应用按服务端 voice preset 语义发送请求并接收 WAV，生成仍发生在用户另行运行的 HTTP 服务中。
- VCPToolBox 的媒体结果事实源在服务端插件/文件服务，不能推断存在统一桌面资产库、版本编辑器或最终用户媒体项目。
- Chatbox 的真实生成涉及外部模型和计费；参考图 DAG 与取消/恢复/回填已由单元测试覆盖，跨重启行为仍主要由静态代码确认。
- OpenClaw 的媒体能力是 Agent 工具面而非工作台：任务账本为通用 Task Registry（同时服务 ACP、subagent、cron 与 CLI），Provider 轮询与任务状态分层；取消主要是任务层投影，未见统一 Provider Job 撤销。主链为静态确认，未运行真实 Provider 或 Gateway/Control UI。
- VCPChat 的 Hi-Fi 播放器是本机媒体播放子系统；除非补出创作输入、可保存工程或 Agent 编辑链，否则不与生成能力重复计数。
- VCPChat 的 Loom 与 Scriptorium 经 direct 插件框架共享 Agent 通道，但对象、数据和进程不统一，不合并为同一功能族；ComfyGen 属外部 VCPToolBox 仓库的独立配置面板，不在 VCPChat 插件框架内。

## 未验证事项

- 九个核心样本均未统一运行真实模型调用、长任务取消、重启恢复和大文件性能；AIO Hub 真实生成、资产索引性能与运行恢复仍待人工运行（需真实模型与图形环境）。
- VCPToolBox 的托管 Chrome 渲染、插件启用配置的实际防护效果未验证；FFmpeg 编码、音频合成 Worker 与 manifest 解析已通过零依赖实测。
- AIO Hub 资产索引性能、重复导入事件和跨工具并发写入未运行验证。
- Chatbox 图像生成的计费错误、参考图实际构图和跨重启恢复未实测；取消/恢复/回填逻辑已有单元测试覆盖，应用级重启未实测。
- Cherry Studio 真实生成、异步 job 崩溃行为、清理 pass 与 UI 视觉未实测；job `recovery:'abandon'` 明确不跨重启，恢复语义为源码事实。
- LobeHub 真实生成、S3 存储、webhook/后台轮询网络行为、计费与配额 stub 未实测；用户取消入口本次未找到。
- VCPChat ComfyUI 连接、Loom WebCore 页面动作和 Scriptorium PR/导出测试目录均未运行验证；ComfyUIGen 插件处于 `.block` 禁用态。
- OpenClaw 未运行真实 Provider/ComfyUI，也未启动 Gateway 与 Control UI；`tasks.cancel` 对已提交 Provider 远端 Job 的影响、Gateway 重启后的轮询接管与并发清理未验证。
