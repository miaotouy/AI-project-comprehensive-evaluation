# 媒体创作调查指南

本指南用于调查 AI 客户端如何把模型或用户输入变成可继续创作、管理和复用的图片、视频、音频、动画或可编排媒体资产。通用写作、元数据、证据和调查深度要求见 [`../AGENTS.md`](../AGENTS.md)。本类目由独特功能中的“创作与媒体工作站”自然聚类正式化而来，不取代生成式输出与运行时、Agent 工具或 LLM 渠道类目的交接结论。

## 类目定义

**媒体创作**研究以下产品主链：

```text
提示词、参考资产、工作流或用户素材
  -> 模型/渲染/合成任务
  -> 媒体结果与元数据
  -> 历史、任务、资产或工程对象
  -> 预览、编辑、重试、分支、导出或再次调用
  -> 结果回流到聊天、Agent 或下一次创作
```

满足下列条件中的至少三项，且必须形成一次完整主链，才纳入正式横向比较：

1. 存在媒体专用入口、工作台、渲染器、插件族或模型能力目录；
2. 结果具有独立的任务、历史、资产、工程或版本身份，不只是消息附件；
3. 用户或 Agent 可以调整参数、提供参考、重试、分支、编辑、合成或继续创作；
4. 生成、渲染或异步任务具有失败、取消、回调、资源限额或恢复语义；
5. 结果可以进入资产库、文件服务、聊天回流或其他下一步工作流。

仅有一次图片 API 调用、普通音视频附件、播放器、静态 Markdown/Artifact 预览或通用 FFmpeg 工具，默认不满足准入。若这些能力与历史、资产、编辑或异步任务组成完整工作站，再按工作站整体纳入。

## 统一术语

| 术语 | 含义 |
|---|---|
| 媒体任务 | 一次生成、渲染、转码、合成或编辑请求及其状态 |
| 创作历史 | 保存提示词、参数、参考资产、分支和结果关系的记录 |
| 资产 | 可被其他任务、会话或 Agent 再次引用的图片、视频、音频、动画或工程文件 |
| 媒体工程 | 除最终文件外还保存工作流、源码、页面、节点图或可继续编辑的项目对象 |
| 媒体插件族 | 通过统一协议暴露多个生成、渲染、合成或回注能力的插件集合 |
| 结果回流 | 结果、URL、文件引用、元数据或任务状态进入聊天/Agent/下一次任务 |
| 工作站闭环 | 入口、任务执行、结果持久化、预览/编辑和再次使用至少形成一条可走通链路 |

## 与相邻类目的边界

| 相邻类目 | 媒体创作记录 | 留在相邻类目的内容 |
|---|---|---|
| 生成式输出与运行时 | 媒体结果成为可保存、可编辑、可继续维护的专用对象时的产品闭环 | 通用 Artifact/iframe/代码沙箱的协议、执行环境和对象生命周期 |
| Agent 工具 | 媒体工具如何进入工作站、结果如何回流和再次创作 | 工具注册、参数校验、审批、进程调度和通用异步任务机制 |
| LLM 渠道管理 | 媒体模型目录、能力标记和媒体参数如何影响创作入口 | Provider、Key、Base URL、模型健康和普通请求路由 |
| 消息渲染器 | 媒体结果回流到消息后的内容投影 | 普通图片/音频/视频 part 的解析、气泡和附件展示 |
| 会话与消息管理 | 创作历史与会话如何关联、分支如何落盘 | 通用会话树、消息 schema、索引和迁移 |
| 对话请求与上下文 | 模型调用触发媒体任务、流式和取消交接的位置 | 通用上下文拼装、发送、重试和中断结算 |
| 对话导出与分享 | 媒体对象被作为分享稿或交付物输出时的交接 | 媒体对象自身的生成、编辑、版本和资产生命周期 |
| 应用界面基础设施 | 专用创作工作台的窗口/路由仅在影响对象生命周期时记录 | 通用主题、弹窗、布局、快捷键和平台 UI |

播放、转写、字幕覆盖和普通附件可以作为边界样本。它们只有在同时具备创作输入、可保存工作成果或 Agent 可继续操作的契约时，才升级为媒体创作能力。

## 必查问题

1. 用户目标是生成、合成、编辑、转码、编排还是资产管理？
2. 入口由用户、Agent、插件、工作流、定时任务还是外部服务触发？
3. 核心事实对象是任务、历史树、资产、工程、工作流还是媒体文件？
4. 生成器、渲染器、编码器和外部模型的执行位置分别在哪里？
5. 参数、参考图/音频、模型能力和上下文如何进入请求？
6. 结果怎样预览、编辑、重试、分支、导出和再次引用？
7. 异步任务如何报告进度、回调、取消、失败、重启和重试？
8. 资产如何命名、去重、索引、关联来源和跨工作流复用？
9. Agent 能否发现媒体能力、读取历史、调用已有资产并接收结果？
10. 外部服务、ComfyUI、FFmpeg、浏览器、文件服务和 CDN 的依赖边界是什么？
11. 文件、网络、进程、额度、资源大小和脚本执行有哪些权限与限额？
12. 哪些结论是源码事实，哪些只由文档声明，哪些经过运行验证？

## 能力分型

| 类型 | 典型链路 | 关注重点 |
|---|---|---|
| `M1 模型生成工作站` | 提示词/参考资产 -> 图片、视频、音频或 3D 结果 | 模型能力目录、参数清洁、历史、重试和资产回流 |
| `M2 可编程媒体渲染` | HTML/SVG/JS/节点或合成代码 -> 图片、动画、音频或视频 | 资源白名单、渲染环境、帧/采样限制和结果托管 |
| `M3 资产与工程工作区` | 结果/用户素材 -> 资产库、工程文件、版本或 DAG | 去重、索引、来源、编辑、版本和复用 |
| `M4 插件化媒体编排` | 统一协议 -> 多个生成/渲染/回注插件 | 插件发现、异步回调、任务归属和扩展边界 |
| `M5 Agent 驱动创作` | Agent 读取历史/资产 -> 调参、生成、编辑或发布 | Agent 可见性、审批、结果回流和人机接管 |

一个项目可以同时属于多个分型，但同一条用户工作流只计一个产品功能族。播放、转写和字幕等支撑能力单独列为边界或机制，不按媒体创作主贡献重复计数。

## 调查方法

- 先找创作对象和事实源，再看生成按钮或媒体组件；一次 API 调用不能证明存在工作站。
- 至少走通“入口 -> 参数/素材 -> 任务 -> 结果 -> 持久化 -> 再次预览、重试或复用”主链。
- 对模型触发的能力补查 Agent 方法、审批、任务回注和额度边界；对插件族补查 manifest、执行器、回调和结果托管。
- 将生成源、媒体结果、资产记录和预览/运行实例分开，确认谁是真源、何时同步、失败如何收口。
- README、产品截图和插件说明只生成候选；源码可执行路径优先。真实模型调用、编码效果、视觉保真和网络服务可用性需标为未验证。

## 推荐结构

```md
## 结论摘要
## 系统边界与完整主链
## 1. 创作入口、触发者与事实对象
## 2. 参数、素材与模型/渲染执行
## 3. 任务状态、异步回调与取消
## 4. 结果、历史、资产与工程持久化
## 5. 预览、编辑、重试、分支与复用
## 6. Agent 回流、插件与外部依赖
## 7. 权限、资源边界与失败恢复
## 8. 设计取舍、已确认边界与未验证事项
## 9. 关键源码索引
```
