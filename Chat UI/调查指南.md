# Chat UI（对话工作台与交互）调查指南

本指南用于调查项目自己控制的最终用户聊天表面，包括桌面 GUI、Web、移动端、TUI 和项目内置 WebChat。通用写作、元数据、深度和证据要求见 [`../AGENTS.md`](../AGENTS.md)。

本类目关注用户如何发现、触发、观察和恢复聊天能力。会话数据语义属于 [`../会话与消息管理/调查指南.md`](../会话与消息管理/调查指南.md)，生成任务的真实执行属于 [`../对话请求与上下文/调查指南.md`](../对话请求与上下文/调查指南.md)，消息内容与列表如何绘制属于 [`../消息渲染器/调查指南.md`](../消息渲染器/调查指南.md)，对话导出的内容口径、分享稿、生成版本与交付语义属于 [`../对话导出与分享/调查指南.md`](../对话导出与分享/调查指南.md)。

## 适用性

- 项目拥有自己控制的聊天 GUI、WebChat、移动端或 TUI 时，建立单项目 Chat UI 笔记。
- 项目只提供后端协议、无状态网关、运维面板或第三方页面增强时，标记为不适用并说明边界，不创建空洞的功能清单。
- 外部 QQ、Telegram、Slack 等客户端的 UI 不归项目所有；项目自带的 WebChat 或管理端聊天入口可以单独调查。

## 调查目标

走通一条“进入聊天表面 -> 创建、选择或恢复会话 -> 组织输入和发送前配置 -> 提交或排队 -> 观察和控制生成 -> 操作消息 -> 搜索、切换或离开 -> 再次进入并恢复现场”的用户主链。

## 必查问题

1. **工作台结构**：聊天入口、会话导航、消息区、输入区和辅助面板如何组织？哪些区域可折叠、分离、多开或切换布局？
2. **会话导航**：新建、切换、分组、置顶、归档、未读、拖放、搜索和定位通过哪些界面完成？切换时保留哪些局部状态？
3. **输入与草稿**：文本、富文本、命令、提及、附件、语音、变量和快捷回复如何输入？草稿按会话、窗口还是全局保存？
4. **发送前配置**：用户如何看到和修改 Agent、模型、参数、工具、知识库、联网和推理设置？设置作用域是否可辨认？
5. **生成状态与控制**：排队、发送、流式、等待审批、后台生成、停止、错误、重试和完成如何反馈？控件状态与真实任务状态如何对应？
6. **消息操作工作流**：复制、编辑、删除、重试、续写、分支、版本切换、翻译、导出和审批从哪里进入？何时禁用或隐藏？
7. **搜索、分支与阅读导航**：会话内搜索、跨会话搜索、消息跳转、分支树、版本导航、minimap 和滚动恢复如何协作？
8. **并发与多路对话**：多会话、多模型、群聊、子 Agent 和后台任务如何区分？用户如何知道哪一条仍在运行并返回对应现场？
9. **跨窗口与跨平台连续性**：桌面、Web、移动端、TUI、悬浮窗和系统通知之间如何同步当前会话、草稿和生成状态？
10. **关键路径可用性**：键盘能否完成选择会话、输入、发送、停止和消息操作？焦点、可访问名称、响应式变化和错误恢复是否保持主链可用？
11. **UI 状态所有权**：draft、selection、panel、scroll、active message、pending input 和 busy 状态存在哪里？切换会话、刷新和重连时如何恢复？

## 与相邻类目的边界

| 同一能力 | Chat UI 记录 | 相邻类目记录 |
|---|---|---|
| 停止生成 | 停止入口、按钮状态、等待反馈和失败恢复 | 对话请求与上下文记录 abort、任务取消、最终化和落盘语义；消息渲染器记录 partial 与错误块显示 |
| 搜索 | 搜索入口、过滤器、结果列表和跳转工作流 | 会话与消息管理记录索引、查询对象和命中数据；消息渲染器记录 DOM 高亮和滚动锚定 |
| 分支 | 分支按钮、兄弟版本导航、树图和确认流程 | 会话与消息管理记录树模型和 active pointer；对话请求与上下文记录从哪个节点重建请求 |
| Composer | 编辑器、附件、命令、提及、快捷键和发送前配置 | 对话请求与上下文记录输入如何转换为请求 parts 和参数 |
| 消息操作 | 操作入口、可用性、菜单、确认和反馈 | 会话与消息管理记录数据变更；消息渲染器记录操作栏的组件装配 |
| 导出与分享 | 导出入口、范围选择、编辑/预览界面、生成状态和交付反馈 | 对话导出与分享记录内容口径、格式、版本、图片/PDF 生成、链接权限与撤销 |
| 工具审批 | 待处理提示、审批入口和用户返回路径 | Agent 工具记录审批语义和执行校验；消息渲染器记录工具卡内容 |
| 多会话生成 | 运行标记、切换反馈、通知和返回入口 | 对话请求与上下文记录并发、队列、后台任务和取消粒度 |

## 通用 UI 过滤规则

### 纳入

- 会话侧栏在移动端如何变为抽屉，以及切换后是否保持输入；
- 发送、停止、排队和审批控件的状态与反馈；
- 消息搜索弹窗如何返回并定位目标消息；
- 附件拖入 Composer 时的反馈和失败恢复；
- 回复完成通知能否返回对应会话；
- 分离窗口如何同步草稿、busy 和 active session；
- 键盘能否完成聊天关键路径。

### 排除

- 全项目 Modal、Toast、Tooltip 或菜单库的完整盘点；
- 所有页面的主题 token、动画时长和响应式断点清单；
- 设置页、关于页、许可证页和首次启动流程；
- 与聊天无关的托盘、更新器、资源管理器和窗口管理；
- 仅用于评价视觉风格的颜色、阴影和装饰细节。

通用组件只记录与聊天主链的交点。例如 Chat 页面使用 Toast 时，说明错误、完成或审批通知能否让用户继续工作，不统计全仓库 Toast 调用。

## 调查注意事项

- 代码可确认控件、状态和事件绑定；视觉效果、焦点顺序、键盘可用性、响应式行为和系统通知属于需要在目标环境中观察的独立维度。
- 按钮存在不能证明能力有效。发送、停止、审批和重试必须链接到实际 action、command、RPC 或 API，并把执行语义交给对应专项。
- 不把 React、Vue、Svelte、TUI 组件名称直接作为横向维度，优先比较用户任务、状态反馈和现场恢复。
- 消息操作栏既涉及 Chat UI 又涉及消息渲染器：本类目记录操作为何出现、何时可用和触发什么工作流；渲染器记录它如何装配进消息壳。
- 无障碍只覆盖聊天关键路径及其直接依赖，不升级为全应用审计。

## 横向比较字段

至少记录：工作台拓扑、会话导航、搜索与恢复、Composer 类型、草稿粒度、附件入口、发送前配置可见性、生成状态反馈、停止入口、消息操作、分支导航、多会话与后台生成、多窗口或多端连续性、UI 状态事实源，以及关键路径的键盘和焦点可用性。
