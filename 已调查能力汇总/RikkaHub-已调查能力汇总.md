## 项目概览

RikkaHub 是一个原生 Android 的大模型聊天客户端，采用 Kotlin 与 Jetpack Compose，按 Material 3 / Material You 组织界面，底层使用 Room 持久化、DataStore 存偏好、Koin 注入、OkHttp 联网，并以 kotlinx.serialization 序列化。仓库是单 Gradle 多模块工程，应用模块为 app、ai、search、speech、common、document、web、material3、ui、workspace、terminal、mediagen、oauth、app:baselineprofile，另有 build-logic 复合构建与 web-ui 前端工程，开发脚本集中在 tools/（i18n、trace、models-dev）。快照含 1536 个跟踪文件、1095 个源码文件 / 206401 行源码，其中 Kotlin 约占 83% 行数，TypeScript 与 Java 次之。[仓库分布调查笔记](../仓库分布/RikkaHub-仓库分布调查笔记.md)

产品主体是一部手机上的聊天工作台：会话以助手为配置单位，可切换 OpenAI 兼容、Google（含 Vertex 与 Interactions API）、Claude、ChatGPT 账号与 Grok 账号五类渠道；聊天之外还提供内嵌 Web 服务器实现的浏览器访问、可运行 Linux 命令的 PRoot 工作区（或 SSH 远程工作区）、MCP 工具接入、图像与视频媒体创作，以及可后台整理的记忆文件库。下文的“已调查能力”按主题而非来源目录组织，同一机制在多个类目出现时合并叙述。

## 已调查能力

### 聊天主链与移动端界面

- **回合制生成与上下文拼装**：一次输入由 `ChatService` 编排，先落库用户消息，再由 app 侧的 `ChatRequestFactory` 装配合成系统消息、工具集与裁剪后的历史，交给 ai 模块的 `AgentLoop` 执行步进、工具调用与重试；流式回复按 chunk 合并，整轮结束（完成、失败或取消）统一经 `finishGeneration` 落库。同一会话严格串行、不同会话并行，待发消息进入队列而非打断当前运行。上下文裁剪是条数口径的滞回截断，压缩改为插入带标记的检查点消息，旧消息保留。证据状态：`主链确认`（静态源码）。[对话请求与上下文调查笔记](../对话请求与上下文/RikkaHub-对话请求与上下文调查笔记.md)、[主动Agent与后台任务调查笔记](../主动Agent与后台任务/RikkaHub-主动Agent与后台任务调查笔记.md)

- **会话与消息存储**：会话元信息与消息分两张 Room 表，消息按“节点”保存，每个节点内是候选消息列表加一个选中下标，分支表现为同节点追加候选而非通用消息树；会话落库时还会从助手拍一份固定配置（模型、推理强度、搜索、MCP、工作区、技能）。全文检索为独立 FTS5 虚表，配合 `simple` 扩展与单字 NEAR 查询只索引文本部件，标题搜索另走模糊匹配。当前数据库版本 32。证据状态：`主链确认`（静态源码）。[会话与消息管理调查笔记](../会话与消息管理/RikkaHub-会话与消息管理调查笔记.md)

- **聊天界面与消息呈现**：单 Activity 加 Navigation 3 导航栈，会话切换清空返回栈；发送、停止、长按仅入库、消息队列面板、工具审批卡片、分支切换与消息操作条在聊天页装配，并有可选的后台生成悬浮窗。消息渲染交给外部 BetterText 组件，Markdown 主题与组件槽由应用提供，代码高亮、公式、表格与选择能力由该库承担；Mermaid 与 HTML/SVG 预览仍交给 WebView。证据状态：`主链确认`（静态源码）。[Chat UI 调查笔记](<../Chat UI/RikkaHub-ChatUI调查笔记.md>)、[消息渲染器调查笔记](../消息渲染器/RikkaHub-消息渲染器调查笔记.md)

### Provider、模型与角色配置

- **五类渠道与模型能力目录**：可序列化的渠道设置有 OpenAI 兼容、Google、Claude 三个密钥型子类与 ChatGPT、Grok 两个账号型子类，运行时管理器在构造时固定注册五个实现，新增协议属编译期行为。模型能力来自 models.dev 目录（随包快照 + 按天更新）与内置注册表的兜底推断，在模型加入渠道时快照进模型对象；远端只刷新模型 ID。多 Key 仅做持久化的最近最少使用轮换，无健康检查、冷却或跨渠道故障转移；重试由请求侧策略注入，只在同一渠道内对网络异常做有限次数。证据状态：`主链确认`（静态源码）。[LLM 渠道管理调查笔记](../LLM渠道管理/RikkaHub-LLM渠道管理调查笔记.md)

- **助手配置与两级覆盖**：助手是纯数据类，涵盖身份展示、系统提示词、会话覆盖开关、采样与上下文参数、注入扩展、工具与记忆开关、请求头体与外观，整体存进偏好存储的同一键。会话绑定助手 id 并在每次生成前读取，历史消息不保存助手快照；会话开始后配置固定在会话上，之后的助手改动只影响新会话。提示词与注入支持会话级覆盖。证据状态：`主链确认`（静态源码）。[Agent 角色配置调查笔记](../Agent角色/RikkaHub-Agent角色配置调查笔记.md)

- **提示词工程与注入**：注入只在请求期存在，不写回会话。规则分“模式注入”与“正则注入”两种触发，位置为固定五种（系统提示前后、对话顶/底、按深度），命中后按优先级降序与位置分组应用；另有占位符替换与 Pebble 消息模板。助手的输入/输出正则按是否仅视觉生效分流。证据状态：`主链确认`（静态源码）。[上下文编译与提示词工程调查笔记](../上下文编译与提示词工程/RikkaHub-上下文编译与提示词工程调查笔记.md)

### Agent 工具与外部协作

- **工具注册、审批与回注**：工具协议是自定义轻量数据类，参数校验下放给各工具。启用来源包括记忆、搜索、本地、会话、工作区、Skill 与 MCP，注册顺序在源码中与仓库文档描述不一致。共八个本地工具选项（含图表展示）。审批是编排层状态机（自动、待定、批准、拒绝、代答），拒绝与代答由框架合成结果；工具结果内联写回触发它的助手消息。输出超过 32KB 且工作区具备本地 Rootfs 时截断并写入文件，搜索工具除外。证据状态：`主链确认`（静态源码）。[Agent 工具调查笔记](../Agent工具/RikkaHub-Agent工具调查笔记.md)

- **MCP、工作区与内嵌 Web 服务器**：外部协作有三条独立主链。MCP 客户端只支持 SSE 与可流式 HTTP 两种传输，工具以服务器名前缀命名，OAuth 走授权规范发现、PKCE 与动态注册。工作区有本地与远程两种后端：本地是用户态 PRoot 环境，文件区与技能、工具输出、上传目录通过挂载进入，shell 默认需审批；远程经 SSH 把同一套文件与命令接口转发到用户主机。内嵌 Ktor 服务器在同一进程内复用会话服务与数据库，是唯一的非本机生成入口。证据状态：`主链确认`（静态源码）。[外部执行体与应用协作调查笔记](../外部执行体与应用协作/RikkaHub-外部执行体与应用协作调查笔记.md)

### 检索、记忆与生成运行时

- **记忆文件库与多入口检索**：记忆是按助手隔离的 Markdown 文件库，核心文件正文常驻系统提示，其余文件只给目录；模型用六个工具读写，对话停下来后由后台整理进程合并，另有手动整理。网页搜索对接二十个平级供应商；历史会话检索走 FTS5 关键词匹配，并提供跨会话查询工具。全仓 Kotlin 源码未找到可用的向量检索或嵌入调用方。证据状态：`主链确认`（静态源码）。[检索增强与认知编排调查笔记](../检索增强与认知编排/RikkaHub-检索增强与认知编排调查笔记.md)

- **生成输出与运行时对象**：输出对象只有消息部件模型，没有 artifact / canvas 协议或对象 id、版本。聊天内图片在生成结束时被物化为本地文件并改写部件地址，落库前禁止残留内联 base64 图片。代码块不可执行，仅 HTML/SVG 在围栏闭合时可送入应用内 WebView 预览；唯一的脚本运行时是模型可调用的 JavaScript 工具（QuickJS，无 DOM，默认免审批）。工作区文件是唯一具备“写入—再读回”闭环的对象面。证据状态：`主链确认`（静态源码）。[生成式输出与运行时调查笔记](../生成式输出与运行时/RikkaHub-生成式输出与运行时调查笔记.md)

### 媒体创作

- **图像与视频创作子系统**：媒体创作独立于聊天，按“会话 → 时间线节点 → 生成记录”组织版本，由前台服务向后端提交任务、轮询、下载并落盘，任务 id 持久化以支持进程重启后续接；图像与视频共用同一状态机，支持取消与删除。聊天内仍只有服务端内置图片工具，与媒体创作是两条路径；旧图片生成页仍在。语音为边界样本：TTS 分片队列内存播放不落盘，ASR 用于听写。证据状态：`主链确认`（静态源码）。[媒体创作调查笔记](../媒体创作/RikkaHub-媒体创作调查笔记.md)

### 多端、导出与界面基础设施

- **导出、分享与备份**：对话导出与配置导出、全量备份互不复用。对话导出在聊天多选后仅提供 Markdown 与 PNG 两种格式，含推理内容的开关，粒度是每条节点当前选中的那条消息。二维码分享只服务 Provider 配置，明文携带密钥、无访问控制。备份是唯一可往返能力：数据库快照加设置与附件打包，恢复在下次启动经暂存与原子移动安装；WebDAV 与 S3 只是同一压缩包的远端存放。外部迁移单向，可读 Chatbox 备份与 Cherry Studio 的 Provider。证据状态：`主链确认`（静态源码）。[对话导出与分享调查笔记](../对话导出与分享/RikkaHub-对话导出与分享调查笔记.md)

- **界面基础设施**：公共依赖用五组 CompositionLocal 在路由根一次性注入而非全局 store；通用视觉组件抽成独立的 `ui` 库模块（图表、裁剪、彩蛋、图标、富文本、画板、表格、Toast、WebView）。导航是 Navigation 3 加自研薄封装，预测性返回仅声明过渡。主题在一处解析：色模式经动态取色或预置/自定义主题（HCT 生成）后叠加 AMOLED 覆盖。反馈分应用内提示与系统多通道通知两套。证据状态：`主链确认`（静态源码）。[应用界面基础设施调查笔记](../应用界面基础设施/RikkaHub-应用界面基础设施调查笔记.md)

- **独特能力：PRoot 工作区与手机即服务端**：Android 端以用户态 PRoot 提供本机 Linux rootfs 与 shell，模型工具与人类终端共享同一环境，另有 SSH 远程后端；内嵌 Ktor 服务器配合随包 Web 界面实现浏览器访问，主机名经 mDNS 广播，复用宿主同一会话服务与数据库。两者构成该项目最显著的辨识度来源。证据状态：`主链确认`（静态源码）。[独特功能调查笔记](../独特功能/RikkaHub-独特功能调查笔记.md)

## 已知边界与未覆盖事项

- 全部结论以静态源码为主。未构建或运行应用，未在真机验证 PRoot 安装与子进程回收、SSH 远程工作区、Web 服务器与令牌往返、FTS 原生扩展装载、媒体生成落盘、MCP 连接与 OAuth、记忆整理、二维码扫码、提示词注入效果以及各供应商真实响应。
- 渠道侧确认没有跨渠道故障转移与多 Key 健康管理；模型能力来自 models.dev 目录与静态注册表，可能与实际模型存在覆盖差异。ChatGPT/Grok 的账号登录与 token 刷新只在代码层面确认。
- 检索侧确认没有可用的向量检索；`conversation_search` 工具未按助手限定作用域，与 `recent_chats` 的范围不对称。
- 主动 Agent 形态确认不存在定时调度：仓库内无 cron、无 Worker 入队、无 AlarmManager、无广播接收器；后台工作只有回合派生的记忆整理、媒体创作任务与会话生成保活。WorkManager 已接入但未接线。
- 媒体生成依赖云端 provider，离线不可用；媒体创作的产物不与聊天附件共用目录与备份路径，旧的图片生成页与其并存。
- 仓库自带文档 `docs/references/chat-generation-pipeline.md` 与实现存在漂移（核心类名、工具注册顺序、记忆形态），各来源笔记均以可执行路径为准。
- 批次默认不包含“产品结构与设计基因”类，本项目未建立该类笔记；本汇总的项目概览来自仓库分布与其他主题笔记，未做产品演变专项调查。
