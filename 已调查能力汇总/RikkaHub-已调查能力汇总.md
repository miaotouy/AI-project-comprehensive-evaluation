## 项目概览

RikkaHub 是一个原生 Android 的大模型聊天客户端，采用 Kotlin 与 Jetpack Compose，按 Material 3 / Material You 组织界面，底层使用 Room 持久化、DataStore 存偏好、Koin 注入、OkHttp 联网，并以 kotlinx.serialization 序列化。仓库是单 Gradle 多模块工程（app、ai、search、speech、common、document、web、material3、workspace、videogen、oauth、highlight 及 baselineprofile），另挂 web-ui（React Router 7 + TypeScript）、locale-tui（Python）和 trace-cli（TypeScript/Bun）三个旁路子项目。快照含 1381 个跟踪文件、906 个源码文件 / 160600 行源码，其中 Kotlin 约占 82% 行数。[仓库分布调查笔记](../仓库分布/RikkaHub-仓库分布调查笔记.md)

产品主体是一部手机上的聊天工作台：会话以助手为配置单位，可切换 OpenAI 兼容、Google（含 Vertex）与 Claude 三类供应商；聊天之外还提供内嵌 Web 服务器实现的浏览器访问、可运行 Linux 命令的 PRoot 工作区、MCP 工具接入，以及图片生成工作台。下文的“已调查能力”按主题而非来源目录组织，同一机制在多个类目出现时合并叙述。

## 已调查能力

### 聊天主链与移动端界面

- **回合制生成与上下文拼装**：一次输入由 `ChatService` 编排，先落库用户消息，再经 `GenerationLoop` 组装合成系统消息（生效系统提示 + 记忆 + 工具说明）与裁剪后的历史，穿过输入变换器后交给 Provider；流式回复按 chunk 合并，成功时整体写回。同一会话严格串行、不同会话并行，待发消息进入队列而非打断当前运行；停止会取消全部生成 Job 并补全未执行工具。上下文裁剪是条数口径的滞回截断，用于稳定请求前缀以命中提示词缓存。证据状态：`主链确认`（静态源码）。[对话请求与上下文调查笔记](../对话请求与上下文/RikkaHub-对话请求与上下文调查笔记.md)、[主动Agent与后台任务调查笔记](../主动Agent与后台任务/RikkaHub-主动Agent与后台任务调查笔记.md)

- **会话与消息存储**：会话元信息与消息分两张 Room 表，消息按“节点”保存，每个节点内是候选消息列表加一个选中下标，分支表现为同节点追加候选而非通用消息树；生成中只改内存状态，助手回复在成功时整会话重写落库。全文检索为独立 FTS5 虚表，配合自定义分词（jieba 词典）只索引文本部件，标题搜索另走模糊匹配。证据状态：`主链确认`（静态源码）。[会话与消息管理调查笔记](../会话与消息管理/RikkaHub-会话与消息管理调查笔记.md)

- **聊天界面与消息呈现**：单 Activity 加 Navigation 3 导航栈，会话切换清空返回栈；发送、停止、长按仅入库、消息队列面板、工具审批卡片、分支切换与消息操作条在聊天页装配。消息渲染按部件类型分派，Markdown 走 GFM 抽象语法树原生渲染，代码高亮是随包自研引擎（覆盖约 30 种语言），数学用本地库绘制，Mermaid 与 HTML/SVG 预览交给 WebView；流式期间维护展示与持久两条通道。证据状态：`主链确认`（静态源码）。[Chat UI 调查笔记](<../Chat UI/RikkaHub-ChatUI调查笔记.md>)、[消息渲染器调查笔记](../消息渲染器/RikkaHub-消息渲染器调查笔记.md)

### Provider、模型与角色配置

- **三类渠道与静态能力推断**：可序列化的渠道设置只有 OpenAI 兼容、Google、Claude 三个子类，运行时管理器在构造时固定注册对应实现，新增协议属编译期行为；用户可在同一类型下建多个实例。模型能力不来自远端：远端只刷新模型 ID，模态、工具、推理与上下文长度由内置注册表按模型 ID 分词打分静态推断并快照进模型对象。多 Key 仅做持久化的最近最少使用轮换，无健康检查、冷却或跨渠道故障转移；重试只在应用层对网络异常做有限次数。证据状态：`主链确认`（静态源码）。[LLM 渠道管理调查笔记](../LLM渠道管理/RikkaHub-LLM渠道管理调查笔记.md)

- **助手配置与两级覆盖**：助手是纯数据类，涵盖身份展示、系统提示词、会话覆盖开关、采样与上下文参数、注入扩展、工具开关、请求头体与外观，整体存进偏好存储的同一键。会话绑定助手 id 并在每次生成前重新读取，所以修改助手立即作用于既有会话的下一次请求，历史消息不保存助手快照；提示词与注入支持会话级覆盖，覆盖开启时替换助手的对应绑定。证据状态：`主链确认`（静态源码）。[Agent 角色配置调查笔记](../Agent角色/RikkaHub-Agent角色配置调查笔记.md)

- **提示词工程与注入**：注入只在请求期存在，不写回会话。规则分“模式注入”与“正则注入”两种触发，位置为固定五种（系统提示前后、对话顶/底、按深度），命中后按优先级降序与位置分组应用；另有占位符替换与 Pebble 消息模板，模板变量按消息创建时间取值以稳定前缀。助手的输入/输出正则按是否仅视觉生效分流，生效的一组在生成收尾时改写权威助手消息。证据状态：`主链确认`（静态源码）。[上下文编译与提示词工程调查笔记](../上下文编译与提示词工程/RikkaHub-上下文编译与提示词工程调查笔记.md)

### Agent 工具与外部协作

- **工具注册、审批与回注**：工具协议是自定义轻量数据类，参数校验下放给各工具。启用来源包括搜索、本地、会话、工作区、Skill、MCP 与记忆，注册顺序在源码中与仓库文档描述不一致。审批是编排层状态机（自动、待定、批准、拒绝、代答），拒绝与代答由框架合成结果；工具结果不建工具角色消息，而是内联写回触发它的助手消息，序列化时再拆成工具调用与工具结果。输出超过 32KB 且工作区 shell 可用时截断并写入文件。证据状态：`主链确认`（静态源码）。[Agent 工具调查笔记](../Agent工具/RikkaHub-Agent工具调查笔记.md)

- **MCP、工作区与内嵌 Web 服务器**：外部协作有三条独立主链。MCP 客户端只支持 SSE 与可流式 HTTP 两种传输，工具以服务器名前缀命名，OAuth 走授权规范发现、PKCE 与动态注册，回调绑定本机回环端口。工作区是用户态 PRoot 环境，文件区与技能、工具输出、上传目录通过挂载进入，shell 工具默认需审批、越界写路径强制审批。内嵌 Ktor 服务器在同一进程内复用会话服务与数据库，以口令派生密钥签发令牌，是唯一的非本机生成入口。证据状态：`主链确认`（静态源码）。[外部执行体与应用协作调查笔记](../外部执行体与应用协作/RikkaHub-外部执行体与应用协作调查笔记.md)

### 检索、记忆与生成运行时

- **三类检索素材，无向量 RAG**：记忆每次生成全量拼入系统提示并可由模型工具增删改，按助手隔离，全局记忆是复用同一表的保留标识；网页搜索对接约 19 个供应商平级分派，单次候选无融合重排；历史会话检索走 FTS5 关键词匹配，并提供跨会话查询工具。全仓 Kotlin 源码未找到可用的向量检索或嵌入调用方，附件、记忆与会话都不做分块嵌入。证据状态：`主链确认`（静态源码）。[检索增强与认知编排调查笔记](../检索增强与认知编排/RikkaHub-检索增强与认知编排调查笔记.md)

- **生成输出与运行时对象**：输出对象只有消息部件模型，没有 artifact / canvas 协议或对象 id、版本。聊天内图片在生成结束时被物化为本地文件并改写部件地址，落库前禁止残留内联 base64 图片。代码块不可执行，仅 HTML/SVG 在围栏闭合时可送入应用内 WebView 预览；唯一的脚本运行时是模型可调用的 JavaScript 工具（QuickJS，无 DOM，默认免审批）。工作区文件是唯一具备“写入—再读回”闭环的对象面。证据状态：`主链确认`（静态源码）。[生成式输出与运行时调查笔记](../生成式输出与运行时/RikkaHub-生成式输出与运行时调查笔记.md)

### 媒体创作

- **图片生成闭环与未接线的视频能力**：图片生成是独立于聊天的完整闭环，入口在聊天抽屉菜单，仅用户可触发，Agent 无对应本地工具；只有 OpenAI 实现覆盖专用生成与编辑接口，Claude 明确不支持。结果落盘为本地 PNG 加 Room 记录，无任务对象、进度、重试或参数历史。视频生成模块已封装阿里云、火山、MiniMax 的创建与轮询，状态机自洽，但应用侧只有依赖声明，没有调用点与产物下载。语音为边界样本：TTS 分片队列内存播放不落盘，ASR 用于听写。证据状态：`主链确认`（静态源码）。[媒体创作调查笔记](../媒体创作/RikkaHub-媒体创作调查笔记.md)

### 多端、导出与界面基础设施

- **导出、分享与备份**：对话导出与配置导出、全量备份互不复用。对话导出在聊天多选后仅提供 Markdown 与 PNG 两种格式，粒度是每条节点当前选中的那条消息，图片导出是离屏复刻且会裁剪文档与音视频内容。二维码分享只服务 Provider 配置，明文携带密钥、无访问控制。备份是唯一可往返能力：数据库快照加设置与附件打包，恢复在下次启动经暂存与原子移动安装；WebDAV 与 S3 只是同一压缩包的远端存放。外部迁移单向，可读 Chatbox 备份与 Cherry Studio 的 Provider。证据状态：`主链确认`（静态源码）。[对话导出与分享调查笔记](../对话导出与分享/RikkaHub-对话导出与分享调查笔记.md)

- **界面基础设施**：公共依赖用五组 CompositionLocal 在路由根一次性注入而非全局 store；导航是 Navigation 3 加自研薄封装，只实现部分栈操作，预测性返回仅声明过渡。主题在一处解析：色模式经动态取色或预置/自定义主题（HCT 生成）后叠加 AMOLED 覆盖，持久化分偏好存储与系统偏好两轨。反馈分应用内单例提示与系统多通道通知两套。响应式只有一条宽度判定线，未使用多窗格骨架。证据状态：`主链确认`（静态源码）。[应用界面基础设施调查笔记](../应用界面基础设施/RikkaHub-应用界面基础设施调查笔记.md)

- **独特能力：PRoot 工作区与手机即服务端**：Android 端以用户态 PRoot 提供本机 Linux rootfs 与 shell，四个模型工具与人类终端共享同一环境，属于外部执行体而非普通工具沙箱；内嵌 Ktor 服务器配合随包 Web 界面实现浏览器访问，主机名经 mDNS 广播，复用宿主同一会话服务与数据库。两者构成该项目最显著的辨识度来源。证据状态：`主链确认`（静态源码）。[独特功能调查笔记](../独特功能/RikkaHub-独特功能调查笔记.md)

## 已知边界与未覆盖事项

- 全部结论以静态源码为主。未构建或运行应用，未在真机验证 PRoot 安装与子进程回收、Web 服务器与令牌往返、FTS 分词扩展装载、图片生成落盘、MCP 连接与 OAuth、二维码扫码、提示词注入效果以及各供应商真实响应。
- 渠道侧确认没有跨渠道故障转移与多 Key 健康管理；模型能力来自静态注册表而非真实远端能力，可能与实际模型存在覆盖差异。
- 检索侧确认没有可用的向量检索；`conversation_search` 工具未按助手限定作用域，与 `recent_chats` 的范围不对称，来源笔记将其列为待确认而非定论。
- 主动 Agent 形态确认不存在：仓库内无 Worker、AlarmManager 或定时调度入口，WorkManager 只做注入接线；“后台”指生成期间的前台服务保活，进程死亡即静默终止且无恢复。
- 视频生成模块在产品侧未接线；媒体生成的产物不与聊天附件共用存储与备份路径。
- 仓库自带文档 `docs/references/chat-generation-pipeline.md` 与实现存在漂移（核心类名与工具注册顺序），各来源笔记均以可执行路径为准。
- 批次默认不包含“产品结构与设计基因”类，本项目未建立该类笔记；本汇总的项目概览来自仓库分布与其他主题笔记，未做产品演变专项调查。
