## 项目概览

AstrBot 是面向 IM 平台（QQ/Telegram/Discord/微信等）的消息驱动异步聊天框架：一条入站消息经 EventBus 与按配置实例隔离的调度器按固定九阶段流水线处理，Agent 执行结果经消息渲染与平台适配器投递回聊天线程。产品表面是 IM 线程本身，项目自带 WebChat 聊天工作台与 Dashboard 管理后台，无最终用户 GUI。仓库将 Python 服务核心与 Vue Dashboard 合仓为一个部署单元。README 四大招牌能力中，Agent Sandbox 与主动式 Agent 已确认为独立能力卡，语音能力形成完整管道列为辅助贡献，多 IM 消息投影与插件生态归并到已有类目（见[独特功能调查笔记](../独特功能/AstrBot-独特功能调查笔记.md)与[特色功能贡献统计](../AI客户端特色功能贡献统计.md)）。

## 功能能力摘要

### 角色与上下文

- **Agent 角色（Persona）配置**：纯指令 + 能力白名单模型，由系统提示词、预设开场对话、工具与 Skills 白名单及自定义错误文案组成，无头像、语音等富媒体字段；解析优先级为会话规则 → 对话级绑定 → 全局默认 → webchat 特例，v4 起存 SQLite 并保留 v3 兼容层；只对内置 Agent 执行器生效，第三方 runner 不注入，system 消息受压缩保护。证据：静态源码确认。来源：[Agent 角色配置调查笔记](../Agent角色/AstrBot-Agent角色配置调查笔记.md)。
- **上下文拼装与双层压缩**：历史、persona、媒体附件、引用正文、系统提醒块、群聊上下文按序拼入请求载体；压缩先按轮次截断再按 token 压缩（82% 阈值触发，摘要或截断二选一、折半兜底），system 消息保护、工具调用配对修复。证据：静态源码确认。来源：[对话请求与上下文调查笔记](../对话请求与上下文/AstrBot-对话请求与上下文调查笔记.md)、[Chat 调查笔记](../Chat/AstrBot-Chat调查笔记.md)。

### 会话与消息

- **两级会话与持久化**：会话（聊天窗口，以统一消息源标识）内可建立多个对话（子对话），LLM 历史存 SQLite、OpenAI 格式，当前对话指针经偏好存储持久化；写入即时、无防抖，旧版"60 秒防抖保存"为死代码。证据：静态源码确认。来源：[会话与消息管理调查笔记](../会话与消息管理/AstrBot-会话与消息管理调查笔记.md)、[Chat 调查笔记](../Chat/AstrBot-Chat调查笔记.md)。
- **WebChat 消息操作与线程分支**：编辑（仅最新用户消息）、重生成（整回合重跑）、侧线程（基于检查点复制历史、独立演进）、推理/引用面板；无版本树，"分支"只有线程一种形态（详见末尾小节）。证据：静态源码确认。来源：[会话与消息管理调查笔记](../会话与消息管理/AstrBot-会话与消息管理调查笔记.md)、[Chat UI 调查笔记](../Chat%20UI/AstrBot-ChatUI调查笔记.md)。
- **群聊上下文与群历史**：群聊上下文按会话环形记录最多 1000 条原始消息并注入为系统提醒块；群历史可选持久化（默认关，700 条上限）并暴露读取工具；开启按发送者隔离会话后可让每人拥有独立上下文。证据：静态源码确认。来源：[Chat 调查笔记](../Chat/AstrBot-Chat调查笔记.md)、[会话与消息管理调查笔记](../会话与消息管理/AstrBot-会话与消息管理调查笔记.md)。
- **事件总线与九阶段洋葱流水线**：EventBus 每事件一个异步任务，按配置实例取调度器，固定九阶段（唤醒、白名单、会话状态、限流、内容安全、预处理、处理、结果装饰、回复）；阶段返回异步生成器时递归执行后续阶段后回到挂起点收尾，事件可在任意点截断。证据：静态源码确认。来源：[对话请求与上下文调查笔记](../对话请求与上下文/AstrBot-对话请求与上下文调查笔记.md)、[Chat 调查笔记](../Chat/AstrBot-Chat调查笔记.md)。
- **并发控制与 follow-up**：按会话粒度锁串行化 LLM 请求、跨会话天然并行；Agent 运行期间同发送者的新消息捕获为 follow-up，捕获时分配单调序号、队首放行，避免唤醒顺序漂移。证据：静态源码确认。来源：[对话请求与上下文调查笔记](../对话请求与上下文/AstrBot-对话请求与上下文调查笔记.md)、[Chat 调查笔记](../Chat/AstrBot-Chat调查笔记.md)。

### 生成与创作

- **消息渲染（统一组件链 + 平台自治转换）**：22 种组件枚举与消息链归一化，各平台适配器自实现出站/入站转换、无统一转换函数；结果装饰阶段集中做链重写（推理注入、语音合成、转图、转发、@/回复前缀），回复阶段分段发送；WebChat 用半开放协议与前端分块渲染。证据：静态源码确认。来源：[消息渲染器调查笔记](../消息渲染器/AstrBot-消息渲染器调查笔记.md)。
- **生成式输出：GenUI 内联 HTML 预览**：模型以纯文本产出 `<html-genui>` 块，前端沙箱 iframe（不含同源权限）按 500ms 节流整文档重建，源码随消息持久化、重新打开会话后重建；无独立对象身份（无 ID/版本/diff/能力桥），修订只能整块重出，能力谱系评定 G1 成立、G3 部分成立。证据：静态源码确认（UI 与端到端行为未运行验证，见口径）。来源：[生成式输出与运行时调查笔记](../生成式输出与运行时/AstrBot-生成式输出与运行时调查笔记.md)。
- **工具执行结果物化与工作区**：执行产物经文本协议转成带附件标识的文件 part 并可下载，同一文件落会话/项目工作区，前端只读文件树浏览；模型侧经读写/编辑/搜索工具形成"查询→读取→定向修改"闭环；本地为每次调用独立子进程、远端走沙箱运行时。证据：静态源码确认（未运行验证，见口径）。来源：[生成式输出与运行时调查笔记](../生成式输出与运行时/AstrBot-生成式输出与运行时调查笔记.md)。

### Agent 运行时与外部协作

- **Agent 工具体系（统一执行器 + 多来源注册）**：内置、插件、MCP、子 Agent Handoff 四路注册汇合为统一工具对象，由主 runner 串行消费；OpenAI/Anthropic/Google 三种协议 schema 由同一工具集导出；同名工具激活态优先、参数按声明过滤、非内置工具经权限代理，另有超时、大结果落盘、重复调用提示、步数截断与双段重查五种产物级防护。证据：静态源码确认。来源：[Agent 工具调查笔记](../Agent工具/AstrBot-Agent工具调查笔记.md)。
- **MCP 工具支持**：配置文件声明、启动时并行初始化，生命周期自管理（连接/启用超时、幂等启动、同任务清理）；供 LLM 使用的工具名做字符清洗，原名保留用于实际调用；云端同步依赖外部服务（详见末尾小节）。证据：静态源码确认。来源：[Agent 工具调查笔记](../Agent工具/AstrBot-Agent工具调查笔记.md)。
- **子 Agent（Handoff）**：按 `transfer_to_{agent.name}` 生成交接工具注册进工具列表，支持前台与后台交接。证据：静态源码确认。来源：[Agent 工具调查笔记](../Agent工具/AstrBot-Agent工具调查笔记.md)。
- **外部 IM 平台接入**：18 个平台适配器（Telegram/Discord/Slack/飞书/企业微信/钉钉/QQ/OneBot/KOOK/LINE 等）构成带身份、连接、入站事件、命令、会话映射、媒体转换与出站投递的产品主入口；AstrBot 是 IM Agent 宿主而非从 IM 遥控桌面客户端；统一消息源承担身份与配置路由，平台元数据声明流式/主动消息能力。证据：主链确认（静态证据）。来源：[外部执行体与应用协作调查笔记](../外部执行体与应用协作/AstrBot-外部执行体与应用协作调查笔记.md)。

### 渠道与调度

- **LLM 渠道管理**：渠道拆为来源与模型实例两级配置，"一个配置项 = 一个能力实例"；42 个适配器、五类能力子类（对话、语音识别、语音合成、Embedding、Rerank）统一抽象；路由优先级为会话偏好 → 全局默认 → 实例列表第一个；错误处理分传输层重试与适配器内错误分类降级两层，Key 轮换为错误驱动、无定时轮换；fallback 仅图片模态降级与空输出降级两处消费；WebUI 提供 source/provider 两级管理。未实现渠道池/权重/负载均衡、API Key 明文落盘（详见末尾小节）。证据：静态源码确认。来源：[LLM 渠道管理调查笔记](../LLM渠道管理/AstrBot-LLM渠道管理调查笔记.md)。

## 工程与基础设施摘要

- **仓库分布**：Python 服务核心与 Vue 管理界面合仓的前后端项目，Dashboard 构建产物在 Python 打包时嵌入发行包，形成一个部署单元；Git 跟踪 1,623 个文件，可识别源码约 30 万行（Python 66.9%、Vue 23.6%、TypeScript 5.8%），文档 441 个文件、测试 186 个文件；`astrbot/core` 与 `dashboard/src` 量级接近。来源：[仓库分布调查笔记](../仓库分布/AstrBot-仓库分布调查笔记.md)。

## 已知边界与待验证事项

**声明不符**：无成立项。唯一被评估的候选（Agent Sandbox）经核为"声明不符不成立"——能力存在，仅默认关闭、需显式启用（[独特功能调查笔记](../独特功能/AstrBot-独特功能调查笔记.md)）。

**暂缓、未闭合与外部依赖**：
- Agent Sandbox 远端容器运行时（shipyard/cua 云镜像、shipyard_neo 技能流水线服务端）依赖外部服务可用性，本地运行需配置 endpoint/token；`computer_use_runtime` 默认 none，能力默认关闭；主动回复默认关闭（概率 0.1）（独特功能笔记）。
- Live Mode（实时对话）前端组件未挂载、入口按钮已注释，仅后端 live-chat WebSocket 与 run_live_agent 路径保留，界面侧当前不可达（[Chat UI 调查笔记](../Chat%20UI/AstrBot-ChatUI调查笔记.md)）。
- 桌面 wrapper 属外部 AstrBot Desktop 项目，本仓只消费 bridge 不实现；桌面端渠道操作覆盖未验证（应用界面基础设施、LLM 渠道笔记）。
- `/persona` 指令实现不在本仓库，按文档记载为准（Agent 角色笔记）。

**未覆盖类目**：`对话导出与分享`、`媒体创作` 两个类目未找到 AstrBot 调查笔记，本次汇总不含相关内容。

**共性未验证（方法学约束，不否定代码完备性）**：
- 未启动真实平台实例：IM 平台登录、webhook 签名、断线重连、命令同步与限额行为；各平台出站/入站转换的线上表现（外部执行体、消息渲染笔记）。
- 流水线时序：九阶段在真实平台上的行为、follow-up 与流式并存交互、洋葱递归与停止竞态（Chat、对话请求与上下文笔记）。
- 生成式输出：GenUI iframe 实际运行与隔离表现、流式半截标签解析容错、重新打开会话后的预览重建；沙箱远端容器行为与技能同步流程（生成式输出、独特功能笔记）。

**已确认的能力边界（未实现项）**：
- LLM 渠道：无渠道池/权重/负载均衡，无密钥级负载均衡，fallback 不覆盖普通 API 错误；API Key 明文落盘，列表 API 向有权限前端返回完整 key（LLM 渠道笔记）。
- 生成式输出：GenUI 无对象身份/版本/diff/导出，bot 消息不可就地编辑，工作区文件对用户只读，本地 Python 执行无持久 kernel（生成式输出笔记）。
- WebChat：无版本树（分支仅线程一种形态）、草稿不持久化、会话搜索入口未找到（会话与消息管理、Chat UI 笔记）。
- 应用界面：无应用级错误边界、无公共灯箱与统一上传层、无主题市场/自定义 CSS（应用界面基础设施笔记）。
- Agent 工具：权限表仅 admin/member 两态，工具超时仅包单次迭代，图片参数收集不递归（Agent 工具笔记，静态推断）。
