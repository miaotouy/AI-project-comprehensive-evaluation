## 项目概览

OpenOcta 是面向 IT Ops 的桌面 Agent。它的辨识度不在通用聊天，而在把 Agent 放进巡检、告警分析、排障与远程派单的闭环：定时任务和外部 Hook 可以在无人对话时启动一轮分析，数字员工把「人设 + 技能白名单 + 专属 MCP」打包复用，知识库提供本地可编辑的 Runbook，蜂群把任务拆给一棵可介入的 Agent 树。

控制平面是本机 Gateway（默认 `127.0.0.1:18900`）。Wails 只提供单窗口壳：启动页探活成功后跳转到网关托管的页面，业务通信走网关 WebSocket，而不是 Wails 运行时事件。Control UI 是 Lit 3 + TypeScript 的 light DOM 单页应用，源码与元素名仍保留上游 openclaw 命名。模型循环由 Eino ADK 的 DeepAgent 与 Runner 驱动，OpenOcta 负责装配工具、中间件、审批、执行后端并消费流式事件。

会话没有数据库：每个 agent 一份 `sessions.json` 索引，每个会话一份 `<sessionId>.jsonl` 追加日志；会话键同时决定存储位置、agent、运行时池分片与前端订阅。Agent 角色分两套对象——可持久化的数字员工模板与配置文件里的 `agents.list` 运行主体，两者通过会话键在同一次运行中汇合。

主要产品面是 Control UI 的九个顶栏入口：消息、定时任务、员工市场、技能库、知识库、工具库、模型、教程、配置；AgentSwarm 是独立于消息页的第二个协作表面。外部接入包括企业微信、微信、钉钉、飞书、QQ 五个 IM 渠道、OpenAPI、Hooks webhook、MCP 工具服务，以及作为工具被调用的本机 CLI Agent。

重要外部依赖包括模型 Provider（25 个内置模板与用户自定义条目）、仓库外的数字员工市场与技能市场、各 IM 平台账号、内嵌 GGUF 模型运行时，以及默认开启并带内置工作区凭据的 CozeLoop 链路追踪。仓库快照有 908 个跟踪文件、720 个源码文件 / 159,843 行源码，其中 TypeScript 约 7.2 万行、Go 约 6.7 万行、CSS 约 1.9 万行；文档 71 个文件，测试 43 个文件（42 个在 `ui`）。

## 产品结构与入口地图

| 层 | 入口 | 已确认形态 |
|---|---|---|
| 桌面壳 | Wails 单窗口 | 启动页轮询本地网关健康检查后加载网页界面；只有 Windows 启用页面内最小化/最大化/关闭按钮；无托盘、系统通知、全局快捷键或多窗口入口 |

## 功能能力摘要

### 会话、消息与上下文

- **两层文件会话存储与会话键**：会话事实源是每个 agent 的 `sessions.json` 索引加每个会话的 `<sessionId>.jsonl` 转录，没有数据库。会话键是带语义的命名空间字符串，覆盖 `agent:<id>:...`、`custom:<uuid>`、渠道 peer、员工、cron 与蜂群等来源；条目里的 sessionId 才是 UUID 并决定转录文件名。键与 sessionId 不是一一映射：多个键可指向同一文件，条目缺失时按键派生 ID。`session.store` 可覆盖索引路径，但默认转录目录仍按 agent 推导。转录头写死版本 2，读取只检查首行类型，不校验也不迁移；索引损坏会让整个 store 读取失败。证据状态：主链确认（静态）。[会话与消息管理调查笔记](../会话与消息管理/OpenOcta-会话与消息管理调查笔记.md)

- **线性追加消息模型**：消息角色只有 user、assistant、toolResult；内容块覆盖文本、思考、图片、视频、文件、工具调用、工具结果与 A2UI。写入粒度是回合：用户消息在模型调用前落盘，assistant 内容在每次 `message_stop` 追加一行，工具结果单独成行，取消时用快照函数补写半截内容。每条消息行写了 `parentId`，但读取路径从不使用，只按文件顺序取最后若干条，因此没有可切换的消息分支。同一份 JSONL 还承载 `token_usage` 与 `tool_call` 旁路行，只服务成本与工具统计，不进入上下文。证据状态：主链确认（静态）。[会话与消息管理调查笔记](../会话与消息管理/OpenOcta-会话与消息管理调查笔记.md)

- **会话生命周期与行级压缩**：创建有新建与幂等 ensure 两条路径；修改与置顶统一走 patch，但真正写回条目的只有标题、思考级别、详细级别、来源与置顶时间。`/new` 与重置做同一件事：换新 sessionId 与新文件，保留标题、渠道与两个生成偏好，并中止在飞运行。删除有主会话保护、可选择只删索引、并会中止运行；返回结构里的 `archived` 字段实际列出的是永久删除的路径。压缩是文件级截断：默认保留最后 400 行，超过才把原文件改名为 `.bak.<时间戳>` 并重写，不生成摘要；它按行而不是按回合，可能把一条消息切成两半。证据状态：主链确认（静态）。[会话与消息管理调查笔记](../会话与消息管理/OpenOcta-会话与消息管理调查笔记.md)

- **列表、预览与元数据检索**：列表把所有 agent 索引读入内存后过滤、按置顶与更新时间排序、再补 token 统计，可选补派生标题与末条摘要（后两项各需再读一次转录）。预览按会话读文件尾部 64KB、最近 50 行，默认返回 12 条。搜索只覆盖显示名、标签、主题、sessionId 与会话键的子串匹配；消息内容全文检索本次未找到，`session_search` 也没有对应工具。聊天历史一次读取整个文件后取最后 N 条，默认 100、上限 1000，界面固定请求 500 条，没有游标分页或向上加载入口。证据状态：主链确认（静态）。[会话与消息管理调查笔记](../会话与消息管理/OpenOcta-会话与消息管理调查笔记.md)、[Chat UI 调查笔记](<../Chat UI/OpenOcta-ChatUI调查笔记.md>)

- **生成请求主链与状态机**：一次生成是 WebSocket 方法调用加后台 goroutine 加会话级 TurnLoop。入口 `chat.send` 先做参数校验、命令分流与附件落盘；任务身份是调用方传入的幂等键，缺省生成 UUID，并立刻成为 runId。同一 runId 与 sessionKey 的重复请求直接返回在飞状态；控制器在响应 `started` 之前注册，避免客户端立刻中止却找不到任务。执行阶段依次创建模型工厂、装配资源、从转录水化历史、组装请求并进入流式回合；进度通过 `chat` 事件的 `state` 字段下发，取值为 delta、turn、final、complete、aborted、interrupted、a2ui。每条事件带本 run 自增的 seq；前端最可靠的结果信号是 `complete`，不是 `final`。请求超时按请求参数、配置或环境变量、默认 600000 毫秒三档决定，引擎侧另有默认 10 分钟的回合预算。证据状态：主链确认（静态）。[对话请求与上下文调查笔记](../对话请求与上下文/OpenOcta-对话请求与上下文调查笔记.md)

- **上下文拼装、预算与摘要**：每轮模型输入由四段合成：运行时创建时构造的系统提示、按员工与本地代理场景生成的每轮覆盖、从当前转录读取的历史、当前输入。历史转换做角色过滤、按最大条数取尾部，并重排工具轮以修补「工具结果先于调用行落盘」的乱序。关闭网关历史水化开关后，下层仍会按转录路径补读历史；本轮文本已提前追加到转录，空转录时也会回退到当前 Prompt，因此不能将该开关理解为不携带历史的保证。预算是模型上下文窗口，取不到时兜底 128000 token；上下文中间件在 45% 清理旧工具输出、65% 触发摘要，单个工具结果默认截断 8KB，清理保留 4 条后缀且至少清 8000 token。清理与摘要各写自己的运行时文件，与会话级的行级压缩不共享状态，也不可逆。证据状态：主链确认（静态）。[对话请求与上下文调查笔记](../对话请求与上下文/OpenOcta-对话请求与上下文调查笔记.md)、[会话与消息管理调查笔记](../会话与消息管理/OpenOcta-会话与消息管理调查笔记.md)

- **同会话等待、运行时驱逐与取消**：运行时池按会话键保存条目，运行期间持有条目互斥锁。新请求先等待旧条目释放，首段最多 30 秒；超时后删除池映射并再检查可用性，旧实例的关闭则等其运行释放锁。因而长运行场景可出现同键的新旧 Runtime 并存，不能据池锁推导整个会话严格串行。

  请求虽携带抢占标记，但标记要在获取 Runtime 后才送入 TurnLoop；等待旧运行结束或驱逐后换新实例的路径都无法保证立即抢占旧轮。显式停止另有消息命令、指定 runId 和整会话三个入口，先停 TurnLoop 再取消上下文。不同会话各自建运行时，本次未找到全局并发上限或队列；`chat.resume` 只用于审批中断后继续。证据状态：主链确认（静态），双运行条件由锁与驱逐路径推导，未做并发实测。[对话请求与上下文调查笔记](../对话请求与上下文/OpenOcta-对话请求与上下文调查笔记.md)

### 聊天工作台与消息渲染

- **单壳层任务会话工作台**：消息页把壳层左侧导航整块替换为会话侧栏，主区成为线程加可拉开的 Markdown 侧栏，底部是独立 Composer；线程与输入框各自是自定义元素，避免按键重绘整页。聊天上下文加载时一次拉取最多 5000 条带末条预览的会话，搜索是纯客户端子串过滤；行尾菜单提供重命名、置顶、复制本地会话链接与删除。侧栏没有归档、分组或未读概念，也没有「哪些会话正在生成」的总览标记。当前会话键同时写进本地设置与 URL 的 `session` 查询参数，刷新时 URL 优先。证据状态：主链确认（静态）。[Chat UI 调查笔记](<../Chat UI/OpenOcta-ChatUI调查笔记.md>)

- **发送、客户端排队、流式阶段与停止**：发送入口先识别三类文本命令——停止类、重置类、其它斜杠或感叹号命令，再决定直发还是排队。直发先乐观插入一条用户消息，用本地 runId 兼作幂等键，把阶段置为思考中。同会话仍在生成时，新消息只进内存队列，界面显示可逐条移除的队列条。流式界面按思考、调用工具、生成回复三阶段显示文案，有推理文本时同屏展开折叠面板，上下文压缩另有独立提示条。停止与「新会话」共用同一个按钮位；没有全局快捷键，只能点按钮或发送停止类文本。重连只清当前宿主的运行字段，后台会话映射没有统一清除；错过终态的后台会话切回时仍可能恢复旧运行快照。证据状态：主链确认（静态）。[Chat UI 调查笔记](<../Chat UI/OpenOcta-ChatUI调查笔记.md>)

- **按会话分桶的运行态与现场恢复**：运行态不是全局 busy 标记，而是模块级映射按会话保存 runId、阶段、流式文本、推理文本、A2UI 消息与终止 run 集合。切换会话时先持久化当前会话再恢复目标会话；非当前会话的事件不丢弃，而是更新该会话快照。因此在 A 会话生成中切到 B，A 仍继续累积，切回即可看到现场。刷新只能恢复会话、历史与设置项；流式现场、队列、草稿与本次资源限定都会丢失，多窗口之间也没有同步层。证据状态：主链确认（静态）。[Chat UI 调查笔记](<../Chat UI/OpenOcta-ChatUI调查笔记.md>)

- **发送前的模型、资源与附件配置**：模型下拉框由 Agent 默认模型别名与 Provider 模型数组合并生成，首项是「默认」；选择只存在界面状态，切换会话即重置，不写入会话配置。资源弹层提交本次技能与 MCP 选择，默认全部候选可用，选择不持久化。后端仍会补入全局 MCP，技能按目录再次扫描，因此界面选择不能独立保证最终能力集合。附件一次只接受一个文件，图片与常见文档 5MB、视频 50MB，压缩包与可执行文件按扩展名和 MIME 双拦截；图片发送时转 base64 内容块，视频与文档降级成一行文字标记。Composer 还提供本机 CLI Agent 的 `@` 提及、场景模板快捷指令与「提炼 SKILL」入口。证据状态：主链确认（静态）。[Chat UI 调查笔记](<../Chat UI/OpenOcta-ChatUI调查笔记.md>)

- **宽松输入归一与 Markdown/节点渲染**：渲染器不消费固定 part schema，而是接受历史消息与实时字符串，用防御性提取函数把字符串、parts 数组、工具调用、推理块、A2UI 与附件标记归一，再按角色分组、把助手回合切成「思考过程」「工具运行」与最终回答。Markdown 管线是修复、截断、`marked` 解析、表格包滚动容器、DOMPurify 白名单清洗；超过 14 万字符先截断，超过 4 万字符不再解析 Markdown。没有语法高亮、数学公式或 Mermaid。列表不虚拟化，一次渲染最近 500 条；工具卡由静态展示表驱动，按工具名归组并展开输入输出；附件有四条发现路径，其中「正文路径引用」会把回答里提到的文件补成可预览交付物。证据状态：主链确认（静态）。[消息渲染器调查笔记](../消息渲染器/OpenOcta-消息渲染器调查笔记.md)

### 模型渠道

- **Provider 与模型数据模型**：渠道是 `models.providers` 下的一个条目，键名就是模型引用里的 provider 标识，值是单一 `baseUrl`、单一 `apiKey` 与一个可手填的模型数组。代码另有一张 25 项的内置模板表，在用户没写配置时提供默认端点与环境变量名。模型引用固定为 `provider/modelId`，只按首个斜杠切分，裸模型名默认归到 anthropic。同一 provider 可挂多个模型，但不能有多个 Endpoint；`models.mode`、provider 的自定义 Header、鉴权方式、环境变量映射以及模型的兼容性与价格字段都只在 schema 中声明，模型请求路径没有消费点。证据状态：主链确认（静态）。[LLM 渠道管理调查笔记](../LLM渠道管理/OpenOcta-LLM渠道管理调查笔记.md)

- **配置生命周期与管理入口**：配置固定为状态目录下的 `openocta.json`，Windows 落在 `%APPDATA%\openocta`，可用状态目录或配置路径环境变量覆盖。首次启动写入示例配置，权限 0600；桌面模式若使用 token 鉴权，会把 token 强制改成内置固定值。桌面 Control UI 可查看、新增、编辑、删除 Provider 与模型，设置默认模型与环境变量映射；Gateway 提供配置读取与补丁接口。保存语义是「读快照拿 baseHash，再整文件覆盖」，补丁以原始 JSON 文本为基底合并以保留未知键，写盘后再解析成结构体。保存模型配置不会清理或重建运行时池。复制 Provider、启用/停用开关、导入导出与通用连接测试本次未找到；技能与员工市场属于仓库外服务。证据状态：主链确认（静态）。[LLM 渠道管理调查笔记](../LLM渠道管理/OpenOcta-LLM渠道管理调查笔记.md)

- **凭据与密钥暴露面**：上游凭据只有 Provider 的 `apiKey` 一个字段，支持字面量、`$ENV` 引用与按 Provider 名推导的环境变量名；查找顺序是模型级映射、顶层映射、进程环境。静态存储是配置文件里的明文，写盘 0600，没有字段级加密。配置读取接口会把密钥结构原样返回前端，模型可调用的配置工具也能读到；日志脱敏字段只在 schema 中，没有读取点。模型 HTTP 客户端显式禁用代理，总超时 180 秒，因此系统代理与代理环境变量对模型请求无效。入站 API Key 是另一套体系：`octa_` 前缀、SHA-256 哈希校验、AES-GCM 加密回显、路径与模型白名单、月度 token 上限与员工绑定，在对外 completion 接口上强制执行。证据状态：主链确认（静态）。[LLM 渠道管理调查笔记](../LLM渠道管理/OpenOcta-LLM渠道管理调查笔记.md)

- **协议适配与请求组装**：真正的协议适配只有两条：Anthropic Messages 与 OpenAI Chat Completions；Provider 的 `api` 为 anthropic 两个别名时走前者，其余一律落到 OpenAI 兼容分支。组装很薄，只传密钥、模型名、可选端点与最大输出，没有自定义 Header 注入、请求体重写或字段名兼容分支。唯一按「模型能力 + 输入模态」改变协议路径的是讯飞图片理解：Provider 为讯飞/星火且请求带图片时改用自定义 WebSocket 客户端，缺凭据则回退 OpenAI 兼容端点。内嵌模型走 Gateway 自己的 OpenAI 兼容代理，按请求体里的模型名路由到本地实例。上游返回长度截断只作为停止原因映射，不触发续写。证据状态：主链确认（静态）。[LLM 渠道管理调查笔记](../LLM渠道管理/OpenOcta-LLM渠道管理调查笔记.md)、[对话请求与上下文调查笔记](../对话请求与上下文/OpenOcta-对话请求与上下文调查笔记.md)

- **运行时选择与池化复用**：解析顺序是请求显式模型引用、会话键解析出的 Agent 模型、全局默认；解析失败不回退默认工厂，而是把错误写进转录并结束本次运行。运行时池以会话键为粒度，指纹包含工作区、Agent、员工、模型引用、讯飞图片模式、联网开关、系统提示覆盖、工具 schema 标记、提示版本以及排序后的 MCP 与技能键。指纹不含 Provider 的端点、密钥、协议类型与模型参数，而这些值只在创建引擎时读进适配器；因此修改同一 Provider 的端点或密钥后，已池化会话可能继续使用旧连接参数，直到模型引用、提示版本、MCP/技能集合变化或运行时被显式驱逐。该结论来自代码结构推断，未用运行中的 Gateway 验证。模型别名只在聊天页生成下拉标签，不参与路由。证据状态：主链确认（静态）。[LLM 渠道管理调查笔记](../LLM渠道管理/OpenOcta-LLM渠道管理调查笔记.md)

- **用量、成本与链路追踪**：每次模型调用结束把输入、输出、缓存命中与总量追加成一条旁路记录；写入时 provider 固定为空字符串，模型字段通常只有模型 id，因此按 Provider 汇总不可用。成本聚合只在条目自带 cost 时累计，而用量写入器不产生 cost，价格表也没有被使用，所以用量页能返回结构但价格通常为零。链路追踪默认开启：配置没有 CozeLoop 段时自动填入内置工作区与 API Token；关闭需要显式禁用且 token 与工作区都为空，只要两者仍有值就会被重新置为启用。普通日志按级别写文件并可按日期滚动，界面读取尾部若干行；没有按请求维度归一化的上游错误码、延迟或重试计数。证据状态：主链确认（静态）。[LLM 渠道管理调查笔记](../LLM渠道管理/OpenOcta-LLM渠道管理调查笔记.md)

- **重试、多 Key 与故障转移**：上游 Key 是单个字符串，没有 Key 列表、轮询、冷却或健康状态；`auth.cooldowns` 与模型 fallback 链只在 schema、注释与示例配置中出现，没有执行逻辑。模型请求路径没有重试层，检索到的重试只属于下载、MCP 传输回退、渠道消息回退与运行时池忙重试。失败处理是逐次冒泡：工厂或运行时创建失败会写错误并结束本次运行，运行中 panic 尽量先冲刷已生成文本。限流只有入站维度，上游 429 或配额错误只作为本次错误返回。证据状态：确认不支持（本次检索范围内）。[LLM 渠道管理调查笔记](../LLM渠道管理/OpenOcta-LLM渠道管理调查笔记.md)

### Agent 角色与工具

- **数字员工模板**：数字员工是可持久化的目录型模板，`manifest.json` 保存 ID、名称、描述、人设 Prompt、启停、技能 ID 列表、专属 MCP、分类与来源。它没有模型、工作区、工具或版本字段；模型始终跟随 Agent 或请求。Prompt 非空时作为系统提示覆盖值进入运行时，语义是替换内置基础提示而不是追加。创建与更新走 `employees.create`；站点安装按员工、技能、MCP 三类下载 zip，员工包必须含 `config.json` 与 `README.md`，可选含技能包。删除员工会先清理该员工的会话再删模板，角色生命周期与会话生命周期绑定。证据状态：主链确认（静态）。[Agent 角色配置调查笔记](../Agent角色/OpenOcta-Agent角色配置调查笔记.md)、[独特功能调查笔记](../独特功能/OpenOcta-独特功能调查笔记.md)

- **`agents.list` 运行主体配置**：普通 Agent 由配置文件中的 `agents.list` 条目提供，字段覆盖标识、工作区、模型、技能、知识库、工具、子 Agent、沙箱与身份展示；该结构没有 Prompt 字段。`chat.send` 主链只读取其中的 Agent ID、工作区、模型与身份名称；Agent 级技能、工具、子 Agent 与沙箱字段本次未找到读取点，实际生效的技能过滤来自请求资源，工具装配来自运行时默认集合。Gateway 的 `agents.*` 处理器是占位实现：列表固定返回空数组，创建、更新、删除多数返回未实现，因此没有通过专用 RPC 创建普通 Agent 的可执行路径。证据状态：主链确认（配置路径）；专用 RPC 为入口确认。[Agent 角色配置调查笔记](../Agent角色/OpenOcta-Agent角色配置调查笔记.md)

- **角色装配优先级**：系统提示按「员工 Prompt 覆盖，否则内置模板」决定，随后仍可能追加技能说明、知识库说明与演进快照；因此员工 Prompt 是基础指令的唯一来源，但不是最终系统提示的全部内容。模型优先级为请求参数、Agent 配置、全局默认；工作区只按 Agent ID 解析，员工共享其 Agent 的工作区。技能先选员工或工作区候选，再筛条目并解析单个目录；MCP 先由员工覆盖全局、按请求筛选，非空结果随后又补回全局启用项。两条选择链均不能简写成严格能力白名单。内置提示里的工具、Shell 与安全约束会随基础提示一起被员工 Prompt 替换，若员工提示没有重新声明，这些约束就不在最终提示中。证据状态：主链确认（静态）。[Agent 角色配置调查笔记](../Agent角色/OpenOcta-Agent角色配置调查笔记.md)

- **技能与 MCP 的合并注入**：员工技能先加载旧版目录，再加载独占目录并覆盖同名项，`skillIds` 非空时从工作区技能池补充；员工候选为空会回退工作区；最终只把一个目录交给中间件，过滤名单没有随之传入。普通会话可能返回完整工作区根，员工分支先返回技能自身目录；扫描层级和最终可见集合需与条目筛选分开理解。技能不是独立执行域，技能可以指示模型调用命令或脚本，仍受同一审批与命令校验约束。MCP 请求筛选结果非空时会重新合并全部全局启用项，上下文工具回调也不逐服务筛选；筛选为空才关闭这两条装配入口。连接随运行时驱逐关闭。证据状态：主链确认（静态）。[Agent 角色配置调查笔记](../Agent角色/OpenOcta-Agent角色配置调查笔记.md)、[Agent 工具调查笔记](../Agent工具/OpenOcta-Agent工具调查笔记.md)

- **工具来源与动态目录**：模型可用工具不是静态清单。文件读写、编辑与 Shell 执行来自 Eino DeepAgent 自带能力；OpenOcta 追加配置工具、浏览器、本机 CLI Agent、MCP 工具、蜂群工具与知识库检索；联网搜索与抓取工具的实现仍在仓库中，但编译期开关恒为 false，运行时注册函数直接返回 false。`write_todos` 只有环境变量为真时才启用。工具目录通过检索中间件动态暴露，触发阈值是 1，因此只要存在动态工具，基础工具列表就为空，全部工具走动态检索。文档声称默认包含 echo、cron、sessions 等工具，与当前可执行路径不一致。证据状态：主链确认（静态）。[Agent 工具调查笔记](../Agent工具/OpenOcta-Agent工具调查笔记.md)

- **参数守卫、软失败与结果回注**：工具参数在模型调用与真实执行之间经过守卫中间件：空参数或非法 JSON 判为无效，`execute` 命令不能为空且上限 4096 字符，文件工具的路径别名统一为 `file_path` 并拒绝空路径、`.` 与当前目录。参数错误不抛到聊天层，而是格式化为工具输出返回模型，并区分截断 JSON 与一般非法 JSON，模型可在同一回合修正。Shell 非零退出码不当作 Go 错误，退出码、stdout 与 stderr 组合成正常输出，由模型自行判断失败。工具结果写入工具结果行并广播，可交付文件同时转成附件块；历史里缺失结果的工具调用会由读侧补占位结果。证据状态：主链确认（静态）。[Agent 工具调查笔记](../Agent工具/OpenOcta-Agent工具调查笔记.md)

- **审批门控与命令策略**：执行前使用从策略转换的遗留校验器，仅带入 deny、禁用参数与长度等限制。命令名封禁只检查整条字符串的首词，片段和参数另行匹配；完整的复合命令分段求值器没有接入这条执行链，allow/ask 也未在此处决策。

  Eino 审批是独立机制：显式开启审批队列后，只拦截 `execute`，首次调用保存参数并中断，恢复时按批准结果执行或返回拒绝理由；本机 CLI Agent、MCP 与文件写入不在该中间件范围。前端审批浮层与审批表没有接通事件生产和恢复接口，不能据界面推定执行闭环。证据状态：主链确认（后端）；界面侧为入口确认。[Agent 工具调查笔记](../Agent工具/OpenOcta-Agent工具调查笔记.md)、[生成式输出与运行时调查笔记](../生成式输出与运行时/OpenOcta-生成式输出与运行时调查笔记.md)

- **执行边界与子 Agent**：工具执行发生在 Gateway 宿主进程：Shell 以当前用户权限启动，Windows 用 `cmd.exe /c`，Unix 交给 Eino 本地后端；没有容器、命名空间、用户切换或系统调用过滤，沙箱开关字段存在但未被运行时读取。文件写入会把相对路径与 Windows 盘根文件重定向到工作区，`execute` 的工作目录却没有设置，仍是 Gateway 进程当前目录。工具执行没有统一的逐工具超时；工具循环迭代上限固定为 50。运行检查点写在状态目录，以会话为 ID 基准，用于中断恢复与会话清理，但没有启动扫描把上次未完成的运行重新推入循环。本机 CLI Agent 支持状态探测、单任务与并行多任务，默认 10 分钟，输出在进程结束后一次性返回，没有外部会话映射、流式回传或审批。蜂群子 Agent 复用宿主运行时，硬上限为每成员 5 个直接子成员、10 层树深、每工作区 55 个成员。证据状态：主链确认（静态）。[Agent 工具调查笔记](../Agent工具/OpenOcta-Agent工具调查笔记.md)

### 检索增强与记忆

- **Vault 摄取与全量重建**：Markdown Vault 经手动同步、保存或目录切换触发全量扫描，启动仅打开索引。切块按整行累加到 2400 字节阈值并重叠两行；长行可越界，非末块消费不超过两行时起点可能不前进。重建先替换全文索引与正文，再生成整库向量；嵌入失败会报错，但前段变更已提交且没有回滚。重建持写锁阻塞检索，当前没有快照式切换。证据状态：主链确认（静态）。[检索增强与认知编排调查笔记](../检索增强与认知编排/OpenOcta-检索增强与认知编排调查笔记.md)

## 独特与差异化能力

独特功能笔记列出八张能力卡：无人值守运行、数字员工、Knowledge Vault、Agent Swarm、IM 渠道双向、会话经验提炼、命令审批、A2UI。其中数字员工、Knowledge Vault、IM 渠道、经验提炼、命令审批与 A2UI 已分别归并到本汇总的角色、检索、外部协作、导出、工具与生成式输出章节，以下只展开不与其他章节重复的两项，并说明归并口径。

- **无人值守运行（Cron + Alert Hook + 结果投递）**：定时任务定义存 `cron/jobs.json`，运行日志存 `cron/runs/*.jsonl`，支持按时间点、固定间隔与 cron 表达式三种调度、系统事件与 Agent 回合两种负载、主会话与隔离会话两种目标，并可绑定数字员工、资源过滤与投递配置。调度器按最近到期时间睡眠，最多 60 秒唤醒一次，取到期任务逐个执行；手动强制运行使用带运行 uuid 的键，定时运行复用任务键。执行最终汇入 `chat.send`，因此与用户聊天共享转录、工具与权限链路。完成后取「最后一个工具块之后」的文本作为摘要，按配置发往 IM 渠道或 POST 到 Webhook，10 秒内重复摘要去重、header 截断到 50 字符。外部告警另走告警 Hook，不要求固定结构，解析失败时把整个请求体当作消息。证据状态：主链确认（静态）。[独特功能调查笔记](../独特功能/OpenOcta-独特功能调查笔记.md)、[对话导出与分享调查笔记](../对话导出与分享/OpenOcta-对话导出与分享调查笔记.md)

- **Agent Swarm 房间式多 Agent 协作**：蜂群是独立于消息页的协作表面，左侧房间列表、上方成员树与关系图、中间成员对话、右侧面板。创建房间时同时建立根成员；派生在父成员下创建子成员，先做配额检查再落库，然后把初始指令作为一条消息发给子成员。成员消息先写用户历史、把状态置为忙碌，再启动任务；流式增量、最终输出与错误分别广播，结束后写助手历史并恢复状态。房间与成员一起写入单个 JSON 文件，历史最多 500 条，重启后可继续。停止是整房间级的「中止全部」，没有单成员停止入口；删除房间会级联删除成员、蜂群历史与关联聊天会话。成员侧注入创建子成员与发送消息工具，并可在允许时注入会话派生别名，工具说明要求同一子 Agent 只创建一次。证据状态：主链确认（静态）。[独特功能调查笔记](../独特功能/OpenOcta-独特功能调查笔记.md)、[Chat UI 调查笔记](<../Chat UI/OpenOcta-ChatUI调查笔记.md>)、[Agent 工具调查笔记](../Agent工具/OpenOcta-Agent工具调查笔记.md)

已归并到其他章节的独特能力包括：数字员工归并 Agent 角色；Knowledge Vault 归并检索增强；IM 渠道双向归并外部协作；会话经验提炼归并对话导出；命令审批归并 Agent 工具；A2UI 归并生成式输出。Wails 桌面壳、应用内更新、日志导出与本地模型下载属于基础设施或已由其他类目承接，不计入差异化能力。

- **仓库分布与规模**：Go 后端加 Wails 桌面壳加前端控制界面，`src` 集中 Go 命令、服务与能力包，`ui` 集中前端与静态资源，`deploy` 提供 Windows/macOS 与场景部署文件。快照有 908 个跟踪文件、720 个源码文件 / 159,843 行源码；TypeScript 71,947 行、Go 67,140 行、CSS 19,304 行；文档 71 个文件，测试 43 个文件，其中 42 个在 `ui`、1 个在 `src/test`。Go 代码主要在 `src/pkg`，前端模板与样式占源码近半。证据状态：Git 跟踪文件机械统计与构建配置复核。[仓库分布调查笔记](../仓库分布/OpenOcta-仓库分布调查笔记.md)
