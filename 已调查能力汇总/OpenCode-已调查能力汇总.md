## 项目概览

OpenCode 是 Bun/TypeScript monorepo，交付 CLI、TUI、Web 工作台、桌面端、服务端、SDK、客户端库、插件与内建 GUI 插件。2.x 已收敛为单一架构：Schema 定义契约，Core 承担会话与执行，Protocol 用 Effect `HttpApi` 声明端点，Server 实现处理器并通过 SSE 广播事件，客户端由协议生成，SDK 在进程内直接运行服务端路由。会话持久化只有一套 Drizzle/SQLite v2 模型（会话、消息、内容、收件箱、指令、blob），不再有 v1 双轨。

模型请求不再经 AI SDK：`packages/ai` 提供原生协议实现，执行器以步骤（step）为单位运行，工具调用、结果回流与压缩都在服务端完成。界面层分三套：TUI（opentui + Solid）、Web App（Solid + Kobalte + Tailwind，Web/桌面使用 `packages/session-ui`，TUI 独立终端渲染）、桌面 Electron 薄壳复用 App；非外壳功能全部是 GUI 插件。生成式输出以真实文件系统为事实源，回合边界用快照服务记录文件版本，撤销按消息粒度分阶段执行；此外新增 Artifact 托管与 Code Mode 受限执行两条独立产物通道。

## 功能能力摘要

### 角色与上下文

- **Agent 角色配置体系**：Agent 是由配置与插件构建的只读内存对象，会话只保存 agent 名字引用；来源包括配置文件、角色 Markdown 文件（`{agent,agents}/**/*.md` 与 `{mode,modes}/*.md`，后者强制 primary）与插件；默认基线为 `*` allow、`.env` ask。内置 general/explore/compaction/title/summary 等 agent，plan 插件限制编辑。选择优先级为显式/会话值 → 配置默认 Agent → build → 首个可选条目；配置加载与插件装配顺序见笔记。[Agent 角色配置调查笔记](../Agent角色/OpenCode-Agent角色配置调查笔记.md)

- **system prompt 与指令加载**：第一段按环境（目录、平台、日期）→ 指令文件 → MCP 指令 → 技能顺序拼装，第二段由 agent 自定义提示或 provider 风格提示前缀后合并用户 system 与结构化输出提示；指令文件按全局 → 项目祖先链 → 配置追加顺序加载，每条带来源头。[Agent 角色配置调查笔记](../Agent角色/OpenCode-Agent角色配置调查笔记.md)、[对话请求与上下文调查笔记](../对话请求与上下文/OpenCode-对话请求与上下文调查笔记.md)

- **上下文装配与压缩**：`SessionContext.select`/`load` 从数据库重建历史，按模型输入上限与输出预留计算可用预算；压缩由自动、溢出、手动三种触发，压缩后以 summary 加尾部消息重建历史，原生压缩信息随步骤事件记录；执行器在溢出时返回 `Compacted`/`RecoverFull` 等结果继续或重载。触发阈值未实测。[对话请求与上下文调查笔记](../对话请求与上下文/OpenCode-对话请求与上下文调查笔记.md)

- **模型与参数解析**：生效模型来自请求、agent 与会话记录；参数与变体按 provider → model → agent → variant 合并；模型目录来自 `core/src/models-dev.ts` 的远端目录（含磁盘快照回退）。无参数级发送前配置界面。[LLM 渠道管理调查笔记](../LLM渠道管理/OpenCode-LLM渠道管理调查笔记.md)

### 会话与消息

- **单轨持久化模型**：SQLite 表为会话（含 fork 关系、挂起、恢复次数、空闲结论）、消息（唯一 `(session, seq)` 索引）、内容（主键为消息与序号）、收件箱、指令条目/blob/状态、blob 与引用。ID 前缀分层：会话 `ses_`（升序生成、倒序排列）、消息 `msg_`、内容由事件 id 转换（`evt_` → `msg_`）。[会话与消息管理调查笔记](../会话与消息管理/OpenCode-会话与消息管理调查笔记.md)

- **消息与内容模型**：消息按用户、助手、系统、合成、技能、shell、压缩、空闲与状态切换等类型区分；助手内容项为文本、推理、工具三种，工具项带流式输入、运行中、完成、失败状态。附件以 blob 存储并记录哈希引用。[会话与消息管理调查笔记](../会话与消息管理/OpenCode-会话与消息管理调查笔记.md)、[对话请求与上下文调查笔记](../对话请求与上下文/OpenCode-对话请求与上下文调查笔记.md)

- **事件即写入与投影**：写入先发布 durable 事件，由投影器落库，事件顺序即持久化顺序；服务端经 SSE `/api/event` 广播，客户端投影到 store。事件类型覆盖会话、步骤、文本、推理、工具、shell、压缩、执行体、收件箱、用量与指令等。[Chat 调查笔记](../Chat/OpenCode-Chat调查笔记.md)、[会话与消息管理调查笔记](../会话与消息管理/OpenCode-会话与消息管理调查笔记.md)

- **会话生命周期**：创建、重命名、归档、挂起、恢复、删除、分叉各有端点；删除级联清理子会话与消息；导出/导入通过转移服务；回退分暂存、确认、清除三阶段，按消息边界生效。[会话与消息管理调查笔记](../会话与消息管理/OpenCode-会话与消息管理调查笔记.md)

- **列表、分页与搜索**：会话列表按项目与工作区分页；消息列表用游标分页；搜索只对会话标题做 `LIKE` 匹配，本次未找到消息内容全文搜索。[会话与消息管理调查笔记](../会话与消息管理/OpenCode-会话与消息管理调查笔记.md)、[Chat 调查笔记](../Chat/OpenCode-Chat调查笔记.md)

- **Chat UI 工作台**：App 按服务端、工作区、会话三层组织，支持同时连接多个服务端；Composer 按需挂载提问、审批、待办、回退、中断等 dock；会话页有时间线、子 Agent 与终端标签。TUI 复用同一套服务端会话，键盘为第一交互协议。[Chat UI 调查笔记](<../Chat UI/OpenCode-ChatUI调查笔记.md>)

- **发送、排队与中断**：提示提交分命令、shell 与普通三条路径；`SessionInbox` 提供 steer 与 queue 两种投递；中断端点支持随后恢复（resume）；重试状态由独立组件展示尝试次数与倒计时。[Chat UI 调查笔记](<../Chat UI/OpenCode-ChatUI调查笔记.md>)、[对话请求与上下文调查笔记](../对话请求与上下文/OpenCode-对话请求与上下文调查笔记.md)

- **草稿与现场恢复**：Web 草稿（文本与图片）经 IndexedDB 与本地存储持久化，桌面端按窗口持久化；会话与消息全量落库，再次进入经事件订阅恢复。[Chat UI 调查笔记](<../Chat UI/OpenCode-ChatUI调查笔记.md>)

- **消息渲染管线**：时间线行模型由投影函数从消息生成，支持行复用；App 用虚拟列表渲染可见行；markdown 管线为「marked 切块 → Worker 解析与高亮（`@pierre/highlights`）→ DOMPurify 清洗 → 节点树按 key 增量更新」，流式正文以 24ms 步进渲染，支持 katex 与 Mermaid；工具渲染器按工具名分派十余种专用视图，读取类工具合并为上下文组。[消息渲染调查笔记](../消息渲染器/OpenCode-消息渲染调查笔记.md)

### 生成与创作

- **执行器主链**：`session/runner/` 把一次生成拆成步骤：选择模型与工具、构造请求、流式消费、处理工具调用、判定结果并决定继续、重试或压缩。同一会话由运行协调器串行，不同会话并行；结果以标签化枚举表达（完成、重试、继续、重载、压缩、输出超限）。[对话请求与上下文调查笔记](../对话请求与上下文/OpenCode-对话请求与上下文调查笔记.md)

- **流式落库与收口**：文本与推理按增量事件推送并在步骤结束时以完整内容收口；工具状态迁移即时落库；失败与中断按结果类型收口，未执行完的工具在重放时转为错误内容，不重复执行。[对话请求与上下文调查笔记](../对话请求与上下文/OpenCode-对话请求与上下文调查笔记.md)、[Agent 工具调查笔记](../Agent工具/OpenCode-Agent工具调查笔记.md)

- **停止、重试与续写**：中断经运行协调器取消执行，可带恢复语义；重试由执行器判定并可带退避，耗尽后上报错误；续写即同会话追加，也可通过 steer/queue 控制投递。重试可能重复计费为静态推断。[对话请求与上下文调查笔记](../对话请求与上下文/OpenCode-对话请求与上下文调查笔记.md)

- **自动标题与摘要**：首轮后由小模型生成标题；回合摘要与文件变更在步骤结束时写入。摘要生成失败不影响主链。[会话与消息管理调查笔记](../会话与消息管理/OpenCode-会话与消息管理调查笔记.md)

- **工具调用驱动的文件工作区**：模型通过 read/write/edit/patch/shell 等工具操作真实工作区；快照服务在步骤前后捕获文件树版本、生成差异并可恢复，步骤结束事件携带快照与变更文件。模型跨回合通过读取工具感知文件，通过定位替换做定向修改。能力主体仍在"可编辑工作区"，未找到容器级隔离执行。[生成式输出与运行时调查笔记](../生成式输出与运行时/OpenCode-生成式输出与运行时调查笔记.md)

- **Artifact 托管**：模型用 `artifact` 工具创建/更新/删除产物（文件映射 + 入口 + URL），需显式启用实验性 artifacts；本地默认 Provider 只托管静态文件，其他能力由 Provider 实现决定；另有实验性端点管理 Provider 与按路径访问产物。[生成式输出与运行时调查笔记](../生成式输出与运行时/OpenCode-生成式输出与运行时调查笔记.md)、[独特功能调查笔记](../独特功能/OpenCode-独特功能调查笔记.md)

- **Code Mode**：execute 工具让模型以受限程序编排工具，另提供按 webfetch 动作授权的 fetch；独立检查入口不提供网络。宿主限制执行时间、调用次数、输出与数据量，直接文件、进程与包访问不可用。[Agent 工具调查笔记](../Agent工具/OpenCode-Agent工具调查笔记.md)、[独特功能调查笔记](../独特功能/OpenCode-独特功能调查笔记.md)

### Agent 运行时与外部协作

- **工具系统**：工具以 `schema/src/tool.ts` 的 `Tool.Info` 定义（名称、输入、描述、执行、输出、选项），插件形态实现位于 `core/src/tool/plugin/`，覆盖文件、检索、shell、编辑、补丁、提问、技能、子 Agent、待办、网络访问、Artifact、调度等；另可接 MCP 工具与 MCP 资源工具。工具由插件运行时装配，插件侧可增删工具并挂前后钩子。[Agent 工具调查笔记](../Agent工具/OpenCode-Agent工具调查笔记.md)

- **权限与执行边界**：目录过滤与执行授权分开，工具叶子策略按资源判断，必要时等待用户；无人值守时待审批动作复评为允许或拒绝。命令在本机子进程执行，未找到容器级隔离；Code Mode 为独立受限解释器，HTML 文件预览另有 sandbox iframe。Session runner 对结果做 2000 行 / 50 KiB 通用截断，超限全文落盘。[Agent 工具调查笔记](../Agent工具/OpenCode-Agent工具调查笔记.md)、[生成式输出与运行时调查笔记](../生成式输出与运行时/OpenCode-生成式输出与运行时调查笔记.md)

- **结果回流与重放**：工具调用与其结果通过稳定调用 id 配对；完成与失败内容在下一轮重建模型消息时分别转为结果或错误内容；被中断的调用不重放执行。[Agent 工具调查笔记](../Agent工具/OpenCode-Agent工具调查笔记.md)

- **MCP 接入**：支持本地与远程两种运输，工具名由服务器名与工具名拼接，调用前按全名审批；能力变更会触发工具重拉；MCP 指令进入系统提示。[Agent 工具调查笔记](../Agent工具/OpenCode-Agent工具调查笔记.md)

- **子 Agent 与后台任务**：`subagent` 工具创建子会话执行子 Agent，权限从父会话收窄；后台执行时立即返回并在完成后向父会话注入结果；后台任务与调度由服务端管理，进程重启后的恢复有独立机制。[Agent 工具调查笔记](../Agent工具/OpenCode-Agent工具调查笔记.md)、[对话请求与上下文调查笔记](../对话请求与上下文/OpenCode-对话请求与上下文调查笔记.md)

- **外部执行体与应用协作**：OpenCode 以 HTTP + SSE 为唯一控制面，对外提供会话、提示、中断、审批、回退、分叉、终端与事件订阅端点；服务端可选密码鉴权，客户端经一次性配对码换取会话令牌；CLI `service` 管理后台守护，`pair` 输出可扫描链接，可选远程隧道。ACP 实现位于 CLI 包，供外部宿主客户端驱动。[外部执行体与应用协作调查笔记](../外部执行体与应用协作/OpenCode-外部执行体与应用协作调查笔记.md)

- **GUI 插件体系**：桌面与 Web 的非外壳功能全部是内建 GUI 插件（终端、审查、文件、浏览器、SSH、WSL、更新器等），与第三方插件共用窗口进程与主进程两套 SDK；插件通过注册表声明界面项，跨进程调用走带 schema 校验的桥接。[独特功能调查笔记](../独特功能/OpenCode-独特功能调查笔记.md)、[应用界面基础设施调查笔记](../应用界面基础设施/OpenCode-应用界面基础设施调查笔记.md)

### 渠道与调度

- **模型渠道三层结构**：Integration（连接方式：OAuth、命令、Key、外部、环境变量，含登录尝试状态）与 Credential（凭据值）分离，Provider 组装二者；凭据存 SQLite 并有旧版 `auth.json` 迁移；凭据明文保存。[LLM 渠道管理调查笔记](../LLM渠道管理/OpenCode-LLM渠道管理调查笔记.md)

- **模型目录**：目录来自远端服务并在本地缓存，带有效期与磁盘快照回退；条目含上下文与输出上限、价格分层、模态、能力与 API 形状。[LLM 渠道管理调查笔记](../LLM渠道管理/OpenCode-LLM渠道管理调查笔记.md)

- **协议实现**：`packages/ai` 提供原生 provider 与协议实现，入口分为 generate/stream/loop/compact，另有 Effect 与实验性子路径；没有 AI SDK 依赖。跨 provider 失败转移与请求级多 Key 轮询本次未找到。[LLM 渠道管理调查笔记](../LLM渠道管理/OpenCode-LLM渠道管理调查笔记.md)

- **重试与故障边界**：重试由执行器按错误类别判定，尊重退避与重试提示；上下文溢出不重试而是走压缩；重试不改变目标渠道与模型。[对话请求与上下文调查笔记](../对话请求与上下文/OpenCode-对话请求与上下文调查笔记.md)、[LLM 渠道管理调查笔记](../LLM渠道管理/OpenCode-LLM渠道管理调查笔记.md)

- **可观测性与用量**：用量与开销按价格分层累计到会话；追踪与日志可导出；重试与运行状态经事件广播到界面。[LLM 渠道管理调查笔记](../LLM渠道管理/OpenCode-LLM渠道管理调查笔记.md)

- **并发与调度**：当前进程按会话合并唤醒与恢复、跨会话并行；执行 claim 是重启恢复标记，成功/失败/用户中断时释放，关闭或死亡时保留。自动恢复有持久次数上限并具有至少一次语义，无法保证外部副作用仅执行一次；收件箱在安全步骤和空闲边界分别投递 steer/queue。[对话请求与上下文调查笔记](../对话请求与上下文/OpenCode-对话请求与上下文调查笔记.md)

## 工程与基础设施摘要

- **仓库分布**：Bun/TypeScript monorepo，Git 跟踪 9221 文件；可识别源码 5942 文件 / 1,089,965 行（TypeScript 93.8%），文档 877 文件，测试 1965 文件。规模最大的目录为 app、core、tui、ai、gui-plugins 与 ui；原 `packages/opencode` 已拆分为 core + cli + server，`llm` 更名为 `ai`，`docs` 并入 web，新增 session-ui、codemode、theme、patchmark、latex、merman、process-daemon、gui-plugins 等包。[仓库分布调查笔记](../仓库分布/OpenCode-仓库分布调查笔记.md)

- **应用界面基础设施**：TUI 为 opentui + Solid，自建键位映射、对话框栈、Toast 与提示历史；Web App 分基础外壳（主题、语言、错误边界、查询、弹窗栈）、应用外壳（服务端注册表、设置、标签、命令、项目图标、语音）与业务层；组件库按领域拆分到 overlays、feedback、forms、layout、navigation、typography、motion、theme 等目录。主题分两套：Web 注入 CSS 变量，TUI 从终端调色板派生，主题解析与旧主题迁移下沉到 `packages/theme`。通知由 App 协调器统一分发为通知列表、Toast 与提示音；App 内置 60 余种语言。桌面 Electron 主进程负责窗口、菜单、深链、文件与插件桥、原生外观、诊断；打包桌面版经 GUI 更新插件定时检查、下载暂存并支持安装重启；托盘与全局快捷键本次未找到。[应用界面基础设施调查笔记](../应用界面基础设施/OpenCode-应用界面基础设施调查笔记.md)

## 已知边界与待验证事项

### 已确认边界

- 搜索只覆盖会话标题，无消息内容全文检索；无整体编辑消息端点，编辑按内容项进行。
- 工具执行在本机进程内，无容器或沙箱隔离；只对命令文本做风险解析，风险最终由权限规则集与人工审批收口。
- 生成式输出无 hunk 级接受/拒绝与冲突解决；回退按消息粒度，分支通过会话 fork 表达。
- 渠道侧无跨 provider 失败转移、无请求级多 Key 轮询；凭据明文保存。
- 主题可由 GUI 插件注册进入选择器；独立主题市场、壁纸、自定义 CSS 编辑入口、托盘与全局快捷键本次未找到，桌面更新插件已有实现。
- 分享链接与 PR 续作在当前快照未找到；会话档案只剩 JSON 导出导入。

### 未验证事项

- 全部来源笔记均为静态源码调查，未运行构建、真实对话、真实模型请求或界面；视觉效果、无障碍、性能与跨平台行为未实测。
- 多端配对、远程隧道、事件续播与多客户端并发未实测；持久终端重连与偏移重放未实测。
- 快照跨进程重启后的差异与恢复、压缩触发阈值、重试的实际计费影响、Code Mode 与 Goal 的限额行为未实测。
- ACP 与真实宿主客户端、Artifact 不同 Provider 的能力差异、GUI 插件第三方加载与版本兼容未实测。
- 工具输出截断后的全文落盘保留与清理策略、MCP 热重连、动态安装在离线环境下的行为未实测。
