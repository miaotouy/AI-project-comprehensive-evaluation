## 项目概览

AIO-Hub 是以 Vue/TypeScript 为主体、Rust/Tauri 提供桌面能力的多功能应用，并带独立移动端 workspace。它在 2025-07-24 从正则、对比、格式化、媒体信息读取和桌面交互等工具起步；LLM Chat 到 2025-10-16 才加入，Tool Calling 于 2026-02-17 接入，Agent Manager 又到 2026-07-09 才从 Chat 中拆成独立工具。当前 README 已把产品描述为"一站式 AI 创作与开发工作站 + 专业级上下文工程引擎"，这代表当前宣传重心，不能覆盖其多功能工具应用的产品前史。

更稳定的产品结构是"统一框架下的可扩展能力枢纽"：轻量工具页、复合工作台和 Chat、媒体、Recall 等系统级工作区共用工具注册、导航、窗口、设置及本地数据基础设施。人类 UI、内部服务、Agent、插件/Skill 和外部 VCP 节点是并列入口；Agent 已经深度接入部分能力，但不是全部工具的默认调用者，也不是产品形成的起点。产品演变和该判断的证据见[产品结构与设计基因调查笔记](../产品结构与设计基因/AIO-Hub-产品结构与设计基因调查笔记.md)。

会话、Agent、媒体资产、画布和多种工具配置主要以本地文件或 SQLite 为事实源；LLM 推理、部分媒体生成、网页目标和 VCP 节点依赖用户配置的远程模型或外部环境。因此这里的"本地优先"描述数据所有权与本地工作区，不表示全部能力离线。Agent 工具总开关默认关闭，新工具默认不启用、不自动批准；工具审批默认无限等待，可配置超时自动拒绝；当前模型通信协议只有 VCP 一种实现。

- **Agent 持久化、导入导出与实时配置引用**：Agent 以 `agent.json` + 索引分文件持久化，可导出 JSON/YAML、ZIP/文件夹/PNG 包并携带资产与世界书；既有会话不保存完整配置副本，下一次发送/续写/重新生成实时读取当前 Agent 配置，历史消息保留生成时快照。证据状态：`主链确认`。来源：[Agent 角色配置调查笔记](../Agent角色/AIO-Hub-Agent角色配置调查笔记.md) 9。

### 会话与消息

- **树形会话模型与分文件持久化**：会话 = 树形消息结构 + `activeLeafId` 活动路径指针；轻量索引与重量详情分文件存储（`sessions-index.json` + `sessions/{id}.json`），磁盘为权威源，落盘走 Rust 原子写（临时文件 + fsync + 原子替换 + revision 校验 + 进程锁 + 备份轮换）。证据状态：`主链确认`。来源：[会话与消息管理调查笔记](../会话与消息管理/AIO-Hub-会话与消息管理调查笔记.md) 1/2、[Chat 调查笔记](../Chat/AIO-Hub-Chat调查笔记.md)。

- **分支、重试、续写与删除语义**：创建分支 = 同父下新增兄弟节点；重试 = 同一用户消息新增助手兄弟；续写 = 带 `isContinuation` 前缀的节点（发送时 `prefix: true`，收尾补回前缀）；硬删除递归收集后代，压缩节点删除走"归还子节点"特殊路径。证据状态：`主链确认`。来源：[会话与消息管理调查笔记](../会话与消息管理/AIO-Hub-会话与消息管理调查笔记.md) 4、[Chat 调查笔记](../Chat/AIO-Hub-Chat调查笔记.md)。

- **流式渲染与持久化解耦**：渲染走可重放流源（RAF 节流，几乎实时），节点内容落盘走 setTimeout 节流（默认 2 秒或增量保存间隔）；两套独立节流，崩溃可能丢失最后几秒流式内容。证据状态：`主链确认`。来源：[对话请求与上下文调查笔记](../对话请求与上下文/AIO-Hub-对话请求与上下文调查笔记.md) 5、[消息渲染器调查笔记](../消息渲染器/AIO-Hub-消息渲染器调查笔记.md) 2。

- **生成排队与多会话并发**：生成中再发消息写入 `isQueued` 节点并持久化但不触发请求，当前回合结束后按 `queueReplyMode`（合并/链式）自动触发；`generatingNodes` 为节点粒度集合，天然支持多会话并发生成。证据状态：`主链确认`。来源：[对话请求与上下文调查笔记](../对话请求与上下文/AIO-Hub-对话请求与上下文调查笔记.md) 8、[Chat 调查笔记](../Chat/AIO-Hub-Chat调查笔记.md)。

- **跨会话与会话内搜索**：跨会话搜索为 Rust 目录全量扫描 + 正则预过滤，命中只能到会话级（无索引）；会话内搜索为当前活动路径内存线性扫描（最多 50 条），搜索不到分支外消息。证据状态：`主链确认`。来源：[会话与消息管理调查笔记](../会话与消息管理/AIO-Hub-会话与消息管理调查笔记.md) 5。

- **撤销/重做与崩溃恢复、索引自愈**：撤销/重做栈从不持久化（重启清空）；崩溃残留的生成中节点加载时按是否有内容自动修复；索引损坏时后台并发回填恢复，正常启动增量核对不阻塞首屏。证据状态：`主链确认`。来源：[会话与消息管理调查笔记](../会话与消息管理/AIO-Hub-会话与消息管理调查笔记.md) 2.2/2.3、[Chat 调查笔记](../Chat/AIO-Hub-Chat调查笔记.md)。

- **消息元数据与状态五态**：正文为单一 `content` 字符串，富内容放在 metadata（reasoning 回放、翻译、工具调用、Agent/模型快照、压缩节点、会话变量快照、附件等）；状态五态 `complete/generating/waiting/queued/error`，旧 `pending` 在展示层按 queued 兼容。证据状态：`主链确认`。来源：[会话与消息管理调查笔记](../会话与消息管理/AIO-Hub-会话与消息管理调查笔记.md) 1.3、[消息渲染器调查笔记](../消息渲染器/AIO-Hub-消息渲染器调查笔记.md) 1.1。

- **聊天工作台、树图视图与分离窗口**：三栏工作台（Agent 侧栏/消息区/会话侧栏），线性与树图（Vue Flow）双视图共用同一节点数据；树图支持缩放、拖拽嫁接、节点操作与右键菜单，双击节点只切活动分支；标题栏与输入框可分离成悬浮窗口，经 `useWindowSyncBus` 同步状态，不创建会话副本。证据状态：`主链确认`。来源：[Chat UI 调查笔记](<../Chat UI/AIO-Hub-ChatUI调查笔记.md>) 1/6/8。

- **对话导出与截图分享工作台**：分支可按 Markdown、结构化 JSON、Raw JSON 导出（纯输出管线，无导入入口）；截图链从活动路径消息选择范围，进入独立 `ScreenshotRenderer` 编排布局/水印/品牌后生成 PNG，带运行时生成历史（组件内存态，不持久化）。证据状态：`主链确认`。来源：[对话导出与分享调查笔记](../对话导出与分享/AIO-Hub-对话导出与分享调查笔记.md)。

### 渠道与调度

- **LLM 渠道管理与 Provider 适配**：一条渠道建模为一个 `LlmProfile`，同时持有协议类型、Base URL、多 Key、模型目录、自定义 Header/端点、网络策略与 Provider 专属参数；桌面端有 21 种可见渠道类型，包括 New API、Sub2API、通用聚合和 OpenCode Go 四类聚合渠道。渠道类型负责配置身份，真实请求仍由模型执行路由解析到协议适配器；适配器注册通过完整类型约束保证每个 Provider 都有实现。证据状态：`主链确认`。来源：[LLM 渠道管理调查笔记](../LLM渠道管理/AIO-Hub-LLM渠道管理调查笔记.md) 1/6。

- **多 Key 轮询与熔断**：同渠道多 Key 按轮询选择并过滤健康状态，记录启停、连续错误、429 熔断与自动恢复；多 Key 不是请求级重试器，某次失败只更新 Key 状态并把错误抛给上层。证据状态：`主链确认`。来源：[LLM 渠道管理调查笔记](../LLM渠道管理/AIO-Hub-LLM渠道管理调查笔记.md) 5。

- **模型目录与运行时路由**：模型属于渠道（`profileId:modelId` 唯一标识），可手工维护或经模型列表端点获取；请求分发经 `resolveModelExecution()` 按"模型路由绑定→端点类型唯一识别→Provider 默认映射"解析，是渠道内路由而非跨渠道故障转移。证据状态：`主链确认`。来源：[LLM 渠道管理调查笔记](../LLM渠道管理/AIO-Hub-LLM渠道管理调查笔记.md) 3/4。

- **网络传输与请求执行**：Provider 请求构造/响应解析在共享 TypeScript Core，桌面默认经本地 Rust 代理（`auto` 实际等同默认代理路径），`relaxIdCerts`/`http1Only` 默认均开启以兼容私有网关；无同模型多渠道池、渠道权重、优先级或跨渠道自动故障转移。证据状态：`主链确认`。来源：[LLM 渠道管理调查笔记](../LLM渠道管理/AIO-Hub-LLM渠道管理调查笔记.md) 1.3/8。

- **其他人类工具与第二梯队入口**：embedding-playground、media-info-reader、user-profile-manager、text-diff、api-tester、config-converter、data-filter、dir-search、directory-janitor、git-analyzer、color-picker 已确认人类 UI、数据服务或 Agent 接入中的一种或多种入口，但尚未统一走完整主链，证据状态为 `入口确认`。code-formatter、json-formatter、symlink-mover、system-pulse、service-monitor、wallpaper-detector 等轻量工具经扫描未发现额外的跨工具、Agent 或后台面；这表示它们主要按自身工具目标工作，不表示功能不存在或因缺少 Agent 接口而未完成。来源：[独特功能调查笔记](../独特功能/AIO-Hub-独特功能调查笔记.md) 第二梯队小节、[产品结构与设计基因调查笔记](../产品结构与设计基因/AIO-Hub-产品结构与设计基因调查笔记.md) 来源覆盖缺口。

## 工程与基础设施摘要

- **仓库分布**：AIO-Hub 是以 Vue/TypeScript 前端为主体、Rust/Tauri 为桌面壳并带独立移动端 workspace 的多端仓库。`src/tools` 单一区域约 44.9 万行，占全仓可识别源码约 62%，工具实现与工具说明（随工具就地维护的 Markdown）在物理目录上重叠；TypeScript 46.5% / Vue 43.9% / Rust 8.5%；测试 343 文件主要落在 `src/tools`、`mobile`、`tests/`（新增 Tauri E2E）等区域。`packages/llm-core` 是较小但独立的发布边界。统计为 Git 跟踪文件的机械统计，未运行构建与测试。来源：[仓库分布调查笔记](../仓库分布/AIO-Hub-仓库分布调查笔记.md)。

- **应用界面基础设施**：Vue 3 + Element Plus 构成的 Tauri 桌面界面。BaseDialog 承担多数业务弹窗（Esc/遮罩关闭、300ms 退场动画、z-index 自增计数）；`customMessage` 统一业务级即时反馈，通知中心（el-drawer + 内嵌 BaseDialog）保存长期消息，错误反馈分三级（Toast / 常驻 ElNotification / 错误处理分级去重），无组件级 ErrorBoundary。主题分明暗、主色色阶与外观效果三层并持久化到设置文件；自定义 CSS 覆盖在主窗口和分离窗口初始化时主动从持久化配置恢复。`useWindowSyncBus` 提供主窗口与分离窗口间的 8 种消息协议、12 个 llm-chat 状态键与 40+ 命名空间操作同步（主题/通知/窗口布局不在总线职责内）。无障碍、视觉效果与真实多窗口恢复仍需运行验证。来源：[应用界面基础设施调查笔记](../应用界面基础设施/AIO-Hub-应用界面基础设施调查笔记.md)。

- **已调查的可靠性机制与证据边界**：会话持久化已确认采用临时文件、fsync、原子替换、revision 拒绝旧写、进程锁、备份轮换、tombstone 与损坏隔离，并有对应 TypeScript/Rust 单测文件；aio-file-operator 对 Agent/外部传输路径先做真实路径解析，再检查目录包含关系，并在 Rust 侧复核。它们是具体子系统的正面静态证据，尚未经过本轮崩溃复现、双实例并发或真实外部调用验证；同样不能用来替代整个项目的可靠性测试。来源：[会话与消息管理调查笔记](../会话与消息管理/AIO-Hub-会话与消息管理调查笔记.md) 2/8、[Agent 工具调查笔记](../Agent工具/AIO-Hub-Agent工具调查笔记.md) 4/7/9。

## 已知边界与待验证事项

### 局部声明与接口差异

- **media-generator 通用 `generateMedia` Agent 方法**：`media-generator/ARCHITECTURE.md` 声明该方法存在但未实现（占位），Agent 触发生成实际走 `buildAgentMethods` 动态方法族。证据状态：`声明不符`（文档对代码）。来源：[独特功能调查笔记](../独特功能/AIO-Hub-独特功能调查笔记.md) 声明不符项。
- **regex-applier 的可选 Agent 调用面**：`getFormattedTextResult`/`getFormattedFileResult` 方法已实现，但 `getMetadata().methods` 为 TODO 空数组，Agent 无法发现和调用；用户在独立工作台中的预设、堆叠和批处理主链不受影响。证据状态：来源笔记标记为 `声明不符`（代码对注册），在本汇总中按局部 Agent 接入差异解释。来源：同上。
- **content-deduplicator 的模糊匹配**：fuzzy 模糊匹配未实现、`minSimilarity` 为 dead code、自定义忽略模式未生效；实际能力为精确哈希 + 规范化匹配，非语义去重。证据状态：`声明不符`（介绍对实现）。来源：同上。
- **translator 的术语表/批量文件翻译**：仅在设计文档阶段，未实现。证据状态：`声明不符`（文档对代码）。来源：同上。

### web-canvas 子系统的当前边界

审批改用不落盘候选覆盖层，错误经窗口总线回到主窗口，当前画布目录有递归 watcher，Monaco 写入捕获原目标并在生命周期边界 flush/cancel，dirty 状态按 canvasId 分区，canvas iframe 使用 opaque origin、专用 CSP 与消息来源校验，文件入口限制为规范化相对路径，并新增专项回归测试。

仍需保留的边界如下：

1. 审批候选层只存在于内存，应用重启或窗口异常关闭后不能恢复；
2. watcher 一次只绑定 store 当前打开的画布，多画布和快速切换行为未运行验证；
3. 用户与 Agent 没有 revision、CRDT 或冲突合并，实际并发写入仍是最后写入者；
4. 预览 CSP 允许 HTTP(S)、WebSocket、外部 frame 和 asset 资源，不是断网沙箱；
5. 专项单测不覆盖真实 Tauri 窗口、WebView CSP、watcher、跨窗口错误时序、Git 适配与保存恢复端到端行为。

证据状态：`主链确认`（含专项单测与未运行边界）。来源：[生成式输出与运行时调查笔记](../生成式输出与运行时/AIO-Hub-生成式输出与运行时调查笔记.md)。
