## 项目概览

AIO-Hub 是 Tauri 桌面应用（Vue 3 + Element Plus 前端 + Rust 后端），并带独立移动端 workspace。README 自述定位为"一站式 AI 创作与开发工作站 + 专业级上下文工程引擎"，核心由几大模块构成：`llm-chat` 树形消息聊天模块、`tool-calling` 工具系统（当前唯一模型协议实现是 VCP）、`rich-text-renderer` 富文本渲染引擎、`media-generator` + `asset-manager` 媒体创作与资产层、`web-canvas` Agent 协作工作区，以及 47 个工具 registry 组成的"本地工具枢纽"。

数据完全本地化：会话、Agent、媒体资产、画布均以本地文件为事实源，无外部平台或网关。生成的共同边界是：请求依赖用户配置的远程 LLM Profile（渠道+模型），本地无生成引擎；Agent 工具总开关默认关闭，新工具默认不启用、不自动批准；工具审批默认无限等待，可配置超时自动拒绝；当前模型通信协议实现只有 VCP 一种。

### 已确认结构性断点（web-canvas）

web-canvas 主链能力成立，但当前快照存在八项已确认的结构性断点，均为静态源码确认、未运行验证：

1. 运行时错误闭环在窗口边界断开：预览引擎只在独立画布窗口运行，捕获的错误写入该窗口自己的 store，跨窗口同步不传 `runtimeErrors`，主窗口 Agent 上下文通常看不到；
2. 审批预览不是可逆事务：预览钩子与批准后的真实工具调用会重复应用同一 diff，拒绝时按当前 Git HEAD 回退会一并丢弃审批前已存在但未提交的修改；
3. 外部编辑无实时检测：仓库内没有文件系统 watcher 或轮询，VSCode 修改需重新打开/触发读取；
4. Monaco 防抖写盘有跨文件竞态：500ms 后读取当时的 `activeTab`，未捕获编辑发生时的路径，快速切换文件可能把旧内容写入新文件；
5. 画布状态不是按项目隔离：`dirtyFiles` 为 store 级单一 Map，Agent 绑定画布与 UI 当前画布不同时会附带另一画布的未提交文件列表；
6. 画布预览没有专用 CSP，且宿主消息校验只检查事件类型字段、不校验来源；
7. Agent 文件路径缺少画布根目录约束：读写删方法未拒绝绝对路径或 `..`，注册表也没有安全策略钩子；
8. web-canvas 无专项测试。

证据状态：`主链确认`（含已确认断点）。来源：[生成式输出与运行时调查笔记](../生成式输出与运行时/AIO-Hub-生成式输出与运行时调查笔记.md)。
