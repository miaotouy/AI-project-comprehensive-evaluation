## 项目概览

Codex 是 OpenAI 的本地编码 Agent，主体是一个 Rust Cargo workspace（约 165 个成员 crate），产品形态是“原生 CLI 与终端 TUI + app-server 协议面 + 跨语言 SDK 与安装器”，而非 Electron/Web 客户端。它不提供图形聊天前端：用户工作面是终端，`codex app-server` 以 JSON-RPC 把同一套线程、回合与审批语义开放给 IDE、脚本和 SDK，`codex exec` 则把内核包成适合 CI 的非交互入口。

Codex 的会话单位是 Thread，历史不是消息表，而是一条**追加式事件日志**：每个线程一个 rollout JSONL 文件，模型可见项、UI 事件、轮次上下文、世界状态与压缩检查点混写在同一流里；SQLite 只保存列表字段、轮与项分页投影和扫描位点，是可重建的索引。分支靠新建线程，回退靠换一个物理文件，因此没有消息树。

生成侧的设计取向是“把模型输出约束进可审批、可回放、可被外部进程驱动的本地执行环境”。工具是每步重建的中央注册表加分层暴露策略，审批与沙箱责任留在本机；模型产物没有独立富对象存储，文件改动走专用补丁语言落到真实文件系统，会话事实源是 rollout。渠道侧收敛到 Responses 单一协议，配置驱动而非界面驱动，没有多 Provider 面板。

## 功能能力摘要

### 会话、线程与历史

- **线程对象与标识体系**：会话单位是 Thread（UUIDv7），SessionId 与 ThreadId 同值可双向转换，回退产生的新物理文件另用独立 RolloutId。线程之间还有逻辑分叉父、控制派生父、附属线程与多 Agent 角色字段，构成“一条主线加若干关系”而非树。状态：静态源码确认。[会话与消息管理调查笔记](../会话与消息管理/Codex-会话与消息管理调查笔记.md) 第 1 节

- **rollout 作为权威历史**：一个线程一个 JSONL 文件，顶层是 13 类记录的追加序列——模型响应项、协议事件、压缩检查点、轮次上下文、token 用量、世界状态等并列写入同一文件。写入由持有文件句柄的后台单写者串行完成，核心只向容量 256 的通道投递；新线程延迟到首条可持久化记录才建文件，轮末 flush 作为持久化屏障，超过 7 天的文件压缩为 zstd 且读取端透明解码。状态：主链确认。[会话与消息管理调查笔记](../会话与消息管理/Codex-会话与消息管理调查笔记.md) 第 2、7 节

- **SQLite 作为可重建索引**：状态库保存列表字段、轮与项两张投影表以及扫描位点，迁移集已达 62 个。回填只播种缺失行、不覆盖已有 rollout 路径，因为回退后同一线程可能对应多个文件；读取时按差异做读修复，列表可选择只读库而不扫 JSONL。名称另有一份追加式小索引，因此改名不需要重写历史。状态：静态源码确认。[会话与消息管理调查笔记](../会话与消息管理/Codex-会话与消息管理调查笔记.md) 第 2 节

- **创建、恢复、归档、删除与组织**：创建时解析模型、cwd、权限、动态工具与历史模式，ephemeral 线程不落盘；恢复回放 rollout 重建运行期历史并处理压缩点；归档移动文件并在同一次加锁流程里更新标记，支持批量；删除先做“存在附属线程则拒绝”的检查，再删文件后删行，使失败可重试。分组、项目与置顶只是 SQLite 元数据。守护进程重启后可依据已记录的轮输入恢复指定轮。状态：主链确认。[会话与消息管理调查笔记](../会话与消息管理/Codex-会话与消息管理调查笔记.md) 第 3 节

- **回退与分支是两套机制**：回退以轮为界，保持线程 id 但生成新的不可变文件，并用 CAS 式指针检查切换，旧文件保留以便审计；分支新建线程，可按“含该轮”或“不含该轮”两种边界截断，也可只引用父历史基址而不复制前缀。附属线程隐藏于普通列表、被父线程拥有且阻止父线程删除。状态：主链确认。[会话与消息管理调查笔记](../会话与消息管理/Codex-会话与消息管理调查笔记.md) 第 4 节、[对话导出与分享调查笔记](../对话导出与分享/Codex-对话导出与分享调查笔记.md) 第 4 节

- **列表、分页与检索**：列表游标是“时间戳 + 线程 id”的不透明串，文件扫描版有 1 万文件上限并回传已达上限标记；轮与项分页直接读投影表，游标绑定投影序号并额外给反向游标。全文搜索用 ripgrep 扫 JSONL（缺失时退化为进程内扫描），线程内定位基于投影项子串匹配并给出字符区间。没有 SQL 全文索引。状态：主链确认。[会话与消息管理调查笔记](../会话与消息管理/Codex-会话与消息管理调查笔记.md) 第 5 节

### 对话请求与上下文

- **轮输入的单点判定**：app-server 的启动轮请求校验输入大小、cwd、环境、线程设置覆盖与 Provider 可用性后，交给核心的一个判定点，结果只有“开始新轮、并入当前轮、拒绝”三种，拒绝原因是结构化枚举（并发、模式、schema 不匹配、空输入等）。输入模式有四种，区别只在何时接受新输入——从“空闲即开始、忙则并入”到“忙则拒绝”。状态：主链确认。[对话请求与上下文调查笔记](../对话请求与上下文/Codex-对话请求与上下文调查笔记.md) 第 1 节

- **世界状态式上下文拼装**：上下文不是拼成一条 system prompt，而是每步重新渲染一组世界状态区块：工具声明、模型指令、token 预算提示、AGENTS.md 与权限、协作与持久执行模式、环境与插件、工具命名空间、多 Agent 与模型目录，共八段固定顺序。首轮写完整快照，后续只写与上一基线的差异，并作为 rollout 记录落盘。模型指令在历史里有一份副本，而 base instructions 同时位于请求的独立字段，两者可能并存。状态：主链确认。[对话请求与上下文调查笔记](../对话请求与上下文/Codex-对话请求与上下文调查笔记.md) 第 2 节

- **预算判定与四处压缩触发**：预算综合活跃 token、按百分比折算的硬上限，以及自动压缩作用域（全量上下文或只算初始前缀之后的增量）；轮前、轮中、轮末与异步预压缩四个位置都可能触发。压缩是重写历史：生成摘要后构造“摘要 + 真实用户消息 + 重新注入的初始上下文”的替代序列，作为压缩检查点落盘，旧历史只是不再可见而非被删除。另有 TokenBudget 重置窗口与 Provider 远端压缩两条旁路。状态：主链确认。[对话请求与上下文调查笔记](../对话请求与上下文/Codex-对话请求与上下文调查笔记.md) 第 3 节、[检索增强与认知编排调查笔记](../检索增强与认知编排/Codex-检索增强与认知编排调查笔记.md) 第 7 节

- **请求契约与传输交接**：核心不直接用 SDK，而是经 codex-api 生成 Responses 请求；请求对象含输入项、工具定义、并行开关、base instructions、输出 schema 与缓存键。一个轮复用一个客户端会话，以便在重试之间保留 WebSocket 连接与粘性路由；传输优先 WebSocket，失败可切回 HTTP。模型与推理强度取自本步设置而非会话创建快照，服务端返回的模型不一致会产生一次告警事件。状态：主链确认。[对话请求与上下文调查笔记](../对话请求与上下文/Codex-对话请求与上下文调查笔记.md) 第 4 节

- **流式事件与工具派发的顺序**：事件按到达顺序处理，工具调用在项完成时先写入历史、再起一个执行 future；工具之间可以并行，但结果要等该响应流结束、完成事件处理完毕后才统一等待并按调用顺序回注。因此模型看到工具结果必然在下一轮请求之前。核心与 app-server 的投递路径本次未找到面向客户端的批量合并或节流层。状态：主链确认。[对话请求与上下文调查笔记](../对话请求与上下文/Codex-对话请求与上下文调查笔记.md) 第 5 节、[Agent 工具调查笔记](../Agent工具/Codex-Agent工具调查笔记.md) 第 5 节

- **完成判定与异常收口**：是否继续由“需要跟进或仍有排队输入”决定；单次采样收尾按固定顺序刷新未完成文本段、等待在途工具、发 token 计数、取消检查、发轮 diff。终态依中断原因发中断或完成事件，后者带最后消息、错误、起止时间与首 token 时间，随后清活动轮、发空闲、flush。异常分上下文超限、内容过滤、非法图片与其它四类；半截流中未完成的项不进历史，中断轮额外写中断标记并先 flush 再发事件。状态：主链确认。[对话请求与上下文调查笔记](../对话请求与上下文/Codex-对话请求与上下文调查笔记.md) 第 6 节

- **停止、重试与续写**：停止映射为核心中断，先置取消令牌再 abort 任务句柄；若开启流内中断且走精简响应流，取消时还会向该流发送带一秒截止的 Cancel。重试分层——采样循环内按 Provider 的流重试预算并尊重错误给出的等待时间，WebSocket 耗尽后切 HTTP 并清零计数，开启无界连接重试时可无限退避；用户重发会产生新的轮。没有单条助手消息重生成或编辑后重发的独立入口，等价路径是回退到某轮之前再重新提交。状态：主链确认。[对话请求与上下文调查笔记](../对话请求与上下文/Codex-对话请求与上下文调查笔记.md) 第 7 节

- **同线程串行与两类抢占**：同一线程同时最多一个运行任务，忙时新输入要么并入当前轮的待处理队列、要么被拒绝。来自其它 Agent 的邮箱消息可在助手输出或推理阶段抢占当前响应以便尽快送达，也可配置为当前响应结束后再处理。不同线程各自独立任务并行，并发上限由 Agent 运行时控制。状态：主链确认。[对话请求与上下文调查笔记](../对话请求与上下文/Codex-对话请求与上下文调查笔记.md) 第 8 节

### 终端工作台与渲染

- **单窗口垂直工作台**：主画面由上方 transcript 与下方底部面板组成，没有侧栏或多列布局。底部面板按优先级组合：警告视图整体替换、视图栈顶优先、否则依次排内联横幅、状态行、Hook 状态、执行页脚、待审批列表、待发送预览、问题编辑器、输入框与快捷键提示。全屏或模态入口包括会话选择器、transcript 覆盖层、全文查找、活动视图、警告列表、审批弹窗与 Agent 总览。状态：静态源码确认。[Chat UI 调查笔记](<../Chat UI/Codex-ChatUI调查笔记.md>) 第 1 节

- **输入框状态机与三层草稿**：输入框不是文本框，而是维护多行编辑、附件、弹窗路由、原子化斜杠命令、粘贴突发检测、Vim 模式与历史召回的状态机；输入类型含 @ 提及、$ 技能、/ 命令、! 本地 shell、本地与远程图片、语音。草稿分三层：按 thread 捕获并在切换或重连时恢复、跨会话的持久纯文本历史（能恢复提及绑定但不含附件）、仅进程内的完整历史。状态：主链确认。[Chat UI 调查笔记](<../Chat UI/Codex-ChatUI调查笔记.md>) 第 3 节

- **提交、双通道排队、停止与审批**：提交前处理错位策略、限流恢复、待提交图片与会话未配置；有活跃轮时优先插入当前轮，否则开新轮。运行中直接提交进入“待插入”通道，不可插入时转入拒绝队列等待重试；显式排队走另一键位，轮结束后依次发送，底部同时展示排队、待插入与被拒绝三种状态。停止键在回合 id 不匹配时会按错误返回的实际 id 重试一次。四类审批（执行命令、权限提升、应用补丁、MCP 征询）共用一个模态浮层并按到达顺序排队。状态：主链确认。[Chat UI 调查笔记](<../Chat UI/Codex-ChatUI调查笔记.md>) 第 5 节

- **多会话切换与子 Agent 观察**：同一时刻只有一个活跃 thread 占用主循环的消息接收端，其它 thread 在服务端继续运行并把通知留在缓冲。切回时恢复该 thread 的输入状态与队列。观察入口包括 Agent 总览、子 Agent 切换、后台终端列表与停止、侧对话返回、活动分组展开。运行中的回合不会因界面切换而停止。未找到群聊、多模型同时回答或一个窗口并排多会话。状态：主链确认。[Chat UI 调查笔记](<../Chat UI/Codex-ChatUI调查笔记.md>) 第 7、8 节

- **渲染管线与自适应节流**：输入是协议增量，输出是终端逻辑行。流式阶段只把以换行结束的完整行段推进稳定队列，未闭合残段留在可丢弃预览，避免表格与代码围栏在增量中反复变形；提交分“每 tick 一行”与“批量排空”两档，进入批量取决于队列深度或最老行等待，退出带迟滞与再进入抑制。完成后用一个保存原始 Markdown 的 cell 替换整段流式 cell，并按当前宽度重渲染。状态：主链确认。[消息渲染器调查笔记](../消息渲染器/Codex-消息渲染器调查笔记.md) 第 2 节

- **Markdown 与富文本降级**：用解析器事件写入器直接产出终端行：表格恒开、任务列表可配、代码块用语法高亮（超 512KB、1 万行或单行 4KiB 时降级纯文本）、数学用有界 Unicode 近似小型 TeX 子集、Mermaid 渲染为字符图且失败时回退高亮源码。HTML 作为字面文本逐行写入，不解析标签、不执行脚本；链接以终端超链接携带，本地文件链接按会话工作目录缩短并可重定向。状态：主链确认。[消息渲染器调查笔记](../消息渲染器/Codex-消息渲染器调查笔记.md) 第 5、7 节

- **历史分页与两种列表模式**：初次恢复取最近 5 轮、单页条目上限 100，在顶部继续滚动会请求更早一页并保持阅读位置。列表有两条互斥路径：一条把已提交 cell 通过转义序列写进终端原生回滚区，列表的“存储”就是终端历史；另一条在备用屏内由自有视图逐可见行绘制并维护滚动、选择与搜索。没有 DOM 高度测量或虚拟列表。状态：静态源码确认。[消息渲染器调查笔记](../消息渲染器/Codex-消息渲染器调查笔记.md) 第 3 节

### 生成式输出与产物

- **专用补丁语言 apply_patch**：补丁是以开始与结束标记包裹的文本语言，内部按新增、删除、更新、改名与上下文分段表达变更，不是通用 unified diff；工具参数以自由文本载荷承载整段补丁。处理链为解析文法、按当前环境校验目标文件、把越界路径折算成额外权限请求、做安全评估，再进入审批。执行保留“已提交前缀”，因此补丁可能部分提交后失败而非原子回滚；回合 diff 跟踪器对单次渲染设 100ms 预算，超时退化为粗粒度但仍内容精确的 diff。shell 里出现的补丁 heredoc 也会在 spawn 前被拦截走同一实现。状态：主链确认。[生成式输出与运行时调查笔记](../生成式输出与运行时/Codex-生成式输出与运行时调查笔记.md) 第 1、2 节、[独特功能调查笔记](../独特功能/Codex-独特功能调查笔记.md) 能力二

- **唯一的可执行产物面：内联 HTML 可视化**：模型在回答中写一条内联可视化指令指向本线程目录下的 HTML 片段，TUI 把片段包进固定 viewer 模板、复制到 codex home 的 viewer 目录，并把消息里的指令改写成指向该文件的链接。片段上限 2MiB，viewer 以只带脚本权限的 iframe 沙箱承载（不授予同源），CSP 禁止外部连接、表单与 object；运行在用户浏览器而非 Codex 进程内。没有通用 Artifact、Notebook 或 iframe 运行时。状态：静态源码确认。[生成式输出与运行时调查笔记](../生成式输出与运行时/Codex-生成式输出与运行时调查笔记.md) 第 4、10 节

### 模型渠道与请求容错

- **Provider 实体与内置表**：Provider 是配置文件里的一条定义，或六个内置 ID 之一：OpenAI、两个 Bedrock 变体、GCP、Ollama、LM Studio。结构与用法都是单值：一个 Provider 只有一个基础地址、一个凭据来源，要接多个兼容端点必须定义多个 ID。内置 ID 受保留名单保护，同 ID 覆盖只允许有限字段（例如 OpenAI 只允许改模型目录地址）。OpenAI 的基础地址还会按认证方式在 ChatGPT 后端与 API 地址之间切换。状态：静态源码确认。[LLM 渠道管理调查笔记](../LLM渠道管理/Codex-LLM渠道管理调查笔记.md) 第 1 节

- **配置分层与 profile**：配置是带来源记录的分层结构，优先级从打包默认经 MDM、系统、企业托管、用户、用户 profile、项目与会话覆盖递进到遗留托管层；用户配置文件位于 codex home。profile 有两条路径：旧式配置表，以及按名字加载独立的 profile 文件作为带标记的用户层参与合并。命令行覆盖可写任意键，app-server 提供按键路径与批量写入，但两者都没有 Provider 专用增删改查。状态：静态源码确认。[LLM 渠道管理调查笔记](../LLM渠道管理/Codex-LLM渠道管理调查笔记.md) 第 2 节

- **凭据、Header 与出站代理**：认证加载顺序为专用环境变量、临时注入、访问令牌、持久化存储；存储有四种模式（明文 JSON 文件、系统钥匙串、自动选择、仅内存），Windows 默认“钥匙串保存文件密钥 + 本地密文”。Provider 级的 env_key 优先于全局认证，可配置静态 Header 与“Header 名到环境变量名”的动态 Header（变量为空则跳过）。基础地址、Header 值、查询参数与实验性 Bearer 用脱敏串保存；出站代理可跟随系统/PAC，环境变量回退按目标 scheme 取代理，代理地址在调试输出中被替换。状态：主链确认。[LLM 渠道管理调查笔记](../LLM渠道管理/Codex-LLM渠道管理调查笔记.md) 第 3 节

- **模型目录三层来源**：目录由编译进二进制的快照、Provider 的模型端点与磁盘缓存三层构成，缓存默认 300 秒 TTL，刷新失败保留上一次成功快照而不是当作空目录；也可用本地 JSON 覆盖。目录提供上下文窗口、自动压缩阈值、推理档位、输入模态等字段，没有价格或计费字段。允许“同一 Provider 内的模型回退”——请求的模型不在目录中时替换为该 Provider 的默认模型，这不是 Provider 之间的故障转移。状态：主链确认。[LLM 渠道管理调查笔记](../LLM渠道管理/Codex-LLM渠道管理调查笔记.md) 第 4 节

- **协议收敛到 Responses**：线协议只有 Responses 一个取值，chat 取值在反序列化阶段直接报错并给出迁移说明。因此没有 OpenAI Chat Completions、Anthropic Messages 或 Gemini 原生协议的适配层，兼容性依靠对方实现 Responses 兼容端点。Azure 不是独立适配器，只作为兼容端点用自定义地址与查询参数表达部署名与版本；仓库内的响应转发代理是转发器而非协议转换器。状态：静态源码确认。[LLM 渠道管理调查笔记](../LLM渠道管理/Codex-LLM渠道管理调查笔记.md) 第 5 节

- **会话与 Provider 绑定**：恢复或继续会话时，服务端比较会话保存的 Provider 与当前配置，不一致、不存在或与组织策略冲突分别返回结构化错误，而不是静默把历史发给另一个后端。代价是切换 Provider 后旧会话不能直接继续。Provider 选择的优先级是策略强制值、会话或命令行显式覆盖、配置值，最后默认 OpenAI。状态：主链确认。[LLM 渠道管理调查笔记](../LLM渠道管理/Codex-LLM渠道管理调查笔记.md) 第 6 节

- **重试层级与故障转移边界**：重试分四层——HTTP 请求重试（默认预算 4，5xx 与传输错误重试，429 在 HTTP 层不重试）、流式重连（默认 5 次，连接失败另有独立退避）、每请求一次的 401 凭据刷新后重放、WebSocket 失败回退 HTTP。服务端给的等待时间参与决策但不扩大配置上限。跨 Provider 故障转移、多 Key 轮询、冷却与健康状态持久化本次均未找到：客户端持有的是单个 Provider，配了多个不等于运行时会自动切换。状态：主链确认。[LLM 渠道管理调查笔记](../LLM渠道管理/Codex-LLM渠道管理调查笔记.md) 第 7 节

- **诊断与可观测性**：医生命令检查存储模式、存在的认证环境变量与凭据类型并给出修复提示；端点探测只发 HEAD/GET 验证可达性与模型目录状态，不发送模型输入，也不验证具体模型是否可用。限流快照来自响应头的专有字段（主次窗口、重置时间、credits 余额与促销），token 用量进入会话遥测与上下文预算；请求日志只记模型、线协议与传输类型。状态：静态源码确认。[LLM 渠道管理调查笔记](../LLM渠道管理/Codex-LLM渠道管理调查笔记.md) 第 8 节

### 外部协作与交付

- **app-server 作为被驱动方**：长驻 JSON-RPC 服务，传输可选 stdio（默认）、unix、ws 或关闭监听，默认会话来源是编辑器。协议分三层：客户端请求、服务端通知、服务端请求。服务端请求是它与普通 RPC 的最大差异——命令与文件变更审批、工具提问、MCP 征询、权限申请、动态工具调用、令牌刷新都要客户端按请求 ID 回复，否则回合停在等待状态。初始化是硬门禁，回合准入会在服务端排空或工作区切换时拒绝新请求。审批权不下放：客户端只能回答允许或拒绝，不能凭协议字段放宽本机沙箱。Python SDK 即该协议客户端；TypeScript SDK 走 exec 的 JSON 通道而非此协议。状态：主链确认。[外部执行体与应用协作调查笔记](../外部执行体与应用协作/Codex-外部执行体与应用协作调查笔记.md) 第 2.1、3.1、5.1 节、[独特功能调查笔记](../独特功能/Codex-独特功能调查笔记.md) 能力四

- **exec-server 作为控制方**：方向相反——Codex 是控制方，进程、文件系统与 HTTP 委派给独立执行体（本地子进程、远端主机或经密钥注册的 Noise 连接）。进程用客户端选择的逻辑句柄而非操作系统 PID，重连后仍可按同一句柄找回；启动参数携带“可移植沙箱意图”与托管网络要求，由执行体解析成本地包装命令，要求托管网络却缺参数时必须拒绝执行。文件系统是“打开句柄 + 分块读写 + 关闭”，HTTP 响应体也分块回传。连接断开后环境进入恢复态，无法恢复才转入断开。状态：主链确认。[外部执行体与应用协作调查笔记](../外部执行体与应用协作/Codex-外部执行体与应用协作调查笔记.md) 第 2.2、3.2、5.3 节

- **remote control 作为被远程控制方**：app-server 复用同一连接模型但反向连出：向中继注册取得环境、服务与令牌后建立 WebSocket，再生成配对码让外部客户端接入本机线程；状态机为禁用、连接中、已连接、错误。配对参数只接受一种码型，同时给出或都不给都会被拒绝；客户端列表与撤销是管理入口，撤销后对应流失效。令牌到期前刷新，认证主体变化会直接中断当前会话而不是静默重连到旧身份。状态：主链确认（源码层，真实中继未验证）。[外部执行体与应用协作调查笔记](../外部执行体与应用协作/Codex-外部执行体与应用协作调查笔记.md) 第 2.3、3.3、6.3 节

- **codex exec 非交互自动化**：脚本入口启动进程内 app-server 客户端，复用同一内核，因此线程、轮、审批与动态工具语义与交互面一致。`--json` 保证每行一个合法 JSON 事件（线程、轮、条目的生命周期与错误），`-o` 只在成功轮后写最后消息（失败不覆盖旧文件），`--output-schema` 约束最终消息形状，`--ephemeral` 明确不落会话文件。事件流没有“用户消息”条目，只描述 Agent 侧行为，不能单独重建完整对话；线程 id 可用于后续 resume。状态：主链确认。[对话导出与分享调查笔记](../对话导出与分享/Codex-对话导出与分享调查笔记.md) 第 5 节、[独特功能调查笔记](../独特功能/Codex-独特功能调查笔记.md) 能力五

- **云端任务提交与本地应用**：云端命令把提示词、环境 ID、分支与 1–4 次尝试提交到服务端环境并返回任务 ID；状态与列表读取任务与尝试，diff 取统一 diff，apply 把指定尝试交给 git apply 写入本地工作树。任务状态、环境定义与执行都在服务端，仓库内只有 CLI、环境 ID 参数与 HTTP 客户端，没有本地任务库或离线执行路径。它与补丁工具是两条不同路径：一条应用云端结果，一条是模型编辑工具。状态：主链确认（静态；外部服务未验证）。[独特功能调查笔记](../独特功能/Codex-独特功能调查笔记.md) 能力七

- **Markdown 导出是唯一用户交付物**：导出命令重新向 app-server 取全部历史（不依赖屏幕缓冲，因此长会话必须先拉完），过滤审查模式产生的重复项，再按条目类型转段：用户消息只留正文与图片编号标签，推理只输出摘要（是否含原始推理取决于本地配置），文件变更写状态与每个文件的 diff 全文，MCP 结果把图片、音频与嵌入资源降级为占位或 URI。产物只有一级标题与按角色分节的正文，不含模型、时间、token 或会话 ID；终点是剪贴板或文件，同名文件拒绝覆盖。状态：主链确认。[对话导出与分享调查笔记](../对话导出与分享/Codex-对话导出与分享调查笔记.md) 第 1、2、7 节

- **从 Claude Code 单向导入**：唯一的导入入口把外部会话、配置、项目与近期会话转成 rollout 条目，并在历史中插入外部会话标记；再次导入时用检查点账本追加缺失后缀，默认只发现 30 天内最多 50 条外部会话。这是单向迁移，没有把 Codex 历史转成通用交换格式再导回的往返路径，也没有任意 JSON 的通用导入命令。状态：主链确认。[对话导出与分享调查笔记](../对话导出与分享/Codex-对话导出与分享调查笔记.md) 第 8 节

## 工程与基础设施摘要

- **仓库分布**：单个 Rust Cargo workspace（成员约 165 个），叠加 Bazel 发行构建与只含三个发布包的 pnpm 工作区。可识别源码约 231 万行，Rust 占 95.9%；TypeScript 的 784 个文件里有 760 个是协议生成的类型绑定，真正的应用级 TS 只存在于 TypeScript SDK，因此本仓的 TS 不代表前端运行时。文件数被协议 schema、渲染快照与动画帧夹具抬高，判断模块规模应看源码行。发行覆盖 macOS 双架构、Linux MUSL 双架构与独立 Windows 工作流，每个目标另出配套的 app-server 工件；安装渠道含脚本、npm、Homebrew 与 winget。状态：Git 跟踪文件机械统计 + 构建配置复核。[仓库分布调查笔记](../仓库分布/Codex-仓库分布调查笔记.md)

- **应用界面基础设施是终端设施，不是图形栈**：在 ratatui 与 crossterm 之上自建终端抽象，保留帧缓冲差分绘制并增加视口、光标与图片占位管理；渲染由请求驱动而非固定帧率，多个帧请求合并到最早截止时间并以上限节流后广播一次绘制。主循环是多路等待，终端事件归一化为八类，尺寸与绘制分开以便走独立重排。自研的“渲染入口 + 期望高度”契约让内联视口可以“先测量再分配”，这是历史写入终端回滚区这一取舍的前提。浮层只有底部面板一个宿主，另有可临时接管整屏的覆盖层；通知分三层（桌面通知协议、终端状态协议、界面内状态行），默认只在终端失焦时发送且失败即静默禁用；主题本质是语法高亮主题加启动时探测的终端能力分级，键位是“上下文 × 动作”的二维表并在解析期做冲突检测；响应式只有宽度守卫与重排，没有断点；没有托盘、原生菜单或窗口管理。状态：静态源码核对。[应用界面基础设施调查笔记](../应用界面基础设施/Codex-应用界面基础设施调查笔记.md)

## 已知边界与待验证事项

### 确认不支持或本次未找到

以下结论均带来源笔记的检查范围，不等同于跨版本或项目级绝对判断。

- **无消息级编辑、删除或单条重生成**：在协议请求枚举中检索删除、更新与消息编辑均无结果，可变的只有线程元数据、设置与历史边界；等价路径是回退到某轮之前再由客户端重新提交。（检查范围：app-server 协议请求枚举）[会话与消息管理调查笔记](../会话与消息管理/Codex-会话与消息管理调查笔记.md) 第 4 节、[对话请求与上下文调查笔记](../对话请求与上下文/Codex-对话请求与上下文调查笔记.md) 第 7 节
- **无会话分享、公开页面或撤销接口**：搜索覆盖 CLI 子命令、TUI 斜杠命令、app-server 方法与全仓 share 字样，命中的都是网络连接共享、UNC 路径与注释语义，没有对话分享对象。导出侧也没有脱敏开关，正文会含命令输出、diff、绝对路径与仓库信息。[对话导出与分享调查笔记](../对话导出与分享/Codex-对话导出与分享调查笔记.md) 第 9 节
- **无浏览器、桌面或移动聊天前端**：按 Rust 工作区、SDK、npm 包装与根目录检查后未找到；`/app` 只是把当前线程以深链交给外部桌面应用，不在本仓库渲染。桌面应用与 IDE 扩展本体均在本仓库之外。[Chat UI 调查笔记](<../Chat UI/Codex-ChatUI调查笔记.md>) 第 1、10 节

- 并发与时序类结论未做故障注入：steer 插入与邮箱抢占同时发生的事件顺序、压缩触发阈值与长上下文截断、SQLite 与 rollout 在崩溃窗口内的不一致程度、回退在压缩与附属线程组合下的行为。
- 补丁在超大文件、歧义上下文与并发修改下的定位成功率；流式补丁事件除协议层外是否有其它客户端消费，未验证。
- 记忆流水线真实抽取与合并质量、限流余量与租约在真实账号下的表现、外部上下文把线程标记为污染后的后续消费路径，均未验证。
- 长会话、超大代码块、复杂表格与 Mermaid 图的渲染性能未做运行时测量；图片在支持图形协议的终端中的布局与滚动行为未观察。
