# 主动 Agent 与后台任务调查指南

本指南用于调查可在当前用户回合之外被触发，并以独立运行状态完成、失败、取消或恢复的 Agent 工作单元。通用写作、元数据、证据和调查深度要求见 [`../AGENTS.md`](../AGENTS.md)。

## 类目定义

本类目的事实对象是主动运行或后台任务，而不是定时表达式、工具调用或会话本身。它至少应具备以下链路：

```text
触发源或调度规则
  -> 创建或认领任务/运行
  -> 独立执行或重新进入会话
  -> 结果、错误或状态交付
  -> 取消、重试、下一次调度或恢复
```

候选应同时满足：

1. 触发不依赖当前用户即时发送的一条消息；触发者可以是用户配置的日程、模型后续动作、系统空闲检查或外部事件。
2. 能识别本次运行、任务或其等价对象，并追踪执行中、完成、失败、取消或下一次运行中的至少一项状态。
3. 执行结果能交付到可识别的会话、任务记录、通知、工作区或外部目标，而非仅留在进程日志。

## 不纳入范围

- 当前用户回合内的单次工具调用、模型循环和内建子 Agent；它们留在 Agent 工具或请求与上下文。
- 只有定时器、轮询循环或后台线程，但未形成可识别运行对象及结果交付链的实现。
- 外部 CLI、业务应用或远端 Agent 的发现、身份绑定和托管；这些关系留在外部执行体与应用协作。其内部调度仅在解释交接时引用。
- 普通消息同步、推送通知和跨设备恢复；除非它们承接同一主动运行的身份、控制或终态。
- 记忆整理、检索或生成式输出本身；只有其由独立后台运行驱动时，记录调度链和结果交接，其对象语义留在相邻类目。

## 必查问题

1. 触发者是谁，规则、事件或模型后续动作保存在哪里？
2. 本次运行的事实对象是什么，状态权威位于内存、数据库、文件还是外部调度器？
3. 调度器如何决定到期、空闲、忙碌、并发或跳过？
4. 执行重新进入既有会话、创建隔离会话，还是执行独立任务处理器？
5. 执行使用哪些 Agent、模型、工具和权限边界？本类只说明执行域的归属，工具细节回链 Agent 工具。
6. 成功、部分结果、错误和超时分别交付给谁，以消息、任务记录、通知还是外部动作体现？
7. 用户或系统如何暂停、取消、修改、重试或防止同一运行复活？取消是否能到达真实执行体？
8. 重启、断线或重复触发后如何恢复、补跑、去重或明确结算？
9. 资源与治理边界是什么，例如并发、频率、预算、默认启用状态、审批和可见性？
10. 与会话管理、Agent 工具、外部执行体、记忆演化和多表面连续性的交接在哪里？

## 比较分型与字段

横向比较先按运行形态分型，不把名称相似的 cron、heartbeat 和后台队列直接视为等价：

| 分型 | 判据 | 典型交付 |
| --- | --- | --- |
| 隔离日程运行 | 日程创建独立会话或任务上下文 | 独立记录、通知或后续会话 |
| 会话内续作 | 触发重新认领或推进既有会话 | 同一会话中的新消息或状态 |
| 条件唤醒 | 空闲、概率、事件或系统条件决定运行 | 目标会话、平台消息或任务状态 |
| 后台工作队列 | 任务对象入队后由 worker 或处理器执行 | 任务结果、文件、工作区或回调 |

每个主链至少记录：触发来源、运行对象与状态权威、执行位置、结果归属、并发与取消、失败与重试、重启语义、默认启用状态，以及证据状态。没有证据时使用“未调查”或“未确认”，不要补写为不支持。

## 推荐结构

```md
## 结论摘要
## 系统边界与主链
## 触发、调度与运行对象
## 执行、结果交付与状态更新
## 并发、取消、失败与恢复
## 相邻类目交接与已确认边界
## 未验证事项
## 关键源码索引
```

## 调查注意事项

- 先定位任务或运行的权威状态，再追踪 UI 开关、cron 配置或消息入口。
- “支持定时任务”必须拆开确认任务创建、实际派发、执行结果和停用/取消；只有创建表单不构成主链确认。
- 静态证据可确认路由、状态流转和调用关系；实际触发时刻、平台投递、进程中断和重启后的时间语义需在运行环境验证。
- 横向文档只保留统一字段上的结论。单项目注册表、完整配置和工具参数留在单项目笔记。
