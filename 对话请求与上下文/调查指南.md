# 对话请求与上下文调查指南

本指南用于调查一次生成任务如何从用户提交进入执行层，完成历史选择、上下文拼装、Provider 或 Agent 调用、流式消费、取消和最终回写。通用写作、元数据、深度和证据要求见 [`../AGENTS.md`](../AGENTS.md)。

会话与消息对象如何持久化属于 [`../会话与消息管理/调查指南.md`](../会话与消息管理/调查指南.md)，用户如何通过界面提交和控制任务属于 [`../Chat UI/调查指南.md`](<../Chat UI/调查指南.md>)，工具执行循环的内部语义属于 [`../Agent工具/调查指南.md`](../Agent工具/调查指南.md)。

## 调查目标

走通一条“提交输入 -> 选择历史与外部信息 -> 构建模型请求 -> 执行 -> 消费增量 -> 取消、失败或完成 -> 最终回写”的完整主链。项目只提供无状态网关或协议转换时，从它实际接管请求的位置开始，明确上游会话状态不归它所有。

## 必查问题

1. **任务入口与状态机**：输入提交后由哪个 command、action、RPC、API 或事件创建生成任务？占位消息、任务 ID 和运行状态如何初始化？
2. **上下文来源与顺序**：历史消息、system prompt、角色、用户档案、记忆、摘要、知识库、附件、工具结果和临时指令按什么顺序进入请求？
3. **预算、截断与压缩**：token 或字符预算如何计算？按消息、turn、part 还是优先级裁剪？摘要、压缩和回填何时触发，是否可逆？
4. **请求模型与 Provider 交接**：内部消息如何转换为 SDK 或协议请求？Provider、模型、参数和渠道实例在何处解析？协议 Adapter 从哪里接管？
5. **流式事件链**：文本、reasoning、工具调用、引用、媒体和状态事件如何从执行端到达状态层？缓冲、合并、节流和顺序保证在哪里实现？
6. **最终化与回写**：完成、异常、超时和半截流如何收口？临时状态如何转换为权威消息，何时持久化并刷新会话索引？
7. **停止、重试与续写**：停止按钮、网络 abort、任务取消和 Agent 中断分别作用在哪一层？重试、续写、重新生成和编辑后发送如何选择起始上下文？
8. **队列与并发**：同一会话是否串行，不同会话是否并行？再次发送会排队、steer、follow-up、替换当前任务还是报错？后台生成如何管理？
9. **外部能力注入**：本次任务在何处取得 Agent、工具目录、知识库、记忆、联网、变量和附件的实际结果，并按什么顺序注入？只记录调用点与交接契约，筛选和能力内部机制链接对应类目。
10. **退出、恢复与可观测性**：切换会话、关闭窗口、应用退出、服务重启和网络重连时任务如何处理？日志、trace、用量和错误如何关联到具体任务？

## 推荐结构

```md
## 结论摘要
## 系统边界与生成任务主链
## 1. 提交入口、任务对象与状态机
## 2. 历史选择与上下文拼装顺序
## 3. 预算、截断、摘要与压缩
## 4. SDK、Provider、模型与协议交接
## 5. 流式事件、缓冲、节流与顺序
## 6. 完成、异常、半截流与最终回写
## 7. 停止、重试、续写与重新生成
## 8. 队列、多会话并发与后台生成
## 9. Agent、工具、知识库与附件注入点
## 10. 退出恢复、日志与已确认边界
## 11. 未验证事项
## 12. 关键源码索引
```

## 与相邻类目的边界

| 相邻类目 | 本类目记录 | 留在相邻类目的内容 |
|---|---|---|
| 会话与消息管理 | 任务读取和写回持久化对象的交接点 | 会话 schema、CRUD、分支数据语义、索引、迁移和恢复 |
| Chat UI | action、command、RPC 或 API 入口之后的真实执行 | Composer、发送前配置、按钮状态、排队提示、停止反馈和消息操作工作流 |
| 消息渲染器 | 流式事件进入可见状态前的最后交接点 | 消息列表、内容解析、DOM 更新、滚动和消息壳反馈 |
| 上下文编译与提示词工程 | 编译后的规则结果何时进入本次请求 | 规则对象、作用域、选择条件、编译顺序，以及请求、消息与显示三个消费面的分流 |
| Agent 角色 | 角色字段如何进入最终 system prompt 和请求参数 | 角色实体、配置、资产、导入导出和配置 UI |
| Agent 工具 | 本次任务何时调用工具目录构建，并将实际目录、schema 和结果放入整体上下文 | 工具来源、过滤算法、参数校验、执行、审批、循环上限和结果限制 |
| LLM 渠道管理 | 本次任务何时请求解析模型与渠道，并接收哪种协议 Adapter | Provider、Endpoint、凭据、模型目录、路由、重试和故障转移机制 |
| 生成式输出与运行时 | 输出对象的创建或更新事件在任务中的位置 | 输出对象的身份、专用表面、执行环境、版本、持久化和模型回流 |

## 调查注意事项

- “点击了停止”不能证明底层网络、Agent 或服务端任务已取消，需要沿调用链确认实际中断层。
- 区分流式视图更新、内存消息更新和持久化写入三种频率，不把其中一条路径代替整条执行链。
- 上下文构建应以最终请求为准。配置界面、文档说明或中间 store 中存在某字段，不代表本次请求实际携带。
- Provider fallback、同 Provider 重试、工具循环继续、消息重新生成和用户手动重试是不同机制，应分别说明触发者和重复执行风险。
- 静态代码可以确认入口、顺序和状态分支；取消效果、退出恢复、并发竞态和长上下文行为需要运行验证。

## 横向比较字段

至少记录：任务入口、状态机、上下文拼装顺序、预算策略、压缩方式、Provider 交接点、流式状态源、节流位置、最终化时机、中断层级、重试语义、并发粒度、后台任务、外部能力注入点、退出恢复和可观测性。
