# 应用界面基础设施调查指南

本指南用于调查项目跨页面复用的界面基础设施，以及这些基础设施如何约束产品的一致性、反馈、适配与可用性。通用写作、元数据、调查深度和证据要求见 [`../AGENTS.md`](../AGENTS.md)。

本类目关注应用级的界面机制，不承担某一业务流程的完整说明。聊天工作台中的会话导航、Composer、生成反馈和消息操作属于 [`../Chat UI/调查指南.md`](<../Chat UI/调查指南.md>)；消息内容和结构化 part 的绘制属于 [`../消息渲染器/调查指南.md`](../消息渲染器/调查指南.md)。其它业务类目也只记录基础设施与自身主链的交点。

## 适用性

- 项目拥有自己控制的 Web、桌面、移动端或 TUI 界面，且存在可跨页面复用的弹窗、通知、主题、布局或交互基础设施时，可以建立单项目笔记。
- 项目只提供后端服务、协议网关、SDK 或第三方平台机器人时，本类目通常不适用；不要把外部客户端的界面能力算作项目自身实现。
- 只有零散业务组件、没有形成应用级机制时，可以在相关业务笔记中记录交点，不必创建内容空泛的独立笔记。
- 单一通用主题的材料较短时，可作为其它调查笔记的“扩展调查”；覆盖多个共同维度且能够独立阅读时，再拆入本类目。

## 调查目标

说明应用如何统一承载浮层、状态反馈、主题、响应式布局和常见内容交互，并区分公共机制、业务侧配置与平台能力。调查重点是实现边界、状态所有权、消费方式和已确认行为，不以组件数量统计或视觉风格评价代替机制分析。

## 基础必查问题

1. **界面栈与装配边界**：项目采用哪些 UI 框架、设计系统和自研公共组件？应用根节点如何挂载 Provider、Portal、Overlay Host、Toast Host 或主题容器？多窗口、多入口是否共享同一套基础设施？
2. **弹窗、浮层与菜单**：Modal、Drawer、Popover、Tooltip、上下文菜单和命令式弹窗由什么机制提供？层级、Portal、滚动锁定、Esc、遮罩关闭、嵌套浮层及销毁时机如何处理？
3. **通知与状态反馈**：Toast、Snackbar、站内通知、系统通知、Loading、骨架屏、空状态和错误边界分别承担什么场景？反馈是否支持堆叠、更新、取消、持久化或返回原任务？
4. **主题与视觉 token**：明暗模式、系统跟随、强调色、字体、密度和 CSS token 的权威源在哪里？如何初始化、持久化、跨窗口同步并避免首屏闪烁？第三方组件如何接入主题？
5. **响应式与窗口适配**：断点、容器查询、侧栏折叠、移动端路由或独立入口、窗口最小尺寸和安全区域如何协作？哪些变化自动发生，哪些由用户手动控制？
6. **常见内容交互**：图片或附件预览、拖放、上传反馈、尺寸调整和剪贴板操作是否使用公共机制？能力边界和状态反馈是什么？
7. **状态所有权与消费方式**：界面偏好、浮层队列、通知、主题和窗口布局由本地组件、全局 store、主进程还是服务端持有？业务模块如何调用，跨页面或跨窗口如何同步？
8. **验证边界**：哪些结论来自公共组件源码，哪些只确认了业务调用，哪些经过运行验证？依赖库内部未下钻的行为必须明确标为未核实。

## 可选扩展调查

以下主题只在用户明确要求、项目机制具有代表性，或已有材料足以形成独立结论时展开。未调查不等于项目不支持。

- **无障碍**：焦点进入与归还、焦点陷阱、可访问名称、语义角色、键盘等效路径、读屏反馈、对比度及 reduced-motion。静态代码不能证明 WCAG 合规。
- **动画与过渡**：动画库、统一时长或缓动 token、路由与浮层过渡、列表或内容动画、性能边界以及 reduced-motion 支持。
- **桌面与系统集成**：托盘、原生菜单、系统通知、窗口注意力、标题栏、快捷键、文件关联、更新提示和多窗口基础设施。具体业务通知仍归对应业务类目记录。
- **国际化与本地化界面机制**：语言切换、布局方向、日期数字格式、字体回退和多窗口同步；翻译内容质量不属于本类目。
- **设置与首次启动框架**：设置页的分区、检索、作用域和持久化框架，以及 onboarding、版本迁移提示和功能发现机制；具体业务设置语义归对应业务类目。
- **极端性能与大规模界面**：Overlay 数量、长列表、复杂布局或低端设备表现。只有源码机制、基准或运行证据充分时记录性能结论。

## 与相邻类目的边界

| 同一能力 | 本类目记录 | 相邻类目记录 |
|---|---|---|
| 弹窗与浮层 | 公共底层、Portal、层级、关闭与焦点机制 | 业务类目记录弹窗入口、表单内容、操作结果和返回主链的路径 |
| Toast 与通知 | Host、队列、堆叠、持续时间、严重级别和系统通知通道 | 业务类目记录何种业务状态触发反馈、是否能恢复对应任务 |
| 主题与响应式 | token、权威源、持久化、断点和应用级布局策略 | 业务类目记录主题或布局变化如何影响自身关键路径 |
| 拖放与附件 | 公共拖放、上传、预览和反馈机制 | Chat UI 等业务类目记录拖入目标、数据转换和提交工作流 |
| 图片预览 | 灯箱或查看器底层、通用工具和窗口承载方式 | 消息渲染器等类目记录哪些内容触发预览及消息壳中的入口 |
| 无障碍 | 应用级公共组件和跨页面机制的扩展调查 | 业务类目记录关键任务是否存在键盘、焦点和反馈路径 |
| 桌面集成 | 托盘、窗口、系统通知和快捷键的公共设施 | 业务类目记录生成完成、审批等具体事件如何接入这些设施 |
| 设置系统 | 设置框架、作用域表达、持久化和同步 | 角色、工具、渠道等类目记录各自设置的含义与执行影响 |

## 调查规则

- 从应用根装配和公共实现入手，再抽样核对业务消费方；不能只凭依赖清单推断项目正在使用某个库。
- 区分“组件存在”“业务已接入”“用户路径可到达”和“运行表现已验证”。按钮、组件或设置字段存在，不能单独证明能力有效。
- 不以 Modal、Toast 或 ARIA 调用次数作为主要结论。数量可用于说明实现分散程度，但应给出搜索范围，并结合入口和状态机制解释。
- 依赖库的默认行为只有在版本和接入方式明确时才能作为静态推断；未阅读依赖实现或未运行验证时，不把 focus trap、Esc、动画和读屏表现写成已确认事实。
- 视觉效果、焦点顺序、触摸手势、系统通知、窗口行为和响应式切换需要运行验证。静态调查只确认元素、样式规则、事件绑定与状态路径。
- 全应用无障碍调查只能记录证据和验证边界，不据此宣称项目通过或不符合某项标准，除非存在相应的完整审计依据。
- 不把设计偏好写成缺陷评价。颜色、圆角、动画多少和组件库选择只有在影响机制、一致性或已验证的用户任务时才进入结论。
- 当旧笔记由其它类目摘出时，应重新按本指南组织标题和元数据，刷新相对链接，去除“原第几节”“待迁移”等过渡叙述；历史来源交给版本库保存。

## 横向比较字段

基础对比至少记录：产品表面、界面框架与公共层、Overlay/Portal Host、主弹窗机制、Esc/遮罩与焦点边界、Toast/通知机制、Loading/空状态、主题权威源、系统跟随与持久化、响应式策略、移动端或多窗口差异、图片预览、拖放基础设施、状态所有者，以及运行验证范围。

扩展字段按共同覆盖情况选取：动画体系、reduced-motion、应用级无障碍、桌面系统通知、托盘与快捷键、国际化切换、设置框架和 onboarding。横向对比必须区分“项目不支持”“笔记未调查”“依赖内部未核实”和“未经运行验证”。
