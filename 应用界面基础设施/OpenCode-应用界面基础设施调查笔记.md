## 结论摘要

OpenCode 同时维护两套原生界面：TUI 基于 opentui 与 Solid，Web/桌面共用 App 包。Web 侧已形成工作台结构：顶部按服务端、工作区与会话组织，支持同时连接多个 OpenCode 服务端，界面基础件下移到 `packages/ui` 的领域目录（overlays、feedback、forms、layout、navigation、typography、motion、theme 等），会话与消息渲染单独在 `packages/session-ui`。

主题系统分两套：Web 由 `packages/ui/theme` 在运行时把主题 token 注入 CSS 变量；TUI 的主题解析与旧主题迁移下沉到新包 `packages/theme`。桌面端是 Electron 壳：主进程负责窗口、菜单、深链、文件选择、插件与存储桥、原生外观细节，渲染层直接加载 App 源码。本次未找到托盘、全局快捷键与自动更新实现。

## 系统边界与总体装配

### TUI（`packages/tui`）

根装配在 `app.tsx`：创建终端渲染器与键位映射后，挂载分层 Provider 树，涵盖退出、渲染器环境、启动、剪贴板、键位、参数、配置、存储、Toast、路由、会话标签、终端、权限、位置、数据、客户端、主题、本地状态、草稿暂存、对话框、常用访问、提示历史、编辑器上下文、注意力提醒、面板与插件。路由在 Home 与会话之间切换，插件插槽与更新通知由外层 Provider 提供。

### Web App（`packages/app` + `packages/ui` + `packages/session-ui`）

入口是 `entry.tsx`，分三层：

- **基础外壳**：元信息与标题、主题、语言与 i18n 桥、错误边界与错误页、查询客户端、弹窗栈、文件组件注入。
- **应用外壳**：服务端注册表与全局运行时、设置、会话标签、项目图标、命令与桌面菜单桥、语音。
- **业务层**：工作台布局（侧栏、标签、移动抽屉）、会话页、首页、设置页、用量页。

### 桌面（`packages/desktop`）

主进程拆为生命周期（初始化、环境、深链、引导、关闭）、窗口与 IPC、原生菜单、文件与外部链接策略、桥接处理器（文件、菜单、插件、存储、窗口）、诊断与日志。渲染层复用 App，preload 暴露受控接口。主进程未见托盘、全局快捷键与自动更新模块。

## 1. 界面栈与公共组件

- **TUI 栈**：opentui（core/solid/keymap）+ Solid；自建键位映射、对话框栈、单条 Toast 与提示历史。
- **Web 栈**：Solid + Kobalte 原语 + Tailwind CSS；组件库按领域拆分——`components`（基础组件）、`overlays`（弹窗、菜单、popover）、`forms`（表单控件）、`feedback`（Toast、空状态、进度）、`data-display`（表格、列表）、`layout`、`navigation`、`typography`、`icons`、`motion`、`theme`、`i18n`、`hooks`、`storybook`。
- **共享渲染**：`packages/session-ui` 提供时间线、消息、工具与 markdown 渲染，App 与 TUI 复用。
- **状态所有权**：弹窗栈在 DialogProvider 的 context 中；Toast 由 `ui/feedback/toast` 统一；主题与语言各自 Provider；服务端连接与数据在 `runtime/server` 的注册表内；标签、布局偏好与会话草稿分别由 App 的 shell 与持久化层管理。

## 2. 弹窗、浮层与命令

- **Web**：DialogProvider 提供命令式弹窗栈（show/push/close、Esc 关闭、退场动画），菜单、popover、hover card 走 Kobalte 原语；浮层共用统一 z-index 与焦点管理策略。
- **TUI**：对话框通过模块级 store 维护栈，支持确认、提示、警告、选择等命令式对话框；面板与浮层按终端尺寸约束布局。
- **命令面板**：App 的命令系统支持搜索、快捷键与桌面菜单同步（`shell/commands/`）；TUI 有独立命令面板与斜杠命令补全。
- **桌面菜单**：主进程原生菜单与渲染层命令双向映射，菜单项可触发渲染层动作。

## 3. 反馈、通知与错误

- **Toast**：单条/短列表，支持动作按钮与自动消失；业务方统一从 ui 包调用。
- **更新提示**：TUI 有更新通知 Provider；Web/桌面在设置页展示版本与更新入口。
- **错误页**：全局错误边界渲染错误页并提供重试；服务端不可用时显示连接错误面板而不是空白页。
- **通知**：App 的通知协调器统一分发会话完成等事件，产出界面通知列表、Toast 与提示音，并支持点击跳转到对应会话标签；设置页可关闭或调整。
- **多语言**：App 内置 60 余个语言资源，UI 包的组件文案经 i18n 桥接，桌面端也有独立的本地化资源。
- **日志**：桌面主进程有独立日志与诊断导出；Web 端错误可上报。

## 4. 主题与样式体系

- **Web**：主题 token 注入 CSS 变量，支持浅色/深色/跟随系统；桌面端把主题模式同步给窗口标题栏与原生外观。
- **TUI**：主题由终端调色板派生，支持 system 主题生成与旧主题迁移（`packages/theme/src/tui/`）。
- **样式组织**：组件级 CSS 文件与 data 属性钩子，主题变量集中在 ui 包的 theme 模块；动效参数集中在 motion 模块。
- **代码高亮主题**：Web 使用共享高亮主题，代码块颜色映射主题变量；TUI 有语法高亮规则。
- **本次未找到**：主题市场、壁纸、用户自定义 CSS 入口。

## 5. 响应式与移动形态

- App 布局按断点切换：窄屏时侧栏折叠为移动抽屉（`shell/mobile-drawer.tsx`），会话页与设置页按可用宽度调整面板；Composer 在移动端把 Agent/模型信息上移到输入区。
- TUI 按终端行列自适应，窄终端下降级表格与工具卡片。
- 桌面窗口有最小尺寸与窗口几何恢复。

## 6. 常见内容交互

- **复制**：消息、代码、diff、路径都有复制入口，复制反馈短暂显示。
- **搜索**：全局命令面板搜索会话与命令；文件搜索、技能选择各自有面板。
- **拖拽与粘贴**：Composer 支持文件拖入、粘贴图片与附件预览。
- **链接**：站内链接走路由，站外链接在浏览器或系统浏览器打开；桌面端有外部 URL 白名单策略。
- **图片预览**：消息图片与附件可放大查看。
- **深链**：桌面端支持通过协议链接打开会话/工作区。

## 8. 设计取舍与已确认边界

- **多服务端**是工作台的核心结构，Provider 树因此先建服务端注册表再建业务状态。
- **组件库领域化**让基础件与业务组件分离，Storybook 与动效参数便于统一验证。
- **主题分两套**：Web 走 CSS 变量，TUI 走终端调色板，共享的只是主题语义与迁移工具。
- **桌面是薄壳**：不复制 UI，只补窗口、菜单、文件、深链与平台外观。
- **边界**：未找到托盘、全局快捷键、自动更新、主题市场与用户自定义 CSS。
