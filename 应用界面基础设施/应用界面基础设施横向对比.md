# 应用界面基础设施横向对比

> 对比对象：AIO Hub、AstrBot、Chatbox、Cherry Studio、DeepChat、Hermes Agent、Jan、LobeHub、Manifold Desktop、NextChat、Open WebUI、OpenCode、SillyTavern、VCPChat、VCPToolBox（共 15 个项目；Pi 为纯 TUI 项目，机制见文末"Pi：TUI 形态映射"节）
>
> 对比更新日期：2026-08-13
>
> 依据：`应用界面基础设施` 类目下各单项目调查笔记（`AIO-Hub-`、`AstrBot-`、`Chatbox-`、`Cherry-Studio-`、`DeepChat-`、`Hermes-Agent-`、`Jan-`、`LobeHub-`、`Manifold-Desktop-`、`NextChat-`、`Open-WebUI-`、`OpenCode-`、`SillyTavern-`、`VCPChat-`、`VCPToolBox-` 的 `-应用界面基础设施调查笔记.md`）及各自代码快照；主题维度行含 2026-08-13 各项目"主题体系专项核对"补充结论；原跨层综合结论保留于 `../Chat/Chat横向对比.md`
>
> 对比方法：按弹窗底层与关闭/焦点机制、通知/Toast、主题切换、图片预览、动画方案等统一维度逐项对照；各项目的聊天主链交点由 Chat UI 类目笔记记录，不在本对比范围
>
> 对比范围：弹窗底层、通知/Toast、主题切换、图片预览、动画方案，以及各项目的特殊实现差异；Hermes Agent 的桌面/TUI/Web 三套 UI 基础设施不同，对比行取桌面端为准，TUI/Web 差异在本项目笔记内说明；VCPToolBox 是管理台 Web UI（无最终用户聊天表面），本类目按应用级界面机制纳入对比；Pi 是纯 TUI 项目（自研终端 UI 库，无 Web/桌面 GUI 表面），本表现有维度的遮罩/焦点陷阱/灯箱/framer-motion 等术语均按 GUI 形态定义，与 TUI 的 Esc/焦点还原/flash/终端颜色协议不可直接对齐，不纳入对比行，其机制见 `Pi-应用界面基础设施调查笔记.md` 与文末"Pi：TUI 形态映射"节
>
> 文档定位：实现学习与跨项目横向比较，不作为整改方案

## 结论摘要

十五个项目的界面基础设施没有共享模式：弹窗底层有十余种互不相同的技术栈（自研 Vue 组件、Mantine+vaul+Radix 三套并存、Radix 封装、shadcn-vue/Reka 薄封装、shadcn/Radix 全套封装、命令式库封装、原生 `<dialog>` 自研类、纯手写 DOM、手写 DOM 单例、Solid 双表面各一套）；通知系统每个项目各自为战，且多数项目存在两套以上并行 Toast 机制；主题切换从 CSS 变量热替换到整窗口重载都有，跟随系统的支持度参差；图片预览有页面内灯箱、独立子窗口、CSS class toggle、无灯箱内联图等不同形态。无障碍与焦点管理覆盖不一，三方包内部行为普遍未核实。Hermes Agent 是其中唯一的多 UI 表面项目（桌面/TUI/Web 三种装配），其桌面端把贡献注册表当作应用壳的唯一组织方式，弹窗内浮层通过改投弹窗 DOM 修复 Radix 嵌套失效。DeepChat 是唯一把"通知"拆成 renderer 管理层（请求归一化/优先级仲裁/展示预算）与主进程跨窗口语义路由两层并配策略契约的项目。VCPToolBox 与 Manifold Desktop 都走"无组件库、全部手写"路线，但前者有完整的 BaseModal 焦点陷阱与 feedback 总线，后者的原生层刻意做薄到零浮层控件。

## 弹窗/对话框：十余种互不相同的底层技术栈

| 项目 | 弹窗底层 | Esc/遮罩关闭 | 焦点管理 |
| --- | --- | --- | --- |
| AIO Hub | 自研 `BaseDialog.vue`（非 Element Plus），自增 z-index，300ms 入退场动画 | 支持（由 `showCloseButton`/`closeOnBackdropClick` prop 控制；Esc 与关闭按钮绑定为复合开关） | 基本缺失；唯一例外：`RenameDialog` 输入框有 `autofocus` |
| AstrBot | Vuetify `v-dialog` 直接使用（100 处以上），无公共封装；命令式确认框自研 `confirmPlugin`（`ConfirmDialog.vue` 单实例挂 body，`Promise<boolean>`，无 onOk/onCancel 回调面） | Esc/遮罩/滚动锁定/焦点均交 Vuetify 3.7 内部实现（**未下钻**）；项目只传 `persistent`/`fullscreen`/`scrollable` 等属性 | 无项目级焦点管理代码；对话框样式一致性靠 AGENTS.md 的标题类 + text/tonal 按钮约定而非组件抽象 |
| Chatbox | 三套并存：Mantine `Modal`（主力）+ `vaul`（移动端底部弹起）+ Radix `Dialog`（预留）；`@ebay/nice-modal-react` 统一管命令式调用 | 逐弹窗配置：登录/许可证类三项全禁；`trapFocus={false}` 在四个弹窗里有意关闭（iOS Safari 文本选中 workaround） | `trapFocus={false}` 的四个弹窗键盘 Tab 可穿透到背景——有代码提交记录的已知取舍 |
| Cherry Studio | 自建 `@cherrystudio/ui` 包裹 Radix `Dialog`；`services/popup` 用 `useSyncExternalStore` 做 store | 支持；两阶段关闭，延迟 200ms 播放退场动画 | Radix `DialogContent` 默认交给 `FocusScope` 管理焦点；业务侧可用 `focusOnClose` 指定关闭后的焦点落点 |
| DeepChat | `src/shadcn`（shadcn-vue 原始件，底层 Reka UI）薄封装；三种消费方式：主进程命令式全局 `MessageDialog`（Promise 化 + 超时自动默认键）、`dc-ui` 的 `DcConfirmDialog` 业务壳（AlertDialog + 自研 AsyncAction）、组件内 `Dialog`（图片全屏查看等）；自实现 `SpotlightOverlay`（Teleport + 自管键盘导航）；z-index 走统一 `--dc-z-*` 刻度（popover 50 / modal 100 / toast 1000） | Esc/遮罩/焦点陷阱均交 Reka 默认（封装层未覆盖，**内部未下钻**）；Spotlight 自实现 Esc/方向键处理与 `mousedown.self` 遮罩关闭，**无 focus trap**；全局确认对话框单窗口单实例 | 无显式焦点归还代码；图片查看对话框用 `open-auto-focus` preventDefault 后手动聚焦容器以避开关闭按钮首焦 |
| Hermes Agent（桌面端） | 直接包 `radix-ui` 合并包（Dialog/Sheet/ContextMenu/Tooltip/Select…），无自研 UI 包；命令面板 = Radix Dialog + cmdk（自研搜索排序）；覆盖层视图是路由驱动全尺寸视图 | 交 Radix 默认（Esc/遮罩/焦点陷阱未覆盖）；弹窗内 Select/Popover 经 `DialogPortalContainerContext` 改投弹窗 DOM 内，修复嵌套时误关与 z-index 不可控；应用自有 window 级 Esc 处理器用 `escape-layers.ts` 优先级串行化 | Radix FocusScope 默认；`preventCloseButtonAutoFocus` 抑制无输入框弹窗的首焦落在关闭按钮；tooltip 焦点开启被 `suppressNonKeyboardFocusOpen` 限定为键盘焦点 |
| Jan | shadcn 风格 `components/ui`（Radix 全套：dialog/sheet/dropdown-menu/popover/tooltip/hover-card）+ vaul Drawer + 自研 `DropDrawer`（桌面 DropdownMenu↔移动 Drawer 双模）；无命令式弹窗服务，跨组件弹窗走"全局 zustand 门控 + Promise resolver"（如附件摄取确认），根级六个全局对话框 | Esc/遮罩/焦点/滚动锁定全部交 Radix/vaul 默认实现（**未下钻**）；业务侧仅少数对话框干预（`onInteractOutside` 阻止遮罩关闭、`showCloseButton={false}`） | Radix 默认 FocusScope（未下钻）；`ModelCombobox` 是少数自绘浮层（`fixed z-9999`）不走 Radix Portal |
| LobeHub | `@lobehub/ui` 的命令式 `createModal`/`confirmModal`（主流）+ `ImperativeModal` 兼容层（迁移期遗留） | 高危操作（如清空工作区）把 `maskClosable` 设为 `false` 并要求勾选确认框；其余遮罩点击可关闭 | 业务调用方未发现统一的显式配置；`@lobehub/ui/base-ui` 内部是否有 focus trap 未下钻，结论应保留为未核实 |
| Manifold Desktop | 原生层**零浮层控件**（ContentDialog/Flyout/TeachingTip/InfoBar 全仓库 Grep 无命中）；Web 侧手写 DOM 单例：`confirm.js`（`Promise<boolean>`）、`search-overlay.js`、`settings-panel.js`、提示词下拉，各自管理挂载与 z-index（100/200/250/300） | Confirm 遮罩点击关闭（`e.target === overlay`）但**无 Esc**、无焦点陷阱；搜索浮层有 Esc/方向键；设置抽屉**无 Esc、无遮罩层**（`.settings-overlay` 遮罩样式是死样式）；提示词下拉无 Esc | Confirm 打开 `ok.focus()`，无焦点归还；搜索浮层/设置抽屉关闭后均无焦点管理 |
| NextChat | `ui-lib.tsx` 自研命令式 API：`showModal/showConfirm/showPrompt/showImageModal` 每次调用新建 div + `createRoot` 直挂 `document.body`——无 Portal、无 host、无队列与单例 | Modal Esc 由组件内 `window` keydown 监听（依赖闭包常驻）；遮罩点击 `e.target === div` 判定；关闭即 unmount 移除，无两阶段退场 | 无焦点陷阱/归还逻辑；仅 `showConfirm` 确认按钮与 PromptInput `autoFocus` |
| Open WebUI | 自研 `common/Modal.svelte`（Portal + `focus-trap` 库）+ 独立 `ConfirmDialog` + 底部 `Drawer` + 自研 popover `Dropdown`；无组件库，bits-ui 仅 Switch/Pagination/LinkPreview | Esc 支持且带 `isTopModal` 最上层判定；遮罩 `mousedown` 关闭（Modal/ConfirmDialog/Drawer） | Modal/ConfirmDialog 用 focus-trap 库（Modal 显式 `allowOutsideClick` 放行 toast，ConfirmDialog 用默认配置）；**Drawer 无陷阱**；关闭后无显式焦点归还代码 |
| OpenCode | **双表面两套**：TUI 自建 Solid store 对话框栈（`dialog.replace` single-flight 语义，Esc/ctrl+c/遮罩关闭，关闭后 1ms 显式 refocus）；Web `@opencode-ai/ui` 的 `DialogProvider` 栈（Kobalte Dialog + show/push/close 命令式 API，window 级 capture Esc，100ms 退场延迟，owner 继承） | TUI：Esc/ctrl+c 双键弹栈 + 遮罩点击关闭（选区复制中挂起）；Web：window 级 capture Esc + Overlay 点击 `close(id)` | TUI：`refocus()` 关闭后重查焦点 Renderable 再聚焦；Web：owner 取栈顶弹窗 owner + Kobalte 内部焦点管理（未下钻） |
| SillyTavern | 原生 `<dialog>` + 自研 `Popup` 类（非 jQuery UI Dialog）；阻塞性弹窗需**双击 Esc** 强制关闭（注释自曝为"踩坑后留下的防御代码"） | **点遮罩不会关闭**（与大多数现代弹窗库相反） | 无（有焦点归还机制：`lastFocus` 记录 + 弹窗栈内归还，但无 focus trap） |
| VCPChat | 全部自定义 DOM；通用 Modal 用 `<template>` 懒加载 + `modal-ready` 事件通知 | 确认对话框支持 Esc/Enter/遮罩点击；无 focus trap，Tab 可穿透背景 | 无 focus trap |
| VCPToolBox | 自研 `BaseModal.vue`（Teleport + 焦点陷阱 + 滚动锁定 + Esc/遮罩，props 可控）+ 命令式 `feedbackState` 单例（confirm/input/loading/message 四通道，Promise + 队列，一次展示一个）+ `FeedbackHost` 渲染层；ConfirmDialog/InputDialog 是独立实现**不用 BaseModal** | BaseModal 遮罩 `event.target === currentTarget` + Esc 均可关（props 控制）；InputDialog 有 Esc/Enter/Ctrl+Enter；**ConfirmDialog 无 Esc 绑定**；两者都无 Tab 陷阱与滚动锁定（与 BaseModal 不一致） | BaseModal 记录 `previousActiveElement`、打开聚焦首个可聚焦元素、Tab 首尾循环、关闭归还焦点；ConfirmDialog/InputDialog 无焦点管理；层级 confirm/input 为 `--z-index-modal+1`（10001），在 BaseModal（10000）之上 |

**跨项目结论**：SillyTavern 的遮罩点击不会关闭弹窗；Chatbox 有可追溯的提交记录说明关闭 focus trap 的原因。焦点管理覆盖不一：Cherry 的 Radix 基础层提供 `FocusScope`，其余项目在自动聚焦、关闭后的焦点落点和业务控件语义上各有缺口；LobeHub 的 `@lobehub/ui` 包内部实现尚未核实。只有 Cherry Studio、SillyTavern、VCPToolBox（BaseModal）与 OpenCode TUI（refocus）具备关闭后的焦点归还/落点机制，其余项目未见。Hermes Agent 桌面端的 `DialogPortalContainerContext` 是唯一显式解决"弹窗内再弹浮层"嵌套问题的机制（把弹窗内 popover 改投为弹窗 DOM 子节点）。Open WebUI 的弹窗层级是"最后挂载者优先"判定（`isTopModal`，无 z-index 栈），body 滚动锁无共享计数器（代码注释自述为已知边界）。DeepChat 的全局确认对话框由主进程 `DialogService` 持有 Promise 状态、renderer 只做呈现，是唯一"主进程命令式 + 超时自动默认键"的弹窗所有权形态。VCPToolBox 同一应用内存在能力不对齐的两套命令式弹窗（BaseModal 有完整焦点管理，ConfirmDialog/InputDialog 没有）——静态可见的不一致。

## 通知/Toast：每个项目各自为战

| 项目 | 实现 | 位置 | 特殊行为 |
| --- | --- | --- | --- |
| AIO Hub | 三层：`customMessage`（ElMessage 包装，offset 54px 避开无边框标题栏）→ `errorHandler` 四级分发（CRITICAL 走常驻 `ElNotification`，duration:0）→ 独立 `NotificationCenter`（持久化） | 顶部 | CRITICAL 级常驻不消失 |
| AstrBot | 自研 Pinia `toast` store（单例 FIFO 队列）+ `App.vue` 全局唯一 `v-snackbar` 串行消费；`utils/toast.js` 提供 success/error/info/warning | 顶部居中（top center） | 默认 3s；**单条顺序展示，无堆叠、无同 key 更新、无 loading→success、无持久化**（store 源码 31 行）；长任务（更新/重启/升级恢复）用模态对话框 + 轮询而非 toast |
| Chatbox | 两套分工：MUI `Snackbar`（聊天主流程，右上角，3s）+ `sonner`（Settings 弹窗内部，底部居中，`z-index: 2147483647`）；错误 toast 先出原文再追加异步翻译 | 右上角 / 底部居中 | 多条 MUI toast 会互相重叠（未处理堆叠位移） |
| Cherry Studio | 自研 store（非 antd/sonner），`role="alert"`/`role="status"` 区分严重程度，error 默认不消失 | 顶部居中 | 默认 3s，error 永不自动消失；loading→success/error 有 Symbol 令牌桥接防误写 |

| Hermes Agent（桌面端） | 自研模块级 `$notifications` atom 单例 + 双栈：顶部居中栈（最新一条 + "+N more" 展开 + clear-all）管 error/warning/带 action，右下 ambient 栈管例行确认；`notifyError` 带错误摘要规则表（磁盘满/API key 拒绝等）；错误 detail 用 `<details>` 折叠 + 复制 | 顶部居中 / 右下 | 栈上限 4 条、同 id 原地替换；error/warning 不自动消失，其余 5s；`role="alert"/"status"` + haptic；后端 `notification.show` 协议映射为 toast（key 作 id、剥离 CLI 字形、额度用量 75%/90% 变色）；原生 OS 通知独立通道（7 类 kind 按类开关、仅后台发送，approval/input 例外） |
| Jan | sonner 单一 Host：`ToasterProvider` 全局一份 `<Toaster richColors>`，位置来自 `useInterfaceSettings.notificationPosition`（四角可选，Windows+Tauri 默认 bottom-right 避开自绘标题栏，其余 top-right），`visibleToasts={5}` | 按配置四角 | 常驻提示用"命名 id + 完成时 dismiss"配对（模型下载 `duration: Infinity`）；`toast.loading` 全 src 仅 llamacpp 退出拦截一处；**无系统通知通道**（浏览器 Notification 与 Tauri 插件均未使用）；WebView2 CSP 限制下 toast 底色用 `.toaster` 类 `color-mix` 混入 `--primary` |
| LobeHub | antd `App.useApp()` 单例（`AntdStaticMethods`），桌面端整体下移避开 Electron 标题栏；另有独立自绘悬浮通知卡片组件 | 顶部（偏移）+ 悬浮卡片 | 两套并存：antd 管临时提示，自绘卡片管持久通知 |
| Manifold Desktop | 手写 `toast.js` 单例（`#toast-container`，类型 class 无 CSS 区分），4s 渐退 200ms 再移除 | 底部右侧（z-index 200） | **唯一调用点是全局 `window.onerror`/`unhandledrejection` 兜底**——业务流程（聊天/设置/导入导出）均不弹 Toast；无队列上限、无更新/取消、无 aria-live |
| NextChat | `showToast(content, action?, delay)` 命令式（每次独立 div，`.show` 类，3s 后 `.hide` 0.3s 退场再移除） | 底部居中（z-index 99999） | **无堆叠/队列**（多个并存时 fixed 底部同区域视觉重叠）；支持单 action 按钮（如删除会话 5s 撤销）；无成功/错误级别区分、无 role/aria-live |

## 动画方案：只有 LobeHub 引入了 framer-motion 体系

- **AIO Hub**：自研 CSS transitions + Element Plus 内置动效；消息内容块 `fade-in-up 0.3s` 由 `enableEnterAnimation` 偏好控制，9 类节点在 `NO_ANIMATION_NODE_TYPES` 名单外应用；侧栏折叠 `v-if` 硬切换无过渡。
- **AstrBot**：无动画库；Vuetify 自带 transition 体系（全屏对话框 `dialog-bottom-transition`、抽屉 `slide-x-reverse-transition`、dialog/menu 默认过渡）；手写 `@keyframes` 仅 `scss/_container.scss` 的 `blink`/`bounce` 与 `_override.scss` 的 `progress-circular-rotate`；`prefers-reduced-motion` 仅侧栏 rail 过渡一处（`_sidebar.scss:234-241`），全应用覆盖未逐一确认。
- **Chatbox**：无 framer-motion；`tailwindcss-animate` + Mantine 内置过渡预设 + `vaul` 弹簧动画 + 手写 SVG `<animate>` + 手写 CSS keyframes；消息卡片首次出现**无入场动画**。
- **Cherry Studio**：无 framer-motion；`tw-animate-css` + Radix `data-state` 驱动 + 手写 CSS keyframes；折叠展开是 `hidden` 硬切换，**无高度渐变过渡**。
- **DeepChat**：无 framer-motion；`tw-animate-css` + `tailwindcss-animate` + Reka `data-[state]` 动画类（shadcn 组件层）；`dc-ui/styles/motion.css` 统一 Reka tooltip/select/context-menu 的 `transform-origin`；业务自写动画集中在 Spotlight 进出场（80ms transition）与通知托管组件（spinner/progress keyframes）；`--dc-motion-*`（140/220/320ms）与 `--dc-ease-*` 时长/缓动 token 统一消费；全局 `prefers-reduced-motion` 兜底（transition/animation 压 1ms）。
- **Hermes Agent**（桌面端）：无 framer-motion 体系，仅两处局部 `motion/react`（diff 计数、文件树折叠）；开合动画全走 Tailwind `data-[state=open|closed]` 类；自研 SVG 数学曲线 Loader（rAF 驱动 21 种曲线）；命令面板退场由 CSS `animationend` 驱动卸载。TUI 的"动画"是终端字符级（共享 shimmer 时钟、FaceTicker 表情帧）。
- **Jan**：无 framer-motion 体系（`package.json` 声明但**仅 `DropDrawer` 移动端子菜单一处 import**，`AnimatePresence` 页面级滑入滑出）；主体走 tw-animate-css + Radix `data-[state]` 类（dialog/sheet 等统一 z-50）；消息卡片无入场动画。
- **LobeHub**：`motion/react`（framer-motion 新包名）用在 `WorkflowCollapse` 折叠动效和文档编辑器侧栏滑动；消息本身进场**无动画**；且两处自定义动画对全局 `animationMode` 开关的遵守程度不一致（一处读、一处不读）。
- **Manifold Desktop**：纯 CSS transition（设置抽屉 `right: -360px→0` 200ms、Toast 透明度渐退 200ms、hover 显隐）；无动画库、无 JS 动画；`prefers-reduced-motion` 未使用；流式指示/加载点是 CSS 脉冲动画（`.streaming-indicator`）。
- **NextChat**：无动画库；手写 CSS——`animation.scss` 的 `slide-in`/`slide-in-from-top` keyframes（弹窗/列表进场）、Toast opacity/translateY transition 退场、代码块复制按钮 hover 显隐；`prefers-reduced-motion` 处理本次未找到。
- **Open WebUI**：无 framer-motion；Svelte 自带 transition（`fade`/`fly`/`slide`）+ 自研 `flyAndScale`（200ms cubicOut）+ CSS keyframes（`shimmer`、`smoothFadeIn`）；`prefers-reduced-motion` 处理本次未找到。
- **OpenCode**：无动画库；TUI 无过渡系统（加载 spinner 帧动画、flash 反显），Web 走 `tw-animate-css` + Kobalte `data-state` 类 + v2 toast 的 160ms 缩放脉冲（跳 reduced-motion）；对话框退场有 100ms 延迟语义。
- **SillyTavern**：自研 `stream-fadein.js`（流式输出渐显）+ jQuery UI + CSS transitions；全局动画时长 `--animation-duration` 变量可在设置里改；面板级开合与文本级逐词淡入是两个层面。
- **VCPChat**：CSS transitions；三种 presentation mode 切换是 body class 变换，由 CSS 控制；流式输出进行中有 `vcp-border-flow` 流光边框动画。
- **VCPToolBox**：无动画库（无 framer-motion/GSAP）；全部 Vue `<Transition>` + CSS（fade/slide/backdrop-fade）+ `@keyframes`（spinner、emoji shimmer）；用户级开关 `animationsEnabled`（localStorage，顶栏系统菜单可切换）控制星空背景、Nova 动画与 dashboard 动画；`prefers-reduced-motion: reduce` 覆盖面广（BaseModal/ConfirmDialog/InputDialog/UiButton 等 30+ 组件与页面各有一处）。

**跨项目结论**：各项目都没有为消息卡片首次出现设置明显的入场动画。LobeHub 引入了 framer-motion，但只用于少数组件；Jan 虽声明 framer-motion 但仅 DropDrawer 一处消费。Cherry Studio 的折叠展开采用 `hidden` 硬切换，属于代码中明确可见的实现方式。DeepChat 与 Cherry 的动画技术栈同源（tw-animate-css + Radix/Reka data-state + 少量手写 keyframes），额外有一致的时长/缓动 token 层。`prefers-reduced-motion` 覆盖最广的是 VCPToolBox（30+ 处），AstrBot 与 DeepChat 各有显式 token/单点处理，NextChat、Open WebUI、Manifold Desktop 本次未找到。

## 各项目的特殊实现差异（汇总）

- **AIO Hub**：主题持久化在 `settings.json` 而非 localStorage（与"通常在浏览器层存"的预期相反，因为是 Tauri 原生应用）。
- **AstrBot**：`vue-i18n` 在 `package.json` 声明但源码全量 grep 无 import（运行时是自研 i18n composables，缺键返回 `[MISSING: key]`）；`SET_FONT` action 与 `Customizer_drawer` 无消费方、"声而不用"；无 Vue 错误边界（无 errorHandler/errorCaptured），错误靠 axios 拦截器（401 统一登出）+ try/catch + toast；`isMobile = window.innerWidth < 768` 只在组件初始化时判定、窗口缩放不自动切换（静态推断）；多标签页无 BroadcastChannel/storage 主题同步（仅侧栏定制一处 storage 监听）。
- **Chatbox**：文件拖入输入区**没有任何高亮遮罩或视觉反馈**；桌面端 `SessionItem` **没有右键菜单**；初始断点判定用 599.95px，后续响应式用 640px，两个数字之间存在窄缝（聊天主链交点见 Chat UI 横向对比）。
- **Cherry Studio**："助手回复完成通知"开关可勾选，但全仓库找不到任何发送调用——**是个不生效的死开关**。
- **DeepChat**：`DcToast` 门面（dc-ui 的 notifyRenderer 包装）已导出但全仓库零调用——新旧入口并存；应用级错误边界缺失（renderer 无 errorHandler/onErrorCaptured/onerror 挂载，错误反馈全下放到功能场景）；侧栏折叠是纯手动开关且不持久化（无断点驱动）；主聊天窗未设最小尺寸（可无限缩小，设置窗 900×640）；`MessageItemAssistant` 的 Reka 右键菜单是新路径，默认仍走 `useLegacyActions` legacy 行为。
- **Hermes Agent**：桌面端是唯一多 UI 表面项目（Electron 桌面 / Ink TUI / Web dashboard 三种独立装配，共享 `apps/shared` 连接层与后端皮肤/通知协议）；TUI 浮层分三种形态（flow 提示推挤内容、浮层面板 absolute 向上生长、widget 模态九宫格+伪 scrim），键盘由单一 `useInput` 管线按浮层类型分派 Esc（双击 Esc 丢弃草稿）；桌面应用壳是贡献注册表驱动（pane/标题栏/快捷键/命令面板/路由/主题全走同一 `area` 注册 API，核心与插件同权，插件崩溃按 slot 降级为 `ContribBoundary` 内错误）。
- **Jan**：无命令式弹窗服务，跨组件弹窗走"全局 zustand 门控 + Promise resolver"（与 Cherry 的 PopupHost 单例相反的设计取向）；后端存储迁移**不清理 localStorage**（降级兼容策略），导致防闪烁脚本与窗口创建读到的 localStorage 主题值可能陈旧；主题键名两处脱节（`jan-theme`/`theme`/backend storage）是代码级确认的静态不一致；未使用依赖（next-themes/react-resizable-panels/matter-js）与声明不符；窗口最小尺寸本次未找到任何配置。
- **LobeHub**：移动端是独立路由树 + 独立构建产物（`vite.config.ts` 按 `isMobile` 切 entry），不是同构响应式；资源管理器的文件拖拽是团队主动放弃 `dnd-kit`、自建原生 HTML5 drag/drop（注释明确写了性能理由）。
- **Manifold Desktop**：原生壳刻意做薄——WinUI 层除 WebView2 承载、系统对话框、剪贴板、DPI 外零界面实现；死代码存量经 Grep 确认（`FRONTEND_READY` 原生无 handler、`GET_SETTINGS` 前端无发送点、`OPEN_FILE_DIALOG`/`FILE_ATTACHED` 前端无消费点、`.settings-overlay`/`.loading-dots`/`.streaming-dots` 无 JS 使用点）；深浅色边界不一致（`index.html` 首帧硬编码 dark + WebView2 默认背景硬编码 #18181B + 高亮 CSS 固定深色，与持久化主题解耦）；侧栏宽度 token 260px 与 CSS 实际 240px 不一致；`--sidebar-width` token 与硬编码并存。
- **NextChat**：零组件库（无 antd/Radix/Tailwind/framer-motion），浮层命令式 `createRoot` 直挂 body；上传依赖 ServiceWorker 拦截 `/api/cache`（SW 不可用回退 ≤256KB canvas 压缩 base64，HEIC 先经 heic2any 转 JPEG）；PWA 非离线壳（`cache.addAll([])` 空列表、SW 只服务 `/api/cache`）；Tauri 薄壳：单窗口 960×600 Overlay 标题栏、`stream_fetch` 命令做流式 HTTP 桥接（绕 CORS）；系统通知仅应用更新场景；无托盘/原生菜单/全局快捷键/多窗口；桌面 Web 形态是"窗口卡片"（90vw/1200px 圆角）。
- **Open WebUI**：弹窗层级无 z-index 栈，靠 body append 顺序 + `isTopModal` 最上层判定；body 滚动锁直接 `unset` 无计数器（`ImagePreview.svelte` 注释自述"如未来支持多 modal 堆叠需共享 lock manager"）；主题不随账户同步（localStorage 设备本地）；`manifest.json` 为空对象 `{}` 且无 service worker 注册（仅保留注销逻辑）；全应用无自绘右键菜单；移动端靠单一 768px 断点 + `$mobile` store 显式分支；`window.electronAPI`/`applyTheme` 由外部桌面壳仓库注入（壳侧未调查）。
- **OpenCode**：双表面两套完全独立的基础设施（TUI opentui+Solid / Web Kobalte+Solid，无 Ink，桌面 Electron 复用同一 renderer）；Web Toast 双代并存（v1 Kobalte / v2 solid-sonner 按新旧布局静态切换，注册表分离）说明界面基础设施正处于迁移期；桌面端无托盘/全局快捷键/主进程通知通道（系统通知走渲染层浏览器 Notification，仅窗口不聚焦时发）；TUI 无上下文菜单（右键语义是选区复制）；Web 移动/桌面 768px 硬断点无 token 常量。
- **SillyTavern**：swipe（候选回复切换）在移动端是**点按钮，不是划手势**，与功能名字暗示的手势操作不符；主题系统的 CSS 是服务端存储而非 localStorage，切换后需要页面刷新。
- **VCPChat**：compact navigation 由 `sidebarAvatarOnly` 字段显式控制，**不是宽度断点自动触发**；表情包选择器是平铺图片网格，无搜索无分类，点击插入原始 `<img>` HTML 标签。
- **VCPToolBox**：feedback 总线可替换（`FeedbackSink` 接口 + `noopSink` 回退原生 confirm/prompt，`main.ts` 才接线）——机制上允许无 UI 环境调用不崩溃；z-index 双轨不一致（token 声明 `--z-index-loading:10001`/`--z-index-message:10003`，但 FeedbackHost 用硬编码 9999/10000，静态推断全局 loading 遮罩低于 BaseModal 与 confirm/input）；应用级滚动策略是 body 锁死 + 内容区独立滚动；无右键菜单/错误边界/公共灯箱/系统跟随（均为 Grep 范围的"本次未找到"）；Dashboard 网格用 `@container` 容器查询 + `getComputedStyle(gridTemplateColumns)` 反推列数判定三档模式。

## Pi：TUI 形态映射

Pi 是纯 TUI 项目（自研 `packages/tui`，差分渲染 + regular/fullscreen 双渲染器，无 Web/桌面 GUI 表面），上述 GUI 维度不可直接对齐。按 TUI 形态映射（详见 `Pi-应用界面基础设施调查笔记.md`）：

- **弹窗/浮层** → 自研 overlay 栈（`showOverlay`：锚点/百分比尺寸/可见性回调/焦点捕获与 preFocus 还原）；常规"对话框/命令面板"形态是**编辑器插槽替换**（`showSelector` 单实例互斥）；确认以选择器内嵌确认行实现，无独立 Modal 组件。
- **Esc/焦点** → Esc 语义由各组件消费 `tui.select.cancel`（默认 escape/ctrl+c），无框架级全局 Esc；单焦点模型，overlay 关闭焦点回退到下一个可见 capturing overlay 或 preFocus 链（有专门测试）。
- **Toast/通知** → 三套：聊天区追加文本（showError/showWarning/showStatus，连续状态复用末行防刷屏、随滚动无自动消失）+ fullscreen 反显 flash（约 1s 自动消失）+ OSC 9;4 终端进度条；无全局 toast host 概念。
- **主题** → JSON token 文件 + `globalThis` 符号全局单例；truecolor/256 色降级、`vars` 引用、`light/dark` 斜杠自动模式；三级终端主题检测（DSR 996 颜色方案通知 / OSC 11 背景色 / COLORFGBG）；自定义主题文件 fs 监听热重载（100ms debounce）；持久化在 global settings.json。
- **图片** → Kitty/iTerm2 协议能力探测渲染（tmux/screen 保守关闭），无协议时文本 fallback；cell size 查询校准行高；fullscreen 下离屏缓存与淘汰（上限 16 张/32MB/64MB）。
- **拖放** → 终端无拖放事件通道；"drop files" 通过粘贴文件路径 + `@` 附件补全（`CombinedAutocompleteProvider`，fd 模糊搜索、gitignore 感知）。
- **键盘** → TUI 层 + 声明合并的单注册表，`keybindings.json` 用户覆盖、同键冲突检测、旧键名迁移；Kitty 键盘协议协商 + Windows `ENABLE_VIRTUAL_TERMINAL_INPUT` 修复。
- **动画/无障碍/桌面集成** → 无过渡系统（loader 帧动画 + flash 反显）；可访问性靠键盘全功能 + 反显/强调色（无读屏协议通道）；桌面集成为 OSC 通道（9;4 进度条、52 剪贴板、0 标题），无托盘/系统通知概念。
