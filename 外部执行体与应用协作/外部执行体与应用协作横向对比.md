# 十六个项目外部执行体与应用协作横向对比

> 对比对象：LobeHub、DeepChat、Cherry Studio、OpenCode、Jan、AstrBot、Hermes Agent、VCPToolBox、VCPChat、AIO Hub、DeepSeek Harness、OpenClaw、VCPMobile、RikkaHub、Codex、OpenOcta
>
> 对比更新日期：2026-11-04
>
> 依据：同目录十六份单项目调查笔记（本轮单项目笔记均为 2026-11-04 快照；Codex 与 OpenOcta 的代码快照分别为 `021fccb046508938c4754982efccfb51d6e8356e` 与 `0c7dac2284211facdfc813166fe648d093153bb6`，均为 `main`）、各项目现有独特功能/Agent 工具/Chat/对话请求调查笔记（链接见文末依据索引），以及当前代码快照的关键入口复核
>
> 对比方法：按“外部执行体、外部应用、外部控制与交互表面”三种接入角色，比较身份、协议方向、状态映射、执行位置、结果回流、取消恢复和治理边界
>
> 对比范围：具有持续身份与双向生命周期的外部 Agent、业务连接和控制表面；排除普通 Provider、任意 MCP、一次性导入、单向通知和宿主内建子 Agent
>
> 文档定位：实现学习与跨项目横向比较，不作为功能数量排名、兼容性承诺或安全审计报告

## 结论摘要

当前 16 个主要调查项目（清单见根目录 [`AI客户端项目评分.md`](../AI客户端项目评分.md)）中，至少 14 个已经出现可比较的外部协作主链，数量和实现差异都足以建立正式类目。它不是“独特功能”中的单点能力：这些项目反复面对外部身份、协议方向、会话映射、取消、重连和权限所有权等共同问题。

最关键的差异是**谁控制谁**：

- LobeHub、Cherry Studio 主要把外部 Agent runtime 当执行者（LobeHub 另有完整 Bot 平台层与 Agent Share 访客面）；Cherry 另有受管 Code CLI：为十余个第三方编程代理写配置并在本机终端拉起进程，DeepSeek Harness 已从进程内 runtime 迁到这一面；DeepChat 同时接入 39 个可安装的 ACP runtime，应用关闭时回收孤立子进程，并允许 IM/CLI 控制自己的本地任务；其 Discord 与 QQBot 请求带固定超时，stop 会取消等待中的重连退避。
- OpenCode、Hermes Agent 主要把自身 Agent runtime 暴露给多个客户端或协议宿主（Hermes 另有 ACP adapter 与 REST API 被宿主控制）。OpenCode 本轮把接入方式改为后台服务守护 + 一次性配对码 + 二维码/链接接入 + 可选远程隧道，服务端鉴权改为密码或配对会话令牌；ACP 实现已迁到 CLI 包。
- OpenClaw 以同一 Gateway 同时充当宿主与被控端：经 ACPX 启动 Claude/Codex/Gemini/Pi 等外部 harness 并用进程租约托管，也把自身 Gateway 会话暴露给 CLI/TUI/浏览器 Control UI、移动 companion 与原生 ACP client，还经 `attach` 给外部 Claude Code 短期授权访问自身能力；session 另可被放置到受管 worker environment 并按 placement 状态机 recovery/reclaim。节点侧新增可复用的 Rust node host：节点连接、身份与配对、重连、有界命令运行时由 `crates/openclaw-node-host` 承担，可独立作为 headless host 运行，并与平台 supervisor 以带长度前缀的 sidecar 协议通信。
- Jan 同时提供本地 Agent HTTP 服务，并主动为 Claude Code/OpenClaw 写入本地模型连接配置。
- AstrBot 以多个 IM 平台作为主要交互表面；它不是远程驾驶另一个桌面应用，但外部 endpoint、线程和主动投递具有完整生命周期。
- VCPToolBox 更像执行与能力供给层：外部 coding Agent、分布式 WebSocket 节点、SSH 主机、托管浏览器和人类工具 API 均由服务端编排；VCPChat 与 AIO Hub 是其节点侧反向样本，前者注册本机插件并执行远端分派，后者桥接远端插件工具。
- DeepSeek Harness 同时提供两种反向样本：把外部进程 Agent 当一次性执行体委派，也把自身 Agent 会话经 ACP 服务器暴露给外部客户端；MCP 客户端桥与 hooks 双桥负责外部协议兼容。
- Codex 把控制面与执行面拆成两套协议：app-server 供 IDE 与 SDK 驱动自身会话，exec-server 把进程、文件系统与 HTTP 委派给本地子进程或远端主机，remote control 再复用 app-server 经中继接受远程控制，是“同一运行时正反两用、执行位置独立”的样本。
- OpenOcta 是“单运行时多入站汇聚”样本：IM、OpenAPI、Hooks 三条外部入口都汇入 `chat.send`，共享同一 Agent 运行时与会话键；外部执行只有一次性 `local_agent` 子进程，A2A 只有 AgentCard 发现、ACP 为占位。

LobeHub 当前覆盖最宽：十三种本地执行体（本轮新增 Factory Droid、Devin，并含 `cursor-acp`、`droid-acp`、`claude-code-sdk` 等传输）、Bot 平台层、Connector/Composio、Messenger、内置浏览器桥与 Agent Share 访客面同时落在三种接入角色中。DeepChat 的强项是把桌面会话、IM、CLI、审批和 pending interaction 接到同一事实源。OpenCode 与 Hermes Agent 则提供了重要反向样本，说明“可被外部控制”本身也是一类成熟产品边界。

### DeepSeek Harness

三条主链均达 `主链确认`（静态证据）。`ctx.subagents` 注册表下四个进程外 provider（ACP 子进程、Claude Code SDK+CLI、codex app-server stdio、dsh-sdk 子进程）共用一次性 run 契约：结果永不 reject、整树静止 teardown，差异集中在协议、权限自动应答与取消路径。反向面上，ACP 服务器经 JSON-RPC stdio 把宿主 Agent 会话暴露给程序化客户端，无鉴权、authMethods 为空。协议兼容层包含 MCP 客户端桥（mcp__serverName__rawName 命名、两阶段代际注册、有界指数退避重连）与 Claude Code/Codex hooks 双桥（审批按 deny>ask>allow 最严格合并）。执行边界由 sandbox 策略、持久化 PTY 终端、code-runtime worker 与 E2B 远程沙箱 POC 共同承担。

Cherry Studio 的统一 Agent 会话服务接入 Claude Code、Pi 与 Pi-Durable，跨会话投递有独立持久化结果链；DeepSeek Harness 另由专门服务托管 Web 子进程，保持独立的会话与控制边界；VCPToolBox 的托管浏览器则会复用可用的 DevTools 端点，并由服务端统一编排远端节点、SSH 与人类工具审批。两者分别补充了“应用收容外部运行时”和“服务端供给外部执行体”的对照。

### OpenClaw

OpenClaw 的主链（静态证据）把“托管外部 harness”和“自身 runtime 被多表面控制”放在同一个 Gateway 平面：`sessions_spawn({runtime: "acp"})` 经 acpx 插件启动外部 harness，Gateway 保留会话元数据、审批/结果回流并按 cwd、命令、session 身份条件续接、oneshot 结束后回收进程租约；同一 Gateway 又向 CLI/TUI/Control UI、移动 companion 与原生 ACP client 暴露自身 session。Jan 侧主要提供自身运行时被外部控制的协议，这里则同时覆盖宿主与被控方向；与 DeepSeek Harness 的单向一次性委派也不同，其外部 harness 会话可按身份复用并跨渠道回投。

### RikkaHub

RikkaHub 的三条主链（静态证据）分别落在外部工具服务、外部执行体和外部控制表面三种角色，发现方式与执行位置彼此独立：

- MCP 客户端由宿主发起，传输只有 SSE 与 Streamable HTTP 两种，没有 stdio 或本地进程；连接在运行时注册表中串行建立，断线按最多 5 次、1 秒起指数增长并封顶 30 秒的退避重连，工具目录每次同步按服务器返回覆盖，同时保留用户设置的启用开关与审批需求。
- workspace 是宿主自己拉起的 PRoot 子进程，命令在用户态 Linux 沙箱内执行，文件区与技能、工具输出、上传目录经挂载表进入；写路径越出约定目录即强制审批、shell 工具默认需审批，但这是用户态重映射而非内核级隔离。
- 内嵌 Ktor 服务器与 App 同进程复用会话服务、Room 数据库与设置存储，浏览器凭访问口令换取的 JWT（主题固定、30 天）经 HTTP/SSE 驱动同一会话并提交工具审批。

OAuth 授权采用规范发现加 PKCE 与动态注册，回调绑在 IPv4 回环的固定端口上；与 DeepSeek Harness、OpenClaw 的进程外 Agent 委派不同，这里没有宿主与外部 Agent 之间的会话协议，外部身份粒度只有“每台服务器一份凭据”和“一次 JWT”两种。

## 1. 外部 Agent 作为执行者

LobeHub 的适配层最完整。注册表登记十三种本地执行体（本轮新增 Factory Droid、Devin），分别由 driver 组装命令和输入、或经 ACP/SDK 传输接入，再归一为 `AgentStreamEvent`；注册表另含 `claude-code-sdk`、`cursor-acp`、`droid-acp` 三种传输（Codex app server 由 Codex 会话内部选择），由 lab 开关门控；OpenClaw/Hermes 走 gateway task 与 notify 路径。宿主保存原生 session id、工作目录、工具事件、干预和取消状态，因此不是终端日志查看器。

Cherry Studio 是窄而深的外部执行体样本：`AgentSessionRuntimeService` 以 Claude Agent SDK 运行独立会话，SDK 自身持有 Bash/Read/Write 等执行，Cherry 负责工作区、消息后端、工具曝光、审批 hook 和 UI 投影；同时它又把宿主自身注册为 SDK 会话内的 MCP 工具面（assistant server），并拥有独立的 IM 渠道控制主链（见第 3 节）。另有一条受管 Code CLI 面：服务维护十余个第三方编程代理的预设，写配置、准备二进制并在本机终端拉起进程；该面托管配置与终端会话，进程由终端持有。DeepSeek Harness 的主入口则由专门服务启动本机 Web 子进程、校验就绪地址并挂载独立界面，另走专用 IPC，不属于统一 Agent runtime。执行域与状态映射应分别比较（[来源](<./Cherry-Studio-外部执行体与应用协作调查笔记.md>)）。

DeepChat 的 ACP 侧拥有 39 个条目的 Agent 注册表与安装生命周期（下载、sha256 校验、依赖安装），是"发现/安装外部对象"环节的直接证据；其工具目录明确由 ACP backend 自己承担，且 ACP 会话还可反向作为 DeepChat harness 的 LLM provider。Jan 主要作为被控执行体：HTTP 编排由 Jan 持有工具循环，RPC 客户端经握手创建会话，声明 host tools 后接收调用并回填结果；多会话共用一个活动回合，进程内恢复与项目线程持久化分开。它与宿主启动另一个外部 Agent 的方向不同（[来源](<./Jan-外部执行体与应用协作调查笔记.md>)）。

VCPToolBox 的 AICodeWorker 以 jobId 调度 opencode/Antigravity 两种 CLI，另有 SSH 主机、外部 WebSocket 节点（含 SnowBridge）和托管浏览器执行域；它应作为“后端编排外部执行资源”的样本，而非桌面 Agent 控制台。AIO Hub 构成该体系的反向样本：`vcpNodeProtocol` 让远端 Agent 经工具注册、执行、取消、审批与心跳帧驱动 AIO 本地执行，并把远端插件工具桥接进本地注册表。

VCPChat 是同一分布式协议中独立的正式节点样本：主进程在开关开启时连接 VCPToolBox、扫描并注册本机插件 manifest；宿主以 requestId 下发 `execute_tool`，节点在本机插件子进程或 Electron handler 执行后以 `tool_result` 回流。文件回取反向请求来源节点并缓存副本，证明其不仅显示远端工具文本。节点另有 Loom 直接执行面，可把多步页面动作保存为本机 LoomSkill，同步或异步执行，任务仅存进程内、不能跨重启继续查询。服务端超时和断线会清理 pending 状态，但本机进程是否一定被终止仍未运行确认。

DeepSeek Harness 是“一次性委派契约”的样本：`ctx.subagents` 下四个进程外 provider（ACP、Claude Code、Codex、dsh-sdk）都以一次性 run 启动外部 Agent，结果只回传最终文本、永不 reject，teardown 以整树静止为完成条件；差异集中在协议、权限自动应答与取消路径。与 LobeHub 的统一事件模型相比，它不回流 reasoning、工具事件或文件变化，是“窄结果”端点样本。

OpenClaw 的 ACPX 是“按身份可续接的进程托管”样本：外部 harness 保留自身工具循环与原生 session，OpenClaw 以 actor queue/租约管理并发、以 stateDir 保存上游 session record，只有 cwd、命令、session 身份与状态匹配才复用，oneshot turn 结束即关闭。与 DeepSeek Harness 的一次性窄结果委派相比，它回投 text/tool/done/approval 并可把渠道 thread/topic 直接绑定到 ACP session 回投；与 LobeHub 的 driver 适配相比，其进程回收与续接判断是同一个控制面协议的一部分。真实外部 harness 的启动、审批、取消与跨平台进程树终止尚未运行验证。

Codex 把执行位置从控制协议中拆出去：app-server 只负责外部驱动自身会话，exec-server 另立协议，把进程、文件系统与 HTTP 委派给本地子进程或远端主机。逻辑进程句柄独立于操作系统 PID，连接断开后环境进入恢复态并允许重连；进程输出带序号，文件按句柄分块读写，沙箱与托管网络要求以意图而非包装命令传给执行体。app-server 的方法面继续扩展：线程队列的增删、排序、启动与更新，线程目标的读取/设置/清除，线程采样与取消，预测请求，附件增删查，线程分叉、元数据与设置更新，以及 elicitation 计数器，其中多项标记为 experimental；协议也携带上下文窗口 ID，便于按窗口关联恢复。与 DeepSeek Harness 的一次性窄结果委派相比，它回流增量输出与退出状态，但不让执行体参与模型决策。

OpenOcta 的外部执行面只有一个 `local_agent` 工具：探测本机已安装的 CLI Agent，按单任务或并行多任务启动子进程，再把合并后的标准输出与错误文本交回模型。它没有外部会话 ID、流式事件、取消确认与审批，重启后也不恢复，因此停在 `入口确认`；与 Codex 的独立执行协议相比，这里只是宿主内的一次性命令封装。

## 2. 外部应用作为可操作对象

八个首批样本中，LobeHub 是业务应用连接的明确主样本。Connector 保存 OAuth2、bearer、API key 或 header 凭据，连接和工具目录是持久对象，逐工具权限为 `auto / needs_approval / disabled`，Composio 预置 24 种业务应用类型。普通 MCP 配置没有这套账号、作用域、刷新和动作治理，因此不纳入本分型。

VCPToolBox 的托管浏览器、DeepWiki MCP 客户端、邮箱和外部检索插件属于更松散的应用/运行环境连接。它们有协议和动作回流，但账号生命周期与统一权限模型弱于 LobeHub，横向比较时不能按 Connector 等价处理。

DeepSeek Harness 本轮未发现业务应用连接对象：MCP 客户端桥只持有 serverName 与 rawName 组成的工具目录，没有账号、凭据或资源状态，不按 Connector 等价处理。

OpenClaw 的“外部应用”对象是自有的 iOS/Android companion app，它们作为设备节点持有本地执行能力，而不是带账号、作用域与刷新语义的第三方业务连接；相机、录屏、语音等采集在设备侧执行，本次只静态确认入口与状态机，真实平台权限与采集回流为未验证。

Codex 的 MCP 应用连接器已有账号授权与应用工具目录，但它服务的是工具调用，没有独立 Agent runtime 或双向回合，因此只作相邻能力记录；OpenOcta 一侧，OpenAPI 的 API key 是调用方身份而非业务应用连接，MCP 也只把外部工具桥接给模型。两者都不按 Connector 等价处理。

## 3. 外部控制与交互表面

DeepChat 的 IM 远程控制是最清楚的“远程驾驶桌面会话”：endpoint 绑定现有 session，远端可发送 Agent 命令、回答 pending interaction、停止生成，并接收任务或 cron 结果。CLI 控制面再通过 localhost RPC、token scope、approval broker、工件暂存和审计落盘提供脚本化入口。

OpenCode 与 Hermes Agent 代表“自身 runtime 服务化”。OpenCode 以 HTTP + SSE 为唯一控制面，把会话创建、提示、中断、审批、回退、分叉、PTY 与事件订阅暴露成端点；接入方式改为后台服务守护加一次性配对码与二维码/链接，客户端凭配对码或密码换取 HMAC 签名的会话令牌，可选远程隧道把本地服务端暴露到公网，ACP 实现迁到 CLI 包并由宿主经标准输入输出驱动。多端共享同一服务端数据库与事件序列，客户端 store 只是投影，工作目录、模型与 Agent 配置仍由服务端持有。Hermes 常规桌面经 gateway ensure 附着规范 owner，稳定请求身份持久受理后进入 FIFO；关闭 viewer 不结束 owner。legacy stdio 桥是另一入口，恢复语义分别理解；ACP 与 REST 继续提供外部控制面。Cherry Studio 的八平台 IM 渠道把外部线程映射到 Agent Session，体现宿主接入执行体与外部控制宿主可并存（[Hermes 来源](<./Hermes-Agent-外部执行体与应用协作调查笔记.md>)、[Cherry 来源](<./Cherry-Studio-外部执行体与应用协作调查笔记.md>)）。

AstrBot 的 IM 平台是产品主入口，不是附加遥控器。平台 endpoint 经 UMO 映射到会话，18 个适配器承担鉴权、注册/登录绑定（含二维码与 app registration）、入站、命令注册、媒体转换和出站；群对象已从只有群 ID 扩展为按平台能力补齐名称、头像、所有者与成员列表，Lark 私聊在按 open ID 主动发送被拒后用同一去重 UUID 回退已知 chat ID，Telegram 论坛 topic 则以 `<chat_id>#<thread_id>` 形成会话边界。它适合比较“外部表面如何成为事实入口”，但不能与 DeepChat 的“控制既有桌面会话”混为一类。

DeepSeek Harness 的 ACP 服务器是“无鉴权反向控制面”的样本：外部客户端经 JSON-RPC stdio 建会话、发 prompt、收已提交文本、取消与一次性权限应答，会话 id 直接对应宿主 Agent session，连接关闭即逐会话 cancel 并释放全部 Agent，安全模型依赖本地 stdio 与可信调用方。

OpenClaw 是“多表面控制 + 反向 ACP + 外部 harness 宿主”并存的样本。CLI、TUI、浏览器 Control UI 与移动 companion 经 WebSocket 指向同一 Gateway，Gateway 持有会话与事件事实源，控制表面不拥有主 runtime；连接首帧即做认证、设备证明与角色/scope 准入，事件带序号、断线可恢复历史。原生 `openclaw acp` 是 stdio NDJSON 的 ACP server 面，外部 ACP client 可 new/load/resume、prompt、cancel，session 直接映射 Gateway-backed session，方向与 ACPX 启动外部 harness 相反。与 OpenCode/Hermes 的 runtime 服务化相比，OpenClaw 的控制面协议同时覆盖设备节点编排与外部 harness 托管，浏览器与移动端的真实运行仍为未验证。

Codex 的 app-server 是“编辑器优先”的控制面：外部 IDE 扩展与 Python SDK 经 JSON-RPC 建立线程、发起回合并接收条目通知，审批、用户输入、MCP elicitation 与动态工具调用再以服务端请求反向回到客户端；三种传输中只有 WebSocket 面额外校验 token 或 JWT。remote control 复用同一协议但方向相反，服务端主动连出中继，外部客户端凭配对码接入本机线程，并可逐个撤销。审批权仍留在本机，客户端只能回答允许、拒绝或中止。

OpenOcta 走的是相反路线：IM、OpenAPI 与 Hooks 三条外部入口都汇入同一个 `chat.send`，共享宿主 Agent 运行时，没有独立的外部 runtime。IM 渠道把渠道与 peer 映射成会话键，OpenAPI 用 API key 的路径白名单、模型白名单与月额度约束调用方并同步返回最终文本，Hooks 只回 202 与 run ID。三者的取消与恢复都停在宿主会话层；IM 与 Hooks 的调用方看不到工具事件与审批，OpenAPI 也不支持流式。

## 4. 状态、取消与恢复

| 模式 | 代表项目 | 关键状态语义 |
|---|---|---|
| 原生外部会话续接 | LobeHub、Cherry Studio、OpenClaw | 保存 runtime session id/SDK 会话与工作目录，下一轮 resume；OpenClaw 按 cwd、命令与 session 身份条件复用 ACPX harness，oneshot 结束即回收进程租约 |
| 宿主会话被多表面控制 | DeepChat、OpenCode、Hermes Agent、OpenClaw | 多客户端指向同一事实源；支持 stop/interrupt，OpenCode 以服务端数据库与事件序列为权威状态、经配对或令牌接入同一服务端，OpenClaw 的 CLI/TUI/浏览器/移动端经 WebSocket 指向 Gateway、按 seq 检测缺口并可恢复历史，并把 session 放置到受管 worker environment 后按 placement 状态机与 generation/owner epoch 结算 recovery/reclaim |
| endpoint 到会话映射 | DeepChat、AstrBot | IM endpoint/UMO 绑定本地 session 或 conversation，结果回原线程 |
| 请求级编排 + 进程内 RPC 会话 | Jan | HTTP 编排偏请求级；RPC resume 限当前进程，成功且非 ephemeral 才保存项目线程，host tools 派回客户端 |
| job/node/runtime 映射 | VCPToolBox、VCPChat、AIO Hub | VCPToolBox 的 jobId、节点、SSH 主机和浏览器 runtime；VCPChat/AIO Hub 的节点连接与 requestId 分别持有生命周期 |
| 一次性 run 委派 + 整树 teardown | DeepSeek Harness | 每次委派独立 run、无 resume；取消本地先结算、远端 cancel 尽力、SIGTERM->SIGKILL 整树静止 |
| 控制/执行双协议 + 逻辑进程 | Codex | app-server 以线程与回合映射外部会话，并以上下文窗口 ID 关联窗口恢复；exec-server 以环境 ID 与逻辑进程 ID 保存句柄，断线进入恢复态并可重连 |
| 入站会话键 + 一次性命令 | OpenOcta | IM peer、API key 加 conversation、hook runId 归并为 sessionKey；local_agent 只有一次子进程，无外部会话、流式与恢复 |

取消需要分别核对“控制面受理、传播至执行体、进程或设备停止”三个阶段。

| 路径 | 已确认交接 | 验证边界 |
|---|---|---|
| LobeHub、DeepChat、OpenCode、Hermes | 各自运行时接收任务中断；按适配器终止进程、网关任务或会话 | 外部执行体版本与真实进程树回收仍需运行验证 |
| VCPToolBox、AIO Hub、VCPMobile | 跨节点取消带请求身份；节点清理在途执行，另有断线或超时路径 | 服务端发送时机、网络丢帧与真机副作用撤销分开判断 |
| OpenClaw | 经过会话队列、上游适配器与进程清理，节点超时/中断生成取消或结构化失败 | 未运行真实外部 harness 或设备 |
| Jan、AstrBot | Jan 的请求级编排与 AstrBot 的会话停止各有控制边界 | 本轮未确认 Jan 进行中取消；平台连接关闭不等于 Agent 停止 |

DeepSeek Harness 的取消是三级路径：signal abort 先让结果以 aborted 结算并保留部分文本，再发起远端 cancel/interrupt，最终经 SIGTERM->SIGKILL 升级、以整树静止为完成条件。

Codex 的取消分两层：app-server 的回合中断结束当前回合，exec-server 另有进程信号与终止，连接断开后环境进入恢复态并保留逻辑进程句柄。remote control 的重连由连接状态机与令牌刷新驱动，认证主体变化会直接中断会话，而不是静默续到旧身份。

OpenOcta 的 `local_agent` 只把取消传到子进程上下文，既没有向外部 Agent 发送取消意图，也不确认其子任务已清理；IM、OpenAPI 与 Hooks 的取消同样止于宿主运行，平台侧没有撤回或断点续传。

## 5. 权限与治理

- LobeHub 的强项是 Connector 凭据加密、作用域和逐动作权限，以及异构 Agent 工具事件与 intervention 的统一投影。
- DeepChat 的 CLI 使用 token scope、mutation guard、approval broker 和审计落盘；IM 平台凭据保存在本地设置，endpoint 绑定需配对授权。
- Cherry Studio 通过禁用名单、使用权限回调与执行前钩子三类 SDK 机制管理工具曝光，另经 assistant server 把宿主能力（导航白名单、设置、创建 Agent）反向暴露给外部 runtime；SDK 持有真实执行，宿主无法完全替代 runtime 的权限边界。
- OpenCode 的 ACP permission 与 session owner 解决多客户端并发控制；本机文件和 shell 权限仍由 OpenCode runtime 承担，HTTP 面另有密码或配对令牌鉴权、会话令牌作用域与 CORS 三层，远程隧道需用户显式同意后才启用。
- AstrBot 的平台 token/webhook secret 与 UMO 路由是入口治理，注册/登录绑定流（二维码、app registration）承担身份绑定；Agent 工具审批和沙箱另归相邻类目。
- VCPToolBox 的分布式节点、SSH、浏览器和人类工具 API 各有独立鉴权或配置面，统一治理程度较低；工具审批是全局通用面（approveAll/approvalList/SilentReject）；默认关闭、外部服务依赖与未确认的浏览器私网限制需单列。AIO Hub 节点侧以暴露白名单、disabledToolIds、审批帧和文件速率限制承担治理。
- DeepSeek Harness 的子进程环境以擦除后的父环境为基：凭据形状的变量名与 DSH_* 前缀全部擦除，显式注入才能携带；外部 Agent 权限自治度较高——Claude Code 禁用提问工具、Codex 全自动应答，ACP provider 的 permission 配置是唯一可配置的自动审批策略；ACP 服务器本身无鉴权，hooks 审批按 deny>ask>allow 最严格合并。
- OpenClaw 的准入区分 client identity/role/scope、token/password、设备签名与节点配对代际；`attach.grant` 明确要求 operator.admin，并把 grant 绑定到 session key、短 TTL 与 loopback MCP 配置，revoke 撤销授权并清理临时目录。外部 harness 保留自身执行与审批边界（permissionMode 的 approve-all/approve-reads/deny-all 与 nonInteractivePermissions 的 deny/fail），Gateway 以进程租约（gateway 实例、session key、wrapper、PID、command hash）限制回收范围；普通 MCP server 不因存在协议就算外部执行体，ACPX 的 MCP bridge 需显式 opt-in。凭据加密与 OAuth 刷新等部署级保证未深入验证。
- Codex 的 app-server 把审批策略、沙箱与权限保留在本地，客户端只回答允许、拒绝或中止；动态工具是受信任扩展面，宿主不重新验证其行为。exec-server 以 token 或 Noise 密钥证明执行体身份，每个进程请求显式携带沙箱与托管网络要求，缺少必要参数时失败关闭，执行体自报可用的技能与插件根。remote control 另有启动策略、enrollment 令牌刷新与客户端撤销三层。
- OpenOcta 的三个入站入口各校验自己的凭据：API key 保存哈希并绑定路径白名单、模型白名单、月额度与数字员工，Hooks 可整体禁用并校验 token，IM 依赖平台凭据。本地 CLI Agent 有允许列表但审批开关未接线；网关的 HTTP 令牌校验被编译期常量短路，WebSocket 仍校验，两者准入并不一致。

## 候选与对照

- **Dify**：service API、MCP/插件工具和 webhook/schedule/plugin trigger 分别确认了外部调用、平台调用外部能力和外部事件入口；但尚未确认持续外部身份、双向最终结果回流与接管治理的完整链。因此按本类目准入规则只记为 `入口确认`，不计入十六个正式样本。详见 [Dify 调查笔记](Dify-外部执行体与应用协作调查笔记.md)。

- **Pi**：`--mode rpc` 已接线（stdio JSONL 双向协议 + 客户端库 + 官方 rpc 文档），建议从 `候选观察` 升为 `入口确认`；网络形态 `pi server/client` 仍未接通，且 Slack lane 在独立仓库，身份与网络治理缺项使其仍未达 `主链确认`。Pi 同时是 LobeHub 六种被托管 CLI 之一，两者语境不同，需分开计。
- **Open WebUI**：多 Connector/工具与 Channels 很丰富，但本轮补查确认 channel webhook 为单向发布（不触发模型响应）、OAuth 为身份层、外部知识库连接为单向检索，远程 pipeline 也只在存在候选过滤器时才发起 HTTP 调用、无过滤器时直接短路返回原 payload，仍未达门槛，维持 `候选观察`。
- **Chatbox**：`app_action` 实为宿主内应用动作审批，OAuth 为模型 Provider 渠道，chatbox-cli 是模型专用虚拟 CLI；无外部身份和状态映射，维持 `候选观察`。
- **VCPChat**：分布式节点已确认连接、注册、本机执行与结果回流，且具跨节点文件回取和人类工具入口，现作为 `主链确认` 正式样本进入一览矩阵；不把聊天工具卡或 DESKTOP_PUSH 旁路计为该主链。
- **AIO Hub**：vcp-connector 分布式节点主链五项门槛全满足，2026-08-13 已补建[单项目笔记](AIO-Hub-外部执行体与应用协作调查笔记.md)并进入一览矩阵；与 VCPToolBox 构成宿主编排/节点被驱动的双向对照。
- **DeepSeek Harness**：2026-08-16 已补建[单项目笔记](DeepSeek-Harness-外部执行体与应用协作调查笔记.md)并进入一览矩阵；三条主链（外部执行体委派、ACP 服务器反向控制、MCP/hooks 协议兼容）均达 `主链确认`（静态证据）。
- Manifold Desktop、NextChat、SillyTavern 本轮未发现达到门槛且比现有类目更适合放入本分类的主链（Manifold server 为模型代理、MCP 调用未接线；NextChat 无 webhook/IM/bot 端点；SillyTavern 当前快照无 MCP 且 extensions 端点为扩展管理），标注 `不纳入`；这不是项目级绝对不存在结论。

## 已确认边界与未验证事项

- 全部结论以静态源码为主；真实 CLI 版本兼容、OAuth、IM 平台回调、网络断线和跨设备接管尚未统一运行验证。
- LobeHub Messenger 已确认安装、binder、webhook/gateway 和 outbound 入口，逐平台完整线程往返仍为 `入口确认`；Bot 平台层的二维码登录与队列回调未运行验证。
- Hermes Agent 的桌面/TUI/Web/REST/ACP 共享 gateway 主链已确认，Telegram 等平台网关未逐适配器走通。
- OpenCode 的配对链接、会话令牌与远程隧道在真实网络下的完整流程未运行验证；多端并发、ACP 与真实宿主的权限往返同样未实测。
- VCPToolBox 的多个接入点属于插件级能力，不能推断存在统一账号目录或一致权限策略；浏览器私网/云元数据防护未在源码中找到，未作为已确认边界。
- VCPChat 的节点链为静态主链确认；未连接真实 VCPToolBox，未验证节点 key 握手、多节点竞争、跨节点文件来源识别或取消帧能否杀灭本机子进程。
- VCPMobile 的分布式节点链为静态主链确认；未连接真实分布式服务，未验证服务端发送 `cancel_tool` 的时机与效果、断线重连幂等和 Android 权限降级行为；iOS 侧的系统分享扩展与分享收件箱（`share_inbox.rs`）未在真机验证。
- AIO Hub 节点协议为静态主链确认，未连接真实 VCPToolBox 服务端做节点往返。
- DeepSeek Harness 三条主链均为静态走通，未运行真实 Claude Code/Codex/外部 ACP 子进程；ACP 服务器无鉴权、无并发限制；MCP 重连与 E2B 远程沙箱（POC）未运行验证。
- OpenClaw 的 ACPX、原生 ACP、节点与 attach 主链均为静态源码确认；真实 Gateway 网络与多客户端争用、浏览器/移动端操作、渠道往返、外部 harness 进程树终止、OAuth 与 APNS 唤醒均未运行验证；节点侧 Rust node host 与 sidecar 握手同样未在设备上运行。
- Codex 的三条主链均为静态源码确认：未启动 app-server 或 exec-server，未连接 remote control 中继，未运行 Python SDK，因此传输握手、配对时序、进程恢复与多客户端争用未验证；`codex exec` 只是本地无头运行入口，复用宿主 runtime，不计入外部协作主链。
- OpenOcta 的 IM、OpenAPI、Hooks 三条入站主链与 local_agent、MCP 入口均为静态确认；未连接真实 IM 平台、未调用真实 OpenAPI 与外部 CLI Agent、未连接 MCP 服务器，A2A 仅发现卡片、ACP 为占位，真实重连、媒体消息与取消后的进程清理未验证。
- 本类目采用稀疏笔记；没有单项目笔记表示本轮未达到准入门槛或尚未调查，不等于不支持。
