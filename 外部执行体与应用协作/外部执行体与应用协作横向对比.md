# 十一个项目外部执行体与应用协作横向对比

> 对比对象：LobeHub、DeepChat、Cherry Studio、OpenCode、Jan、AstrBot、Hermes Agent、VCPToolBox、VCPChat、AIO Hub、DeepSeek Harness
>
> 对比更新日期：2026-08-31
>
> 依据：同目录十一份单项目调查笔记（VCPChat 为 2026-08-31 新增）、各项目现有独特功能/Agent 工具/Chat/对话请求调查笔记（链接见文末依据索引），以及当前代码快照的关键入口复核
>
> 对比方法：按“外部执行体、外部应用、外部控制与交互表面”三种接入角色，比较身份、协议方向、状态映射、执行位置、结果回流、取消恢复和治理边界
>
> 对比范围：具有持续身份与双向生命周期的外部 Agent、业务连接和控制表面；排除普通 Provider、任意 MCP、一次性导入、单向通知和宿主内建子 Agent
>
> 文档定位：实现学习与跨项目横向比较，不作为功能数量排名、兼容性承诺或安全审计报告

## 结论摘要

当前 16 个主要调查项目（清单见根目录 [`AI客户端项目评分.md`](../AI客户端项目评分.md)）中，至少 11 个已经出现可比较的外部协作主链，数量和实现差异都足以建立正式类目。它不是“独特功能”中的单点能力：这些项目反复面对外部身份、协议方向、会话映射、取消、重连和权限所有权等共同问题。

最关键的差异是**谁控制谁**：

- LobeHub、Cherry Studio 主要把外部 Agent runtime 当执行者（LobeHub 另有完整 Bot 平台层）；DeepChat 同时接入 38 个可安装的 ACP runtime，并允许 IM/CLI 控制自己的本地任务。
- OpenCode、Hermes Agent 主要把自身 Agent runtime 暴露给多个客户端或协议宿主（Hermes 另有 ACP adapter 与 REST API 被宿主控制）。
- Jan 同时提供本地 Agent HTTP 服务，并主动为 Claude Code/OpenClaw 写入本地模型连接配置。
- AstrBot 以多个 IM 平台作为主要交互表面；它不是远程驾驶另一个桌面应用，但外部 endpoint、线程和主动投递具有完整生命周期。
- VCPToolBox 更像执行与能力供给层：外部 coding Agent、分布式 WebSocket 节点、SSH 主机、托管浏览器和人类工具 API 均由服务端编排；VCPChat 与 AIO Hub 是其节点侧反向样本，前者注册本机插件并执行远端分派，后者桥接远端插件工具。
- DeepSeek Harness 同时提供两种反向样本：把外部进程 Agent 当一次性执行体委派，也把自身 Agent 会话经 ACP 服务器暴露给外部客户端；MCP 客户端桥与 hooks 双桥负责外部协议兼容。

LobeHub 当前覆盖最宽：六种本地 CLI（加两种额外传输）、Bot 平台层、Connector/Composio、Messenger 和内置浏览器桥同时落在三种接入角色中。DeepChat 的强项是把桌面会话、IM、CLI、审批和 pending interaction 接到同一事实源。OpenCode 与 Hermes Agent 则提供了重要反向样本，说明“可被外部控制”本身也是一类成熟产品边界。

### DeepSeek Harness

三条主链均达 `主链确认`（静态证据）。`ctx.subagents` 注册表下四个进程外 provider（ACP 子进程、Claude Code SDK+CLI、codex app-server stdio、dsh-sdk 子进程）共用一次性 run 契约：结果永不 reject、整树静止 teardown，差异集中在协议、权限自动应答与取消路径。反向面上，ACP 服务器经 JSON-RPC stdio 把宿主 Agent 会话暴露给程序化客户端，无鉴权、authMethods 为空。协议兼容层包含 MCP 客户端桥（mcp__serverName__rawName 命名、两阶段代际注册、有界指数退避重连）与 Claude Code/Codex hooks 双桥（审批按 deny>ask>allow 最严格合并）。执行边界由 sandbox 策略、持久化 PTY 终端、code-runtime worker 与 E2B 远程沙箱 POC 共同承担。

Cherry Studio 也已将 Claude Code、Pi 与 DeepSeek Harness 以各自协议桥接入统一会话服务，并将跨会话投递持久化为可恢复的结果链；VCPToolBox 的托管浏览器则会复用可用的 DevTools 端点，并由服务端统一编排远端节点、SSH 与人类工具审批。两者分别补充了“应用收容外部运行时”和“服务端供给外部执行体”的对照。

## 1. 外部 Agent 作为执行者

LobeHub 的适配层最完整。Amp、Claude Code、Codex、OpenCode、Pi、Qoder 分别由 driver 组装命令和输入，再经 provider-specific adapter 归一为 `AgentStreamEvent`；注册表另含 SDK 进程内与 Codex app server 两种额外传输（后者走 stdio JSON-RPC），由 lab 开关门控；OpenClaw/Hermes 走 gateway task 与 notify 路径。宿主保存原生 session id、工作目录、工具事件、干预和取消状态，因此不是终端日志查看器。

Cherry Studio 是窄而深的外部执行体样本：`AgentSessionRuntimeService` 以 Claude Agent SDK 运行独立会话，SDK 自身持有 Bash/Read/Write 等执行，Cherry 负责工作区、消息后端、工具曝光、审批 hook 和 UI 投影；同时它又把宿主自身注册为 SDK 会话内的 MCP 工具面（assistant server），并拥有独立的 IM 渠道控制主链（见第 3 节）。这证明类目不以“支持多少 CLI”作为准入条件。

DeepChat 的 ACP 侧拥有 38 个条目的 Agent 注册表与安装生命周期（下载、sha256 校验、依赖安装），是"发现/安装外部对象"环节的直接证据；其工具目录明确由 ACP backend 自己承担，且 ACP 会话还可反向作为 DeepChat harness 的 LLM provider。Jan 的方向不同：`jan launch` 主要把 Claude Code/OpenClaw 等 CLI 接到 Jan 的本地模型服务，`converters.rs` 提供 OpenAI/Anthropic/Gemini 多线协议双向转换；外部 Agent 仍持有工具循环，Jan 提供模型、协议与配置桥。

VCPToolBox 的 AICodeWorker 以 jobId 调度 opencode/Antigravity 两种 CLI，另有 SSH 主机、外部 WebSocket 节点（含 SnowBridge）和托管浏览器执行域；它应作为“后端编排外部执行资源”的样本，而非桌面 Agent 控制台。AIO Hub 构成该体系的反向样本：`vcpNodeProtocol` 让远端 Agent 经工具注册、执行、取消、审批与心跳帧驱动 AIO 本地执行，并把远端插件工具桥接进本地注册表。

VCPChat 是同一分布式协议中独立的正式节点样本：主进程在开关开启时连接 VCPToolBox、扫描并注册本机插件 manifest；宿主以 requestId 下发 `execute_tool`，节点在本机插件子进程或 Electron handler 执行后以 `tool_result` 回流。文件回取反向请求来源节点并缓存副本，证明其不仅显示远端工具文本。服务端超时和断线会清理 pending 状态，但本机进程是否一定被终止仍未运行确认。

DeepSeek Harness 是“一次性委派契约”的样本：`ctx.subagents` 下四个进程外 provider（ACP、Claude Code、Codex、dsh-sdk）都以一次性 run 启动外部 Agent，结果只回传最终文本、永不 reject，teardown 以整树静止为完成条件；差异集中在协议、权限自动应答与取消路径。与 LobeHub 的统一事件模型相比，它不回流 reasoning、工具事件或文件变化，是“窄结果”端点样本。

## 2. 外部应用作为可操作对象

八个首批样本中，LobeHub 是业务应用连接的明确主样本。Connector 保存 OAuth2、bearer、API key 或 header 凭据，连接和工具目录是持久对象，逐工具权限为 `auto / needs_approval / disabled`，Composio 预置 24 种业务应用类型。普通 MCP 配置没有这套账号、作用域、刷新和动作治理，因此不纳入本分型。

VCPToolBox 的托管浏览器、DeepWiki MCP 客户端、邮箱和外部检索插件属于更松散的应用/运行环境连接。它们有协议和动作回流，但账号生命周期与统一权限模型弱于 LobeHub，横向比较时不能按 Connector 等价处理。

DeepSeek Harness 本轮未发现业务应用连接对象：MCP 客户端桥只持有 serverName 与 rawName 组成的工具目录，没有账号、凭据或资源状态，不按 Connector 等价处理。

## 3. 外部控制与交互表面

DeepChat 的 IM 远程控制是最清楚的“远程驾驶桌面会话”：endpoint 绑定现有 session，远端可发送 Agent 命令、回答 pending interaction、停止生成，并接收任务或 cron 结果。CLI 控制面再通过 localhost RPC、token scope、approval broker、工件暂存和审计落盘提供脚本化入口。

OpenCode 与 Hermes Agent 代表“自身 runtime 服务化”。OpenCode 的 HTTP/SSE、ACP、TUI、Web 和 Desktop 共享服务端 session 与事件源，并提供 replay 与 owner steal；HTTP 面另有 PTY 终端 attach、TUI 远程控制（appendPrompt/controlNext）与 permission/question 审批回复通道。Hermes 的桌面、TUI 和 Web 通过 JSON-RPC over WebSocket/stdio 控制同一 Python gateway，持久化身份由 profile 与 session lineage 维护，新客户端经 DM pairing 配对码授权；它还把 `acp_adapter` 暴露给 VS Code/Zed/JetBrains 等宿主，并通过 REST API（运行与会话管理接口、cron jobs）提供外部控制。Cherry Studio 的 IM 渠道层（六平台、OpenClaw 家族协议）证明“宿主控制外部 runtime”与“外部线程控制宿主”可以并存在同一产品。

AstrBot 的 IM 平台是产品主入口，不是附加遥控器。平台 endpoint 经 UMO 映射到会话，18 个适配器承担鉴权、注册/登录绑定（含二维码与 app registration）、入站、命令注册、媒体转换和出站。它适合比较“外部表面如何成为事实入口”，但不能与 DeepChat 的“控制既有桌面会话”混为一类。

DeepSeek Harness 的 ACP 服务器是“无鉴权反向控制面”的样本：外部客户端经 JSON-RPC stdio 建会话、发 prompt、收已提交文本、取消与一次性权限应答，会话 id 直接对应宿主 Agent session，连接关闭即逐会话 cancel 并释放全部 Agent，安全模型依赖本地 stdio 与可信调用方。

## 4. 状态、取消与恢复

| 模式 | 代表项目 | 关键状态语义 |
|---|---|---|
| 原生外部会话续接 | LobeHub、Cherry Studio | 保存 runtime session id/SDK 会话与工作目录，下一轮 resume |
| 宿主会话被多表面控制 | DeepChat、OpenCode、Hermes Agent | 多客户端指向同一事实源；支持 stop/interrupt，OpenCode 另有 replay/steal 与 PTY/TUI 控制面 |
| endpoint 到会话映射 | DeepChat、AstrBot | IM endpoint/UMO 绑定本地 session 或 conversation，结果回原线程 |
| 一次任务 + 外部配置持久化 | Jan | orchestration 本身偏请求级；CLI 与桌面共享数据目录，外部 Agent 配置持续存在 |
| job/node/runtime 映射 | VCPToolBox、VCPChat、AIO Hub | VCPToolBox 的 jobId、节点、SSH 主机和浏览器 runtime；VCPChat/AIO Hub 的节点连接与 requestId 分别持有生命周期 |
| 一次性 run 委派 + 整树 teardown | DeepSeek Harness | 每次委派独立 run、无 resume；取消本地先结算、远端 cancel 尽力、SIGTERM->SIGKILL 整树静止 |

取消是否到达真实执行体是本类目的核心检查项。LobeHub 会终止进程树或 gateway task；DeepChat 的 stop/approval 进入本地主进程任务；OpenCode ACP 暴露 cancel；Hermes 提供 `session.interrupt`；VCPToolBox 的跨节点路径传播 `cancel_tool`，AIO Hub 的节点侧以“断线即清理在途调用 + 超时兜底”保持一致。Jan orchestration 不支持 stream，其进行中取消语义本次未确认；AstrBot 的停止按 UMO/request agent stop 处理，具体平台连接关闭不是同一概念。

DeepSeek Harness 的取消是三级路径：signal abort 先让结果以 aborted 结算并保留部分文本，再发起远端 cancel/interrupt，最终经 SIGTERM->SIGKILL 升级、以整树静止为完成条件。

## 5. 权限与治理

- LobeHub 的强项是 Connector 凭据加密、作用域和逐动作权限，以及异构 Agent 工具事件与 intervention 的统一投影。
- DeepChat 的 CLI 使用 token scope、mutation guard、approval broker 和审计落盘；IM 平台凭据保存在本地设置，endpoint 绑定需配对授权。
- Cherry Studio 通过禁用名单、使用权限回调与执行前钩子三类 SDK 机制管理工具曝光，另经 assistant server 把宿主能力（导航白名单、设置、创建 Agent）反向暴露给外部 runtime；SDK 持有真实执行，宿主无法完全替代 runtime 的权限边界。
- OpenCode 的 ACP permission 与 session owner/replay 解决多客户端并发控制；本机文件和 shell 权限仍由 OpenCode runtime 承担，HTTP 面另有 authorization 中间件、PTY ticket 与 CORS 三层。
- AstrBot 的平台 token/webhook secret 与 UMO 路由是入口治理，注册/登录绑定流（二维码、app registration）承担身份绑定；Agent 工具审批和沙箱另归相邻类目。
- VCPToolBox 的分布式节点、SSH、浏览器和人类工具 API 各有独立鉴权或配置面，统一治理程度较低；工具审批是全局通用面（approveAll/approvalList/SilentReject）；默认关闭、外部服务依赖与未确认的浏览器私网限制需单列。AIO Hub 节点侧以暴露白名单、disabledToolIds、审批帧和文件速率限制承担治理。
- DeepSeek Harness 的子进程环境以擦除后的父环境为基：凭据形状的变量名与 DSH_* 前缀全部擦除，显式注入才能携带；外部 Agent 权限自治度较高——Claude Code 禁用提问工具、Codex 全自动应答，ACP provider 的 permission 配置是唯一可配置的自动审批策略；ACP 服务器本身无鉴权，hooks 审批按 deny>ask>allow 最严格合并。

## 候选与对照

- **Dify**：service API、MCP/插件工具和 webhook/schedule/plugin trigger 分别确认了外部调用、平台调用外部能力和外部事件入口；但尚未确认持续外部身份、双向最终结果回流与接管治理的完整链。因此按本类目准入规则只记为 `入口确认`，不计入十一个正式样本。详见 [Dify 调查笔记](Dify-外部执行体与应用协作调查笔记.md)。

- **Pi**：`--mode rpc` 已接线（stdio JSONL 双向协议 + 客户端库 + 官方 rpc 文档），建议从 `候选观察` 升为 `入口确认`；网络形态 `pi server/client` 仍未接通，且 Slack lane 在独立仓库，身份与网络治理缺项使其仍未达 `主链确认`。Pi 同时是 LobeHub 六种被托管 CLI 之一，两者语境不同，需分开计。
- **Open WebUI**：多 Connector/工具与 Channels 很丰富，但本轮补查确认 channel webhook 为单向发布（不触发模型响应）、OAuth 为身份层、外部知识库连接为单向检索，仍未达门槛，维持 `候选观察`。
- **Chatbox**：`app_action` 实为宿主内应用动作审批，OAuth 为模型 Provider 渠道，chatbox-cli 是模型专用虚拟 CLI；无外部身份和状态映射，维持 `候选观察`。
- **VCPChat**：分布式节点已确认连接、注册、本机执行与结果回流，且具跨节点文件回取和人类工具入口，现作为 `主链确认` 正式样本进入一览矩阵；不把聊天工具卡或 DESKTOP_PUSH 旁路计为该主链。
- **AIO Hub**：vcp-connector 分布式节点主链五项门槛全满足，2026-08-13 已补建[单项目笔记](AIO-Hub-外部执行体与应用协作调查笔记.md)并进入一览矩阵；与 VCPToolBox 构成宿主编排/节点被驱动的双向对照。
- **DeepSeek Harness**：2026-08-16 已补建[单项目笔记](DeepSeek-Harness-外部执行体与应用协作调查笔记.md)并进入一览矩阵；三条主链（外部执行体委派、ACP 服务器反向控制、MCP/hooks 协议兼容）均达 `主链确认`（静态证据）。
- Manifold Desktop、NextChat、SillyTavern 本轮未发现达到门槛且比现有类目更适合放入本分类的主链（Manifold server 为模型代理、MCP 调用未接线；NextChat 无 webhook/IM/bot 端点；SillyTavern 当前快照无 MCP 且 extensions 端点为扩展管理），标注 `不纳入`；这不是项目级绝对不存在结论。

## 已确认边界与未验证事项

- 全部结论以静态源码为主；真实 CLI 版本兼容、OAuth、IM 平台回调、网络断线和跨设备接管尚未统一运行验证。
- LobeHub Messenger 已确认安装、binder、webhook/gateway 和 outbound 入口，逐平台完整线程往返仍为 `入口确认`；Bot 平台层的二维码登录与队列回调未运行验证。
- Hermes Agent 的桌面/TUI/Web/REST/ACP 共享 gateway 主链已确认，Telegram 等平台网关未逐适配器走通。
- OpenCode 的 control-plane 远端 workspace 路由与 PTY/TUI 控制面为 `入口确认`，未运行多设备 replay/steal。
- VCPToolBox 的多个接入点属于插件级能力，不能推断存在统一账号目录或一致权限策略；浏览器私网/云元数据防护未在源码中找到，未作为已确认边界。
- VCPChat 的节点链为静态主链确认；未连接真实 VCPToolBox，未验证节点 key 握手、多节点竞争、跨节点文件来源识别或取消帧能否杀灭本机子进程。
- AIO Hub 节点协议为静态主链确认，未连接真实 VCPToolBox 服务端做节点往返。
- DeepSeek Harness 三条主链均为静态走通，未运行真实 Claude Code/Codex/外部 ACP 子进程；ACP 服务器无鉴权、无并发限制；MCP 重连与 E2B 远程沙箱（POC）未运行验证。
- 本类目采用稀疏笔记；没有单项目笔记表示本轮未达到准入门槛或尚未调查，不等于不支持。
