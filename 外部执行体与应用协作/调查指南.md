# 外部执行体与应用协作调查指南

本指南用于调查 AI 产品如何与拥有独立身份、生命周期或执行权的外部 Agent、业务应用和交互表面建立持续协作关系。通用写作、元数据与证据要求见 [`../AGENTS.md`](../AGENTS.md)。

## 类目定义

本类目研究以下三种接入角色：

| 接入角色 | 核心对象 | 典型目标 |
|---|---|---|
| 外部执行体 | CLI Agent、Agent SDK runtime、远端任务、独立进程或协议服务 | 发现、启动、继续、取消和观察另一个 Agent 完成工作 |
| 外部应用 | 持久账号、installation、Connector、业务资源与动作目录 | 让 Agent 在邮件、日历、协作、代码托管等系统中读取或执行动作 |
| 外部控制与交互表面 | IM 线程、CLI、浏览器、设备或其他客户端 | 从宿主之外发起、回答、接管、停止或观察同一任务 |

完整主链通常为：

```text
发现或安装外部对象
  -> 身份绑定与鉴权
  -> 能力发现、会话或任务映射
  -> 发起任务、动作或控制命令
  -> 外部执行、事件或用户输入回流
  -> 本地消息、任务、文件或资源状态更新
  -> 审批、取消、重连、恢复与断开
```

## 准入门槛

候选至少满足下列五项中的四项，才进入本类目：

1. **可识别身份**：外部 Agent、账号、installation、endpoint、设备或客户端不是匿名 URL。
2. **持续生命周期**：存在发现、安装、鉴权、运行、刷新、恢复、断开或取消中的多个阶段。
3. **双向协议**：可发任务或动作，也可回传结构化事件、结果、状态或用户输入。
4. **状态映射**：外部会话、任务、线程或资源与本地 session/topic/task/workspace 有明确对应。
5. **治理边界**：可以说明执行位置、凭据、权限、审批、取消、并发或审计责任。

外部执行体还应拥有自己的 runtime、工具循环或原生任务状态。外部应用还应具有持久连接和动作级权限。外部控制表面必须允许发起、接管、回答、操作或停止，只有通知和分享不计入。

## 不纳入范围

- 普通 OpenAI、Anthropic、Ollama 等模型 Provider；
- 只配置一个 MCP server 并完成 `tools/list -> tools/call`，没有账号、资源或连接生命周期；
- Notion ZIP、聊天记录等一次性导入；
- 单向通知、分享链接、DeepLink 启动或普通 webhook 推送；
- 复用宿主自身 runtime 的内建子 Agent；
- 仅因存在 HTTP API、SDK 或插件接口，就推断形成外部协作主链。

## 稀疏调查原则

本类目不要求所有项目都有笔记，也不为不适用项目批量填空。仅在发现实际接入主链或具有比较价值的反向协议样本时建立单项目笔记。横向文档必须区分：

- `主链确认`：触发、状态、执行、回流与主要治理路径已由源码静态走通；
- `入口确认`：存在协议、模块、设置或持久化入口，完整往返尚未确认；
- `候选观察`：存在 SDK/API 或文档线索，但尚不满足准入门槛；
- `不纳入`：检查后属于 Provider、普通工具、导入、分享或宿主内建能力。

## 必查问题

1. 外部对象是谁，在关系中是执行者、被操作对象还是控制表面？
2. 谁发起连接，身份如何绑定到用户、Agent、Workspace、设备或线程？
3. 使用 CLI、SDK、ACP、MCP、OAuth、webhook、WebSocket、HTTP RPC 还是私有协议？协议方向是什么？
4. 谁持有工具循环、进程、原生会话、任务队列和最终状态？
5. 外部状态如何映射到本地 session/topic/task/message/workspace，重启后如何恢复？
6. 能否回传文本、reasoning、工具、文件变化、子 Agent、审批和结构化提问？
7. 取消是否到达真实执行体？断线后采用重连、重放、轮询、接管还是直接失败？
8. 凭据如何保存、刷新和分作用域？调用代表个人、Agent、团队还是服务账号？
9. 动作采用自动放行、逐次审批、禁用还是策略授权？审计落在哪里？
10. 产品表面是否显示执行位置、账号、工作目录、连接状态和接管入口？
11. 外部内容是否按不可信输入处理，能否触发文件、命令、浏览器或业务账号副作用？
12. 与 Agent 工具、多表面连续性、Agent 角色和 LLM 渠道的交接点在哪里？

## 调查方法

- 先确认外部身份和状态权威，再看按钮、设置页或协议名称。
- 至少走通一次“连接/发现 -> 发起 -> 执行 -> 回流 -> 取消或恢复”。
- 将“宿主控制外部 Agent”“外部客户端控制宿主 Agent”“Agent 操作业务应用”分开记录。
- README、官网和 changelog 只生成候选；项目事实以当前代码快照的可执行路径为准。
- 静态代码可以确认入口、状态机和调用链；真实 OAuth、IM 平台、CLI 兼容、进程终止和网络重连需要运行验证。
