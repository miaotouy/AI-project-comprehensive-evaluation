# 会话与消息管理横向对比

> 对比对象：AIO Hub、AstrBot、Chatbox、Cherry Studio、DeepChat、DeepSeek Harness、Dify、Hermes Agent、Jan、LobeHub、Manifold Desktop、NextChat、Open WebUI、OpenCode、Pi、SillyTavern、Risuai、VCPChat、VCPMobile、VCPToolBox
>
> 对比更新日期：2026-08-31
>
> 依据：本类目 20 篇单项目调查笔记（含 VCPMobile 2026-08-31 专项调查；从 `../Chat/Chat横向对比.md` 迁移；Dify、Risuai 依据同目录专项笔记）
>
> 对比方法：按会话单位、消息事实源、存储模型、分支模型、索引与搜索粒度、异常恢复等共同维度逐项对照；未被单项目笔记共同覆盖的项单独标注范围
>
> 对比范围：会话单位与存储模型、分支语义、索引与搜索（数据侧）、数据层技术债；发送执行与流式在对话请求与上下文横向对比，界面工作流在 Chat UI 横向对比
>
> 文档定位：实现学习与跨项目横向比较，不作为整改方案

## 结论摘要

- **"会话主体"是各项目对会话主链的命名，同一术语在不同项目里可能指不同层级**：Session 在多数项目是顶层会话，唯独在 AstrBot 是账号级容器；Topic 在 Cherry Studio 是顶层、在 VCPChat 是二级单位；Thread 在 Jan 是顶层、在 Chatbox 是 Session 内历史区间、在 LobeHub 是消息级话题线。
- **存储实现分三组**：Cherry Studio、DeepChat、Hermes Agent、Open WebUI、AstrBot 使用数据库行或事务；Chatbox、NextChat 使用 IndexedDB；AIO Hub、Jan 桌面端、SillyTavern、VCPChat 仍有整文件/整对象写入路径。介质本身不保证一致性。
- **"分支"不是一回事**：至少包括消息树切换（Cherry Studio）、树+兄弟记忆（AIO Hub）、多套独立结构叠加（Chatbox）、多模型兄弟组（LobeHub/Cherry 多模型）、独立文件/候选数组（SillyTavern）、父子树+兄弟版本（Jan）、有序 transcript 上的 fork（DeepChat）、会话复制与 lineage（Hermes/NextChat）、服务端回溯重建（Open WebUI）、指针分支（Pi）、删除式回退+复制式 fork（OpenCode）。
- **搜索的索引、命中粒度和跳转是三件事**：Chatbox 与 DeepChat 已确认能从数据层命中并定位具体消息；VCPMobile 的消息终结事务维护本地 FTS，但跨 Topic 查询与 UI 命中跳转尚未确认；LobeHub、Hermes Agent 有数据库或搜索文档基础但定位链路证据不齐；Jan、Open WebUI、AIO Hub、Manifold Desktop 主要返回会话级结果。因此不能由现有材料绝对排除有项目满足"持久化消息索引 + 跨分支/跨会话命中 + 直接定位具体消息"三个条件，VCPMobile 尚有两项未确认。
- **DeepSeek Harness 的会话是 append-only SessionEvent 日志，没有独立消息表**：内存 Session 是交互历史的唯一事实源，消息历史由 deriveMessages() 从表面（surface）折叠派生，仅 user/message、assistant/message、tool/result 三类 SurfaceEventType 进模型历史；事件类型经 SessionEventMap 声明合并扩展，核心加插件共 24 个事件族；持久化是同一抽象契约下的 JSONL（默认 zstd 帧压缩）与 SQLite 双后端互换；SESSION_FORMAT_VERSION=0 无兼容承诺，版本不符直接拒绝而非迁移；fork、resume、transcript 都从日志流派生。
- **Risuai 的会话内嵌于角色对象、落盘是整库单文件**：无独立会话集合，`chatPage` 下标即当前会话指针；内存 `DBState.db` 是唯一事实源，块级增量编码 + 500ms 防抖整库覆写，每次保存另写备份（保留 20 份）。分支是复制整份会话并截断 + `branchedfrom` 注释回链（父会话无记录），分支导航由消息内容哈希前缀树实时计算；Reroll 是纯内存候选、不落盘。消息内容搜索本次未找到。
- **VCPMobile 的 Topic 与消息以 SQLite 为事实源**：Topic 归属于 Agent 或 Group，消息按时间戳与 ID 线性排序；终结事务更新渲染缓存和 FTS，编辑或重新生成以截断后续历史表达，不产生树或候选版本。现有 Chat UI 仅确认 Topic 标题/日期过滤，FTS 的查询入口和命中跳转未确认。

- **流投影的回收不等于持久化模型改变**：VCPChat 以仓库、历史写入权威和 surface 投影分层，并用 conversation key 与 generation 拒绝已撤离 surface 的迟到事件；普通单聊仍以本地历史文件为事实源，没有因此获得事务、文件锁或版本合并。AIO Hub 的队列标记则已持久化在消息节点上，使同一路径串行、分支并行的调度语义可以跨界面状态复查。

## 项目概览

### DeepSeek Harness

把会话建模为 append-only 的 SessionEvent 日志，没有独立消息表：内存 Session 是交互历史的唯一事实源，LLM 消息历史由 deriveMessages() 从表面（surface）折叠派生，仅 user/message、assistant/message、tool/result 三类消息事件进模型历史；事件类型经 SessionEventMap 声明合并扩展，核心加插件共 24 个事件族。持久化是同一抽象契约下的双后端互换：JSONL（每会话一文件、默认 zstd 帧压缩、追加+fsync）或 SQLite（每事件一行、WAL 事务）。SESSION_FORMAT_VERSION=0 无兼容承诺，版本不符直接拒绝而非迁移。fork、resume、transcript 都从日志流派生，历史修正以表面替换表达、不改写日志；代价是日志只增不减，会话删除、导入与跨进程写仲裁本次未找到。

### Risuai

Risuai 的会话与消息没有独立持久化单位：角色对象内嵌会话数组，`chatPage` 下标即当前会话指针。内存 `DBState.db` 是唯一事实源，整库单文件 `.bin` 走块级增量编码 + 500ms 防抖整库覆写，每次保存另写一份备份（保留 20 份），没有按条或按会话的落盘单位。分支是复制整份会话并截断 + `branchedfrom` 注释回链（父会话不记录子分支），分支导航由消息内容哈希前缀树实时计算；Reroll 是纯内存候选、不落盘。消息内容搜索本次未找到；多窗口靠 BroadcastChannel 互斥让后到标签页刷新，多用户同步是 WebRTC 整对象覆盖。角色/会话 10 天无活动自动归档（冷存储）并惰性恢复；bin 支持多版本解码，启动时逐版本迁移，导入导出覆盖 risuChat v1/v2、JSONL Tavern 与 HTML .idat。

### 术语层级：同一个词在不同项目里指不同位置的容器

- **Session 在多数项目里是顶层会话**（AIO Hub、Chatbox、DeepChat、Hermes Agent、NextChat 的 `ChatSession`、Pi、OpenCode），**唯独在 AstrBot 里是账号级容器**：session 由 UMO 标识，其下可切换多个 conversation，conversation 才是"具体对话"。
- **Topic 在 Cherry Studio 是顶层**（消息树本体），**在 VCPChat 是 Agent/AgentGroup 下的二级单位**；LobeHub 则是 Agent → Topic 两级，thread 再作为消息级子维度参与 `messageMapKey`（带 `threadId` 的消息不进主干树）。
- **Thread 在 Jan 是顶层会话**（每 thread 一个目录），**在 Chatbox 是 Session 内的历史区间**（其上还能叠加 Fork 分支），**在 LobeHub 是消息级话题线**——同一词横跨三个层级。
- **Chat 在 Open WebUI 是顶层会话**（history JSON + 消息表双写）；OpenCode 的 Session 内部严格三层（session → message → part）；SillyTavern 不用这类词，会话就是"聊天文件（chat[]）"；Manifold Desktop 的 Chat tab 尚未接通会话持久化。
- **DeepSeek Harness 的 Session 是顶层会话，且会话本体就是事件日志**：无独立消息表，消息历史从日志派生；子 agent 会话只是 header 上的 `origin: 'subagent'` 与 delegationDepth 展示元数据，不是可继续的独立会话。
- **Risuai 的顶层容器是角色，会话内嵌其中**：会话（Chat）是角色对象 `chats[]` 数组里的元素，`chatPage` 下标决定当前会话，无独立会话集合；群聊是与角色同级的群聊对象。顶层都不是会话本身——这与 AstrBot 的账号级容器、VCPChat 的二级 Topic 相似，区别是 Risuai 的会话随角色对象整体导入导出。
- **VCPMobile 的 Topic 是 Agent 或 Group 下的会话**：消息在 Topic 内线性排列；选择状态和分页窗口在前端投影，SQLite 是事实源。这与 VCPChat 的二级 Topic 同名但存储和并发边界不同。
- 会话内还能再派生**子会话**：Open WebUI 的内部子代理占独立会话行、DeepChat 的 subagent session 是独立可读 transcript、Hermes Agent 的子代理是真实子会话——这与 AstrBot/VCPChat 那种"父级角色容器 + 下级对话"是两种不同的层级结构。

命名取向粗略分两类：**用户语义词**（Topic、Conversation、Chat——Cherry Studio、VCPChat、Open WebUI、AstrBot 的二级单位）偏"一段话题/对话"；**实现语义词**（Session、Thread——AIO Hub、Jan、DeepChat、Pi、OpenCode、Chatbox）偏"一条会话记录"。比较时基准应是"该词在自己项目里处于哪一层、内部还能不能再挂子容器或分支"，而不是名称本身。

### 存储实现分组与一致性代价

Cherry Studio、DeepChat、Hermes Agent、Open WebUI、AstrBot 使用数据库行或事务；Chatbox、NextChat 使用 IndexedDB；AIO Hub、Jan 桌面端、SillyTavern、VCPChat 仍有整文件/整对象写入路径，Risuai 的整库覆写也属这一组（块级增量只限定重编码范围，写入仍是整文件），Manifold Desktop 的存储 API 尚未接入正常聊天。介质本身不保证一致性：Open WebUI 需要对齐两份数据，Hermes Agent 需要翻译会话句柄与持久 session id 两套身份，Jan 虽有文件锁仍按 O(消息数) 重写。

DeepSeek Harness 是"追加型文件 + 数据库事务"双后端互换：JSONL 每会话一文件、追加+fsync、默认 zstd 帧压缩，SQLite 每事件一行、WAL 事务；两个后端实现同一持久化抽象并同过契约测试，配置层二选一。与整份覆写型文件项目不同，追加型写入的每轮成本不随消息数增长，代价落在读取时的全量解析与日志体积。

## "分支"不是一回事：消息树、版本、复制和轮转链

十九个项目里的"分支"至少包括消息树切换、消息版本、会话复制、文件截断另存、压缩轮转链和多模型并列，不能统一称作"消息树切换"：

1. **真树 + 指针跳转（Cherry Studio）**：持久层是 DB 树（`parentId` 外键 + CHECK 约束保证虚拟根不变式）；切分支时更新 `topic.active_node_id`，渲染再反向 walk 拼出路径。分支草稿已从渲染层假节点改为**持久化空叶子**：`POST /messages/:id/branches` 经 `MessageService.reserveBranch` 落一条空的 successful user 行，awaiting-input 状态由结构派生；旧的三态 ref 草稿锚点已删除。`buildTopicMessageFlowLiveState` 现在只叠加"流式中尚未持久化的消息"临时节点，分支图 = 持久化树（含空分支叶子）+ 流式 overlay。
2. **树 + 兄弟记忆（AIO Hub）**：`parentId`/`childrenIds`/`lastSelectedChildId` 构成应用层树，`BranchNavigator` 用循环索引在兄弟间切换，并用 `lastSelectedChildId` 记住上次选择。重试、切换模型重试和续写分别创建 assistant 兄弟节点、带 prefix 的同内容兄弟节点、以及空子节点；它没有 Cherry Studio 那样的草稿态覆盖层。
3. **多套独立结构叠加（Chatbox）**：会话列表分组只认 `starred`（`SessionMetaSchema` 没有树/分支字段）；Thread 是 Session 内的历史区间，Fork 是同一消息位置的平行分支（替代回复可折叠为 `ForkGroup` 分支组）。两者可以叠加共存；fork 变换改为纯函数 patch 模型（`buildCreateForkPatch`/`buildSwitchForkPatch` 等），清理函数已收敛为单函数内 root/thread 两条路径（root 层改写消息数组并自动切换分支、thread 层只更新 hash，两者仍不完全对称），旧"两段相似代码"的双写不一致风险范围缩小；分支上下文重建改为从分叉点向上逐段拼接。消息级分支与会话级条目的连接点，是把 thread 移成独立会话。
4. **多模型兄弟组（LobeHub / Cherry Studio 多模型场景）**：多模型 mention 场景下，N 个模型各自产出一条 assistant 消息，共享同一个 `siblingsGroupId`，属于并列结果，不是二选一分支；LobeHub 的 `BranchResolver` 处理的是重新生成后的候选选择，用 `metadata.activeBranchIndex` 存在父消息上，子消息本身不记录激活状态。
5. **独立文件/候选数组，无树（SillyTavern）**：Branch 把 `chat[]` 截断到某条消息后另存为新文件并跳转，Checkpoint 只另存不跳转。两者共享截断函数，但 `extra.bookmark_link` 是单值、`extra.branches` 是数组，记录关系的方式不同。单条消息的候选回复放在 `swipes` 数组中；Branch 可以先选定某个 swipe 再截断。VCPChat 的 Topic 之间没有消息级分支，多个 Topic 是并列历史。
6. **父子树 + 兄弟版本（Jan）**：`parentId` 形成活动路径，`makeSibling` 为编辑或重新生成创建同父新版本，`activeRootId`/版本导航选择可见路径；Continue 则原地续写，不产生新分支。媒体消息编辑回退为纯文本，是版本语义中的明确损失边界。
7. **有序 transcript 上的 fork（DeepChat）**：`SessionTurn` 支持 fork/retry/edit，但上下文恢复主要按 `orderSeq` 截取完整 turn，并非每次都沿 `parentId` 回溯。它更接近"从 transcript 某点复制出新 session/turn"，不能直接等同于 Cherry Studio 的 DB 邻接树。
8. **会话复制与 lineage（Hermes Agent、NextChat）**：Hermes `session.branch` 复制历史并建立 parent/lineage 关系，压缩轮转也会生成新 session id；NextChat 的 `forkSession()` 则深拷贝整个 Session、重发所有消息 id。二者都是会话级派生，但 Hermes 需要保持跨轮转 lineage，NextChat 只是本地独立副本。Hermes 分支与压缩轮转现在都**携带标题**（标题带 derived < llm < user 的 provenance，`/title` 永不被自动标题覆盖），不再对每个 fork/轮转把 `xxx #N` 重编号。
9. **服务端回溯重建（Open WebUI）**：消息本身由 `parentId`/`childrenIds` 构成树；`POST /{id}/fork` 用 `build_fork_history` 从目标节点沿父链重建一个新 Chat。多模型的 `modelIdx` 并列列序与 fork 是另一套正交关系。
10. **指针分支（Pi）**：`branch()` 只移动会话的 `leafId` 指针，下次追加即成为新分支；`createBranchedSession` 把"根到指定叶子"的路径抽成新 JSONL 文件并重链 label；`branchWithSummary` 追加 `branch_summary` 摘要条目参与上下文。历史不修改、无草稿态覆盖层，语义接近 Cherry Studio 的指针跳转但实现是 JSONL 追加树。
11. **删除式回退 + 复制式 fork（OpenCode）**：`revert` 记录回退点（含 git snapshot）并回滚文件，再次 prompt 前**删除目标之后的所有消息**——改的是原消息树而非新建节点；真正的分支是 `POST /session/:id/fork`，新建会话并复制截至某消息的全部消息/parts（parentID 重映射）。多模型/多候选不产生消息级兄弟节点，也没有草稿态覆盖层。
12. **日志派生 fork（DeepSeek Harness）**：`fork(source, boundary, childId)` 把源会话 0..boundary 前缀深拷贝为种子，子会话 header 记 `parentSession` 与 `seedLength`、继承 cwd；boundary 默认当前末事件，落在开着的 turn 内会被拒绝（`OPEN_TURN`）而非静默裁剪。分支是独立子会话，会话身份与日志绑定，没有"移动 leaf 指针"式的活动路径切换；resume 与 transcript 同源地从日志派生，历史修正以表面 `replace` 表达、不修改日志。
13. **复制会话 + 注释回链（Risuai）**：分支按钮深拷贝整个会话、把消息截断到分叉点，尾部插入一条 `branchedfrom` 回链注释（含源会话与源消息 id），再作为新会话跳到列表头；父会话不记录子分支。分支导航视图由 `getChatBranches` 对消息内容哈希做前缀树实时计算，不读取任何分支元数据——文本改动会改变树形。这条复制会话分支会持久化；Reroll/swipe 没有持久化候选，只是独立的内存候选。
14. **线性截断重发（VCPMobile）**：编辑用户消息或重新生成助手消息时，删除指定时间之后的记录，再从保留的用户消息启动下一轮；本次未找到树、兄弟版本或复制会话式分支。

AstrBot 的多个 conversation 是同一 UMO 下可切换的独立对话，不是消息分支；Manifold Desktop 未形成可持久化的正常会话主链，本次也没有可比较的分支机制。

## 索引、搜索粒度与定位标识

比较搜索能力时，要区分索引对象、结果粒度和 UI 跳转（搜索入口与跳转工作流见 Chat UI 横向对比）：

- **AIO Hub**：跨会话搜索由 Rust 全量遍历文件系统并用正则预过滤，没有持久化索引，只能定位到会话。会话内搜索是独立的前端线性扫描，仅覆盖当前活动路径，无法命中隐藏分支。两套搜索没有衔接，跨会话结果不能直接跳到具体消息。
- **Cherry Studio**：搜索使用 `document.createTreeWalker` 遍历已渲染的 DOM 文本节点，没有查询消息数据模型。消息列表由 `virtua` 虚拟化，窗口外消息未挂载到 DOM，因此不会进入搜索范围。这是 DOM 搜索与虚拟列表组合后的范围限制。
- **VCPChat**：`searchTopicsByContent` 只对字符串类型的 `message.content` 做 `includes` 匹配，多模态数组（`[{type:'text',...}]`）会被跳过，形成明确的搜索盲区。当前 HEAD 另有旁路的 VCP-CDS 影子镜像（Rust 聊天数据服务，SQLite 完整镜像 + Tantivy 全文派生索引），但只供 DeepMemo 记忆检索与 VCPMobileSync 消费，**未接入**话题搜索路径。
- **Chatbox**：`sessionHelpers.searchSessions` 分页读取 IndexedDB 中的完整 Session，扫描当前消息与历史 Thread，返回命中的具体消息，点击结果后调用 `scrollToMessage` 定位。实现采用数据层分页全量扫描，没有使用 DOM 搜索或持久化倒排索引。
- **LobeHub**：服务端 `TopicModel.queryByKeyword` 用 BM25 同时匹配 Topic 标题和消息内容，但返回的是 Topic 列表，不直接定位到具体消息。另有 `message.searchMessages` 后端查询端点，但本次未找到聊天 UI 对该端点的调用，因此不能把它等同于用户可见的消息定位搜索。
- **SillyTavern**：本次仍未找到聊天内容检索 UI；现有 `search` 相关代码集中在端点/扩展和 slash command 语义，不应据此断言完全不存在其它未覆盖入口。
- **Risuai**：本次未找到消息内容搜索——检查了全部 UI 组件与 `src/ts` 的 search/filter 入口，未发现对会话消息数组做关键词检索的 UI 或工具函数；MCP 只提供按 offset/count 分页读取当前会话的聊天历史接口，无内容检索。
- **DeepChat**：两层搜索均已确认。跨会话全文搜索把完成/错误消息写入 `deepchat_search_documents`，SQLite FTS5 虚拟表带三个触发器同步，查询用 bm25 或 `LIKE` 回退，命中直接定位到消息（message_id）并可滚动到目标行；搜索同时经 MCP 服务 `conversationSearchServer` 暴露给模型工具与设置页。
- **Hermes Agent**：SQLite `state.db` 带会话搜索 mixin/FTS，会话列表与搜索在 SQL 中完成，前端只取必要字段；笔记确认了后端索引路径，但未把桌面命中跳转逐项展开。
- **Jan**：`useThreads` 用 Fzf 懒建索引，SearchDialog 展示并导航 Thread；这是会话列表搜索，不是消息正文命中后定位。
- **Manifold Desktop**：逐个读取 session JSON，对整份 dump 做不区分大小写子串匹配，无索引和结果上限；而正常聊天未保存，搜索 API 也可能搜不到刚聊过的内容。
- **Open WebUI**：后端 `/search` 支持文本和 `tag:` 查询，结果粒度是 Chat；消息行虽独立存储，本次笔记未确认用户可见的"命中具体消息并跳转"链路。
- **NextChat / AstrBot**：本次单项目笔记没有把聊天内容搜索作为完整链路展开；不能据会话列表或管理页入口推断存在消息级检索。
- **Pi**：搜索是选择器内的 `id+名称+全部消息文本+cwd` token/正则匹配，结果是会话级命中；无消息级持久化索引。harness SDK 另有 `createScanningSessionSearch`（`packages/agent/src/search/`，2026-08 从 `harness/session/search.ts` 迁出），提供异步迭代器接口，可对可读存储逐条目分页扫描，但**未接入 TUI/AgentSession 路径**；`session-backends/sqlite-node` 另提供可选 FTS 搜索后端（懒创建索引 + 触发器同步），coding-agent 当前仍走 JSONL 路径。
- **OpenCode**：仅会话标题 `LIKE` 搜索，结果定位到会话；**消息内容全文搜索本次未找到实现**。消息分页用游标（base64url {id,time}），App timeline 向上加载。
- **DeepSeek Harness**：live-preferred 的逻辑语料层 `session-query` 提供精确读取（会话、表面、事件、标题）与关系追踪，事件读取复用核心表面折叠，把每个事件标记为 current/shadowed/log-only 三类；唯一全文实现是 `session-query-sqlite`——FTS5 配合 `unicode61` 分词，查询按字面短语转义（MATCH 语法当数据），跨会话结果按最强命中事件分组，返回带 snippet 的分页（不透明 branded cursor，generation 变化即失效）。索引是派生的独立数据库，TEMP 表放 live 行、持久表放已落库行，revision 对比后只增量检查新变更日志；`openAt: never` 可整体关闭搜索。命中粒度是事件（消息级），但用户可见的 UI 跳转链路本次未确认（属 Chat UI 类目）。
- **VCPMobile**：SQLite FTS 在助手消息终结事务中更新，删除或截断同步清理关联索引；它是持久化消息索引。已确认的 Chat UI 只有 Topic 标题和日期过滤，未确认 FTS 是否跨 Topic 查询、返回何种命中标识，或能否跳转到消息。

**结论**：Chatbox 与 DeepChat 已确认能从数据层命中并定位具体消息（Chatbox 走 IndexedDB Session 扫描，DeepChat 走 FTS5 全文索引 + 命中 message_id 定位）；VCPMobile 已确认有随消息终结维护、且随删除/截断清理的本地 FTS，但其跨 Topic 查询与 UI 命中跳转未确认。LobeHub、Hermes Agent 具有数据库或搜索文档基础，但用户可见定位链路证据不齐；Jan、Open WebUI、AIO Hub、Manifold Desktop 主要返回会话级结果；Cherry Studio 与 VCPChat 分别受虚拟 DOM 和多模态内容形态限制。现有材料不能断言没有项目满足三个条件，只能说明 VCPMobile 的后两项尚未确认。

## 数据层技术债（有具体代码证据支撑的）

- **AIO Hub**：跨会话搜索无索引，延迟会随数据量线性增长（静态推断，未实测）。
- **Chatbox**：IndexedDB 有意不做 version 升级，代码注释所述的"重试兜底"也未找到实现；侧栏"生成中/回复完成未读"指示是内存态（`sessionActivityStore` + `generation-runtime`），不写 `SessionMetaRecord`、不落盘，重启即清空。
- **Cherry Studio**：删除 Topic 不主动清理磁盘文件（附件经 `chat_message_file_ref` 引用计数 + FileManager 策略化 GC 回收，旧 `TopicService.ts:316` 的 TODO 已随 file-manager 治理移除，回收时机未运行验证）；`docs/references/chat/message-tree.md` 的 Flow canvas "forward reference" 说法已随文档更新删除，并新增 "Persisted awaiting-input branches" 一节描述空分支叶子语义。
- **LobeHub**：`doctor/diagnose.ts` 用于检测和修复读取器无法完整渲染的消息树；`reconcileAssistantToolLinks` 用于修复乐观更新在 step 边界丢失工具引用的问题；另有 `#writeThroughMessageCache`（`query.ts:302-330`）处理本地分桶 key 与服务端缓存 key 不同构时的写缓存跳过。
- **AstrBot**：会话切换/新建的 SharedPreferences 有 60 秒防抖，进程崩溃可能丢失这段时间内的选择状态。
- **DeepChat**：SQLite 加密配置、事务隔离、崩溃恢复和 IPC revision/cursor 在网络中断、快速切换会话时的行为未运行验证；搜索文档、Tape 和 transcript 的完整迁移链也未全部追踪。
- **Hermes Agent**：会话句柄（sid）与持久 session id 的翻译、压缩轮转后的身份重锚是持续 bug 来源。
- **Jan**：桌面 `messages.jsonl` 每次整文件重写，长会话每轮 I/O 随消息数增长；`resume:false` 不恢复未完成回合；编辑消息会丢失媒体 content，分支树迁移完整性未验证。
- **Manifold Desktop**：正常聊天没有调用 `SAVE_SESSION`，assistant 不回写 `messages[]`；`CHAT_CHUNK`/`CHAT_DONE` 无会话标识导致多标签广播串扰，重命名整文件覆盖会清空既有消息。
- **NextChat**：WebDAV 合并时间戳实现可疑但未执行多设备复现。
- **Open WebUI**：history JSON 与 `chat_message` 双写依赖 reconcile。
- **SillyTavern**：`chat_metadata.integrity` 用于检测多标签页并发写覆盖；`swipe()` 失败时会自动恢复，恢复失败后强制整页重载。
- **Risuai**：整库覆写每轮成本随库体积增长，块级增量只限定重编码范围、写入量不减；每次保存都产生整库备份（保留 20 份），磁盘占用随保存频率增长；reroll 候选纯内存、重启即失，回退只靠复制会话；分支父会话不记录子分支，导航依赖单向回链注释；多窗口是后到者刷新、无字段级合并。
- **VCPChat**：群聊历史写盘没有文件锁，存在并发覆盖丢消息的可能，尚未构造场景验证；未读自动判定以"用户是否参与"为边界——`countUnreadMessages` 过滤系统消息与 `isThinking` 占位后，**只要历史中出现任何用户消息就返回 0，否则返回全部 assistant 消息数**（旧"恰有一条非系统 assistant 消息才触发"的窄条件已删除）；持久化标记另带 `unreadSource` 来源（手动标记保留、Agent/TopicSponsor 旧标记在用户参与后由前端主动清除）。
- **Pi**：JSONL 追加型文件随会话持续增长，恢复时全量读入。
- **OpenCode**：无消息内容全文索引（仅标题搜索）；V1/V2 双轨会话体系并存（Legacy 主路径 + 事件溯源 V2 部分实现），客户端需按协议协商切换。
- **DeepSeek Harness**：JSONL 顺序媒体 `readFrom` 每次全量解析后再跳过，长会话读取成本随日志增长（packed chunk 压缩率未实测）；追加型日志只增不减，体积靠 zstd 帧缓解；多进程并发写无锁，revision token 只检测变更、不提供仲裁；无会话删除 API——workspace 的登记删除与归档只移除分组索引，日志与文件保留。

## 设计取舍与已确认边界

- **会话主体命名不能按名字直接对齐**：比较基准应是"该词在自己项目里处于哪一层、内部还能不能再挂子容器或分支"。
- **文件级存储项目共享一致性问题**：整份读写（SillyTavern、VCPChat、Jan 桌面端、AIO Hub）在长会话下 I/O 与解析成本随长度线性增长；数据库行项目则要处理双写对齐（Open WebUI）或身份翻译（Hermes Agent）。
- **VCPToolBox 不拥有会话事实源**：它只做请求级消息编排，会话与历史由外部前端保存（边界记录见 `VCPToolBox-会话与消息管理调查笔记.md`）。
- **Risuai 的会话无独立持久化单位**：会话内嵌于角色、落盘是整库单文件，任何一次编辑最终都触发整库覆写；换来实现简单、单文件易跨端迁移，代价是保存粒度粗、没有会话级文件可独立备份或迁移，格式迁移必须整体重写（启动时逐版本迁移）。
- **分支与回退分离（Risuai）**：分支靠复制会话实现，回退也只能靠分支或复制——消息编辑删除没有版本历史或 undo；reroll 是内存候选、不落盘，与 SillyTavern 的 swipes 数组字段形成对照。
- **多窗口不合并（Risuai）**：BroadcastChannel 互斥让后到标签页刷新，多用户实时同步是会话级整对象覆盖，都没有字段级冲突解决。
- **类目边界**：本对比只回答数据语义；流式节流落盘、压缩触发与中断结算在对话请求与上下文横向对比；搜索入口、分支导航与消息操作的用户工作流在 Chat UI 横向对比。
- **事件日志而非消息表（DeepSeek Harness）**：与其他聊天应用"消息表 + 行更新"模型的根本差异——全部对话状态可重放，消息历史按需从表面派生；压缩等修正以表面替换表达，被影子化的旧事件留在原日志，回放确定性保留。代价是日志只增不减、chunk 级保真使体积增长，靠 zstd 帧与 packed chunk 行缓解。
- **格式版本零迁移（DeepSeek Harness）**：`SESSION_FORMAT_VERSION=0` 在未发布期无兼容承诺，版本不符直接拒绝而非迁移；`ignorable` 标记把词汇增长与结构性变更解耦——未知事件类型且无该标记时拒绝重建，而不是静默跳过。
- **模型历史与 transcript 双投影（DeepSeek Harness）**：模型读表面（遮蔽被替换范围），人类 transcript 读 append-origin 事件，两者同源于日志但语义刻意不同：替换拷贝只服务模型，不吞掉用户已见过的对话。

## 未验证事项

- DeepChat 的 FTS5 搜索索引写入触发点与清理策略未完整追踪。
- SillyTavern 隐藏消息（`is_system`）是否真的被排除出 prompt 构建未核实（属于数据与执行的交界，见请求类对比）。
- VCPChat 群聊写盘并发覆盖风险未构造场景验证；VCP-CDS 影子镜像与 `history.json` 之间的摄取一致性未做运行验证。
- Hermes Agent 压缩轮转后 lineage 重锚的完整行为未实测。
- DeepSeek Harness：崩溃恢复路径（torn tail 截断、interrupted closers 合成）与 resume 往返未运行验证；多进程并发写同一 JSONL/SQLite 的行为、FTS5 召回质量与同步阻塞影响、/export ZIP 端到端均未实测。
- Risuai：冷存储读写与惰性恢复、备份回退、账户迁移、WebRTC 多用户同步、多标签页竞争均未运行验证；多窗口广播与 bin 写入之间的竞争窗口未实测；导入导出（risuChat v1/v2、JSONL Tavern、HTML `.idat`）只核实了识别与转换代码，未用样本文件验证；"消息内容搜索不存在"的结论受检查范围限制（未覆盖插件第三方能力与 Hub 服务端）。
