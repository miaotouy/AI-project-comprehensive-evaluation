# Chat 概览调查指南

本指南用于编写单项目 Chat 概览，提供聊天能力的端到端地图和专项导航。通用写作、元数据、深度和证据要求见 [`../AGENTS.md`](../AGENTS.md)。

Chat 概览不再承担数据、请求、界面和渲染的完整深挖。详细调查分别进入：

- [`../会话与消息管理/调查指南.md`](../会话与消息管理/调查指南.md)：会话、消息、分支、索引、持久化和恢复；
- [`../对话请求与上下文/调查指南.md`](../对话请求与上下文/调查指南.md)：上下文拼装、模型请求、流式、取消、队列和最终回写；
- [`../Chat UI/调查指南.md`](<../Chat UI/调查指南.md>)：工作台、会话导航、Composer、生成反馈和消息操作工作流；
- [`../消息渲染器/调查指南.md`](../消息渲染器/调查指南.md)：消息列表、消息壳、Markdown、结构化 part 和内容交互；
- Agent 角色、Agent 工具、LLM 渠道管理、生成式输出与运行时等专项：记录各自完整机制。

## 调查目标

用较短篇幅回答“这个项目的聊天系统由哪些部分组成、一次对话经过哪些责任边界、详细结论在哪里”。项目没有最终用户聊天界面时，仍可概览它提供的会话服务、请求编排、机器人事件管线或协议网关，但必须明确不拥有的层级。

## 必查问题

1. **产品表面与系统边界**：项目提供 GUI、Web、移动端、TUI、机器人平台、后端服务还是无状态网关？哪些界面或数据由外部系统拥有？
2. **核心对象与事实源**：会话、消息、生成任务和可见 UI 状态的主要对象是什么？各自权威源位于哪里？
3. **端到端主链**：从用户或上游输入到最终输出和持久化，关键入口、交接点和执行层依次是什么？
4. **专项归属**：会话管理、请求上下文、Chat UI、消息渲染、角色、工具、渠道和生成式输出分别由哪些模块承担？对应专项笔记在哪里？
5. **关键能力边界**：分支、搜索、压缩、停止、多会话并发、群聊或后台任务中，哪些是项目的主要特征，哪些不存在或尚未确认？
6. **验证范围**：哪些结论来自源码，哪些经过运行验证，哪些只确认了入口或接口？

## 推荐结构

```md
## 结论摘要
## 产品表面与系统边界
## 端到端聊天主链
## 核心对象与状态权威
## 专项导航
## 关键能力与已确认边界
## 未验证事项
## 关键源码索引
```

## 编写规则

- 概览只保留一条端到端主链，不在正文重新展开每个专项的完整实现。
- 专项已经存在时，用一至两段说明交接点并链接；没有专项时，明确标记“尚未拆分调查”，不把全部细节重新塞回概览。
- 旧版 Chat 长文可以在迁移期保留。后续新增内容应按新边界写入对应类目，原文件逐步缩为概览，不要求一次性重写。
- 通用主题、弹窗库、动画、设置页和全应用无障碍不属于 Chat 概览。只有直接改变聊天主链时才记录交点。
- 横向对比文档只保留能够同时解释多个层级的综合结论，详细表格进入对应专项横向对比。

## 横向比较字段

至少记录：产品表面、会话所有者、消息事实源、请求执行者、Chat UI 表面、消息渲染入口、角色与工具交接、渠道解析位置、生成式输出交接，以及已建立的专项笔记。
