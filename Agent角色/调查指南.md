# Agent 角色配置调查指南

本指南用于调查 Agent、Assistant、Persona、Mask、Character 等角色配置。通用要求见 [`../AGENTS.md`](../AGENTS.md)。项目使用不同名称时，先按实际语义定义概念，不强行统一命名。会话保存角色引用或快照的方式链接 [`../会话与消息管理/调查指南.md`](../会话与消息管理/调查指南.md)，角色字段如何进入本次请求链接 [`../对话请求与上下文/调查指南.md`](../对话请求与上下文/调查指南.md)，聊天中的快速切换与当前角色可见性链接 [`../Chat UI/调查指南.md`](<../Chat UI/调查指南.md>)。

## 必查问题

1. **角色实体**：角色是独立持久化对象、模板、模型包装还是会话预设？唯一标识和版本字段是什么？
2. **配置与存储**：字段定义、默认值、存储位置、迁移和删除策略在哪里？内置与用户角色是否分开？
3. **创建与绑定**：角色如何创建、复制、导入和选择？绑定在会话、消息、路由还是用户级设置上？
4. **生效优先级**：全局默认、角色配置、会话覆盖和临时输入冲突时谁优先？
5. **角色提示字段**：人格、用户档案、规则、示例对话、时间、变量和扩展提示在角色内部如何排序、覆盖和转换？它们从哪个契约交给最终上下文构建？
6. **模型与生成参数**：角色能否绑定 Provider、模型、温度、上下文长度、输出格式或其他参数？切换时如何继承？
7. **外部能力**：工具、知识库、记忆、世界书、Skill 和子 Agent 如何授权或挂接？
8. **资产与变量**：头像、开场白、快捷回复、文件、环境变量和占位符如何解析与持久化？
9. **兼容与分享**：支持哪些导入导出格式？未知字段、脚本、远程资源和敏感配置如何处理？
10. **运行时可见性与快照**：用户能否确认当前角色、实际模型、工具权限和局部覆盖？聊天界面从哪些状态读取这些信息？历史消息是否保存角色快照？

## 与相邻类目的边界

| 相邻类目 | Agent 角色记录 | 留在相邻类目的内容 |
|---|---|---|
| 会话与消息管理 | 角色的可保存引用、覆盖字段和快照契约 | 会话绑定粒度、历史快照落盘、迁移和恢复 |
| 对话请求与上下文 | 角色产生的 system prompt、参数和能力声明 | 角色输出与历史、记忆、摘要、知识库等内容的最终拼装顺序 |
| Chat UI | 配置页提供的角色操作和运行时可见字段 | 聊天中的角色选择器、快速切换、作用域提示和切换反馈 |
| Agent 工具 | 角色声明或授权哪些工具、Skill 和子 Agent | 工具发现、schema 注入、审批、执行和结果回注 |
| LLM 渠道管理 | 角色保存的模型、Provider 或参数引用 | 引用如何解析为具体渠道、凭据和协议 Adapter |

## 调查注意事项

- 配置界面存在某字段，不代表请求链路实际读取它；需要追到最终 prompt 或请求参数。
- 角色描述、system prompt、用户 Persona 和模型预设不是同一概念，应分别说明所有者和覆盖关系。
- 导入兼容性要区分“能够解析”“能够保留字段”和“运行时真正生效”。
- 列举内置角色时，以说明能力边界和配置方向为目的，不需要抄录全部角色内容。

## 横向比较字段

至少记录：角色实体类型、存储粒度、会话绑定方式、提示词优先级、模型绑定、工具授权、知识与记忆、导入格式以及历史快照语义。
