# Agent 角色配置调查指南

本指南用于调查 Agent、Assistant、Persona、Mask、Character 等角色配置。通用要求见 [`../AGENTS.md`](../AGENTS.md)。项目使用不同名称时，先按实际语义定义概念，不强行统一命名。

## 必查问题

1. **角色实体**：角色是独立持久化对象、模板、模型包装还是会话预设？唯一标识和版本字段是什么？
2. **配置与存储**：字段定义、默认值、存储位置、迁移和删除策略在哪里？内置与用户角色是否分开？
3. **创建与绑定**：角色如何创建、复制、导入和选择？绑定在会话、消息、路由还是用户级设置上？
4. **生效优先级**：全局默认、角色配置、会话覆盖和临时输入冲突时谁优先？
5. **提示词拼装**：人格、用户档案、规则、示例对话、时间、变量和扩展提示按什么顺序进入 system prompt？
6. **模型与生成参数**：角色能否绑定 Provider、模型、温度、上下文长度、输出格式或其他参数？切换时如何继承？
7. **外部能力**：工具、知识库、记忆、世界书、Skill 和子 Agent 如何授权或挂接？
8. **资产与变量**：头像、开场白、快捷回复、文件、环境变量和占位符如何解析与持久化？
9. **兼容与分享**：支持哪些导入导出格式？未知字段、脚本、远程资源和敏感配置如何处理？
10. **运行时可见性**：用户能否确认当前角色、实际模型、工具权限和局部覆盖？历史消息是否保存角色快照？

## 推荐结构

```md
## 结论摘要
## 总体生效链路
## 1. 角色数据模型与存储
## 2. 创建、选择与会话绑定
## 3. 提示词字段与最终拼装顺序
## 4. 模型、Provider 与生成参数
## 5. 工具、知识库、记忆与子 Agent
## 6. 资产、变量、开场白与用户档案
## 7. 导入、导出、迁移与兼容性
## 8. 配置 UI 与运行时可见性
## 9. 设计取舍与已确认边界
## 10. 未验证事项
## 11. 关键源码索引
```

## 调查注意事项

- 配置界面存在某字段，不代表请求链路实际读取它；需要追到最终 prompt 或请求参数。
- 角色描述、system prompt、用户 Persona 和模型预设不是同一概念，应分别说明所有者和覆盖关系。
- 导入兼容性要区分“能够解析”“能够保留字段”和“运行时真正生效”。
- 列举内置角色时，以说明能力边界和配置方向为目的，不需要抄录全部角色内容。

## 横向比较字段

至少记录：角色实体类型、存储粒度、会话绑定方式、提示词优先级、模型绑定、工具授权、知识与记忆、导入格式以及历史快照语义。
