# Agent 工具调查指南

本指南用于调查模型可发现、选择和执行的工具。通用要求见 [`../AGENTS.md`](../AGENTS.md)。普通 UI 命令、开发脚本或用户手动触发的功能，只有在模型能够直接或间接调用时才计入 Agent 工具。本次生成任务在何处调用工具目录并注入请求属于 [`../对话请求与上下文/调查指南.md`](../对话请求与上下文/调查指南.md) 的交接范围；审批和工具状态如何呈现给用户分别链接 [`../Chat UI/调查指南.md`](<../Chat UI/调查指南.md>) 与 [`../消息渲染器/调查指南.md`](../消息渲染器/调查指南.md)。

## 必查问题

1. **工具来源**：内置工具、MCP、插件、Skill、OpenAPI 或远程节点如何声明和注册？
2. **发现与注入**：哪些工具会进入本次模型请求？过滤条件、命名冲突和 token 控制在哪里处理？
3. **模型协议**：使用原生 `tool_calls`、文本协议还是自定义结构？不同 Provider 如何适配？
4. **解析与校验**：工具名、参数 schema、必填字段、类型和额外字段在哪里验证？解析失败如何反馈？
5. **编排循环**：谁驱动“模型调用—工具执行—结果回注—继续生成”？迭代、并发、超时和取消上限是什么？
6. **审批与授权**：审批发生在展示层、编排层还是执行端？策略按工具、会话、Agent 或风险分级吗？
7. **执行边界**：工具运行在浏览器、renderer、主进程、服务端、容器还是远程节点？有哪些隔离和资源限制？
8. **结果回注**：结果以什么 role 或 block 返回模型？长度、二进制内容、错误和敏感数据如何处理？
9. **执行状态与恢复**：进行中、等待审批、成功、失败和取消如何持久化？重启后能否恢复或明确结算？这些状态以什么契约交给 UI？
10. **旁路能力**：子 Agent、代码执行、插件或远程协议是否能绕开常规目录、审批或校验路径？

## 推荐结构

```md
## 结论摘要
## 总体调用链
## 1. 工具定义、来源与注册
## 2. 工具发现、过滤与注入
## 3. 模型调用表示与 Provider 适配
## 4. 参数解析、校验与错误处理
## 5. 编排循环、并发与终止条件
## 6. 审批、授权与执行边界
## 7. 结果回注、执行状态与恢复
## 8. MCP、插件、Skill 与子 Agent
## 9. 设计取舍与已确认边界
## 10. 未验证事项

```

## 与相邻类目的边界

| 相邻类目 | Agent 工具记录 | 留在相邻类目的内容 |
|---|---|---|
| 对话请求与上下文 | 工具来源、过滤算法、实际目录、schema 和结果契约 | 本次任务何时调用目录构建、把实际目录注入何处，以及工具回合如何并入整体生成任务 |
| Chat UI | 审批命令、状态查询和用户动作对应的工具语义 | 审批入口、待处理提示、允许或拒绝后的用户反馈与返回路径 |
| 消息渲染器 | 工具结果和状态提供给显示层的数据形状 | 工具卡、进度、错误、折叠和内容交互组件 |
| 会话与消息管理 | 工具调用、结果和审批是否需要持久化，以及恢复所需字段 | 消息 schema、写入时机、索引和会话恢复的整体语义 |
| 生成式输出与运行时 | 工具如何生成或更新输出对象 | 输出对象的专用表面、执行环境、版本和持续维护 |

## 调查注意事项

- “前端弹出确认框”不等于执行端完成鉴权。需要沿调用链确认审批结果是否被可信执行端重新验证。
- “支持 MCP”不等于具有完整工具循环。分别确认目录获取、schema 注入、调用解析、实际执行和结果回注。
- 区分模型理论上可见的工具、当前请求实际注入的工具、最终执行端接受的工具。
- 安全结论应写明攻击前提和信任边界；仅凭危险 API 名称不能直接认定存在可利用问题。

## 横向比较字段

至少记录下列字段：

- 工具来源
- 目录构建位置
- 协议
- 参数校验位置
- 循环驱动者
- 迭代上限
- 审批位置
- 执行域
- 隔离方式
- 结果限制
