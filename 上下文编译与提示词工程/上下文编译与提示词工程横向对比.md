# 上下文编译与提示词工程横向对比

> 对比对象：AIO Hub、SillyTavern、Risuai、VCPChat、VCPToolBox
>
> 对比更新日期：2026-08-31
>
> 依据：本类目 5 篇单项目调查笔记及其复用的对话请求与上下文源码证据
>
> 对比方法：按规则对象、选择和编译顺序、请求层结果、消息生命周期变换、显示投影与调试表面比较；证据只覆盖局部链路的项目明确标记
>
> 对比范围：可持久化或配置驱动的规则、模板、宏、占位符和预处理器的编译与消费面；不比较提交、Provider、流式、会话存储、工具执行和 DOM 实现
>
> 文档定位：实现学习与跨项目横向比较，不作为整改方案

## 结论摘要

- 五个项目都能追到配置或规则驱动的变换进入模型请求或显示投影，但规则对象的完整持久化语义并非都已覆盖。AIO Hub、SillyTavern、Risuai 和 VCPToolBox 有可比较的请求层编译链；VCPChat 当前只确认群聊发言选择和单聊请求附加两个局部交接。
- 请求层的编译单元差异明显：AIO Hub 用可排序处理器管道，SillyTavern 在生成函数中汇合多类规则，Risuai 用模板卡片或旧式分组排序，VCPToolBox 把预设和预处理器串成单次网关请求变换。
- 同一规则系统不必只改变 prompt。SillyTavern 的正则明确分为请求、权威消息写回和显示投影；Risuai 已确认请求前和输出写回作用点，但显示模式尚未追到消费者；VCPToolBox 把初始请求、递归工具消息和客户端投影分成不同数组或通道。
- 最接近最终输入的调试面也不同：AIO Hub 的上下文分析器重跑管道，SillyTavern 留存 itemized prompt，Risuai 提供 requestChatData 数组预览，VCPToolBox 保留首次 fetch 前快照。它们都不能在现有证据下等同于所有条件下的最终网络 payload。

## 对比边界

本类以“规则对象或配置如何被选择并编译到哪个消费面”为中心。对话请求与上下文保留提交、任务和执行主链中的交接点；会话与消息管理保留权威对象的 schema 和持久化；消息渲染器保留 Markdown、DOM 和流式重绘。固定 system prompt、历史截断、检索或工具执行只有在作为规则编译输入或结果时才在这里出现。

## 规则对象与选择范围

| 项目 | 已确认的主要对象 | 已确认的作用域或选择条件 | 证据完整度 |
| --- | --- | --- | --- |
| AIO Hub | 世界书、会话变量、Recall 占位符、压缩节点、管道正则和预设 | 世界书可按绑定、关键词、正则、概率、深度等条件选择；变量沿活动分支回放；压缩只作用活动路径 | 世界书、变量、Recall 和压缩较完整；正则/预设对象语义未覆盖 |
| SillyTavern | 正则、宏、World Info、角色 depth prompt、扩展 prompt、生成拦截器 | 正则按消息位置和标记分流；World Info 扫描聊天内容并按位置注入；拦截器按 manifest 顺序 | 对象存储、完整命中和冲突规则未覆盖 |
| Risuai | 模板卡片、旧式分组顺序、lorebook、触发脚本、Lua、正则脚本 | 模板决定分组顺序；lorebook 按位置、深度和角色进入不同桶；脚本按 start/request/output 等阶段运行 | 模板和请求链已确认；对象 schema 与显示脚本消费者未覆盖 |
| VCPChat | 群聊模式策略、tag/概率规则、requestContext 附加 | 模式按成员、当前消息和内存历史选择发言者；单聊清理未设置参数并附加上下文 | 仅局部链路；未确认完整规则资产与单聊编译 |
| VCPToolBox | VCPTavern 预设、系统占位符、插件预处理器 | 预设和多类占位符限制在 system 或可信系统前缀消息；插件有保存的优先序 | 请求内选择和顺序较完整；通用对象持久化未覆盖 |

## 编译顺序与请求层结果

| 项目 | 已确认的主要顺序 | 模型可见结果的交接 |
| --- | --- | --- |
| AIO Hub | 会话加载应用压缩遮罩后，按 priority 运行正则、转写、世界书、预设、Recall、变量、Token 限制、格式化和附件处理 | 管道产出交给请求执行器；最终 SDK 消息和 Provider payload 未核实 |
| SillyTavern | 历史 prompt 正则、World Info、系统与扩展字符串、格式转换和预算裁剪后，再允许事件替换整体 prompt | text completion 形成 finalPrompt；OpenAI 走独立消息准备路径 |
| Risuai | 规则来源进入分组桶，历史经 editprocess，按模板或 formatingOrder 拼装，再过 depth prompt、Lua editRequest、请求触发脚本和 reformater | requestChatData 收到的数组是已确认请求层依据；Provider 适配后形状另属请求类目 |
| VCPChat | 群聊先选择并排序发言者，再按当前 groupHistory 为各 agent 构建上下文；单聊只确认参数清理和 requestContext 附加 | 未确认完整最终消息数组或 system prompt |
| VCPToolBox | 裁剪、顶层标记消费、预设注入、变量展开、多模态与插件预处理、检测器和角色拆分 | processedMessages 写回 originalBody.messages 并构造首次上游请求 |

## 消息生命周期与显示投影

| 项目 | 请求之外的已确认变换 | 显示层边界 |
| --- | --- | --- |
| AIO Hub | 压缩节点遮罩原历史、保留摘要；变量快照写在消息元数据 | 只确认压缩消息的视觉标记，未确认其他规则的显示专用作用点 |
| SillyTavern | 无标记正则生成后清洗并写回 chat[]；promptOnly 只影响本次 prompt | markdownOnly 正则只进入 Markdown 格式化 |
| Risuai | editoutput 改写流式占位消息；输出脚本在流结束后运行 | editdisplay 已声明但未定位消费者 |
| VCPChat | 后续 agent 会看到同次串行群聊中已更新的内存历史 | 本次未找到独立显示层规则 |
| VCPToolBox | 工具循环维护独立消息数组，不写回跨请求会话 | 推理包装和 VCP 工具信息只投影到 SSE/JSON 客户端输出 |

## 调试与可解释性

| 项目 | 已确认的观测面 | 已确认边界 |
| --- | --- | --- |
| AIO Hub | 上下文分析器复用接近真实的管道并重算 Token | 预览可能触发转写，且不等于已核实的最终 Provider payload |
| SillyTavern | 控制台 prompt、IndexedDB itemized prompts 和消息 Prompt 按钮 | 未确认逐规则命中或各 API 路径与网络负载完全一致 |
| Risuai | DevTool/快捷键 preview、带 chatId 的 fetch 日志和源码日志 | 未确认预览是否覆盖请求脚本、reformater 后结果和全部规则组合 |
| VCPChat | 静态路径和未引用实现的对照 | 未确认 prompt 预览、编译快照或运行时 trace |
| VCPToolBox | finalContextStore 的首次请求快照和可选 ChatLog | 快照最多五组且不含工具递归；ChatLog 默认关闭 |

## 已确认边界与未验证事项

- VCPChat 当前只能作为局部选择和请求变换样本，不能据此与四个完整请求层样本比较规则资产的持久化、模板或最终消息数组。
- 所有项目的编辑器交互、规则实际命中、异步脚本组合和最终 Provider payload 的运行时一致性，仍以各单项目笔记的未验证事项为准。
- 正则不是独立顶层分类依据。同一规则需要按其进入请求、写回权威消息或仅投影显示的结果分别连接相邻类目。
