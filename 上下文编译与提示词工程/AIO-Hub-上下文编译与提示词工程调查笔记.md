## 结论摘要

- 上下文是有顺序的编译产物：默认管道包含会话加载、异步结果、正则、转写、世界书、预设组装、Recall、变量、预算、格式化与附件解析共 11 个处理器，启停与顺序保存到 `llm-chat/pipeline-settings.json`。
- 预设正文可以拆成可启停片段，每段有多个版本并选择一个版本；运行时先编译有效正文，再检测工具宏、展开宏、解析附件并注入。禁用消息组会屏蔽整组，单选组出现多个启用成员会抛配置错误。
- 动态锚点按有效历史中最后的用户、助手或任意消息定位，保留工具原角色以保护完整调用区段。找不到目标就跳过；落入完整工具链时移到边界，工具结果未齐且要求尾部注入时跳过。
- 上下文缓存优化通过稳定前缀和后置动态参考块降低前缀变化：自动工具定义/用法与运行环境分开，自动 Recall 可后移；手写工具宏和手写 Recall 占位符保留作者位置。它改变请求排列，并未直接控制 Provider 缓存命中。
- 上下文分析包含两条证据链：按当前配置重建的预览，与协议适配后捕获的有限实发快照。两者各有来源、预算和隐私边界，预览不能作为历史请求原样回放。

## 系统边界与规则编译主链

```text
Agent/用户档案/全局设置 + 活动路径
  -> 会话加载：启停、压缩遮罩、工具原角色、虚拟文本附件
  -> 正则与转写 -> 世界书
  -> 消息组有效性 -> 模型匹配 -> 组合正文
  -> 工具宏补位 -> 宏展开 -> 深度/静态锚点/动态历史锚点组装
  -> Recall -> 会话变量 -> Token 限制 -> 格式化 -> 附件
  -> 请求适配器 -> 实际发送前观察器 -> 有界快照
```

调度与持久化交接分别见[对话请求与上下文](<../对话请求与上下文/AIO-Hub-对话请求与上下文调查笔记.md>)、[会话与消息管理](<../会话与消息管理/AIO-Hub-会话与消息管理调查笔记.md>)。处理器默认序列见 `src/tools/llm-chat/core/pipeline/defaultProcessors.ts`，实际排序与启停见 `stores/contextPipelineStore.ts`。

## 1. 规则对象与作用域

### 1.1 预设正文、分组与持久化

预设是 Agent 配置中的消息对象。旧式纯正文继续可用；带 `presetComposition` 的对象把片段、版本 ID、当前选择与连接符作为结构保存。编译时只连接启用且选中有效版本的非空片段，并带出片段/版本贡献关系供诊断定位。失效的选中版本、重复 ID 或非法结构抛出配置错误，避免悄悄采用缓存正文（`packages/agent-preset-core/src/index.ts:53-189`）。

消息组先参与启停与单选一致性检查，然后才按当前模型/渠道匹配；被禁用或匹配失败的消息保留在结构中但不进入活动正文。预设编译发生在宏检测和宏替换之前，故未选中版本里的工具宏不会阻止实际正文的工具补位。Agent 配置保存和交换需保留组合结构，运行时物化的是请求副本（`src/tools/llm-chat/core/context-processors/injection-assembler.ts:216-259`）。编辑与导入导出往返效果未运行验证。

### 1.2 正则：请求与显示分别消费

请求正则从全局设置、Agent 和用户档案三层收集已启用预设，只选 `applyTo.request` 为真的规则。预设按自身顺序收集，所有规则再按预设优先级、规则顺序稳定排序；每条消息还按角色与距尾部深度过滤，依次替换。多模态数组仅处理首个文本 part；正则编译错误记日志后继续其它规则，global/sticky 表达式每条消息前重置游标（`core/context-processors/regex-processor.ts:31-220`）。

显示层另按 `applyTo.render` 取规则，交给消息渲染处理；请求变换作用于管道消息副本，显示投影有独立消费点，不能将其中一面概括为权威历史已被改写。显示实现见[消息渲染器](<../消息渲染器/AIO-Hub-消息渲染器调查笔记.md>)。本篇未逐项核实正则预设的交换兼容与跨窗口编辑竞争。

### 1.3 世界书、变量与 Recall

世界书合并全局、用户档案与 Agent 绑定，按关键词/正则、概率、深度、过滤、递归、持续/冷却、分组与权重选择条目，再按位置注入；ST 兼容字段只有被运行处理器消费的部分形成实现事实（`core/context-processors/worldbook-processor.ts`）。复杂条件同时命中的顺序、导入往返与运行表现未实测。

会话变量由 Agent 配置启用，在活动路径最近快照后回放变更标签，按定义执行赋值、四则运算与范围约束，再展开读取宏；有变更的消息与压缩锚点保存变量快照。它具有消息元数据写回交接，不能与只改变显示的规则混同（`core/context-processors/variable-processor.ts`）。

Recall 只执行严格占位符，引用集合还须属于当前启用绑定；旧知识库占位符只产生废弃警告。自动补位只补未引用绑定，显式占位符仍在作者指定位置替换。检索结果与空结果直接替换请求副本中的占位文本（`core/context-processors/recall-processor.ts:133-308`）。

## 2. 注入顺序与动态历史锚点

预设先分为骨架消息、深度注入和锚点注入。静态锚点对应预设占位卡；动态锚点从同一份不可变有效历史定位，支持 `last_user`、`last_assistant`、`last_message`。各注入先独立计算边界，再按 order 和原始顺序合成，避免先插入的预设改变后续深度（`packages/agent-preset-core/src/injection-anchors.ts:59-207`）。

工具调用及其连续结果被视作保护区间，即使结果为兼容上游被转换成用户角色，定位仍读取 `_historyRole`。动态的 before 注入若落入区间，移到整条工具链之前；其它注入移到完整结果之后。结果尚未齐全时没有安全尾部，跳过该次注入并记诊断。缺少目标同样跳过，不自动追加到尾部。深度和高级深度也应用保护区间规则（同文件 `:69-185`）。

管道后半段的 Recall、变量、Token 限制和格式化仍可继续变换组装结果；后续预算裁剪可能改变最终网络消息。因此锚点诊断说明的是组装阶段，而非最终字节排列的充分证据。

## 3. 上下文缓存优化与动静分离

启用 `parameters.contextCacheOptimization.enabled` 后，组装器先在有效历史上计算安全落点并缓存到本次共享数据。尾部为普通用户/助手时放在其前，尾部为工具或带调用的助手时寻求工具链后的落点；定位失败保留原注入方式并记录原因（`core/context-utils/runtime-context.ts:27-84`）。

自动工具补位仍受“启用工具调用、允许缺宏补位、活动预设缺少三个工具宏”的共同条件控制。优化生效且落点可用时，工具定义和用法放在稳定 system 消息，运行环境放在靠近尾部的 user 参考块；没有安全落点时沿用合并补位。作者已写入任一工具宏时保留其显式布局，不额外补齐其余宏（`core/context-processors/injection-assembler.ts:261-379`）。

自动 Recall 也优先使用该安全落点，包成 `<runtime-context>` 参考块；空检索结果移除自动块。显式占位符照常原位替换。系统头部另有稳定说明，提醒模型运行环境按参考数据读取，权限与执行规则仍由系统和预设指令决定（`runtime-context.ts:87-129`；`recall-processor.ts:157-225,281-307`）。

时间显示窗口对预设宏上下文单独冻结，先计算有效时间（含虚拟时间偏移）再向下取整到 5、10、30 或 60 分钟窗口。该调用读取时间窗口字段，不额外要求总开关；其影响范围是此次预设日期时间宏，不修改系统时钟、历史时间戳和其它调用场景的宏上下文（`injection-assembler.ts:311-325`；`macro-engine/macros/datetime.ts:33-80`）。

这里没有向上游承诺某个缓存前缀，也未保证缓存命中率提高。实际命中还依赖最终消息、模型、路由与 Provider 返回的 usage，需结合实发记录区分本地公共前缀估算与服务端报告。

## 4. 消息生命周期与压缩交接

压缩以独立摘要请求生成一条可启停的消息树节点，保存被遮罩节点 ID，原消息保留。后续会话加载器按启用摘要应用遮罩，禁用即可让原消息回到上下文；连续压缩把旧摘要当作前情并一并遮罩。摘要输入包含虚拟文本附件，提交摘要节点前等待 Token 计算并检查取消，取消不留下半成品摘要（`composables/features/useContextCompressor.ts:214-273,280-416,510-654`）。

压缩任务按会话共享 Promise；发送前检查等待已有任务，完成后自动检查以异步方式启动。配置仍从当前选中 Agent 取值，Token 优先取全局当前统计；摘要模型则优先显式摘要绑定，其次目标路径最近助手的请求绑定，最后回退 Agent。前台状态错位的静态边界仍主要落在配置与阈值统计，不能笼统称全部都由前台模型决定。具体执行见[对话请求与上下文](<../对话请求与上下文/AIO-Hub-对话请求与上下文调查笔记.md>)。

## 5. 预览、实发快照与可解释性

预览按所选节点和当前有效配置重跑管道，也可加入待发送输入。它不启动转写；变量处理器仍可更新与历史节点共享的元数据，不能称完全无状态。统计用途还延后读取/编码媒体，依据元数据或已缓存切片计划估算并标记估计。它仍会执行适用的规则与 Recall，因此属于构建预览而非纯粹读取历史请求（`composables/chat/useChatExecutor.ts:306-497`）。

实际请求由单节点执行器安装追踪器，并通过 `requestCapture` 接入协议适配后的发送观察器。记录器关联请求、尝试、来源消息、宏展开、预设片段和处理器变化；捕获请求体及来源映射，不记录 URL 与 headers。请求结束记录完成、失败或取消；服务端 usage 与本地估计分开保存，多段响应共用请求并关联多个节点（`services/requestSnapshotRecorder.ts:23-137`；`composables/chat/useSingleNodeExecutor.ts:145-193,470-500`）。

记录默认启用，文本预览默认关闭；快照不是完整网络日志。单会话最多 10 次尝试、4 MiB，单尝试 1 MiB；超量先删文本预览，再删来源/变换，最终降成摘要。持久化、清空与迟到写入抑制见[会话与消息管理](<../会话与消息管理/AIO-Hub-会话与消息管理调查笔记.md>)。缓存视图属于这些有限记录的诊断投影，不能用公共前缀估算代替 Provider 实际缓存计费。

## 6. 失败、设计取舍与未验证事项

- 组合正文和单选组配置错误会阻止该次构建；正则单规则错误记录后继续，动态锚点缺目标或工具结果未齐采用跳过并诊断。
- 手动压缩跳过自动阈值和自动触发开关，但执行入口仍检查压缩总开关；最近消息保护区继续生效。保存 Token 数是被遮罩消息原量，不扣新摘要，不能解读为净节省。
- 组合预设编辑、版本选择、跨端交换与 ST 导入往返未运行；只确认桌面请求调用共享编译核心，移动端具体接线未逐项调查。
- 世界书复杂命中、多分支变量回放、并行压缩与取消竞态、媒体切片/转写以及真实 Provider 缓存 usage 未运行验证。
- 本篇覆盖请求编译与消息元数据交接；界面编辑器、消息 DOM 和检索算法内部细节由相邻类别承接。
