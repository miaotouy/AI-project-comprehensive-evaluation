# 上下文编译与提示词工程调查指南

本指南用于调查可编辑、可持久化的规则、模板、宏、占位符或预处理器，如何按作用域、角色、深度和阶段编译，并改变模型请求、权威消息或显示投影。通用写作、元数据、深度和证据要求见 [`../AGENTS.md`](../AGENTS.md)。

本类不以正则、模板或脚本的实现形式划分范围；分类依据是规则对象及其编译结果的消费面。普通固定 system prompt、一次性用户输入、历史截断、检索候选和工具执行不因参与请求而自动进入本类。

## 调查目标

走通至少一条“规则对象创建或加载 -> 作用域与启用条件判定 -> 变量、宏或占位符展开 -> 按阶段与顺序变换 -> 请求、权威消息或显示投影消费”的链路。规则仅在配置界面或数据结构中出现、但本次未追到实际消费位置时，应明确标为未确认。

## 必查问题

1. **规则对象与权威源**：规则、模板、宏、占位符或预处理器保存在哪里？其 schema、版本、启停状态和导入导出语义是什么？
2. **作用域与选择条件**：规则如何绑定角色、会话、预设、群组、渠道、模型、消息类型或用户？优先级、互斥、白名单、概率、关键词、深度和冷却等条件如何影响命中？
3. **编译阶段与顺序**：历史选择、变量展开、宏替换、规则匹配、模板拼装、格式化和预算裁剪各处于什么顺序？多个规则冲突时按什么顺序合成？
4. **请求层编译**：哪些结果进入最终模型消息、system prompt、工具说明或 Provider payload？应以最终请求或其紧邻构建器为准，不以编辑器预览代替。
5. **消息生命周期变换**：规则是否在生成前后改写权威消息、生成结果或后续历史？本类记录规则与交接时机；消息 schema、写回和恢复语义链接会话与消息管理或生成式输出与运行时。
6. **显示层投影**：规则是否只改变 Markdown、文本或 DOM，而不改变权威消息和模型请求？这类规则在本类说明对象和分流条件，显示实现链接消息渲染器。
7. **可解释与调试表面**：是否能查看命中规则、展开变量、编译后的 prompt、最终消息数组、差异或 trace？调试快照是实时权威结果还是有限采样？
8. **失败、更新与边界**：规则解析、变量缺失、脚本错误、循环替换和版本更新如何收口？哪些命中、编辑器交互和多作用点组合尚未运行验证？

## 推荐结构

```md
## 结论摘要
## 系统边界与规则编译主链
## 1. 规则对象、权威源与作用域
## 2. 选择条件、优先级与编译顺序
## 3. 请求层编译与模型可见结果
## 4. 消息生命周期变换与交接
## 5. 显示层投影与消息渲染器交接
## 6. 调试、预览与可解释性
## 7. 失败、更新与已确认边界
## 8. 未验证事项
## 9. 关键源码索引
```

## 与相邻类目的边界

| 相邻类目 | 本类目记录 | 留在相邻类目的内容 |
|---|---|---|
| 对话请求与上下文 | 规则何时编译、编译后的请求层结果及其交接 | 提交、任务状态、Provider 调用、流式消费、取消、重试、并发和最终回写 |
| 会话与消息管理 | 规则改变权威历史的条件和交接 | 会话与消息 schema、CRUD、分支、索引、迁移和恢复 |
| 消息渲染器 | 显示规则的对象、选择条件及其不进入请求/权威消息的边界 | 内容解析、DOM、滚动、流式重绘和显示状态 |
| Agent 角色 | 角色如何选择或参数化规则，并进入编译结果 | 角色实体、资产、配置界面和导入导出 |
| 检索增强与认知编排 | 检索结果被规则或占位符消费的位置 | 资产摄取、索引、查询、候选、重排和检索循环 |
| Agent 工具 | 工具说明或结果如何由规则进入模型输入 | 工具注册、筛选、执行、审批和循环内部语义 |

## 调查注意事项

- 区分配置中存在、预览中出现和最终请求实际携带三种证据，不能互相替代。
- 同一规则可以有请求层、消息生命周期和显示层多个作用点；按每个结果的去向记录，不为正则重复建立三套对象描述。
- 显示层规则即使与请求层共用同一配置，也不能据此推断它改写模型输入或权威消息。
- 变量、宏或脚本的静态展开顺序可由代码确认；规则实际命中、编辑器行为、异步脚本和多作用点交互需要运行验证。

## 横向比较字段

至少记录：规则对象与权威源、持久化与导入导出、作用域、选择条件、排序与冲突规则、变量/宏展开、请求层结果、消息写回结果、显示投影结果、调试表面、错误收口和未验证事项。
